## 1. 학습 목표 제안 (블룸 분류)

### 학습 목표 5개

| # | 학습 목표 (블룸 분류) | 동사 | 설명 |
|---|----------------------|------|------|
| LO1 | **이해**: AMBA AHB 프로토콜의 설계 철학과 적용 시나리오를 구분할 수 있다 | Distinguish | Ch15 자체 프로토콜 → AHB 선택 동기를 이해하고, AHB/APB/AXI 적용 케이스 구분 (16.1~16.2) |
| LO2 | **적용**: HADDR/HTRANS/HWRITE/HWDATA/HREADY 신호를 조합하여 마스터-슬레이브 핸드셰이크를 설계할 수 있다 | Design | 신호 7개를 이해하고, 타이밍 다이어그램에서 신호 시퀀스 해석 (16.3~16.4) |
| LO3 | **적용**: AHB Master 신호 생성 로직(요청→주소→쓰기→대기)을 FSM으로 구현할 수 있다 | Implement | 캐시 미스 시 메모리 요청을 AHB Master 신호로 변환하는 상태 머신 설계 (16.5) |
| LO4 | **분석**: AHB Slave의 HREADY 신호 처리와 웨이트 스테이트 동작을 분석하여 프로토콜 위반 사례를 진단할 수 있다 | Analyze | Slave 동작 코드를 읽고, HREADY=0일 때 신호 보유 규칙 검증 (16.6) |
| LO5 | **분석/평가**: 전송 타입(IDLE/NONSEQ/SEQ/BUSY)을 선택하여 다양한 버스 시나리오(단일전송/연속전송/대역폭 절감)를 평가할 수 있다 | Evaluate | 16.4 타이밍 다이어그램을 분석하여 각 전송 타입의 용도와 한계 파악 (16.4, 16.8) |

### 블룸 수준 분포 및 의의

**분포**: 이해(1) · 적용(2) · 분석(2) · 평가(1) → **새로운 도메인(AMBA)의 점진적 습득**

- **LO1 (이해)**: Ch15 맥락에서 "왜 새로운 버스가 필요한가"의 동기 부여
- **LO2-3 (적용)**: 신호 해석 및 FSM 구현으로 실무적 능력 배양
- **LO4-5 (분석/평가)**: 프로토콜 올바름 판단 및 최적 선택 능력 (Part 6 이후 자율 설계 준비)

**Part 5→6 연계성**: Ch15의 "자체 프로토콜 평가(평가)" → Ch16의 "표준 프로토콜 선택(이해)" → Ch16 후반의 "프로토콜 올바름 판단(분석/평가)" 구조로 블룸 분류 자연스러움

## 2. 절별 학습 흐름 설계

### 학습 흐름 도표

```
16.1 (도입)          → Ch15 자체 프로토콜 한계 회상
    ↓ 동기 부여         "왜 표준화가 필요한가"

16.2 (개념 도입)      → AHB/APB/AXI 3가지 선택지
    ↓ 좁혀지는 범위    "이 책에서는 AHB-Lite"

16.3 (신규 개념 1)    → HADDR/HTRANS/HWRITE 신호 정의
    ↓ 점진적 도입      표 → 그림 → 예시 (Gradual Reveal)

16.4 (신규 개념 2)    → 전송 타입 4가지 + 파이프라인 전송 + 웨이트 스테이트
    ↓ 타이밍 이해      SVG 다이어그램(IDLE→NONSEQ→SEQ→BUSY)

16.5 (설계 1)        → AHB Master 설계 (캐시 미스 핸들러 변환)
    ↓ FSM 구현         상태 전이 + 신호 매핑 + 코드 (Ch08 FSM 경험 활용)

16.6 (설계 2)        → AHB Slave 설계 (SRAM + 응답 처리)
    ↓ 프로토콜 규칙    HREADY 보유 규칙 (가장 흔한 오류 지점)

16.7 (통합)          → 인터커넥트 설계 (디코더 + 멀티플렉서 + 버스 중재)
    ↓ 아키텍처 이해    3개 모듈 협력 구조

16.8 (검증)          → 시뮬레이션 + SVA 기초
    ↓ 프로토콜 체크    버스 파형 분석 + 어서션으로 규칙 검증

16.9 (정리)          → Part 6 요약 + Ch17 예고
    ↓ 기초 확인        "다음: APB 브리지로 주변 장치 연결"
```

#### 16.1절 — 왜 버스가 필요한가

| 흐름 단계 | 구현 요소 | 구체적 설명 |
|----------|----------|-----------|

| **개념** | 3개 동기 설명 | ①IP 재사용(여러 회사의 메모리/UART를 그대로 사용), ②팀 협업(인터페이스 사전 정의), ③유지보수(표준 문서로 학습 곡선 단축) |

#### 16.3절 — AHB 신호 정의

| 흐름 단계 | 구현 요소 | 구체적 설명 |
|----------|----------|-----------|
| **도입** | "7개 신호만 기억하면 된다" | 대비: ISA 47개 명령어 vs AHB 7개 신호 (안심 문구) |
| **개념** | Gradual Reveal (3단계) | ① Master 신호 4개(HADDR, HTRANS, HWRITE, HWDATA) 정의 표 · ② Slave 신호 3개(HREADY, HRDATA, HRESP) 정의 표 · ③ "핸드셰이크란?" 비유 |
| **예시** | 신호 매핑 | 각 신호와 Ch15 자체 프로토콜의 신호 대응(req→HADDR 준비, ack→HREADY 확인) |
| **실습** | "신호의미 확인" 미니실습 | Ch15 메모리 컨트롤러 코드의 핸드셰이크를 AHB 신호로 다시 쓰는 연습 (답안 제시) |
| **정리** | 신호 용도 요약박스 | "HADDR 주소, HTRANS 전송타입, HWRITE 읽기/쓰기, HREADY 준비 완료" |

**특징**:
- **Gradual Reveal**: "한 번에 7개 신호를 외워야 한다" 불안 제거. 마스터→슬레이브→사용법 순으로 단계적 공개
- **Ch15 연결**: 자체 프로토콜과 1:1 대응으로 기존 지식 활용
- **실습은 개념 확인 수준**: 직접 코드 수정은 16.5로 위임

#### 16.4절 — AHB 프로토콜 타이밍

| 흐름 단계 | 구현 요소 | 구체적 설명 |
|----------|----------|-----------|
| **도입** | "신호만 아는 것이 아니라, **순서**가 중요합니다" | Ch06 단일사이클 데이터패스와 비유: 신호는 와이어, 타이밍은 FSM |
| **개념** | 3개 핵심 개념 | ① 전송 타입 4가지 (IDLE/NONSEQ/SEQ/BUSY) ② 파이프라인 전송 개념 ③ 웨이트 스테이트(HREADY=0 처리) |
| **예시** | 4개 SVG 다이어그램 | ① IDLE (아무것도 하지 않음) ② NONSEQ (새 주소, 기준 전송) ③ SEQ (연속 전송) ④ SEQ+대기 (웨이트 스테이트 with HREADY=0) |
| **실습** | 타이밍 읽기 | SVG를 보고 "이 다이어그램에서 HADDR는 언제 바뀌는가?" 등 10개 질문 제시 (답안 미제시, 16.8 검증에서 검증) |
| **정리** | "아하!" 박스 | "파이프라인 전송: Master가 다음 주소를 준비하는 동안, Slave는 현재 데이터를 반환한다" |

**특징**:
- **신호 → 타이밍의 계층적 학습**: 16.3에서 신호, 16.4에서 순서
- **파이프라인 전송 개념**: Ch09 파이프라인과 연결. "메모리 요청도 파이프라인이 있다!"
- **웨이트 스테이트**: 가장 흔한 오류 원인(HREADY=0에서 신호 변경). 별도 단계로 강조

#### 16.5절 — AHB Master 설계

| 흐름 단계 | 구현 요소 | 구체적 설명 |
|----------|----------|-----------|
| **도입** | "Ch15 메모리 컨트롤러의 Master 로직을 AHB로 재설계합니다" | 2줄 설명: "req → HADDR 준비", "ack → HREADY 수신" |
| **개념** | Master FSM 4~5 상태 | ① IDLE (요청 대기) ② ADDR (주소 설정) ③ WRITE/READ (데이터 전송) ④ READY (응답 확인) |
| **예시** | 상태 전이 표 | 각 상태에서 Master 신호(HADDR, HTRANS, HWRITE, HWDATA) 값 설정 |
| **실습** | "직접 코드 작성" | Ch15 cache_system.sv의 Master 로직을 AHB 신호로 수정하는 과제 (단, 답안은 16.5절 마지막 제시) |
| **정리** | 코드 발췌 + 해설 | "Master FSM은 단순히 주소/데이터를 버스에 올려두고 준비 신호를 기다리는 것입니다" |

**특징**:
- **Ch08 FSM 경험 활용**: "FSM이 이전에도 써봤다"는 자신감 재활용
- **직접 코드 작성**: 16.3의 "신호 확인 수준"에서 한 단계 업그레이드. 적용(Apply) 블룸 수준 달성

#### 16.6절 — AHB Slave 설계

| 흐름 단계 | 구현 요소 | 구체적 설명 |
|----------|----------|-----------|
| **도입** | "Slave는 Master보다 규칙이 까다롭습니다" | 핵심 규칙 1개: "HREADY=0일 때는 HADDR/HWRITE를 바꾸면 안 됩니다" |
| **개념** | Slave의 3개 책임 | ① HADDR 및 제어 신호 보유(HREADY=0) ② 데이터 읽기 시 1사이클 지연 고려 ③ HRESP 응답(OKAY or ERROR) |
| **예시** | SRAM 컨트롤러 FSM | "Master 요청 수신 → SRAM 주소 설정 → 1사이클 대기(HREADY=0) → 데이터 반환(HREADY=1)" |
| **실습** | "오류 찾기" | Slave 코드 3가지 (올바른 것, 신호 변경 오류, 응답 지연 오류)를 보고 오류 찾는 과제 |
| **정리** | "가장 흔한 오류" 박스 | 위반 사례 2개: ①HREADY=0에서 신호 변경 ②SRAM 읽기 지연을 고려하지 않은 설계 |

**특징**:
- **"규칙 준수" 강조**: 이전 절들의 "개념 이해"에서 "정확한 구현"으로 상향
- **오류 찾기 실습**: Analyze 블룸 수준. 정답 코드 쓰기보다 오류 진단이 실무에서 중요
- **불안 지점 #7 대응**: "AMBA 신호가 복잡하다"는 불안 → "규칙은 단 2개"로 축약

#### 16.7절 — AHB 인터커넥트

| 흐름 단계 | 구현 요소 | 구체적 설명 |
|----------|----------|-----------|

| **개념** | 3개 기본 모듈 | ① 주소 디코더(HADDR의 상위비트 → Slave 선택) ② 쓰기 멀티플렉서(여러 Slave 중 응답 선택) ③ 기본 중재기(Basys 3은 1개 마스터이므로 단순화) |

| **실습** | 실습은 16.8로 위임 | 대신 "메모리 맵에서 Slave 선택 규칙을 유도해보세요" 사고 실습 제시 |
| **정리** | "Basys 3은 간단합니다" | "1개 Master + 3개 Slave(IMEM, DMEM, Peripheral) 고정. 중재기 불필요" |

**특징**:
- **스케일 조절**: "멀티 마스터"는 Part 9에서. 이 책의 범위는 "1 Master 고정"
- **인지 부하 관리**: 전체 SoC 아키텍처를 보는 단계. 16.8의 시뮬레이션 이전에 구조 이해

#### 16.8절 — AHB 버스 시뮬레이션 검증

| 흐름 단계 | 구현 요소 | 구체적 설명 |
|----------|----------|-----------|
| **도입** | "설계한 버스가 정말 올바른가 검증합니다" | 테스트벤치 작성으로 신호 파형 확인 |
| **개념** | 2개 검증 방법 | ① VCD 파형 분석 (직관적, 초보자 친화) ② SVA 어서션 (자동 체크, 산업 표준) |
| **예시** | 5가지 테스트 시나리오 | ① IDLE 상태 ② NONSEQ 단일 읽기 ③ SEQ 연속 전송 ④ 웨이트 스테이트(HREADY=0) ⑤ 오류 응답(HRESP=ERROR) |
| **실습** | 파형 읽기 + SVA 작성 | ① $dumpfile 파형을 보고 신호 시퀀스 확인 ② SVA 어서션 3개 작성: "HREADY=0이면 HADDR 불변", "HRDATA 유효는 HREADY=1과 동기" 등 |
| **정리** | "파형이 설계서와 일치합니다" | 검증 완료 체크리스트 제시 |

**특징**:
- **시각적 검증**: 파형을 직접 보는 경험으로 프로토콜 이해 고착
- **SVA 입문**: Part 4(Ch09~11)에서 경험한 파이프라인 검증을 프로토콜에 확대
- **테스트 설계 원칙**: 정상 케이스 + 웨이트 + 오류 응답으로 3단계

→ 각 파트마다 "낮은 수준 재진입 → 상향"의 나선형 구조로, 학습자의 심리적 부담 최소화

### 인지 부하 관리

- **기존 지식 활용**: Ch15 프로토콜 ↔ AHB 신호 매핑, Ch08 FSM ↔ Master/Slave FSM
- **실습 위임**: 개념 절(16.1~16.4)도 자가 점검 문항으로 능동적 읽기 유도, 실제 코드는 16.5부터
