# Ch19 Phase 1 기획 — 교육심리전문가 Briefing

## 역할 정의

교육심리전문가로서 당신은:
- 학습 동기 유지 전략 수립
- 학습 불안 지점 감지 및 완화
- 자기효능감 관리: 첫 실습은 반드시 성공하도록
- 감정 곡선 분석: 호기심(Curiosity) → 불안(Anxiety) → 이해(Understanding) → 성취감(Accomplishment)
- 실패 정상화 및 메타인지 촉진 장치 설계

## 당신의 Task

### Task 1: 학습 불안 지점 Top 3 식별 및 완화책

**방법:**
1. Ch19의 각 핵심 개념을 분석
2. "학생이 이해하지 못할 가능성"을 평가
3. 왜 어려운지 심리 근거 제시
4. 각 불안을 해소할 교육 전략 제안

**예시 분석:**

**불안점 #1: 우선순위 인코더의 추상성**
```
개념: 8개 interrupt 소스 → 우선순위 판정 → 1개 cause_code
심리 근거:
  - 학생이 "왜 8개가 동시에 올 수 있지?"라고 혼란
  - 하드웨어 동작(동시)과 소프트웨어 사고(순차)의 gap
  - 우선순위 규칙이 "고정"이라는 제약의 필요성 모호

심각도: ⭐⭐⭐⭐ (높음)

완화 전략:
  a) 비유: 응급실 트리아주(우선순위 분류) + 대기 줄
  b) 단계적 예제: 먼저 2개 인터럽트 → 4개 → 8개
  c) 인터랙션: "만약 우선순위가 없다면?" 반사실적 사고
```

**불안점 #2: 벡터화 주소의 비트 시프트 (<< 2)**
```
개념: cause_code → 주소 오프셋 (cause << 2)
심리 근거:
  - 비트 시프트 자체는 쉽지만, "왜 2칸?"이 명확하지 않음
  - 32비트 주소 alignment 개념과의 연결 필요
  - mtvec[31:2]와 (cause << 2)의 조합 형태 복잡

심각도: ⭐⭐⭐ (중간)

완화 전략:
  a) 그림: 메모리 맵 + 각 주소의 4바이트 단위
  b) 계산: 구체적 예 (cause=7 → 7<<2=28 → 0x1C)
  c) 왜 2칸?: 32비트=4바이트 → byte 주소 단위 필요
```

**불안점 #3: 중첩 인터럽트의 메모리 구조**
```
개념:
  - Handler 내부에서 또 다른 interrupt 발생
  - mepc, mcause, mstatus 스택 저장
  - MPIE(저장된 이전 인터럽트 활성화 상태) 복구

심리 근거:
  - 스택(Stack) 개념과 레지스터의 혼동
  - 3개 값이 동시에 저장되는 순서 모호
  - "왜 MPIE만 따로 관리?"하는 설계 이유 불명

심각도: ⭐⭐⭐⭐⭐ (극높음)

완화 전략:
  a) 스택 비유: 함수 호출 스택 (프로그래밍 경험과 연결)
  b) 그림: 메모리 상태 변화 (t=0 → t=interrupt → t=handler 내)
  c) 단계 설명:
     - Step 1: Interrupt 발생 (mepc, mcause 저장)
     - Step 2: mstatus[MIE]←0 (자동으로 인터럽트 비활성)
     - Step 3: mstatus[MPIE]← 이전 MIE (저장)
     - Step 4: Handler 내 MIE←1 (재활성화 허용)
     - Step 5: MRET (복구)
```

### Task 2: 감정 곡선 설계

**목표:** 각 절에서 예상되는 감정 변화를 그래프 또는 서술로 표현

**감정 5단계:**
1. **호기심** (Curiosity): "우선순위 인코더는 뭐지? 흥미롭네"
2. **혼란** (Confusion): "어? 이게 동시에 어떻게 작동하지?"
3. **불안** (Anxiety): "이걸 내가 설계할 수 있을까?"
4. **이해** (Understanding): "아, 우선순위를 이렇게 정하는구나"
5. **성취감** (Accomplishment): "중첩 인터럽트까지 구현했다!"

**섹션별 감정 곡선 예상:**

```
19.1 (개요):        호기심 ↑
19.2 (벡터화 주소):  혼란 →↑ (그림이 도움)
19.3 (우선순위):    불안 ↑ (코드가 필요)
19.4 (Trap 전이):   호기심 ↑ (간단함)
19.5 (중첩 인터럽트): 불안 ↑↑↑ (스택 개념 + 복합성)
19.6 (컨트롤러):    이해 ↑ (종합)
19.7 (실습/C코드):  성취감 ↑↑ (처음 작동 시 극강)
```

**각 섹션별 상세 분석:**

| 섹션 | 감정 상태 | 원인 | 완화 방법 |
|------|----------|------|---------|
| 19.1 | Curiosity | "신규 개념이 많다" | 선수 지식 복습 |
| 19.2 | Confusion | "(cause << 2)의 의미" | 그림 + 계산 예제 |
| 19.3 | Anxiety | "우선순위 로직" | 비유 + 단계적 예제 |
| 19.4 | Relief | "FSM은 익숙함" | 빠른 진행 |
| 19.5 | Anxiety | "스택과 복합 상태" | 메모리 맵 + 단계 추적 |
| 19.6 | Understanding | "종합 설계 패턴" | 코드 구조 강조 |
| 19.7 | Accomplishment | "처음 인터럽트 발생" | 데모(Basys 3) |

### Task 3: 자기효능감 관리 — 첫 성공 지점

**목표:** 학생이 "아, 나도 할 수 있겠다"를 깨닫는 지점 설정

**질문:**
- 첫 성공 경험은 언제 올 것인가?
- 너무 늦으면 중간에 포기할 위험은?
- 너무 빠르면 "이건 쉬운 거 아닌가"라고 착각할 위험은?

**제안 시나리오:**

```
19.3절 말미: 우선순위 인코더 코드 이해 완료
  → "학생: 아, 이건 그냥 if-else로 순서대로 검사하는 거네"
  → 성공감 ⭐⭐⭐⭐ (높음)

19.5절 전: 단순 중첩 인터럽트 예제 (스택 없이)
  → mepc/mcause만 저장하고 복구하는 예제
  → 성공감 ⭐⭐⭐ (중간) — 이전 공식 적용

19.7절: FPGA에서 실제 인터럽트 발생
  → Timer + UART 동시 발생 시 우선순위 확인
  → 성공감 ⭐⭐⭐⭐⭐ (극높음) — 최고 봉우리
```

**위험도 평가:**
- 너무 쉬운가? ❌ (19.3만 해도 어려움)
- 너무 늦은가? ❌ (19.3 말미면 적절)

### Task 4: 메타인지 촉진 장치 설계

**목표:** 학생이 "내가 얼마나 이해했는가?"를 스스로 점검하도록 유도

**메타인지 질문 5~7개:**

1. **19.1 후:** "interrupt와 exception의 차이를 설명할 수 있나?"
2. **19.2 후:** "mtvec MODE=0과 MODE=1의 주소 계산식을 비교할 수 있나?"
3. **19.3 후:** "이 우선순위 인코더에서 MSIP와 MTIP의 우선순위는 누가 더 높은가? 이 규칙은 변경 가능한가?"
4. **19.4 후:** "trap_pc가 발생 직후 mepc에 저장되지 않고 1사이클 지연되는 이유를 추측할 수 있나?"
5. **19.5 후:** "중첩 인터럽트 상황에서 MRET를 3번 실행하면 어디로 돌아갈까? 메모리 맵을 그릴 수 있나?"
6. **19.6 후:** "Interrupt Controller와 Priority Encoder의 관계를 블록 다이어그램으로 그릴 수 있나?"
7. **19.7 후:** "C 코드에서 interrupt handler를 작성할 때, 왜 `volatile` 키워드를 CSR 접근에 사용해야 할까?"

**배치 전략:**
- <aside class="metacognition"> 박스로 각 절 끝에 배치
- 각 박스: 1~2개 질문만 (너무 많으면 피로)
- 직접 답 제시 금지 (스스로 생각하게)
