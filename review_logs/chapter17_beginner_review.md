# Chapter 17 초보자 독자 리뷰
날짜: 2026-03-13

## 종합 이해도: ⭐⭐⭐⭐ (4/5)

전반적으로 매우 잘 구성된 챕터입니다. APB 프로토콜이라는 새로운 개념이 고속도로/골목길 비유 덕분에 자연스럽게 도입되었고, 브리지-UART-GPIO-타이머의 흐름도 논리적으로 연결됩니다. 단, FIFO 내부 구조(원형 버퍼, `$clog2` 포인터 기법)와 W1C 단일 블록의 우선순위 로직은 별도 설명 없이 등장하여 초보자가 막히는 구간이 존재합니다.

## 이해가 어려웠던 부분

1. **FIFO 원형 버퍼 구현 (17.3절, 코드 라인 1034~1076)**: `$clog2(FIFO_DEPTH)+1` 비트 포인터, MSB 비교로 full/empty 판별하는 기법이 설명 없이 코드로 등장합니다. 이 기법은 Verilog 입문 과정에서 다루지 않는 내용으로, 초보자는 포인터가 왜 `FIFO_DEPTH` 비트가 아닌 `FIFO_DEPTH+1` 비트인지, MSB 비교가 왜 full 조건이 되는지 이해하기 어렵습니다.

2. **W1C 단일 `always_ff` 블록의 우선순위 (17.3절, 코드 라인 1132~1145)**: 본문에서 "소프트웨어 클리어가 하드웨어 이벤트 세트보다 높은 우선순위를 가진다"고 설명하지만, 왜 `if-else if` 체인이 우선순위를 만들어 내는지 초보자에게는 직관적이지 않습니다. `if` 브랜치가 먼저 평가되면 `else` 브랜치가 실행되지 않는다는 점, 이것이 하드웨어에서 멀티플렉서로 합성된다는 설명이 보충되면 좋겠습니다.

3. **`valid_reg` 역할 (17.2절, 코드 라인 429, 477~480)**: 변수 선언 주석에 "유효한 전송이 래치됨"이라고만 적혀 있고, FSM next_state 로직에서 `valid_reg`가 연속 전송 처리에 사용된다는 점이 본문에서 설명되지 않았습니다. ST_ACCESS에서 `pready=1` 시 `valid_reg=1`이면 바로 ST_SETUP으로 전이하는 "파이프라인 방지 연속 전송" 경로가 어떤 상황에서 필요한지 추가 설명이 필요합니다.

4. **`prescale_tick`을 `assign`으로 처리하는 이유 (17.5절, 코드 라인 1750)**: `prescale_cnt`는 `always_ff`로 업데이트되는데, `prescale_tick`은 조합 `assign`으로 생성됩니다. 이 방식이 왜 안전한지(동일 클럭에 FSM이 응답하는 타이밍) 초보자는 의아하게 느낄 수 있습니다.

## 설명 없이 등장한 용어

- **`$clog2`**: 17.3절 FIFO 코드에서 `$clog2(FIFO_DEPTH)`가 갑자기 등장합니다. 천장 로그2 함수임을 처음 보는 학생을 위한 설명(또는 각주)이 없습니다.
- **`baud` (보드)**: 17.3절 도입부에서 "115200 baud"라는 단위가 나오지만, baud가 초당 심볼 수(bits per second와 혼용)임을 처음 접하는 학생이 혼동할 수 있습니다. bps와의 관계 설명이 한 줄이라도 있으면 좋겠습니다.
- **`MMIO`(Memory-Mapped I/O)**: 17.6절 C 의사코드 앞에 처음 등장하며 괄호 안에 "메모리 매핑 입출력"이 병기됩니다. 하지만 "왜 일반 메모리 주소처럼 접근하면 UART가 동작하는지"에 대한 한 줄 설명이 없어, Ch16 인터커넥트와의 연결 고리가 흐릿합니다.
- **`ISR`(Interrupt Service Routine)**: 17.5절 면접 포인트 박스에서 등장하는데, 이 챕터에서 처음 나오는 용어입니다. Ch19에서 다룰 내용이지만 간단한 설명이 있으면 더 좋겠습니다.
- **`hsize`**: AHB 신호 중 `hsize`가 브리지 코드에 포트로 있지만 내부에서 실제로 사용되지 않습니다. 왜 포트에는 있지만 로직에 반영되지 않았는지(의도적 단순화인지) 독자가 궁금해할 수 있습니다.

## 비유 평가

### 효과적인 비유

- **고속도로/골목길 (17.1절)**: APB와 AHB의 복잡도 차이를 직관적으로 전달합니다. "나들목=브리지"라는 연결이 17.2절로 자연스럽게 이어져 챕터 전체 구조가 일관됩니다.

- **스위치 패널 (17.4절)**: 방향 레지스터 개념을 "각 스위치 옆의 작은 스위치"로 표현한 것이 탁월합니다. 리셋 시 안전하게 입력으로 초기화한다는 설계 원칙도 비유에서 자연스럽게 도출됩니다.

- **모래시계와 자동 뒤집기 (17.5절)**: 프리스케일러(밸브), AUTO_RELOAD(자동 뒤집기), 인터럽트(알람)의 삼각 관계를 명확하게 전달합니다. 특히 비유의 한계("디지털 타이머는 정확히 동일한 주기를 보장")를 명시한 점이 교육적으로 훌륭합니다.

- **중앙 우체국 (17.6절)**: PRDATA MUX가 "인터폰 시스템"으로 설명된 부분이 적절합니다. `pready_mux = 1'b1` 기본값의 교착 방지 역할도 비유에서 직접 연결됩니다.

### 개선이 필요한 비유

- **모스부호 전신기 (17.3절)**: UART의 비동기 특성(클럭 없이 속도 약속만으로 통신)을 전달하는 의도는 좋습니다. 그러나 "두 기계의 속도가 조금이라도 다르면 신호가 잘못 읽힌다"는 설명은 이후의 16× 오버샘플링 소개와 약간 충돌합니다. 오버샘플링이 바로 이 속도 차이를 일정 범위 내에서 허용하기 위한 기법인데, 비유에서는 이 허용 한계를 암시하지 않아 "그러면 왜 UART를 쓰나?" 하는 의문이 생길 수 있습니다. "속도가 ±2% 이내면 허용된다"는 언급을 비유 단계에서 미리 예고하면 좋겠습니다.

- **비자 발급 창구 (17.2절)**: 입국 심사대 비유는 "프로토콜 변환기"의 역할을 잘 전달합니다. 다만 "외국 여행자"(AHB 마스터)와 "국내 시설"(APB 슬레이브)의 대응이 처음에는 직관적이지 않을 수 있습니다. 고속도로/골목길 비유와 연계(나들목=입국 심사대)를 명시적으로 언급하면 두 비유가 서로를 강화할 수 있습니다.

## 개선 제안

1. **FIFO 구현 앞에 짧은 설명 추가**: "원형 버퍼(Circular Buffer, 순환 버퍼)는 배열의 끝에 도달하면 처음으로 돌아오는 자료 구조입니다. 포인터에 1비트를 추가하면 한 바퀴 차이로 full/empty를 구분할 수 있습니다." 정도의 2~3문장이면 충분합니다. `$clog2`도 각주나 aside로 "SystemVerilog 내장 함수, 인자의 천장 로그2 값 반환 (예: `$clog2(8)=3`)"을 추가해 주십시오.

2. **`valid_reg` 동작 설명 추가**: 17.2절 "핵심 동작 흐름 분석" 단락에 연속 전송 처리 시나리오("전송 A가 완료되기 전에 전송 B가 래치되어 있으면, ACCESS→SETUP으로 즉시 전이")를 한 단락 추가하면 FSM 이해도가 크게 높아집니다.

3. **W1C 우선순위 시각화**: W1C 설명 직후(17.3절, 17.5절)에 타이밍 표나 간단한 의사코드("같은 클럭에 클리어와 세트가 동시에 일어나면? → 클리어 우선")를 추가하면 코드 의미가 즉각 납득됩니다.

4. **MMIO 개념 연결**: 17.6절 C 의사코드 앞에 "Ch16에서 AHB 인터커넥트를 통해 주소 범위를 슬레이브에 배정했습니다. 따라서 소프트웨어에서 해당 주소에 쓰기를 하면 CPU→AHB→브리지→APB→슬레이브 경로로 자동 전달됩니다"라는 한 문장 연결이 있으면 MMIO 개념이 자연스럽게 정착됩니다.

5. **17.7절 타이밍 추적 보조**: 테스트 2(UART 송신)에서 `baud_div=2`를 설정했을 때 몇 클럭 만에 TX FIFO가 비워지는지, 간단한 계산식(10비트 × 16틱 × 2클럭 = 320클럭)을 본문에 넣어 주면 독자가 시뮬레이션 결과를 직접 예측할 수 있어 성취감이 높아집니다.

## SVG 평가

5개의 그림(그림 17-1~17-6) 모두 본문 설명과 연계되어 있으며 figcaption이 충분히 설명적입니다.

- **그림 17-1 (APB 타이밍)**: PSEL=1/PENABLE=0 → PSEL=1/PENABLE=1 전이를 시각적으로 확인할 수 있어 2단계 전송 이해에 결정적으로 도움이 됩니다.
- **그림 17-2 (브리지 FSM)**: ST_IDLE→ST_SETUP→ST_ACCESS 전이와 pready=0 시 웨이트 연장이 한눈에 보입니다.
- **그림 17-3 (UART 블록)**: TX/RX FSM, FIFO, 보드레이트 생성기의 관계가 명확합니다.
- **그림 17-4 (GPIO 블록)**: 2단 동기화기 경로가 입력 측에 명시되고 방향 레지스터가 `gpio_oe`로 연결되는 흐름이 잘 표현되어 있습니다.
- **그림 17-5 (타이머 블록)**: 프리스케일러→카운터→비교기→인터럽트 흐름이 명확합니다. AUTO_RELOAD 피드백 화살표가 있다면 더욱 직관적일 것 같습니다.
- **그림 17-6 (통합 블록)**: `peripheral_top` 내부 구조 전체가 한눈에 보입니다. PRDATA MUX의 위치와 방향이 명확합니다.

## 최종 의견

Chapter 17은 APB 프로토콜이라는 낯선 개념부터 UART, GPIO, 타이머의 실제 구현, 그리고 이를 RISC-V 파이프라인 프로세서에 연결하는 전 과정을 하나의 챕터에서 다룬다는 점에서 분량 대비 밀도가 높습니다. 비유의 품질이 높고 각 절 구조(개념→신호표→FSM/레지스터맵→코드→aside)가 일관되어, 파이프라인 챕터를 이해한 독자라면 충분히 따라올 수 있습니다.

주요 보완 포인트는 세 가지로 압축됩니다.

1. FIFO 원형 버퍼 구현 앞 2~3문장 설명 + `$clog2` aside
2. `valid_reg` 연속 전송 경로 설명 추가
3. W1C `if-else if` 우선순위 의미의 간단한 시각화

이 세 가지가 보완되면 ⭐⭐⭐⭐⭐ 수준에 도달할 수 있습니다. 현재 기준으로는 Verilog 경험이 있는 대학원생이라면 17.3절 FIFO 코드 부분에서 잠시 막힐 수 있으나, 전반적인 흐름을 이해하는 데는 지장이 없습니다.

**승인 조건**: 위 3가지 보완 사항 반영 후 재확인 권고 (현 상태로도 조건부 승인 가능)
