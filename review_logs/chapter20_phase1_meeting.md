## 1. Ch20 개요 및 기술 배경

### Ch20 위치와 의의
- **Part 8 시작** (Ch19 완료 후)
- **선행 지식**: Ch19까지 완전한 5단계 파이프라인 SoC (파이프라인 + 캐시 + AMBA + CSR/예외)
- **대상 독자**: 하드웨어 설계 완료, 이제 FPGA 리소스 제약 내에서 최적화하는 방법 배우기
- **목표**:
  - Vivado 합성 옵션 이해 및 실무 적용
  - 타이밍 제약(XDC) 작성 및 타이밍 분석
  - 임계 경로 식별 및 수동 최적화 기법
  - Basys 3 리소스(LUT, BRAM, FF, DSP) 최적화

### Ch20 핵심 시나리오
- **시작 상태**: Ch19 설계 완료 (단순 합성, 50MHz 가능 여부 미확인)
- **문제**:
  - Vivado 기본 합성으로는 50MHz 달성 불가능 (임계 경로 >40ns)
  - LUT/BRAM 사용률 과다 (70~80%)
  - 메모리 읽기 경로 병목
  - 캐시 미스 FSM 복잡도
- **해결 전략**:
  - 합성 옵션: Retiming 활성화, 리소스 공유 최적화
  - XDC 제약: 클록(create_clock 8ns), 입출력 타이밍
  - 임계 경로 개선:
    - Data forwarding MUX 계층 축소 (EX/MEM/WB 우선순위 재설계)
    - Cache memory 읽기 지연 감소 (BRAM Simple Dual Port 선택)
    - ALU+Shift 조합 최적화
  - 메모리 리소스:
    - IMEM: BRAM 2개 (4KB)
    - DMEM: BRAM 2개 (4KB, D-Cache와 공유 포트 고려)
    - I-Cache: BRAM 1개 + LUTRAM Tag (조합)
    - D-Cache: LUTRAM Data (분산, 조합 읽기) + LUTRAM Tag
- **예상 결과**:
  - 최대 주파수: 65~75MHz (목표 50MHz 초과 달성)
  - LUT 사용률: 60~70% (스릴 확보)
  - 구현 시간: 15~20분 (full implementation)

### 기술 제약사항 (변경 금지)
1. **설계 변경 없음**
   - rv32i_pipeline_complete 아키텍처 유지
   - 포워딩/스톨 로직 변경 불가
   - 캐시 구조 (I/D 분리, 직접매핑/2-way) 변경 불가
2. **부분 최적화만 가능**
   - MUX 깊이 조정 (하드웨어 로직 재배열, 합성 지원)
   - 메모리 추론 타입 선택 (BRAM vs LUTRAM)
   - 파이프라인 깊이 변경 불가
3. **Basys 3 제약**
   - XC7A35T: LUT 20,800개, BRAM 50×36Kb, DSP 90개
   - 타겟: 50MHz (100MHz 클록 2분할, 또는 직접 50MHz)
   - 칩 온도 < 85°C (강화 모드)

## 2. Ch20 학습 목표 (5개, 블룸 분류)

### L1: 이해(Understand) — Vivado 합성 옵션의 의미
"Vivado 합성 옵션 5개(Retiming, FSM Encoding, Keep Hierarchy, Gated Clock Conversion, Resource Sharing)의 동작 원리와 Basys 3에서의 효과를 설명할 수 있다."

**기술 리뷰어 검증**:
- ✅ Retiming: FF-to-FF 경로를 여러 스테이지로 분할, 타이밍 개선
- ✅ FSM Encoding: 원-핫(one-hot)과 바이너리 인코딩 트레이드오프
- ✅ Keep Hierarchy: 서브모듈별 최적화 vs 전역 최적화
- ✅ Gated Clock Conversion: 클록 게이팅 → 다중플렉서 변환
- ✅ Resource Sharing: 여러 연산 (ALU+Shift)을 시간 분할로 공유

### L2: 적용(Apply) — XDC 파일 작성
"create_clock, create_generated_clock, set_input_delay, set_output_delay 네 가지 XDC 명령어를 사용하여 Basys 3 100MHz 클록에 대한 기본 제약을 작성할 수 있다."

**교육 설계자 검증**:
- 단계 1: 시스템 클록 제약 (create_clock -period 10ns CLK_100MHZ)
- 단계 2: 생성 클록 (파이프라인 내부 신호, 선택사항)
- 단계 3: I/O 타이밍 (GPIO/UART, 보수적 여유)
- 단계 4: 거짓 경로 (false path, 동기화기 통과 신호)

### L3: 분석(Analyze) — 타이밍 보고서 해석
"Vivado report_timing 출력에서 WNS(Worst Negative Slack), TNS(Total Negative Slack), 임계 경로(critical path)를 읽고, 병목 단계(EX/MEM/CACHE)를 식별할 수 있다."

**기술 리뷰어 검증**:
- Endpoint: 가장 느린 플로핑 요소 (어느 스테이지인지 판별)
- Startpoint: 경로 시작 플로핑 요소 (이전 스테이지)
- Path Delay: FF-Q → combinational → FF-D 합계
- Slack = 제약 - 실제 지연 (음수 = 타이밍 위반)

### L4: 분석(Analyze) — 임계 경로 개선 전략
"단일 임계 경로(예: Data forwarding MUX + ALU + BRAM read)에 대해 재설계 옵션 3개(MUX 깊이 축소, 파이프라인 재삽입, 메모리 타입 변경)를 제시하고 트레이드오프를 분석할 수 있다."

**심리전문가 검증**:
- 심리적 불안 감소: 경로 특정화 → 자신감 향상
- 실패 정상화: "첫 합성에서 타이밍 위반은 매우 흔함" 메시지

### L5: 평가(Evaluate) — 리소스 최적화 기준
"Basys 3의 LUT/BRAM/DSP 사용률에 따라, 추가 최적화가 필요한지 판단하고 메모리 추론 타입(BRAM vs LUTRAM)을 선택할 수 있다."

**강사 검증**:
- LUT 사용률 기준: <50% (여유), 50~70% (타이트), >70% (위험)
- BRAM 선택: 읽기 지연이 중요하면 Simple Dual Port (1사이클 지연)
- 면접 연결: "메모리 추론은 도구에 따라 자동으로 결정되나, 수동 제어도 가능함"

## 3. 학습 불안 지점 & 완화 전략

### 불안 지점 #1: FPGA 합성이 처음
**증상**: "Vivado가 뭘 하는 걸까? 내 Verilog가 어떻게 하드웨어가 되는 거야?"

**완화 전략** (심리전문가/강사):
1. **"흑박스" 진정 문구**:
   - "Vivado 합성은 당신의 Verilog를 논리식으로 변환한 후, 칩의 LUT/FF에 맞춰 최적화하는 자동화 도구입니다."
   - "우리는 합성 도구를 완전히 이해할 필요 없습니다 — 물리학 박사가 아니어도 자동차를 운전하는 것처럼!"
2. **Gradual Reveal**:
   - 20.1절: "합성이란 무엇인가?" (개념만)
   - 20.2절: "Vivado 기본 옵션 이해" (구체적 옵션 3개)
   - 20.3절: "타이밍 분석" (보고서 읽기)
   - 20.4절: "리소스 최적화" (의사결정)

### 불안 지점 #2: 타이밍 제약 작성이 추상적
**증상**: "XDC 파일에 뭘 써야 하는 거지? 어디서 수치를 가져오는 거야?"

**완화 전략** (교육설계자):
1. **템플릿 제공** (20.2절):
   ```
   # 시스템 클록: 100MHz (주기 10ns)
   create_clock -period 10 -name CLK100 [get_ports CLK_100MHZ]

   # 입력/출력 여유: 2ns (보수적)
   set_input_delay -clock CLK100 -max 2 [get_ports {UART_RX GPIO_IN[*]}]
   set_output_delay -clock CLK100 -max 2 [get_ports {UART_TX LED[*]}]
   ```
2. **단계별 가이드**:
   - 클록 주기 = 1000 / 주파수(MHz) ns (매우 간단)
   - I/O 여유 = 관례적으로 20% (10ns × 20% = 2ns)
   - 거짓 경로 = 클록 도메인 사이의 동기화기 신호

### 불안 지점 #3: 임계 경로가 길면 어떻게?
**증상**: "WNS가 음수면 뭘 해야 해? 설계를 다시 해야 하는 거야?"

**완화 전략** (기술 리뷰어/강사):
1. **불안 정상화**:
   - "타이밍 위반은 첫 설계에서 거의 피할 수 없습니다. 50%의 설계자가 경험합니다."
   - "해결 방법이 3~4가지 있으므로, 인내심을 갖고 하나씩 시도하면 됩니다."
2. **구체적 예시** (20.3절):
   - 경로 A: Data MUX → ALU → 33ns (타이밍 위반 -3ns)
     → **해결책**: 임시 변수로 MUX 깊이 감소 (합성 도구가 자동 최적화)
   - 경로 B: Cache RAM 읽기 → ALU → 42ns (위반 -12ns)
     → **해결책**: 캐시 메모리를 BRAM Simple Dual Port 선택 (Xilinx 추론 규칙)
   - 경로 C: FSM 상태 다음값 계산 → 38ns (위반 -8ns)
     → **해결책**: FSM 인코딩을 원-핫에서 바이너리로 변경 (합성 옵션)
3. **결과 기대치**:
   - "이 3가지 중 1~2가지만으로도 대부분 해결되어, 50MHz 달성 가능합니다."

### 불안 지점 #4: 리소스 부족?
**증상**: "LUT가 20,800개인데, 우리가 15,000개 쓰면 안 돼? 여유가 뭔가요?"

**완화 전략** (교육설계자):
1. **"여유의 의미" 설명**:
   - 합성 도구가 배치/배선(place & route)할 때, 물리적 공간이 필요합니다.
   - 사용률 70% 이상이면, 도구가 최적 배치를 찾지 못해 타이밍이 더 나빠질 수 있습니다.
   - 따라서 60% 이내로 설계하는 것이 관례입니다.
2. **구체적 예시**:
   - "현재 설계: 12,000 LUT 사용 (58%) ← 안전"
   - "최적화 후: 10,500 LUT (50%) ← 초과 달성"

### 핵심 비유
1. **요리 레시피 vs 요리사의 의사결정**
   - Verilog = 요리 레시피 (무엇을 만들지)
   - 합성 = 요리사의 기술 (어떻게 최적으로 만들지)
   - "당신은 요리사에게 "맛있는 스파게티"를 요청하지, 매초 팬 온도를 지시하지 않습니다."
   - **한계**: 도구마다 결과가 다르므로, 완벽한 통제는 불가능함 명시

2. **도로 공사 비유**
   - 단일 레인 도로 (단일 사이클) → 자동차 하나씩 (CPI=1)
   - 4레인 도로 (파이프라인) → 자동차 4개 동시 (처리량 증가)
   - 신호등 최적화 (파이프라인 클럭 주파수) → 신호등이 너무 빠르면 충돌 위험
   - "100MHz는 신호등이 10ns 간격, 50MHz는 20ns 간격입니다."

3. **의료 진단 비유**
   - Vivado 보고서 = 의료 검사 결과 (WNS, LUT%, BRAM%)
   - 타이밍 경로 = 환자의 증상 (어느 부위가 아픈지)
   - "진단 없이 처방은 불가능합니다 — 먼저 report_timing을 읽으세요!"
