## 이해도 평가 (섹션별)

### 24.1.1 M 확장 ISA 정의
- **이해도**: ⭐⭐⭐⭐ (4/5)
- **설명 없는 용어**:
  - "부분적(partial product)" — 24.1.2절에서 설명됨, 24.1.1에서는 등장하지 않으므로 문제 없음
  - "상위/하위 32비트" — 표와 함께 설명되어 매우 명확함 [Yes]
  - "signed/unsigned 곱셈" — MULH/MULHSU/MULHU 표에서 구분 명확함 [Yes]
  - "오버플로 검출" — SRAI+BNE 패턴 코드 예제로 설명되어 이해 가능하나, 왜 SRAI 31이 부호 확장인지 한 줄 보충이면 더 좋겠음 [Minor]
- **비유 평가 (곱셈=전자 계산기의 x 버튼)**:
  - 필산 경험에 와닿는가? [Yes] — 초등학교 필산 비유가 친숙함
  - 하드웨어 병렬화 이해? [Yes] — 24.1.2에서 자세히 다루겠다는 예고가 적절
  - 한계 명시? [Yes] — "실제 하드웨어 곱셈기는 '즉시'가 아닐 수 있습니다" 명시
- **코드 이해도**:
  - Vivado DSP 자동 매핑 — 도입부 실무 팁에서 언급, 처음 알았지만 설명 충분 [Yes]
  - 64비트 {upper, lower} 분할 — MUL+MULH 어셈블리 예제에서 명확 [Yes]
- **특기사항**: 나눗셈 특수 케이스(0으로 나누기, 부호 오버플로)의 결과값이 표로 정리되어 있어 좋음. "예외를 발생시키지 않고 명확한 결과를 정의"라는 설명이 안심됨.

### 24.1.2 M 확장 하드웨어 구현
- **이해도**: ⭐⭐⭐ (3/5)
- **나눗셈 알고리즘 새로운가?** [Yes] — Restoring Division은 처음 접함
- **33→34사이클 필요성 이해?** [Yes, 부분적] — "초기화 + 32반복 + 부호 보정"이라는 설명이 있으나, 코드에서 INIT→COMPUTE(32회)→SIGN_ADJ→DONE이 정확히 몇 사이클인지 세어보면 34사이클(INIT 1 + COMPUTE 32 + SIGN_ADJ 1 = 34)임을 스스로 확인해야 함. 본문에 "최대 34사이클"이라고만 언급하고 각 상태의 사이클 수 breakdown이 없음.
- **장제법 비유 도움?** [Yes] — "100 ÷ 7" 예제가 구체적이고 단계별로 추적 가능
- **SVG(division_longdiv.svg) 중복 없는가?** [Yes] — 왼쪽에 하드웨어 구조, 오른쪽에 수동 추적 테이블, 하단에 FSM 상태 전이를 모두 포함하여 매우 유용. 다만 본문의 수동 추적 예제와 SVG의 예제가 다름: 본문은 "100÷7"이고 SVG는 "13÷3"임 → 혼란 가능성 있음.
- **설명 없는 용어**:
  - "Restoring Division" — "장제법의 하드웨어 버전"이라는 비유로 설명됨 [Yes]. 다만 왜 "Restoring"인지(음수면 복원하기 때문)가 SVG caption에서만 설명되고 본문 텍스트에는 명시적 설명 부족 [Minor]
  - "나머지(remainder)" — 코드에서 `remainder` 변수로 명확 [Yes]
  - "Booth Radix-4" — 표에서 "부분적 수 절반"으로 설명되지만, 어떻게 절반으로 줄이는지 원리 설명 없음 [Minor, 이 챕터 범위를 넘어서므로 수용 가능]
  - "Wallace/Dadda 트리" — 이름만 언급, 원리 없음 [Minor, 동일 사유로 수용 가능]
  - "CSA(Carry Save Adder)" — SVG에서만 등장하고 본문에서 설명 없음 [Minor]
- **코드 이해도 (ch24_mul_divider.sv 나눗셈 FSM)**:
  - 상태 전이 로직(IDLE→INIT→COMPUTE→SIGN_ADJ→DONE) 이해 가능? [Yes] — typedef enum + always_comb case문이 Ch08 FSM 패턴과 동일하여 친숙함
  - 몫/나머지 업데이트 명확? [부분적] — COMPUTE 상태 내 `shifted_rem`, `trial_sub` 변수 선언이 `begin...end` 블록 내부에 있는 것이 SystemVerilog 초보에게는 낯설 수 있음. 또한 `dividend_abs[DATA_WIDTH-1-count[4:0]]`에서 MSB부터 내려가는 인덱싱이 직관적이지 않음.

### 24.2 F 확장: 부동소수점 기초
- **이해도**: ⭐⭐⭐⭐ (4/5)
- **IEEE 754 처음인가?** [Yes, 대부분] — 디지털 논리 수업에서 간략히 들었을 수 있으나 비트 수준 변환은 처음
- **"부호 + 지수 + 가수" 명확?** [Yes] — 표로 비트 범위, 역할이 정리되어 있고, 변환 예제(-6.5)가 구체적
- **과학표기법 비유 도움?** [Yes] — "1.5 x 10^3 = 1500"에서 시작하여 "1.1011 x 2^5"로 자연스럽게 전환
- **정규화 개념 새로운가?** [Yes, 부분적] — "항상 1.xxxxx로 시작 (1은 묵시적)"이라는 설명이 간결하지만 충분
- **설명 없는 용어**:
  - "바이어스(bias)" — "바이어스 127을 빼면 실제 지수"로 설명됨 [Yes]. 다만 왜 바이어스를 사용하는지(음수 지수를 unsigned로 표현하기 위해)가 명시되지 않음 [Minor]
  - "정규화(normalization)" — 표에서 "항상 1.xxxxx로 시작"으로 설명 [Yes]
  - "언더플로우/오버플로우" — 직접 언급되지 않음. E=0, E=255 특수 케이스만 표에서 간략히 언급 [Minor]
  - "NaN" — SVG의 지수 설명에 "E=255: ±infinity/NaN"으로 등장하지만 본문 미설명 [Minor]
  - "비정규수(denormalized number)" — SVG에 "E=0: 비정규수/제로"로 등장하지만 본문 미설명 [Minor]
- **SVG(ieee754_bits.svg) 비트 분해 명확?** [Yes] — 색상 구분 명확(빨강=부호, 파랑=지수, 초록=가수). 변환 예제도 SVG 내에 포함되어 있어 매우 직관적.
- **SW 에뮬레이션 vs HW 비교 표** — 매우 명확, 성능 수치가 구체적이어서 트레이드오프 이해에 좋음

### 24.3 Zicntr 확장
- **이해도**: ⭐⭐⭐⭐⭐ (5/5)
- **Ch18 복습 필요?** [No] — mcycle/minstret이 이미 친숙하고, IPC 측정 코드가 어셈블리로 간결하게 제시됨
- "타이밍 사이드 채널 공격" 언급은 흥미롭고, 별도 확장 분리의 이유가 설득력 있음
- M 확장의 DIV로 IPC를 계산하는 코드가 24.1절과 24.3절을 자연스럽게 연결

### 24.4 미니 설계 과제: 파이프라인 곱셈기
- **이해도**: ⭐⭐⭐⭐ (4/5)
- **2사이클 vs 1사이클 트레이드오프 이해?** [Yes] — 방법 A(전체 스톨) vs 방법 B(파이프라인 곱셈기)의 설명이 명확하고, CPI 영향 계산이 메타인지 박스에 포함
- **mul_busy 스톨 신호 추가 명확?** [Yes] — `pipeline_stall` 확장 코드와 SVG의 스톨 우선순위 다이어그램이 일치하여 이해 용이
- **SVG(twoissue_multiplier.svg) 이해?** [Yes] — 5단계 파이프라인에 곱셈기/나눗셈 FSM이 EX에 추가되는 구조가 시각적으로 명확. 스톨 우선순위가 하단에 색상 바로 표시되어 한눈에 파악 가능
- **구조적 해저드 언급** — "ALU 결과와 곱셈기 결과가 동시에 WB에 도달하면"이라는 설명이 있으나, 구체적 해결 방법(WB 포트 중재기)에 대한 코드 예시는 없음. 설계 과제이므로 수용 가능.
- **강사 팁 "방법 A를 먼저 구현"** — 매우 실용적이고 안심됨

## 불안 지점 감지

  - "원리를 이해한 후에는 도구를 신뢰하세요" 도입부 팁? [Yes]

- **안심 장치 확인**:
  - "5분 읽기 수준의 개념 소개" 명시? [Yes] — 절 도입부에서 명시
  - "FPU 설계는 교재 범위를 넘어서며, 개념적 이해에 집중" 명시? [Yes]

### 3. 0으로 나누기 에러 처리
- **불안**: "0으로 나누면 프로세서가 멈추나?"
- **안심 장치 확인**:
  - "예외를 발생시키지 않고 명확한 결과를 정의" 명시? [Yes] — 24.1.1절에서 특수 케이스 2가지 명확히 정의
  - DIV는 -1(0xFFFFFFFF), REM은 rs1 반환? [Yes]
  - 테스트벤치에 0으로 나누기 테스트 포함? [Yes] — `test_div("DIV x/0", ...)` 포함
- **평가**: 안심 장치 충분 ✅

### 4. 코드 내 begin...end 블록 내 변수 선언
- **불안**: COMPUTE 상태의 `begin...end` 내부에서 `logic` 변수 선언이 처음 보는 패턴
- **안심 장치**: 없음 — 이 패턴에 대한 설명이 본문에 없음 [No]
- **평가**: Minor 이슈. SystemVerilog의 블록 내 변수 선언은 Ch08 등에서 사용했을 수 있으나, 여기서 처음 FSM 내부에서 사용되므로 한 줄 주석이면 충분.

## 개선 권고

### 필수 명확화 (Major)

1. **[M1] 본문-SVG 나눗셈 예제 불일치**
   - 위치: 24.1.2절 비유(line 334: "100 ÷ 7") vs SVG(ch24_sec02_division_longdiv.svg: "13 ÷ 3")
   - 영향: Major — 독자가 비유를 읽고 SVG를 보면 다른 예제여서 혼란
   - 권고: 본문 비유와 SVG 예제를 통일하거나, "SVG에서는 4비트 축소 버전(13÷3)으로 동작을 추적합니다"라는 연결 문구 추가

### 권장 개선 (Minor)

2. **[B1] "부분적(partial product)" 용어 번역 어색**
   - 위치: 24.1.2절 전반 (line 252, 262 등)
   - 영향: Minor — "부분적"만 단독 사용 시 형용사처럼 읽혀서 의미 불명확
   - 권고: "부분곱(partial product)" 또는 첫 등장 시 "부분적(partial product, 중간 곱셈 결과)"로 명확화

3. **[B2] 바이어스 사용 이유 미설명**
   - 위치: 24.2절 (line 487)
   - 영향: Minor — "바이어스 127을 빼면 실제 지수"라고만 하고, 왜 바이어스를 쓰는지 한 줄 없음
   - 권고: "음수 지수를 표현하면서도 지수 필드를 unsigned로 유지하기 위해 바이어스를 사용합니다" 한 줄 추가

4. **[B3] NaN/비정규수 본문 미설명**
   - 위치: 24.2절 — SVG에만 "E=255: ±infinity/NaN", "E=0: 비정규수/제로" 등장
   - 영향: Minor — "5분 읽기" 범위이므로 깊이 다룰 필요는 없으나, 최소한 "이런 특수 값이 존재한다" 한 줄 언급 권장

5. **[B4] COMPUTE 블록 내 변수 선언 패턴**
   - 위치: ch24_mul_divider.sv (line 950~955, HTML 내 전체 소스)
   - 영향: Minor — `begin...end` 내부 `logic` 선언이 처음 보는 독자에게 낯설 수 있음
   - 권고: 주석 한 줄 "// SystemVerilog: begin-end 블록 내 로컬 변수 선언 가능" 추가

6. **[B5] 나눗셈 FSM 사이클 수 breakdown 부재**
   - 위치: 24.1.2절 (line 349)
   - 영향: Minor — "최대 34사이클"이라고만 언급, INIT(1) + COMPUTE(32) + SIGN_ADJ(1) = 34 분해 없음
   - 권고: 괄호 안에 "(INIT 1사이클 + COMPUTE 32사이클 + SIGN_ADJ 1사이클)" 추가
