## 리뷰 요약

### 기술 리뷰어

**전체 판정**: 수정 후 재검토 필요 (Critical 2건 수정 필수)

핵심 이슈:
- **[C-01] Critical**: `ch19_trap_controller.sv`의 `always_comb` 블록 내 `csr_wdata`를 전체 할당 후 동일 블록에서 특정 비트를 개별 재할당하는 패턴(149–155행, 161–165행)은 IEEE 1800-2017 §9.2.2.2에 따라 비결정적 동작을 유발할 수 있음. Vivado 합성 오류 또는 Sim-Synth Mismatch 위험. → 마스킹 연산(`& ~`)으로 단일 할당으로 교체 필수.
- **[C-02] Critical**: `ch19_exception_unit.sv`에서 인터럽트 발생 시 `mepc = mem_pc + 4`는 MEM 스테이지가 버블인 경우 의미 없는 주소를 저장하는 등 RISC-V 특권 스펙 §3.1.14 위반 가능성. 교육적 단순화임을 코드 주석과 HTML 본문에 명확히 경고해야 함.
- **[M-01]**: `mtvec` 하위 2비트(MODE 필드) 미처리. M-mode Direct 모드 전제임을 명시하거나 `mtvec[31:2] << 2` 방식으로 BASE 추출 필요.
- **[M-02]**: 트랩 FSM 4사이클 처리 중 `pipeline_flush`가 1사이클만 활성화 — 교재 본문 설명과 코드 불일치.
- **[M-03]**: 두 모듈 간 `trap_in_progress` 핸드쉐이킹 부재 → 중첩 트랩 방지 불완전.
- **[M-04]**: 테스트벤치가 통합 시나리오를 검증하지 않아 [M-02] 결함 미검출.
- 우수한 점: mcause 코드, 인터럽트 우선순위(MEI>MSI>MTI), 3단 마스킹 구조, 플러시 신호 OR 병합 로직 모두 스펙 정확.

### 초보자 독자

**전체 판정**: ⭐⭐⭐⭐ (4/5) — 승인 (권장 보완 사항 있음)

핵심 이슈:
- **[B-01] 필수**: `mtvec` 레지스터가 이 챕터에서 "트랩 핸들러 주소"로 사용되지만, 그 값이 소프트웨어(부트 코드)가 CSRRW로 미리 설정한다는 설명이 없음. 19.4절 "PC ← mtvec" 설명 앞에 한 문장 추가 필요.
- **[B-02] 필수**: 19.6절 시나리오가 1→3으로 건너뛰어 독자가 혼란. "시나리오 2(EBREAK)는 시나리오 1과 로직이 동일하므로 연습문제로 남긴다" 한 줄 안내 필요.
- 비유 체계 탁월(젓가락, 전화, 비행기, 도미노 모두 효과적), aside 박스 배치 우수.
- CSR 해저드 등장이 예고 없이 갑작스러움 — 연결 문장 추가 권고.
- `trap_controller.sv` 전체 소스 코드 섹션 누락 — 두 모듈 연결 이해 어려움.

### 교육심리전문가

**전체 판정**: A− (우수, 소규모 개선 권장)

핵심 이슈:
- **[P-01] 높음**: 19.5절 CSR 해저드 하위 절 앞에 인지적 분리 신호 명시 필요. 현재 `<hr>` 한 줄뿐이라 학습자가 두 주제 경계를 인지하기 어려움. "이 내용은 19.5절의 두 번째 주제입니다" 안내 추가.
- **[P-02] 중간**: 동기 예외 우선순위 코드 블록(약 38줄) 직후 중간 이정표 문구 부재. "여기까지 이해했다면 19.5절의 절반을 완주한 것입니다" 등 성취 신호 추가 필요.
- 챕터 도입부("연결이지 새로운 학습이 아니다" 프레임) 교육심리적 설계 최고 수준.
- 19.7절 "전체 여정 완성 선언"이 교재 전체에서 가장 강력한 성취감 장치.
- 실패 정상화 2중 배치(챕터 시작 + 19.5절) 전략적으로 우수.

### 교육전문강사

**전체 판정**: 8.8/10 — 강의 현장 즉시 투입 가능 수준

핵심 이슈:
- **[강사P1-1] 필수**: 도미노 비유와 인터럽트 mepc 저장 기준 차이 연결 단락 누락. 동기 예외와 비동기 인터럽트의 mepc 저장 기준이 다른 이유를 도미노 비유와 연결하는 설명 필요.
- **[강사P1-2] 필수**: 19.5절 코드에서 `interrupt_pending`이 19.3절에서 3단 마스킹 후 생성된 변수임을 명시하는 연결 문장 필요.
- **[강사P2-3] 권장**: "동기 예외 vs 비동기 인터럽트 차이" 면접 박스 누락. 19.3절 끝 또는 19.7절에 추가 권고.
- 비유 2(비행기 블랙박스)·비유 5(회사 내선전화) 완벽 구현.
- SVG 6개 전부 적절한 절에 배치 확인.
- 기획안 5가지 비유 모두 원고에 구현됨.

## 편집장 최종 지시

편집장 판단에 따라 아래와 같이 수정 범위를 확정합니다.

**충돌 해결 원칙** (정확성 > 심리적 안전 > 이해도 > 분량):
- M-01~M-03(코드 구조 변경)은 이번 챕터 승인 범위를 벗어나는 설계 변경으로, 현재 교육 목적의 단순화 구현 명시로 갈음하고 다음 개정 반영으로 분류.
- C-01은 합성 가능성 직결 문제이므로 즉시 수정 필수.
- C-02는 완전 재구현이 아닌 주석 강화로 교육적 단순화를 명확히 하는 방향으로 처리.

**기술 저자(편집장 겸직)에게 전달하는 수정 지시:**

1. **`ch19_trap_controller.sv` 149–155행, 161–165행**: `always_comb` 내 비트 단위 재할당 패턴을 마스킹 연산(`& ~(32'h1 << BIT) | (value << BIT)`)으로 교체. 단일 할당으로 비결정적 동작 위험 제거.

2. **`ch19_exception_unit.sv` 212–213행**: `trap_mepc = mem_pc + 32'd4` 주석을 구체적 경고로 강화. "(교육적 단순화: 완전 구현에서는 파이프라인 스테이지 상태에 따라 복귀 주소가 달라짐. MEM이 버블인 경우 이 값은 무의미할 수 있음)" 명시.

3. **`chapter19.html` 19.4절**: 5단계 목록의 "PC ← mtvec" 항목 직전 또는 해당 항목 설명에 "mtvec는 소프트웨어(부트 코드)가 CSRRW 명령어로 미리 설정해 둔 트랩 핸들러 진입 주소입니다(Ch18 참조)" 한 문장 추가.

4. **`chapter19.html` 19.6절 시나리오 1 코드 블록 다음**: "시나리오 2(EBREAK 예외)는 시나리오 1과 처리 로직이 동일합니다. 연습문제 2번에서 직접 구현해 보십시오." 안내 단락 삽입.

5. **`chapter19.html` 19.5절 CSR 해저드 소절(`<h3>CSR 해저드 처리</h3>`) 앞**: 새 주제 시작을 알리는 인지적 분리 신호 단락 추가.

6. **`chapter19.html` 19.5절 우선순위 코드 블록(`</code></pre>`) 직후, `<hr>` 앞**: 중간 이정표 성취 확인 문구 삽입.

7. **`chapter19.html` 19.5절 우선순위 코드 앞 단락**: `interrupt_pending` 변수가 19.3절에서 정의된 3단 마스킹 결과임을 명시하는 연결 문장 추가.

8. **`chapter19.html` 19.3절 끝 또는 19.7절**: "동기 예외 vs 비동기 인터럽트" 핵심 차이를 정리한 면접 포인트 박스 추가.
