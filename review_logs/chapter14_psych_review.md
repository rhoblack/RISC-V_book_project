## 1. 감정 곡선 분석

### 도입부 (14.1절) — 호기심 유발
**평가: 양호 (⭐⭐⭐⭐)**

14.1절은 I-Cache와의 명확한 대비("읽기 전용 → 쓰기 추가")로 시작하여, 독자가 이미 알고 있는 지식 위에 새 문제를 얹는 방식으로 호기심을 잘 유발합니다. 도서관 비유("메모를 하면서 읽는 것")는 추상적인 Write Policy를 일상 경험과 연결하여 인지 부하를 낮춥니다. 비교 표(Write-Through vs Write-Back)는 선택의 이유를 즉시 납득시키므로, 학습자가 "왜 이 방법인가?"라는 의문 없이 이후 내용에 몰입할 수 있습니다.

**개선 여지:** "쓰기를 어떻게 처리할 것인가"라는 근본적 질문을 도입부에서 더 극적으로 제기하면 초반 긴장감이 높아질 수 있습니다. 현재는 질문→답변이 너무 빠르게 이어져 "궁금증의 유예 시간"이 짧습니다.

### 중반부 (14.2~14.3절) — 불안 관리
**평가: 보통 (⭐⭐⭐)**

14.2절의 FSM 5개 상태 도입은 챕터에서 가장 높은 인지 부하 지점입니다. 세 가지 경로(Hit / Clean Miss / Dirty Miss)를 표와 순서 목록으로 제시하여 구조화는 잘 되어 있습니다. 그러나 **"Eviction 주소 생성에서 기존 Tag를 사용해야 한다"**는 코드 분석 포인트 3에서 "이것은 초보자가 가장 자주 실수하는 부분입니다"라고 경고만 하고, **왜** 실수하기 쉬운지, **어떻게** 확인하면 좋은지에 대한 완화 조치가 없습니다. 이 부분은 초보자에게 막연한 공포감("나도 실수하겠구나")으로 남을 수 있습니다.

14.3절의 2-Way 확장은 "지정석 비유" 덕분에 구조 이해 진입 장벽이 낮습니다. LRU 1비트 구현이 직관적으로 설명되어 있어 불안이 급격히 낮아지는 구간입니다.

**불안 고점:** 14.2절 FSM 코드 스니펫 직후 — `// ... (전체 코드는 code_examples/ 참조)` 줄임 처리가 있어, 독자가 핵심 FSM 제어 로직을 확인할 수 없는 상태에서 불안이 잠시 증가합니다. 전체 소스 코드 섹션이 있지만 거리가 멀어 심리적 단절이 생깁니다.

### 통합 (14.4절) — 전체 그림 이해의 성취감
**평가: 양호 (⭐⭐⭐⭐)**

`pipeline_stall = load_use_stall || icache_stall || dcache_stall` 코드는 Ch10~13의 파편화된 개념들이 하나의 신호로 통합되는 순간을 명확히 보여 주어, 누적된 학습의 완성감을 제공합니다. CPI 공식과 수치 예시(CPI = 1.27)는 추상적인 성능 논의를 수치로 구체화하여 "이해했다"는 감각을 강화합니다.

"5%의 미스율이 CPI를 27% 증가시킵니다"라는 문장은 캐시 최적화의 중요성을 단번에 납득시키는 효과적인 동기 부여 구문입니다.

### 검증 (14.5절) — 자기효능감 강화
**평가: 양호 (⭐⭐⭐⭐)**

6개 시나리오를 표로 제시한 뒤 순서대로 추적하는 구조는, 독자가 단계마다 "여기까지 맞다"고 확인하며 성취감을 쌓을 수 있게 합니다. 시나리오 5(Dirty Eviction) 파형 추적의 5단계 올더-리스트는 특히 효과적입니다. "mem_addr_o가 기존 Tag에서 새 Tag로 전환되는 시점"을 명시적으로 짚어 주어, 앞서 14.2절에서 언급한 "가장 자주 실수하는 부분"의 검증 기회를 제공합니다.

## 2. 불안 유발 지점 목록

### 불안 지점 1: 5-state FSM (IDLE→TAG_CHECK→WRITE_BACK→REFILL→UPDATE)
**불안 수준: 중간**

세 가지 경로가 표와 목록으로 명확히 제시되어 있어 구조 파악은 가능합니다. 그러나 TAG_CHECK에서 세 방향으로 분기하는 조건(`cache_hit` / `cache_dirty && !cache_hit` / `!cache_hit && !cache_dirty`)이 코드에서 직접적으로 확인되지 않아, 코드와 상태도의 1:1 매핑이 즉각적이지 않습니다.

**완화 장치:** 강사 꿀팁 박스에서 "색상별로 구분한 상태 전이도를 먼저 그리라"고 안내. 효과적이지만 이는 강사용 조언이며, 독자가 혼자 학습할 때의 완화 장치가 부족합니다.

**권고:** FSM 상태 전이도 SVG 다이어그램(`ch14_sec05_dcache_fsm.svg`)을 14.2절에서 미리 제시하고, 14.5절에서 재참조하는 구조를 추천합니다. 현재 SVG가 14.5절에만 배치되어 있어 초반 FSM 이해 단계에서 시각적 지원이 없습니다.

### 불안 지점 2: 교체 Way 래치 (latched_replace_way)
**불안 수준: 높음**

14.3절 본문에서 "교체 Way 래치"는 단 한 줄("TAG_CHECK 상태에서 결정된 교체 대상 Way를 래치하여 WRITE_BACK과 REFILL 상태에서 일관되게 사용합니다")로만 설명됩니다. 왜 래치가 필요한가(FSM 상태 전이 후 조합 신호인 `replace_way_sel`이 변할 수 있으므로)에 대한 직관적 설명이 없습니다. 이 개념은 FSM 설계 경험이 적은 독자에게 "갑자기 래치를 왜 쓰는 거지?"라는 의문을 남깁니다.

**완화 장치:** 없음. 코드에 `// 교체 Way 래치`라는 주석만 있으며, 본문 설명이 충분하지 않습니다.

**권고:** "TAG_CHECK 상태를 벗어나면 `addr_index`가 달라질 수 있으므로, 래치로 교체 Way를 고정해야 합니다"라는 1~2문장의 직관적 설명을 14.3절 마지막 항목(교체 Way 래치)에 추가해야 합니다.

### 불안 지점 3: Dirty Eviction에서 두 번의 메모리 접근
**불안 수준: 중간**

14.2절 FSM 설명과 14.5절 파형 추적이 잘 연결되어 있어 "두 번 접근한다"는 사실 자체는 명확합니다. 그러나 **총 사이클 수의 체감**이 부족합니다. Dirty Miss 시 최대 (8+8) × 메모리 지연 = 수십 사이클이 소요되는데, 독자는 "얼마나 오래 기다려야 하는가"를 직관적으로 인식하기 어렵습니다. 14.4절의 CPI 계산이 이를 간접적으로 다루지만, "Dirty Miss 페널티 = 34사이클"이라는 수치가 본문에서 한 번만 언급됩니다.

**완화 장치:** 14.5절 파형 추적의 5단계 목록이 효과적으로 보완. 충분합니다.

### 불안 지점 4: 캐시 일관성 문제 (Cache Coherence)
**불안 수준: 낮음 (잘 관리됨)**

14.6절에서 "단일 코어에서도 문제 존재 → FENCE.I로 해결 → 멀티코어는 Ch25에서" 순서로 범위를 명확히 한정합니다. "현재 단계에서는 ... 점만 기억하면 충분합니다"라는 마무리 문장이 학습 불안을 효과적으로 차단합니다. 자기 수정 코드라는 구체적 사례를 통해 추상적 개념을 현실에 고정시키는 점도 우수합니다.

## 3. 자기효능감 장치 평가

### 시나리오 5 (Dirty Eviction) 성취감
**평가: 우수**

5단계로 분해된 파형 추적은 독자가 각 단계를 손으로 따라가며 "이 시점에 이 신호가 이렇게 되어야 한다"고 예측하고 검증하는 능동적 학습을 유도합니다. 시나리오 5를 통과하면 Write-Back 캐시 설계의 가장 복잡한 시나리오를 스스로 이해했다는 성취감이 명확히 옵니다.

### 안심 문구 위치 적절성
**평가: 양호 (위치 최적화 여지 있음)**

"지금 당장 전부 이해하지 않아도 됩니다" 문구가 전체 소스 코드 섹션 앞에 배치되어 있습니다. 이 위치는 분량이 방대한 소스 코드 앞에서 독자의 위축을 막는 데 적절합니다. 단, **14.2절 FSM 코드 스니펫의 줄임 처리 직후**("... (전체 코드는 code_examples/ 참조)")에도 간단한 안심 문구가 있으면 더 효과적입니다. 독자가 불완전한 코드를 처음 마주치는 지점에서 불안이 발생하기 때문입니다.

### 연습문제 난이도 단계적 상승
**평가: 우수**

블룸 분류 기준으로 1번(기억) → 2번(이해) → 3번(적용) → 4~5번(분석) → 6~7번(평가) 순서가 명확합니다. 특히 5번(Write-Through vs Write-Back 메모리 트래픽 계산)은 실제 수치를 계산하는 과정에서 두 정책의 차이를 체감할 수 있어, 단순 이해를 넘어 "아, 이렇게 많이 차이 나는구나"라는 성취 경험을 제공합니다.

**아쉬운 점:** 14.2절(Write-Back 직접 매핑 캐시 설계)과 14.5절(시뮬레이션 검증)에 면접 포인트 박스가 없습니다. 캐시 설계 면접에서 "Dirty Miss 처리 FSM을 설명하라"는 질문이 빈번하므로, 14.2절에 면접 포인트 추가를 권고합니다.

## 5. 실패 정상화 평가

### 캐시 버그의 간헐적 발생 설명
**평가: 우수**

14.5절 첫 문단에서 "캐시 버그는 간헐적으로 발생하여 디버깅이 매우 어렵기 때문입니다"라는 문장은 학습 불안을 정상화하는 데 효과적입니다. "정상적으로 보이는 프로그램이 특정 메모리 접근 패턴에서만 오동작"한다는 설명은, 초보자가 시뮬레이션에서 예상치 못한 실패를 겪을 때 "내가 뭔가 크게 틀렸나?"라는 과도한 자기 비판을 막아 줍니다.

### 시뮬레이션 실패 시 디버깅 가이드
**평가: 부분적 (개선 권고)**

"하나라도 [FAIL]이 있으면 해당 시나리오의 파형을 분석하여 원인을 찾아야 합니다"라는 문장이 있지만, **구체적인 디버깅 접근법**이 없습니다. 실무 팁 박스에서 무작위 테스트와 커버리지 기반 검증을 언급하지만, 이는 검증 고도화 방법이지 실패 원인을 찾는 방법이 아닙니다.

초보자가 가장 막히는 지점은 "파형을 어떻게 해석하는가"입니다. 예를 들어, "dcache_stall이 예상보다 길다면 word_cnt가 올바르게 증가하는지 확인하라"와 같은 1~2가지 디버깅 힌트가 있으면 학습 불안이 크게 줄어듭니다.

**권고:** 14.5절에 짧은 `<aside class="tip">` 박스를 추가하여, "FAIL 발생 시 첫 번째 체크 포인트" 2~3가지를 제시할 것을 권고합니다.

## 7. 승인 여부

- [x] **심리적 안전성 ⭐⭐⭐ 이상 조건 충족** (⭐⭐⭐⭐ 달성)

**조건부 승인.** P-1(latched_replace_way 설명)과 P-2(FSM 상태 전이도 14.2절 배치)는 불안 유발 지점을 직접 완화하는 수정이므로, 가능하다면 반영 후 최종 출력을 권고합니다. P-3~P-5는 선택 사항입니다.

전체적으로 감정 곡선(호기심 → 불안 관리 → 이해 → 성취감)이 잘 설계되어 있으며, 메타인지 질문과 면접 포인트 박스의 질이 높습니다. 연습문제의 단계적 난이도 설계는 특히 우수합니다. 주요 개선점을 반영하면 ⭐⭐⭐⭐⭐ 달성이 가능합니다.
