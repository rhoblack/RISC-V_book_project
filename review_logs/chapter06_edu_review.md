## 4. 진리표 분할 전략 평가 (6.2절)

**결론: 명령어 유형별 분할이 체계적이고 효과적으로 구현됨 (우수)**

### 분할 방식 평가

6.2.2절은 R/I-ALU/Load/Store/Branch/JAL-JALR/LUI-AUIPC로 7개 그룹을 순서대로 제시한다. 각 그룹은 다음 3요소로 구성된다:
1. 해당 명령어의 기능 설명 1~2문장 (맥락 제공)
2. 핵심 차이점 강조 (예: "b_sel=1이 핵심 차이점", "wb_sel=MEM임에 주목")
3. 개별 진리표 (해당 유형에 맞게 컬럼 조정)

이 구조는 다음 교육적 장점이 있다:
- **분절 학습(Segmenting)**: Mayer의 멀티미디어 원리 중 분절 원리를 따른다. 37개 명령어를 단일 대형 표로 제시하지 않고 개념적 단위로 나누었다.
- **점진적 비교(Progressive Comparison)**: R 타입 → I-ALU 타입 순서로, R에서 b_sel 하나만 바뀐다는 사실을 즉시 확인할 수 있다.
- **Don't-care FAQ**: X 값 처리에 대한 FAQ aside가 표 직후에 배치되어 즉각적 의문을 해소한다.

**소폭 개선 가능 사항**:
- Branch 타입 표의 pc_sel 칸이 "조건부"로만 표기되어 있다. "branch_taken ? PC_BRANCH : PC_PLUS4"를 표 안에 명기하거나 각주로 추가하면 표의 자기완결성이 높아진다.
- LUI에서 a_sel=0이지만 실제로 rs1=x0(zero)가 사용된다는 점은 코드에서 주석으로만 표시된다. 표 하단에 "LUI: rs1은 항상 x0(zero 레지스터)으로 고정하여 0+imm을 계산" 주석을 추가하면 혼동을 줄일 수 있다.

## 5. Gradual Reveal 평가 (6.3절)

**결론: SVG 점진적 공개 미구현 — 수정 필요**

### 현재 상태

6.3절에는 SVG 1개(`ch06_sec03_single_cycle_datapath.svg`)가 있다. 이 SVG는 "완성된 단일 사이클 데이터패스" 전체를 한 번에 보여주는 단일 그림이다. 계획 문서(chapter06_plan_edu.md에서 기대했던) 점진적 공개 구조가 구현되지 않았다.

### 문제점

- 6.3절은 MUX 연결(6.3.2)과 Top-Level 구현(6.3.3)의 두 단계로 나뉘어 있으나, 데이터패스 SVG는 6.3.1에서 완성본 하나만 제시된다.
- Sweller의 인지 부하 이론에 따르면, 복잡한 시스템 다이어그램을 한 번에 제시할 경우 외래 인지 부하(extraneous cognitive load)가 증가한다.
- 독자는 SVG를 보면서 "아직 설명하지 않은 연결"도 함께 처리해야 하는 부담이 생긴다.

### 권장 수정 방안

두 가지 접근 중 선택:

**방안 A (SVG 3단계 분할, 권장)**:
1. 6.3.1절: PC → IMEM → 제어유닛만 표시하는 기본 구조 SVG (`ch06_sec03_datapath_step1.svg`)
2. 6.3.2절: MUX 3개가 추가된 중간 단계 SVG (`ch06_sec03_datapath_step2.svg`)
3. 6.3.3절: 완성된 전체 SVG (`ch06_sec03_single_cycle_datapath.svg`) — 현재 파일 재사용

**방안 B (현재 SVG 유지 + 주목 유도 텍스트 추가, 단기 수정)**:
현재 완성본 SVG 아래에 다음 텍스트를 추가:
"위 데이터패스를 한꺼번에 이해하려 하지 마십시오. 아래 순서대로 각 연결을 하나씩 추적하십시오: ① PC→IMEM, ② IMEM→제어유닛, ③ ALU-A/B MUX, ④ WB MUX, ⑤ 메모리 경로."

**즉시 실행 권장**: 방안 B는 기존 파일 수정만으로 구현 가능하므로 이번 원고에 바로 적용하라.

## 6. 마일스톤 설계 평가 (6.4절)

**결론: 피보나치 성취 순간이 효과적으로 설계됨 (우수)**

### 긍정적 요소

1. **성취 예고의 일관성**: 챕터 헤더 도입부(19줄), 챕터 도입 내러티브(58~61줄), 6.4.3절(784줄) 세 곳에서 "피보나치 수열이 실행된다"는 메시지가 반복된다. 이는 기대감(anticipatory set)을 형성하는 효과적인 전략이다.

2. **★★ 마일스톤 표기**: 6.4.3절 제목에 "★★ 첫 번째 대성취"가 명시되어 있고, analogy 박스에서 감정적 연결("이 순간을 기억하십시오")을 제공한다.

3. **구체적 성공 지표 제시**: 예상 시뮬레이션 출력에 F(0)~F(11)의 `[PASS]` 목록이 모두 나열되어 있다. 독자가 "내가 성공했는가"를 즉시 판단할 수 있는 명확한 기준이다.

4. **실패 대응 처리**: 6.4.3절 후반에 "파형이 예상과 다르다면 당황하지 마십시오"라는 디버깅 안내가 포함되어 있다. 이는 성취 감정이 좌절로 전환되는 것을 방지한다.

5. **감정 곡선 구현**: 도입부 호기심 → 6.1~6.3절의 집중 → 6.4.3절의 성취감 흐름이 설계되어 있다.

**소폭 개선 가능 사항**:
- 6.4.3절 analogy 박스에서 "실행 버튼을 누르면"이라는 표현이 Vivado와 VCS 어느 것을 사용하는지 모호하다. "Vivado에서 Run Simulation 버튼을 클릭하거나, VCS에서 ./simv를 실행하면"으로 구체화하면 좋다.
- 피보나치 완주 후 학습자의 성취를 더 강화(reinforcement)하는 문장—"여러분은 방금 하드웨어 설계 엔지니어가 수년 걸려 익히는 작업을 완수했습니다"와 같은—이 현재 단 한 문장만 있다(824줄). 1~2문장 더 추가하면 정서적 마무리가 강화된다.

## 9. 정리 절 평가 (6.6절)

**결론: 자가 점검과 Ch07 예고를 모두 포함 — 합격**

### 구성 요소 체크

| 요소 | 포함 여부 | 내용 |
|------|----------|------|
| 핵심 정리 | 포함 | 6개 bullet (디코더/제어신호/통합/피보나치/임계경로/WNS) |
| 자가 점검 | 포함 | 5가지 질문 (블룸 1~4수준 포괄) |
| Ch07 예고 | 포함 | 멀티사이클 프로세서, FSM 제어 유닛 예고 |
| 학습 목표 재확인 | 미흡 | 학습 목표 6개와 자가 점검 5문항의 1:1 매핑이 명시적이지 않음 |

**강점**:
- 핵심 정리 6개 항목이 학습 목표 6개와 거의 1:1로 대응된다(내용 기준). 학습 설계 일관성이 높다.
- 자가 점검 5문항이 암기형이 아닌 수행형("~할 수 있습니까?") 형식으로 작성되어 있다. 이는 역량 기반 평가(competency-based assessment)에 적합하다.
- "Part 2 핵심 목표를 달성한 것입니다"라는 마무리 문장이 성취 강화(reinforcement) 역할을 한다.
- Ch07 예고에서 "이 챕터에서 완성한 데이터패스 구조와 제어 신호 개념이 그대로 이어집니다"라는 연속성 메시지가 전이 동기를 높인다.

**개선 가능 사항**:
- 자가 점검 질문이 5개인데 학습 목표는 6개다. 자가 점검 1번~5번이 학습 목표 1번~5번에 대응하고, 학습 목표 6번(WNS/TNS)은 자가 점검 5번에 통합되어 있다. 이 매핑을 "(목표 5,6 대응)"과 같은 괄호로 명시하면 학습자의 자기평가 정확도가 높아진다.
