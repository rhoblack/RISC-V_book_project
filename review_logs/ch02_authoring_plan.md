## 2. 각 절의 핵심 메시지 (기술 저자)

| 절 | 핵심 메시지 |
|----|------------|
| 2.1 | RISC-V는 "필요한 것만 골라 쓰는 모듈형 ISA"이며, RV32I는 47개 명령어로 완전한 범용 프로세서를 만들 수 있다. |
| 2.2 | 32개 레지스터와 PC가 프로세서의 전부이며, x0가 항상 0인 이유는 하드웨어 설계를 단순하게 만드는 천재적 트릭이다. |
| 2.3 | RISC-V는 바이트 단위로 주소를 매기고 리틀 엔디언으로 저장하며, 정렬을 지키면 하드웨어가 단순해진다. |
| 2.4 | 32비트 명령어를 6가지 포맷(R/I/S/B/U/J)으로 분류하며, opcode와 funct 필드 위치가 고정되어 디코더 설계가 쉬워진다. |
| 2.5 | 명령어 비트 패턴을 손으로 인코딩/디코딩할 수 있으면, 디코더 하드웨어가 왜 그렇게 생겼는지 직관적으로 이해된다. |
| 2.6 | 6가지 포맷과 32개 레지스터라는 "지도"를 손에 쥐었으니, Ch03에서 각 명령어 동작을 정복할 준비가 되었다. |

## 10. Ch01↔Ch02↔Ch03 연결 전략

### Ch01 → Ch02 브리지 (2.1절 도입부)
> Ch01에서 LED를 깜빡이는 회로를 만들었다. 하지만 LED 패턴을 바꾸려면 회로를 새로 설계해야 한다. 프로세서는 하드웨어는 그대로 두고, 메모리의 명령어(소프트웨어)만 바꿔 동작을 변경한다. 그 명령어 규칙이 ISA이며, 우리가 구현할 ISA가 RISC-V이다.

### Ch02 → Ch03 예고 (2.6절 마무리)
> Ch02에서 명령어의 "겉모습"(비트 포맷)을 이해했다. Ch03에서는 47개 명령어가 실제로 레지스터와 메모리를 어떻게 변화시키는지 정의한다. 이것이 디코더와 데이터패스의 "설계 사양서"가 된다.

### 절 간 전이 문장 (교육 설계자 + 교육전문강사 통합)
| 전이 | 연결 문장 |
|------|----------|
| 2.1→2.2 | "ISA가 정의하는 첫 번째 요소는 프로그래머가 접근할 수 있는 레지스터이다." |
| 2.2→2.3 | "레지스터만으로는 모든 데이터를 담을 수 없다. 더 큰 저장 공간인 메모리를 살펴보자." |
| 2.3→2.4 | "레지스터와 메모리라는 무대가 준비되었으니, 배우인 명령어를 만나보자." |
| 2.4→2.5 | "형식을 알았으니, 직접 비트를 다루어 보자." |
| 2.5→2.6 | "실습을 마쳤다면, 이 챕터에서 얻은 지식을 정리할 시간이다." |

## 12. 추가 합의 사항

- 2.2절 ABI 이름은 "소프트웨어가 레지스터를 부르는 별명" 수준의 한 줄 설명 (초보자 독자 주석 반영)
- 2.4절 즉치수 비트 배치는 반드시 색상 코딩 SVG로 명시 (기술 리뷰어 주석 반영)
- 2.4절 6가지 타입은 한꺼번에 나열하지 않고 "필요에 의한 발명" 서사로 점진적 도입
- 2.5절 실습에서 풀이 과정 템플릿(Step 1~4) 제공
- 하드웨어 강제 vs 소프트웨어 약속 경계를 명확한 표로 구분 (교육전문강사 제안)
