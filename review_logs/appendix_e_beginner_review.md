## E.1 Vivado 설치 섹션 평가

### 강점
1. **"왜 Vivado인가?" 도입이 탁월하다.** 5단계 흐름(설계→합성→P&R→비트스트림→프로그래밍)을 먼저 보여주고, 그 중 Vivado가 담당하는 부분을 명확히 한다. 초보자가 "왜 이걸 설치해야 하지?"라는 의문을 갖기 전에 해소해준다.
2. **건축 시공 비유가 적절하다.** "설계도→시공 회사" 비유가 직관적이며, 비유의 한계(FPGA는 재시공 가능)도 명시하여 오해를 방지한다.
3. **설치 옵션 표가 매우 유용하다.** 필수/권장/선택/불필요를 명확히 구분하여, 초보자가 "어떤 걸 체크해야 하지?" 고민을 줄여준다.
4. **LED 깜박이기 검증이 동기부여에 효과적이다.** 설치 후 바로 "내 코드가 하드웨어에서 동작한다"는 경험을 제공한다.
5. **체크리스트(E.1.5)가 안심감을 준다.** 모든 항목을 통과하면 "Ch01부터 시작할 준비가 완료"라는 메시지가 명확하다.

### 이해도 세부 평가
- **EDA 용어 설명**: "EDA(Electronic Design Automation) 통합 개발 환경"으로 첫 등장 시 괄호 설명 제공 — ✅ 충분
- **합성/P&R 용어**: "합성(Synthesis)", "배치 & 라우팅(Place & Route)" — ✅ 영어 병기 명확
- **WebPACK 라이선스**: "무료 WebPACK 라이선스"로 명시, FAQ에서 40GB 이유도 설명 — ✅ 충분
- **Basys 3 칩셋**: "Artix-7 XC7A35T" 명시 — ✅ 충분
- **ISE**: "이전 도구인 ISE를 대체"로 간단히 언급 — ✅ 이 정도면 충분 (깊은 설명 불필요)

### 개선 권장사항
1. **🟡 B-01: Step 4 드라이버 수동 설치 경로가 실제로 존재하는지 불안하다.**
   - `C:\Xilinx\Vivado\2024.1\data\xilinx_drivers\` 경로를 제시하지만, 초보자는 이 폴더를 찾아가는 것 자체가 어려울 수 있다.
   - 권장: "탐색기 주소창에 위 경로를 복사하여 붙여넣으면 바로 이동할 수 있다" 한 줄 추가.

2. **🟢 B-02: LED 깜박이기에서 XDC 파일이 무엇인지 한 줄 설명 추가 권장.**
   - "XDC 제약 파일"이 갑자기 등장하는데, 초보자는 "제약 파일이 뭐지?"라고 당황할 수 있다.
   - 권장: "XDC(Xilinx Design Constraints) 파일은 FPGA의 물리적 핀과 설계의 논리적 포트를 연결하는 매핑 파일이다" 정도의 한 줄 설명.

### SVG 이해도
- **app_e_vivado_flow.svg**: 5단계 설치 흐름을 시각화 — 시간 순서와 단계 구분이 명확할 것으로 기대됨. ✅ 적절

## E.2 riscv-gnu-toolchain 섹션 평가

### 강점
1. **크로스 컴파일러 개념 도입이 좋다.** "일반 컴파일러는 한국어→한국어, 크로스 컴파일러는 한국어→일본어"라는 비유가 직관적이다. 비유 한계("번역이 아니라 컴파일")도 명시.
2. **도구 이름의 "64" FAQ가 매우 유용하다.** `riscv64-unknown-elf-gcc`의 "64"가 RV32I와 무관하다는 설명은 초보자의 혼란을 사전에 방지한다.
3. **설치 방법 3가지 비교표**가 좋다. 사전 빌드(권장)가 녹색 배경으로 강조되어 선택이 명확하다.
4. **PATH 환경변수 등록 절차가 상세하다.** "제어판→시스템→환경변수" 경로를 단계별로 안내한다.

### 이해도 세부 평가
- **크로스 컴파일러 개념**: ✅ 비유와 설명 충분
- **xPack 선택 이유**: "사전 빌드 = 빠르다" — ✅ 명확
- **riscv64-unknown-elf-gcc 이름**: FAQ에서 "64"가 혼란스럽지 않은지 설명 — ✅ 좋음

### 개선 권장사항 (중요도 순)

3. **🟡 B-03: xPack 다운로드 페이지 찾기가 모호하다.**
   - "xPack 프로젝트의 RISC-V Embedded GCC 릴리즈 페이지로 이동한다"만 있고, 구체적인 검색 키워드나 경로가 없다.
   - 초보자는 "xPack이 뭐지? 어디서 검색하지?"에서 막힐 수 있다.
   - 권장: "검색 엔진에서 'xPack RISC-V Embedded GCC releases'를 검색하면 GitHub 릴리즈 페이지를 찾을 수 있다" 추가. 또는 "github.com/xpack-dev-tools 프로젝트" 정도의 힌트.

4. **🟡 B-04: xPack 도구 이름과 실행 명령어 불일치 혼란.**
   - Step 1에서 다운로드하는 파일명은 `xpack-riscv-none-embed-gcc-*`이고, 실행 파일 경로도 `riscv-none-embed-gcc-*/bin/`인데, Step 4 검증에서는 `riscv64-unknown-elf-gcc --version`을 실행하라고 한다.
   - xPack의 실행 파일 이름이 `riscv-none-embed-gcc`인지, `riscv64-unknown-elf-gcc`인지 초보자가 혼동할 수 있다.
   - 권장: xPack 버전에 따라 실행 파일 이름이 다를 수 있으므로, `riscv-none-embed-gcc --version` 또는 `riscv64-unknown-elf-gcc --version` 중 어떤 것을 사용해야 하는지 명확히 안내. 또는 "실제 bin 폴더 안의 실행 파일 이름을 확인하라"는 안내 추가.

5. **🟡 B-05: sample.c 코드 블록의 language 클래스가 `language-verilog`이다.**
   - 줄 618: `<pre><code class="language-verilog">` — C 코드인데 Verilog로 하이라이팅됨.
   - 기능적 문제는 아니지만, 하이라이팅이 부정확할 수 있다.
   - 권장: `language-c`로 변경하고 Highlight.js에 C 언어 모듈 추가, 또는 language 클래스 제거.

6. **🟡 B-06: `-nostartfiles -nostdlib` 옵션의 의미가 불명확하다.**
   - 컴파일 명령에 `-nostartfiles -nostdlib`이 포함되어 있는데, 초보자는 왜 이 옵션이 필요한지 모른다.
   - 권장: "우리가 설계한 CPU에는 운영체제가 없으므로, 표준 라이브러리와 시작 코드를 제외한다"는 한 줄 설명 추가.

7. **🟢 B-07: ELF 형식 설명이 부족하다.**
   - "ELF → hex 변환"이 언급되지만 ELF가 무엇인지 괄호 설명이 없다.
   - 권장: 첫 등장 시 "ELF(Executable and Linkable Format, 실행 파일 형식)" 추가.

8. **🟢 B-08: Bash 스크립트(app_e_toolchain_asm_to_hex.sh) 실행 방법이 불명확.**
   - Windows 환경에서 .sh 파일을 어떻게 실행하는지 안내가 없다. 대상 독자가 Windows 사용자라면 Git Bash, WSL, 또는 PowerShell에서의 실행 방법을 한 줄 안내해야 한다.
   - 권장: "Windows에서는 Git Bash 또는 WSL에서 실행하거나, 각 명령을 PowerShell/CMD에서 개별 실행할 수 있다" 추가.

## E.3 시뮬레이션 환경 섹션 평가

### 강점
1. **"대부분의 독자는 Vivado Simulator만으로 충분하다"가 매우 명확하다.** 실무 팁 박스에서 결론부터 말하는 구조가 좋다. 초보자는 VCS 미설치에 대한 불안감 없이 넘어갈 수 있다.
2. **X-ray vs MRI 비유가 직관적이다.** "동네 병원의 X-ray(Vivado) vs 대학 병원의 MRI(VCS)"로 성능 차이를 쉽게 전달한다.
3. **비교표가 판단에 도움이 된다.** 라이선스, 속도, 이 교재 범위까지 명확히 비교한다.
4. **테스트벤치 예시 코드가 실용적이다.** E.1의 LED 모듈을 재활용하여 연결성이 좋다.
5. **VCS 안내가 "선택사항"임을 반복 강조한다.** "VCS가 없다고 걱정하지 않아도 된다"는 메시지가 안심을 준다.

### 개선 권장사항
- 없음. 이 섹션은 초보자 관점에서 매우 잘 구성되어 있다.

## E.4 FAQ 및 문제 해결 섹션 평가

### 강점
1. **6가지 오류가 실제로 자주 발생하는 문제들이다.** 라이선스, 드라이버, PATH, Out of Memory 등 현실적인 오류를 다룬다.
2. **E.4.7 "실패는 정상이다" 섹션이 심리적 안전에 기여한다.** "논리 설계 vs 소프트웨어 운영"의 차이를 명확히 하여, 설치 실패가 능력 부족이 아님을 전달한다.
3. **"질문하는 것은 부끄러운 일이 아니다"** 메시지가 포함됨 — ✅
4. **"대기업 신입 설계자들도 여러 번 막혔다"** — 실패 정상화에 효과적.
5. **해결 순서 제시(FAQ→선배/TA→조교실 시연)** 가 단계적이고 현실적이다.

### 개선 권장사항
9. **🟢 B-09: E.4.4 PATH 오류에서 Windows 환경변수 설정 방법 참조 추가.**
