**흐름 평가:** 14.1(이론)→14.2(단순 구현)→14.3(심화 구현)→14.4(통합)→14.5(검증)→14.6(심화 개념)→14.7(정리)의 흐름이 매우 자연스럽습니다. 각 절이 이전 절을 발판으로 삼아 한 단계씩 복잡도를 올리는 나선형 구조가 효과적입니다. I-Cache(Ch13)에서 D-Cache로의 연속성도 명확히 유지됩니다.

**개선 가능 사항 (Minor):** 14.7절 본문이 단 한 단락("이 챕터에서는 L1 데이터 캐시(D-Cache)의 설계를 완성하였습니다.")으로 매우 짧습니다. 핵심 정리와 연습문제는 `<section>` 태그로 분리되어 별도 제공되므로 구조 자체는 문제없으나, 14.7절 본문을 2~3문장 정도 더 보강하면 마무리의 완결성이 높아집니다.

## 3. 인지 부하 분석

각 절에서 새로 도입되는 핵심 개념의 수를 분석합니다. 절당 3개 이하가 적정 기준입니다.

| 절 | 신규 개념 | 개수 | 판정 |
|----|---------|------|------|
| 14.1 | Write-Through, Write-Back, Dirty 비트, 쓰기 정책 비교표 | 3개 (비교표는 정리 도구) | ✅ 적정 |
| 14.2 | FSM 5-state(S_IDLE/TAG_CHECK/WRITE_BACK/REFILL/UPDATE), Byte Enable, Eviction 주소 생성 | 3개 | ✅ 적정 |
| 14.3 | 2-Way 구조(병렬 Tag 비교기), LRU 교체 정책 | 2개 | ✅ 여유 |
| 14.4 | dcache_stall 신호 + 파이프라인 전체 동결, 성능 공식(CPI 계산) | 2개 | ✅ 여유 |
| 14.5 | 시나리오 기반 검증 방법론, 간이 메모리 모델(Fake Memory) | 2개 | ✅ 여유 |
| 14.6 | Cache Coherence, FENCE.I 명령어 | 2개 | ✅ 여유 |

**평가:** 모든 절이 신규 개념 3개 이하를 유지합니다. 특히 14.3절~14.6절은 2개씩만 도입하여 인지 부하가 낮습니다. 14.1절과 14.2절이 각각 3개로 가장 높지만, 두 절 모두 비유와 비교표를 활용하여 누적 부하를 효과적으로 분산시킵니다.

**14.2절 보완 관찰:** Byte Enable은 개념 자체보다 코드 구현에서 처음 등장하는 방식입니다. 코드 분석 포인트 ②에서 충분히 설명하고 있어 부하가 크지 않습니다. 단, SB/SH/SW 명령어별 byte_en 값(4'b0001 / 4'b0011 / 4'b1111)을 표로 별도 정리하면 더 명확해질 것입니다 (Minor 권고).

## 4. 연습문제 품질

7개 연습문제의 블룸 분류를 검토합니다. 최소 3수준 이상 포함이 기준입니다.

| # | 표기 | 블룸 수준 | 내용 | 적절성 |
|---|------|---------|------|--------|
| 1 | [기억] | 기억(Remember) | Dirty 비트 설정/리셋 시점 설명 | ✅ 기초 점검으로 적절 |
| 2 | [이해] | 이해(Understand) | 주소 0x0001_2345의 Tag/Index/Offset 계산 | ✅ 수치 계산으로 이해 확인 |
| 3 | [적용] | 적용(Apply) | Dirty Miss 사이클 수 계산 | ✅ FSM 흐름 적용 |
| 4 | [분석] | 분석(Analyze) | 2-Way vs 직접 매핑 하드웨어 비용 정량 분석 | ✅ 핵심 트레이드오프 분석 |
| 5 | [분석] | 분석(Analyze) | Write-Through/Write-Back 메모리 트래픽 정량 계산 | ✅ 실질적 성능 차이 분석 |
| 6 | [평가] | 평가(Evaluate) | 4-Way 확장 시 LRU vs Tree-PLRU 비교 | ✅ 설계 결정 평가 |
| 7 | [평가] | 평가(Evaluate) | Non-Blocking 캐시 도입 시 구조 변경 논의 | ✅ 고급 설계 방향 평가 |

**블룸 분포:** 기억(1) - 이해(1) - 적용(1) - 분석(2) - 평가(2) = 5개 수준 포함. 최소 3수준 기준을 크게 초과하며, 5개 수준을 모두 포함하는 매우 풍부한 구성입니다.

**특이 사항:** 창조(Create) 수준 문제가 없습니다. "직접 D-Cache 모듈을 작성하시오" 같은 창조 수준 문제를 선택적으로 추가하면 6수준 완성도를 달성할 수 있으나, 현재 7개 문제도 충분히 풍부합니다. 이는 Minor 권고에 해당합니다.

**연습문제 5 확인:** `int A[4096]` 배열 초기화 시 Write-Through 트래픽은 4096 × 4B = 16KB, Write-Back 트래픽은 Eviction 시에만 발생하므로 4KB 캐시 용량 기준으로 계산 유도가 명확합니다. 힌트가 충분합니다.

## 8. 개선 권고

### 8.1 Minor 권고

**M-1: 14.7절 본문 보강 (비중 낮음)**
- 현재: "이 챕터에서는 L1 데이터 캐시(D-Cache)의 설계를 완성하였습니다." 한 문장
- 권고: 챕터 전체의 감정 곡선(호기심→불안→이해→성취감)을 마무리하는 2~3문장 추가. 예: "14.2절의 FSM 설계에서 느꼈던 복잡함이 14.3절의 2-Way 구조로 자연스럽게 확장되었습니다. 이제 여러분은 현대 프로세서의 핵심 캐시 구조를 직접 구현할 수 있는 역량을 갖추었습니다."

**M-2: SB/SH/SW byte_en 값 표 추가 (14.2절)**
- 현재: 바이트 인에이블 개념을 코드 분석 포인트 ②에서 텍스트로만 설명
- 권고: SB(4'b0001), SH(4'b0011), SW(4'b1111) 매핑 표를 간단히 추가하면 명확성 향상

**M-3: 창조 수준 연습문제 선택 추가**
- 현재: 블룸 기억~평가 5수준 포함, 창조(Create) 수준 없음
- 권고 (선택): "직접 매핑 Write-Back D-Cache(14.2절 코드)를 Write-Through로 수정하시오" 같은 창조 수준 문제를 선택 과제로 추가하면 6수준 완성 가능. 필수 아님.

### 8.2 교육 설계 강점 (유지)

- **점진적 복잡도 증가:** 14.1(이론) → 14.2(직접 매핑) → 14.3(2-Way)의 단계적 확장이 탁월함
- **비유의 일관성:** 도서관 메모(14.1), 지정석(14.3) 비유가 핵심 개념을 직관적으로 전달
- **코드 점진적 공개:** 14.2절의 부분 코드 → 14.3절의 핵심 스니펫 → 전체 소스 코드 섹션 구조가 인지 부하 분산에 효과적
- **metacognition 완벽 배치:** 6개 절 모두 자가 점검 질문 포함, 수동 학습에서 능동 학습으로 전환 유도
- **실무 연결 밀도:** tip/faq/interview 박스 10개로 "왜 이것을 배우는가"에 대한 답변이 충분
