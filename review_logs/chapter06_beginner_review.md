## 3. 갑자기 나타난 개념 (선수 지식 없이 이해 불가한 내용)

### 심각도 높음

**문제 1: `control_unit` 모듈의 존재**
- 6.1절에서 `instruction_decoder` 모듈을 상세히 설명함.
- 6.3절 top-level 코드에서 갑자기 `control_unit`이라는 다른 모듈이 인스턴스화됨.
- 6.3절 본문에는 "`instruction_decoder`를 포함하는 `control_unit` 래퍼 모듈"이라는 설명이 없음.
- 독자는 "6.1절에서 만든 `instruction_decoder`가 왜 쓰이지 않고 `control_unit`이 쓰이지?"라고 혼란을 느낌.
- 전체 소스 코드 섹션(6.6절 이후)에 가서야 `control_unit`이 `instruction_decoder`와 `branch_comparator`를 감싸는 래퍼임을 알 수 있음.

**문제 2: `branch_comparator` 모듈**
- 6.1절 디코더 코드에서 `br_eq`, `br_lt`가 입력 포트로 선언됨.
- "누가 이 신호를 생성하는가?"에 대한 설명이 6.1~6.3절 어디에도 명시적으로 없음.
- 전체 소스 코드 섹션에서야 `branch_comparator`라는 별도 모듈이 존재함을 알게 됨.

### 심각도 중간

**문제 3: LUI에서 "ALU에서 0+imm 계산"**
- 6.2절 LUI 설명에서 "ALU에서 0+imm을 계산하는 방식으로 구현합니다"라고 언급.
- 하지만 LUI는 `a_sel=0`(rs1)이고, rs1이 x0(항상 0)인지 어떻게 보장하는지 설명 없음.
- 진리표에 `a_sel=rs1(0, x0)`라고 적혀 있지만, "LUI 명령어에서 rs1 필드는 항상 x0"인지, "rd_addr가 실제로 x0으로 hardwired 되는 건지" 독자가 헷갈릴 수 있음.

**문제 4: JALR 목표 주소의 LSB 클리어**
- 6.3절 PC MUX 코드에서 `PC_JALR: pc_next = alu_result & 32'hFFFF_FFFE;`
- "JALR의 목표 주소는 최하위 비트를 0으로 클리어한다"는 설명이 코드 주석 외에 본문에 없음.
- RISC-V 스펙의 이 규정을 독자가 모를 경우 의아하게 느낌.

## 4. 코드 예제의 이해 가능성

### 긍정적 평가

- `typedef enum` 정의 부분: 주석이 충분하고, 각 열거값의 의미가 명확함. ⭐⭐⭐⭐⭐
- opcode `case` 문: 각 opcode에 한국어 주석이 있고 계층적 case 구조가 명확함. ⭐⭐⭐⭐
- MUX assign 문: 1줄로 표현된 `a_sel ? pc : rs1_data` 패턴이 직관적. ⭐⭐⭐⭐⭐
- 피보나치 어셈블리 의사 코드: 레지스터 별명(a0, a1 등) 주석이 친절함. ⭐⭐⭐⭐⭐
- 테스트벤치 코드: `$display`로 기대값 명시, 독자가 따라하기 쉬움. ⭐⭐⭐⭐

### 개선 필요 부분

- **6.1절 `instruction_decoder` 포트 목록과 6.3절 `control_unit` 포트 목록 불일치**:
  6.1절 `instruction_decoder`에는 `rs1_addr`, `rs2_addr`, `rd_addr`, `funct3_out` 포트가 없음.
  6.3절 `control_unit` 인스턴스에는 이 포트들이 존재함.
  독자는 "디코더를 직접 top에 연결하지 않는 이유가 뭐지?"라며 포트를 찾으려 6.1절로 돌아가다 찾지 못하고 혼란에 빠질 수 있음.

- **`br_un` 순환 연결 의혹**:
  `control_unit` 내에서 `branch_comparator`의 출력 `br_un`을 `instruction_decoder`에 연결하고, `instruction_decoder`가 다시 `br_un`을 출력으로 내보냄.
  이 신호의 방향이 소스 코드를 보지 않은 독자에게는 "닭이 먼저냐 달걀이 먼저냐"처럼 느껴질 수 있음.

- **임계 경로 지연 시간 주석**:
  "Basys 3, Artix-7 -1 등급"이라는 표현이 주석에만 있고 본문에서 FPGA 등급 개념을 설명하지 않음.

## 7. 읽다가 막히는 구간 (구체적 문장 지적)

### 막힘 1: 6.1절 → 6.3절 전환 (★★★ 주요 문제)

**위치**: 6.3절 "서브모듈 인스턴스" 코드 블록
**막히는 문장**:
```verilog
control_unit u_control (
   .instr(instr), .rs1_data(rs1_data), .rs2_data(rs2_data),
   ...
   .rs1_addr(rs1_addr), .rs2_addr(rs2_addr),
   .rd_addr(rd_addr), .funct3_out(funct3)
);
```
**왜 막히는가**: 6.1절에서는 `instruction_decoder`만 설명했는데 `control_unit`이 갑자기 등장함. 또한 `rs1_addr`, `rs2_addr`, `rd_addr`가 `control_unit`의 출력인지, 왜 디코더에서 직접 나오지 않는지 설명이 없음.

**제안**: 6.3절 시작 전 또는 6.3.1절에 다음과 같은 설명 추가:
"이 책에서는 `instruction_decoder`와 `branch_comparator`를 하나의 `control_unit`으로 묶어 top-level에서 사용합니다. `control_unit`은 명령어에서 레지스터 주소(`rs1_addr`, `rs2_addr`, `rd_addr`)와 `funct3`도 추출하여 제공합니다."

---

### 막힘 2: 6.5절 Vivado TCL 코드

**위치**: 6.5.1절 코드 블록
**막히는 부분**: 코드 전체가 주석(//로 시작)으로만 구성되어 있음. 실행 가능한 TCL 명령어와 설명 주석의 경계가 없음.
**왜 막히는가**: "어디서 이 명령어를 실행하는 것인지", "실제 TCL 스크립트가 있는지 아니면 절차 설명인지" 혼란스러움.
**제안**: 실행 가능한 TCL 라인은 주석 없이, 설명은 별도 단락으로 분리.

---

### 막힘 3: 6.2절 Branch 진리표의 pc_sel "조건부"

**위치**: 6.2절 Branch 타입 진리표
**막히는 부분**: `pc_sel` 열의 값이 "조건부"라고만 표시됨.
**왜 막히는가**: 독자는 "조건부"가 어떤 신호에 의해 결정되는지, 그 신호가 어디서 오는지 알 수 없음.
**제안**: "조건부 (branch_taken=1이면 PC_BRANCH, 0이면 PC_PLUS4)"로 명시.

---

### 막힘 4: LUI의 rs1 출처

**위치**: 6.2절 LUI/AUIPC 진리표
**막히는 부분**: `a_sel = rs1(0, x0)`
**왜 막히는가**: 괄호 안 `x0`이 "ALU 입력 A에 x0 레지스터(항상 0)를 사용한다"는 의미인지, 아니면 `a_sel=0`이고 마침 연결된 rs1이 x0이라는 뜻인지 모호함. LUI 명령어에서 rs1 필드가 무시되는지, 아니면 반드시 x0로 인코딩되는지 RISC-V 스펙상 사실이 명시되어 있지 않음.
**제안**: "LUI는 rs1 필드가 없습니다. 내부적으로 a_sel=0(rs1)이 선택되지만, LUI 인코딩에서 rs1 필드는 0으로 고정되어 있어 실질적으로 0+imm 연산이 됩니다"라는 설명 추가.

---

### 막힘 5: 6.4절 파형 점검의 레지스터 이름 혼동

**위치**: 6.4절 스스로 점검 섹션
**막히는 문장**: "t0(x5), t1(x6) 등의 레지스터 값이 피보나치 수열과 일치합니까?"
**왜 막히는가**: 피보나치 프로그램 코드에서는 x10(a0), x11(a1), x12(a2), x13(a3), x14(a4), x15(a5)를 사용한다고 명시했는데, 점검 질문에서 갑자기 t0(x5), t1(x6)이 등장함. 프로그램과 무관한 레지스터임.
**제안**: "x10(a0), x11(a1) 값이 각각 55, 89인지 확인하십시오"로 수정 필요.

## 8. 종합 평가 및 개선 권고사항

### 잘 된 점

1. 챕터 도입부의 레고 비유가 전체 챕터 이해의 프레임을 잘 설정함
2. 각 절에 "스스로 점검" aside 박스가 있어 능동적 학습을 유도함
3. 진리표에서 각 명령어 타입별로 핵심 차이점을 강조한 설명이 효과적
4. 피보나치 어셈블리 코드의 주석이 충분하고, 기대 출력까지 제시한 점
5. 지하철 슬랙 비유가 타이밍 개념을 직관적으로 전달함
6. 임계 경로 단계별 지연 시간 수치를 표로 제시한 점

### 수정이 필요한 사항 (우선순위 순)

| 우선순위 | 문제 | 권고 수정 |
|----------|------|----------|
| P1 (필수) | `control_unit` 갑작스러운 등장 | 6.3절 시작 시 `instruction_decoder` → `control_unit` 래퍼 구조 설명 추가 |
| P1 (필수) | `branch_comparator` 설명 누락 | 6.1절 또는 6.2절에 분기 비교기 모듈 소개 추가 |
| P1 (필수) | 6.4절 스스로 점검의 레지스터 오류 | t0(x5), t1(x6)을 a0(x10), a1(x11)로 수정 |
| P2 (권장) | LUI에서 rs1이 x0인 이유 미설명 | 한 문장 설명 추가 |
| P2 (권장) | Branch 진리표 "조건부" 모호함 | 구체적 조건식 명시 |
| P2 (권장) | JALR LSB 클리어 이유 미설명 | 한 문장 설명 추가 |
| P3 (선택) | `shamt` 용어 미병기 | "시프트 양(shamt, shift amount)"으로 첫 등장 병기 |
| P3 (선택) | Vivado TCL 코드 블록 형식 | 실행 가능 명령어와 주석 분리 |
