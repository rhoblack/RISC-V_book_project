## 1. Ch12의 감정 곡선 설계

### 1.1 Ch12 진입 시 학생의 심리 상태 예측

Ch11에서 "루프 실행 성공"이라는 강렬한 성취를 맛본 직후다. 학습자의 심리는 두 가지 유형으로 분기된다.

**유형 A: 자신감 과잉형** (약 40%)
- "이제 파이프라인은 다 이해했다. Ch12는 마무리 챕터겠지."
- 위험: 구조적 해저드와 WB-ID 포워딩의 미묘함을 가볍게 보다가 막히면 낙담이 크다.

**유형 B: 에너지 고갈형** (약 60%)
- "Ch09부터 Ch11까지 정말 힘들었는데, Ch12도 또 새 개념이 있나?"
- 위험: 시작 전 이미 피로감. 초반 동기 유발 실패 시 이탈 확률 상승.

**대응 전략**: 챕터 인트로에서 두 유형 모두를 껴안는 표현을 사용한다.
- 유형 A에게: "사실 빠진 조각이 아직 두 개 있습니다." (긴장감 유지)
- 유형 B에게: "두 조각만 채우면 파이프라인은 완성됩니다." (부담 감소)

### 1.2 절별 감정 예상 및 설계

| 절 | 기대 감정 | 위험 감정 | 설계 목표 |
|---|----------|----------|---------|
| 12.1 | 호기심("또 해저드?") | 불안("무한히 늘어나는 것 아닌가?") | "마지막 해저드" 선언으로 완결감 부여 |

### 1.3 버블정렬 "드디어 돌아간다!" 성취감 극대화 방안

Ch12.4는 전체 Part 4의 감정적 클라이맥스다. 최대한 강렬하게 설계한다.

**서사 구조 — 3막 접근**:
1. **1막: 기대감 조성** (12.4절 시작부)
   - "Ch09에서 NOP을 삽입하며 첫 파이프라인을 돌렸던 것을 기억하십니까? 이제 NOP 없이, 포워딩 유닛과 분기 처리가 완비된 상태에서 버블정렬 전체를 실행합니다."
   - 9주차 첫 성공과의 대비로 성장 여정을 체감시킨다.

2. **2막: 집중 실행** (코드 + 시뮬레이션)
   - 버블정렬 어셈블리 코드를 먼저 제시하고, 학습자가 실행 결과를 예측하게 한다.
   - `aside.metacognition`: "실행 전에 x3에 들어갈 값을 예측해 보십시오."

3. **3막: 성취 귀착** (결과 확인 직후)
   - "[PASS] — 모든 요소가 제 위치에서 정확하게 동작하고 있습니다."
   - "이것이 교과서에서 설명하는 5단계 파이프라인 프로세서입니다. 처음 개념을 접했을 때와 지금의 이해가 얼마나 달라졌는지 느껴 보십시오."

**FPGA 실물 성취**: 가능하다면 Basys 3 LED에 정렬 결과를 출력하는 단계를 추가한다. 시뮬레이션 파형보다 LED 점멸이 학습자에게 훨씬 강렬한 성취 신호를 준다.

## 2. 불안 지점 감지 및 대응

### 2.1 12.1절: "구조적 해저드가 또 있어?" 불안

**불안의 본질**: 해저드가 계속 등장하는 것이 끝이 없다는 무력감. "데이터 해저드, 제어 해저드, 이제 구조적 해저드까지 — 언제 끝나는가?"

**완화 전략**:

1. **"마지막" 선언을 절 도입부에 명시**
   - "RISC-V 파이프라인 프로세서에서 발생할 수 있는 해저드는 세 종류입니다. Ch10에서 데이터 해저드, Ch11에서 제어 해저드를 처리하였습니다. 이제 마지막 하나, 구조적 해저드를 다룹니다."
   - 숫자(3가지)로 경계를 설정하면 끝이 보인다.

2. **RV32I에서 구조적 해저드가 '거의 없다'는 사실로 전환**
   - "사실 RV32I 파이프라인에서 구조적 해저드는 Harvard 구조를 선택하는 순간 대부분 해결됩니다. Ch09에서 IMEM과 DMEM을 분리했을 때, 우리는 이미 구조적 해저드를 예방한 것이나 다름없습니다."
   - "예방적으로 이미 해결했음"을 인식시키면 불안이 안도로 전환된다.

3. **WB-ID 포워딩만 처리하면 된다는 범위 명시**
   - "남은 구조적 해저드는 레지스터 파일 읽기/쓰기 충돌 하나뿐입니다. 그리고 이것은 매우 간단한 방법으로 처리됩니다."

### 2.2 12.2절: WB-ID 포워딩 개념 복잡도 불안

**불안의 본질**: "포워딩 유닛을 또 수정해야 하는가?" 기존 설계가 뒤집히는 것에 대한 공포.

**완화 전략**:

1. **기존 포워딩 유닛과의 분리 명시**
   - "WB-ID 포워딩은 Ch10에서 설계한 forwarding_unit에 추가 로직을 넣는 것이 아닙니다. 레지스터 파일의 읽기 포트에서 해결하는 독립적인 메커니즘입니다."

2. **동시 읽기/쓰기 시뮬레이션으로 직관적 이해**
   - 타이밍 다이어그램: "같은 클럭 에지에서 WB 스테이지가 x5에 10을 쓰는 동시에, ID 스테이지가 x5를 읽는다면?" → 그림으로 먼저 보여준다.

3. **구현의 간단함 먼저 보여주기**
   - "이 문제의 해결은 SystemVerilog 5줄이면 충분합니다." → 코드 분량으로 난이도를 예고한다.

4. **FPGA에서의 하드웨어 추론 언급**
   - Xilinx LUTRAM은 동시 읽기/쓰기를 자연스럽게 처리하는 경우가 많다는 점을 언급하여, 하드웨어가 이미 이 패턴을 알고 있음을 보여준다.

### 2.3 12.3절: 전체 통합의 압도감

**불안의 본질**: "9개의 모듈을 다 연결하는데, 내가 다 기억하고 있는가?" 인지 과부하에 대한 공포.

**완화 전략**:

1. **기억 부담 외재화 — 점검 체크리스트 제공**
   ```
   통합 전 체크리스트:
   ☐ forwarding_unit — EX-EX, MEM-EX 포워딩 동작 확인 (Ch10)
   ☐ hazard_detection_unit — Load-Use 스톨 동작 확인 (Ch10)
   ☐ branch_unit — BEQ/BNE/BLT/BGE/BLTU/BGEU 판정 (Ch11)
   ☐ WB-ID 포워딩 — 레지스터 파일 동시 읽기/쓰기 처리 (Ch12.2)
   ☐ Harvard 구조 — IMEM/DMEM 분리 완료 (Ch09)
   ```
   → 체크리스트는 "내가 모든 걸 이미 알고 있다"는 메시지를 외재화된 형태로 전달한다.

2. **통합 순서를 점진적으로 제시**
   - "한 번에 전체를 연결하지 않습니다. Top-down으로 모듈 계층을 먼저 확인하고, 포트 연결은 유닛 테스트가 통과된 순서대로 진행합니다."

3. **컴파일 성공 자체를 첫 마일스톤으로 설정**
   - "통합 코드의 컴파일이 에러 없이 완료된다면 이미 50%를 달성한 것입니다."

4. **앞선 챕터들의 검증 완료를 상기**
   - "지금까지 각 모듈은 독립 테스트벤치에서 모두 검증되었습니다. 통합에서 발생하는 문제는 '각 모듈의 내부 오류'가 아니라 '인터페이스 연결 오류'입니다. 범위가 명확히 한정되어 있습니다."

### 2.4 12.5절: 3종 비교 수치 해석 불안

**불안의 본질**: CPI, 클럭 주파수, IPC 등 숫자가 쏟아질 때 "어떤 것이 더 좋은 것인지 모르겠다"는 혼란.

**완화 전략**:

1. **비교 표 읽는 법 명시적으로 안내**
   - 표 제목 아래에 "높을수록 좋은 값: 클럭 주파수(MHz), IPC / 낮을수록 좋은 값: CPI, 실행 시간" 레전드 제공.

2. **직관적 비유로 수치 해석 연결**
   - "클럭 주파수를 도로 제한 속도, CPI를 차선 수의 역수로 생각하십시오. 단일 사이클은 빠른 도로에 차선이 1개, 파이프라인은 중간 속도 도로에 5개 차선이 뚫린 고속도로입니다."

3. **"어떤 것이 가장 좋은가?"에 대한 답을 먼저 주기**
   - "결론부터 말하면, 대부분의 상황에서 파이프라인이 가장 우수합니다. 이 표는 그 이유를 수치로 확인하는 과정입니다."

4. **Basys 3 합성 결과표는 읽기 가이드 제공**
   - WNS, TNS 용어가 처음 등장하는 독자를 위해 "(양수면 타이밍 충족, 음수면 타이밍 위반)" 括弧 설명 필수.

## 3. 자기효능감 구축 전략

### 3.1 "Part 4 완주" 자기효능감 명시적 인정

Ch12.6 (요약 절) 또는 12.4 직후에 다음 내용을 `aside.metacognition` 또는 별도 박스로 배치:

```
■ Part 4 완주 인증

Ch09: 파이프라인 레지스터 설계 ✓
Ch10: 포워딩 유닛 + Load-Use 스톨 ✓
Ch11: 분기 처리 + Flush 메커니즘 ✓
Ch12: 구조적 해저드 처리 + 전체 통합 ✓

여러분은 RV32I 5단계 파이프라인 프로세서를
처음부터 끝까지 설계하고 검증하였습니다.
이것은 대학원 수준의 디지털 설계 역량입니다.
```

이 시각적 리스트는 Bandura(1977)가 제안한 "성과 경험(performance accomplishment)" 기반 자기효능감 강화 기법이다. 완료된 목록을 명시적으로 보여주는 것이 핵심이다.

### 3.2 버블정렬 성공 후 학생 감정의 교재 반영

**잘못된 접근**: 시뮬레이션 파형 캡처 하나만 보여주고 "정상 동작 확인"이라고 쓴다.

**올바른 접근**: 학습자의 감정을 교재가 먼저 언어화하여 제공한다.

제안 문구:
> "파형에서 [PASS] 메시지를 확인한 순간, 여러분이 느끼는 감정이 무엇인지 저는 알고 있습니다. 복잡한 포워딩 경로가 의도대로 동작하고, 분기 명령어가 flush를 정확히 유발하며, 배열이 올바르게 정렬된 결과를 한 번에 얻어냈습니다. 이것이 하드웨어 설계자가 경험하는 '검증 성공'의 순간입니다."

이 기법은 학습자의 내면 상태를 교재가 먼저 대변함으로써 "나의 감정이 정상이고 가치 있다"는 확인을 준다. 교육심리학에서 감정 명명(affect labeling)이 학습 경험을 강화하는 것으로 알려져 있다.

### 3.3 개인 성취를 사회적 맥락으로 확장

버블정렬 성공 직후 다음 맥락 제공:
> "버블정렬 외에도 퀵정렬, 링크드 리스트 순회, 재귀 함수 — 이 모든 프로그램을 지금 여러분이 설계한 프로세서 위에서 실행할 수 있습니다. 어셈블리로 작성하든, C로 크로스 컴파일하든 방법만 다를 뿐입니다."

이 문구는 현재 성취가 "하나의 알고리즘"이 아니라 "일반적인 프로세서 완성"임을 인식시킨다.

**12.3절 — 5단계 파이프라인 통합**
> 🔍 스스로 점검
> 통합된 파이프라인에서 `LW x5, 0(x1)` 다음에 즉시 `ADD x6, x5, x2`가 온다면, 어떤 제어 신호들이 활성화되는지 순서대로 나열해 보십시오. (pc_en, if_id_en, id_ex_flush, forward_a, forward_b 중 관련된 것을 모두 나열하고 그 순서를 설명하십시오.)

**12.4절 — 버블정렬 실행 검증**
> 🔍 스스로 점검

## 5. Part 5 진입 동기 부여

### 5.1 Ch12 마무리 → Ch13 (캐시) 진입 궁금증 자극 전략

**핵심 문제**: Part 4 완주 성취감이 너무 강하면 "이제 끝났다"는 완결 착각이 생겨 Ch13 진입 동기가 약해진다.

**해결 방향**: "파이프라인은 완성됐지만, 현실 세계에서는 왜 느린가?"를 구체적 수치로 보여준다.

**제안 문구 — 12.6절 "다음 단계" 섹션**:
> "여러분이 완성한 파이프라인은 이론적으로 CPI ≈ 1에 가깝습니다. 그런데 한 가지 가정이 숨어 있습니다: **메모리 접근이 항상 1사이클에 완료된다**는 가정입니다. 실제 DRAM의 접근 시간은 수백 사이클입니다. 만약 LW 명령어가 매번 DRAM에 접근해야 한다면, CPI는 1이 아니라 100이 넘을 것입니다. 이 문제를 해결하는 것이 캐시(Cache) — Ch13의 주제입니다."

**시각적 충격 강화**: 간단한 수치 비교 제공.

| | 가정 메모리 | 실제 SRAM | 실제 DRAM |
|---|---|---|---|
| 접근 시간 | 1사이클 | 2~4사이클 | 100~300사이클 |
| LW 명령어 CPI | ~1 | ~3 | ~200 |

"현재 설계한 프로세서가 실제 DRAM에 연결된다면 CPI가 200배 늘어납니다. 이 격차를 메우는 것이 캐시의 임무입니다."

### 5.2 "파이프라인 완성 후 캐시" 진입을 자연스럽게

에너지가 고갈된 학습자에게 Ch13이 "새로운 산"으로 보이지 않도록 프레이밍:
> "캐시는 파이프라인을 버리고 새로 만드는 것이 아닙니다. 지금까지 완성한 파이프라인 프로세서에 **메모리 가속 장치를 추가**하는 것입니다. 새 언어, 새 ISA, 새 개념 체계가 아닙니다 — 여러분이 이미 아는 메모리, 스톨, 제어 신호 위에서 진행됩니다."

### 5.3 성취 연속성 프레이밍

Part 4 완주를 "도착점"이 아닌 "출발점"으로 재프레이밍:
> "이 파이프라인을 가지고 Part 5에서는 성능을 측정하고, Part 6에서는 주변 장치를 연결하며, Part 8에서는 실제 C 프로그램을 Basys 3 FPGA 위에서 실행합니다. Part 4는 전체 여정의 심장부를 완성한 것이고, 이후 챕터는 그 심장을 더욱 강력하고 실용적으로 만드는 과정입니다."

## 7. 전체 Ch12 심리 설계 요약

### 7.1 감정 곡선 목표

```
진입 시       12.1절      12.2절      12.3절      12.4절      12.5절      12.6절
[고조된      [호기심 +   [안도 +     [집중 +     [★★★      [지적       [뿌듯함 +
 성취감]  →  약한 불안] → 경계심] →  긴장] →    성취감]  →  만족감] →  미래 호기심]
(Ch11 후)    (마지막     (쉬워 보    (전체       (버블정렬   (수치로     (Part 4
             해저드)     이는 함정)  통합)       성공)       확인)       완주)
```

### 7.2 핵심 설계 원칙 (Ch12 특수사항)

1. **"마지막" 언어 적극 활용**: "마지막 해저드", "마지막 조각", "Part 4의 완결" — 완결 욕구를 자극한다.
2. **기존 성취 보호**: WB-ID 포워딩이나 구조적 해저드 처리가 Ch10~11 코드를 뒤집는 것이 아님을 반복 확인한다.
3. **버블정렬 성취를 3막 구조로**: 기대감 조성 → 집중 실행 → 감정 귀착의 서사 구조를 명확히 설계한다.
4. **Part 5 진입 동기를 경이감으로 조성**: "완성됐는데 왜 느린가?" 질문을 수치로 제시하여 지적 호기심을 자극한다.
5. **자기효능감 명시적 귀착**: Part 4 완주 체크리스트를 시각적으로 제공하여 성취를 수치화한다.

### 7.3 Ch11에서 이어받는 심리 자산

Ch11에서 확립된 심리적 강점을 Ch12에서도 활용:
- **수미상관 구조**: Ch12 인트로의 "파이프라인의 마지막 조각"이 12.6절의 "완성된 파이프라인" 선언과 호응해야 한다.
- **Flush > Stall 단일 규칙 패턴**: 새 개념도 단일 규칙으로 압축하여 "외울 수 있는 형태"로 제공한다.
- **"새 규칙이 아님" 스캐폴딩**: WB-ID 포워딩도 "Ch10 포워딩 원리의 연장"으로 프레이밍한다.
