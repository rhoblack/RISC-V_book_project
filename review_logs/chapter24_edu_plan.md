- **범위 명시**: M 확장 = 실제 구현, F 확장 = 개념 이해, Zicntr = 기존 구현과 연결
- **Ch23 연결**: "Ch23에서 성능 최적화의 '구조적' 접근을 봤다면, 이번에는 'ISA 확장'이라는 전혀 다른 축의 성능 향상을 탐구합니다"
- **안심 문구**: "이 챕터는 Part 9 선택 챕터입니다. M 확장의 곱셈기 구현만으로도 충분한 성취입니다."

### 24.1 M 확장: 곱셈/나눗셈 명령어
**흐름**: ISA 정의(구체) → 하드웨어 구현 전략(구체) → 파이프라인 통합(분석)

1. **도입** (5분): "왜 곱셈이 기본 ISA에 없는가?" -- RISC-V 모듈형 철학 설명, M 확장 = 선택적 추가
2. **ISA 정의** (10분): 8개 명령어 인코딩 표, funct7=0000001 통일, funct3로 구분
   - MUL/MULH/MULHSU/MULHU: 부호 있음/없음 조합 4가지
   - DIV/DIVU/REM/REMU: 나눗셈/나머지 부호 있음/없음 2×2
   - **비유**: "32비트 × 32비트 = 64비트 결과. 32비트 레지스터 하나에 담을 수 없으니 MUL(하위)과 MULH(상위)로 나눠 담습니다. 마치 큰 짐을 두 상자에 나눠 싣는 것과 같습니다."
3. **하드웨어 구현 전략** (15분):
   - 곱셈: DSP48E1 활용 (Basys 3에 90개), 1사이클 완료 가능
   - 나눗셈: 다사이클 비복원 나눗셈기 (32사이클), FSM 제어
   - **DSP48E1 블록 다이어그램 SVG**: 25×18비트 곱셈기 내부, 32비트 확장 방법
4. **파이프라인 통합** (10분):
   - MUL: 1사이클 → EX 스테이지에 바로 삽입
   - DIV: 32사이클 → 다사이클 점유, `div_busy` 스톨 신호
   - 기존 `pipeline_stall` 신호에 `div_stall` 추가
5. **정리**: 8개 명령어 요약 표, "곱셈은 DSP로 간단, 나눗셈은 복잡 -- 이것이 M 확장을 선택적으로 만든 이유"

> **인지 부하 분석**: 신규 개념 5개(MUL/MULH 구분, DSP48E1 매핑, 다사이클 나눗셈, div_stall, funct7=0000001). 원칙(절당 3개)을 초과하므로 **하위 절 분할 권장**:
> - 24.1.1: ISA 정의 (신규 3개: 8개 명령어, MUL/MULH 구분, signed/unsigned 조합)
> - 24.1.2: 하드웨어 구현과 파이프라인 통합 (신규 2개: DSP48E1 매핑, div_stall)

### 24.2 F 확장 개요
**흐름**: IEEE 754 소개(5분) → F 확장 ISA 개관(10분) → HW vs SW 트레이드오프(10분) → 구현 복잡도 경고(5분)

1. **IEEE 754 기초** (5분): 부호(1) + 지수(8) + 가수(23) = 32비트, 정규화, 특수값(Inf, NaN)
   - **비유**: "부동소수점은 과학적 표기법(1.23 × 10^4)의 이진 버전입니다"
2. **F 확장 ISA 개관** (10분): f0~f31 레지스터, FADD.S/FMUL.S/FLW/FSW 등 주요 명령어 소개 (전체 나열은 하지 않음)
3. **HW vs SW 트레이드오프** (10분):
   - SW 에뮬레이션: soft-float 라이브러리, 수십~수백 사이클/연산
   - HW FPU: 1~수 사이클, but LUT 수천 개 + 별도 레지스터 파일 + 포워딩 경로 이중화
   - Basys 3 리소스 제약: "LUT 20,800개 중 파이프라인+캐시+AMBA가 이미 60~70% 사용"
4. **구현 복잡도 경고** (5분): "F 확장 완전 구현은 이 교재의 범위를 넘습니다" 명시
   - 실무 참조: RISC-V soft-float 라이브러리, Berkeley HardFloat
   - **안심 문구**: "F 확장의 개념을 이해하는 것 자체가 성취입니다. 면접에서도 '구현 경험'보다 'IEEE 754 원리 이해'가 더 자주 질문됩니다."

> **인지 부하 분석**: 신규 개념 2개(IEEE 754 구조, f-레지스터 파일). 3개 이하 원칙 충족. 개념적 절이므로 분량 2000자 이하로 간결하게.

### 24.3 Zicntr 확장
**흐름**: Ch21 성능 카운터 복습(3분) → Zicntr 표준화 의의(5분) → RDCYCLE/RDINSTRET 의사 명령어(5분)

1. **복습**: Ch21.5에서 구현한 mcycle, minstret CSR 재확인
2. **표준화 의의**: "우리가 이미 구현한 것이 사실 Zicntr의 핵심입니다" -- 기존 지식 인정
3. **RDCYCLE/RDINSTRET**: 어셈블러 의사 명령어 → CSRRS x, csr, x0 변환
4. **RDTIME**: mtime MMIO 레지스터 vs time CSR의 차이 (구현 선택지)

> **인지 부하 분석**: 신규 개념 1개(Zicntr 명칭과 표준화). 대부분 기존 지식 재확인이므로 부담 최소. 분량 1500자 이하 권장.

### 24.4 미니 설계 과제: M 확장 곱셈기 구현
**흐름**: 요구 사양 제시(5분) → 단계별 가이드(20분) → 테스트벤치(10분)

1. **요구 사양**: MUL 명령어만 지원하는 곱셈 유닛 설계
   - 입력: rs1_data[31:0], rs2_data[31:0], mul_en
   - 출력: mul_result[31:0] (하위 32비트만)
   - 제약: DSP48E1 추론 (`(* use_dsp = "yes" *)`)
2. **단계별 가이드**:
   - Step 1: 조합 곱셈기 (`assign result = rs1 * rs2;`) -- 합성 도구가 DSP 추론
   - Step 2: 파이프라인 EX 스테이지에 MUX 추가 (alu_result vs mul_result)
   - Step 3: 디코더에 M 확장 funct7 감지 추가
3. **테스트벤치**: 경계값(0, 1, -1, 최댓값, 오버플로) 검증
4. **도전 과제 (선택)**: MULH 지원 추가 (상위 32비트 추출)

> **인지 부하 분석**: 기존 파이프라인 구조(Ch12)에 모듈 하나를 추가하는 작업. 신규 개념 0개 (24.1에서 학습 완료), 순수 적용/창조 단계.

## 불안 지점 & 안심 장치
