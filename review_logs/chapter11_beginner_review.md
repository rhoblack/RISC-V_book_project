### 개선이 필요한 용어 3건 요약
1. **BTB**: 면접 포인트 박스에서만 약어 등장, 정식 정의 없음
2. **id_ex_jalr**: JALR 감지 신호의 생성 경로(디코더 → ID/EX 레지스터 전달) 설명 누락
3. **branch_taken_ex 접미사 규칙**: `_ex`가 "EX 스테이지에서 생성된 신호"임을 명시해 주면 이후 혼동 방지

## 5. 어려운 구간 지적

### 5.1 가장 어려운 절: 11.6 JAL/JALR 처리 ⭐⭐⭐

**이유**:
1. **id_ex_jalr 신호 출처 불명확**: `assign jalr_taken_ex = id_ex_jalr;` 코드에서 `id_ex_jalr`이 어디서 오는지 설명이 없습니다. 디코더에서 생성되어 ID/EX 레지스터에 저장되는 과정이 생략되어 있습니다.

2. **JAL flush 범위 혼란 가능성**: "if_id_flush만 활성화, id_ex_flush 없음"인 이유가 "JAL 자신은 ID 스테이지를 통과 중이므로 영향 없다"는 설명이 있으나, 처음 읽으면 "그럼 ID 스테이지에 있는 JAL도 flush 대상이 아닌가?"라는 질문이 자연스럽게 생깁니다. 현재 FAQ 박스가 이를 해소하지만, 본문에서도 1문장 선행 설명이 필요합니다.

3. **if_id_flush 동작 범위 재확인 필요**: if_id_flush가 "IF/ID 레지스터에 새로 래치되는 값"만 덮어쓴다는 점이 FAQ에만 나오고 본문에는 없습니다. 11.3절의 if/else if 코드(`if (!rst_n || if_id_flush)` → NOP으로 교체)를 다시 참조하게 만드는 구조입니다.

### 5.2 두 번째로 어려운 구간: 11.3절 pc_en 로직

```systemverilog
assign pc_en = if_id_flush ? 1'b1 : hdu_pc_en;
```

이 한 줄의 의미가 처음에는 직관적이지 않습니다. "flush가 발생하면 PC를 강제로 갱신한다"는 목적은 이해되지만, "왜 flush 시에 hdu_pc_en이 아니라 1'b1 고정인가?"에 대한 설명이 팁 박스에 있으나 본문보다 후반에 등장합니다. 이 설명을 코드 직전으로 이동하면 좋겠습니다.

### 5.3 세 번째로 어려운 구간: 11.2절 "단, load는 Ch10의 스톨이 처리하므로 안전"

> "따라서 직전 명령어가 ADD이든 LW이든(단, load는 Ch10의 스톨이 처리하므로 안전)"

이 괄호 안 설명이 너무 압축되어 있습니다. Ch10을 복습하지 않은 독자는 "LW 직후 BEQ가 오면 어떻게 되는가?"라는 의문이 해소되지 않습니다. Load-Branch 해저드에 대한 1~2문장 보강을 권장합니다.

## 7. 전체 이해도 평가: Ch10 지식만으로 Ch11을 이해할 수 있는가?

### 전제 지식 확인

| 필요 지식 | 출처 | Ch11에서 사전 설명 여부 |
|----------|------|----------------------|
| 포워딩 유닛 (forward_a/b) | Ch10 | ✅ "포워딩된 rs1, rs2"로 자연스럽게 참조 |
| Load-Use 스톨 (id_ex_flush=stall) | Ch10 | ✅ 11.3절에서 확장 사용 설명 |
| hazard_detection_unit | Ch10 | ✅ hdu_pc_en으로 참조, 설명 충분 |
| 파이프라인 레지스터 구조 | Ch09 | ✅ id_ex_pc, id_ex_imm 등 자연스럽게 사용 |
| NOP = 32'h0000_0013 | Ch09 | ✅ flush 코드에서 그대로 사용 |
| if_id_flush=0 예약 포트 | Ch09 | ✅ 11.3절에서 드디어 연결한다는 맥락 명시 |

### 결론

**Ch10 지식만으로 Ch11을 이해하는 데 충분합니다 — 단, 아래 2가지 예외 포함:**

1. **id_ex_jalr 신호**: Ch09~10에서 이 신호가 어떻게 ID/EX 레지스터에 전달되는지 다루지 않았습니다. 11.6절에서 파생 로직 없이 바로 사용되므로, 독자는 "이 신호가 어디서 오는가?"라는 의문이 생깁니다. 디코더 → 제어 신호 → ID/EX 레지스터 경로에 대한 1문장 설명이 필요합니다.

2. **fwd_b_data vs id_ex_rs2_data 구분**: 11.2절에서 `branch_unit`이 `fwd_b_data`를 사용한다고 설명하는데, 이 이름이 Ch10의 포워딩 MUX B 출력임을 독자가 정확히 인식하려면 Ch10 코드를 다시 펼쳐야 합니다. 명시적 주석("Ch10 포워딩 MUX B 출력") 1줄이면 해소됩니다.

## 8. 세부 개선 제안 (우선순위 순)

### Critical (반드시 수정)
없음

### Major (강력 권장)
1. **11.6절 id_ex_jalr 출처 설명 추가**: `id_ex_jalr`이 디코더의 jalr 제어 신호가 ID/EX 레지스터를 통해 EX 스테이지로 전달된 것임을 1~2문장으로 설명
2. **11.3절 pc_en 설명 순서 변경**: 팁 박스의 "왜 flush 시 1'b1인가" 설명을 코드 직전으로 이동하거나 인라인 주석으로 추가

### Minor (개선 권장)
3. **BTB 정의 추가**: 11.1절 면접 포인트에서 "BTB — Branch Target Buffer(분기 타겟 버퍼, 타겟 주소를 캐싱하는 테이블)" 1문장 추가
4. **Load-Branch 해저드 보강**: 11.2절에서 "LW 직후 BEQ 시" 1~2문장 설명 추가
5. **11.3절 또는 11.6절에 메타인지(🔍) 박스 1개 추가**: "JAL이 if_id_flush를 발생시킬 때, JAL 명령어 자신은 어느 스테이지에 있습니까?"
6. **fwd_b_data 명시**: branch_unit 인스턴스 코드에 `.rs2_data(fwd_b_data) // Ch10 포워딩 MUX B 출력` 주석 추가
