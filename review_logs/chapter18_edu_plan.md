## 2. 학습 흐름 설계

**도입** (호기심 유발):
- "프로세서가 자신의 상태를 어떻게 관리할까?"
- "인터럽트가 발생했을 때, CPU는 '현재 상태'를 어디에 저장할까?"

**개념** (단계적 확대):
1. M-mode 개념 (특권 수준)
2. CSR의 정의 및 주소 공간
3. 7개 핵심 CSR의 역할
4. CSR 명령어 6개

**예시** (구체적 시나리오):
- "프로세서가 인터럽트를 받으면, mie 비트를 확인한다"
- "예외가 발생하면 mepc에 복귀 주소를 저장한다"

**실습** (동작 검증):
- mstatus 읽기 → CSRRW로 쓰기 → 레지스터 값 확인
- CSRRW, CSRRS, CSRRC 각 1회 실행 및 검증

**정리** (핵심 요약):
- CSR의 용도별 분류
- CSR 명령어의 원자성 보장
- "다음은 실제 예외 처리"

## 3. 인지 부하 분석

**신규 개념** (절당 평균 2~3개):
- 18.1: M-mode + CSR + 주소공간 = 3개
- 18.2: mstatus 구조 + 6개 CSR = 1~2개
- 18.3: CSRRW/RS/RC + I-타입 = 2개
- 18.4: 시뮬레이션 = 0개 신규
- 18.5: 정리 = 0개 신규

**인지 부하 완화**:
- CSR 주소 외우기 금지 → 라이브러리 함수 제공
- 7개 CSR만 학습 (12개 아님)
- 각 비트는 "언제 필요한지"만 명확히

## 4. 연습문제 설계 (총 5개, L2~L4)

**L2 (이해)**:
1. mstatus의 MIE 비트가 무엇인가?
   - 정답: "Machine Interrupt Enable. 인터럽트 신호 수락 여부 제어"

2. CSRRW와 CSRRS의 차이는?
   - 정답: "CSRRW=전체 덮어쓰기, CSRRS=비트 OR(설정)"

**L3 (적용)**:
3. CSRRW로 mtvec을 0x80000000으로 설정하는 어셈블리 코드
   - 정답: `li t0, 0x80000000; csrrw x0, mtvec, t0`

4. C 코드 `uint32_t status = read_csr(mstatus);`를 어셈블리로
   - 정답: `csrr t0, mstatus`

**L4 (분석)**:
5. mie와 mip가 별도로 존재하는 이유는?
   - 정답: "mie='어떤 인터럽트 허용?', mip='어떤 인터럽트 대기중?'. 소프트웨어가 둘을 비교하여 판단"
