## 1. 동기 유지 전략

### 1.1 Ch24의 심리학적 위치: "성능 탐험 이후, 기능 확장"

Ch23에서 슈퍼스칼라/분기예측/비순차 실행이라는 "고급 개념 탐험"을 마쳤습니다. 수강생의 현재 상태:

| 심리 요소 | 상태 | 의미 |
|----------|------|------|
| 자기효능감 | **높음** | Ch22 SoC 완성 + Ch23 탐험 완료 |

**도입부 설계 의도**: "RV32I만으로는 곱셈 하나에 루프 30+사이클, M 확장이면 1사이클"

## 2. 불안 지점 3가지 & 완화 방안

### 불안 #1: M 확장 하드웨어 복잡도 — "나눗셈기 32비트짜리...? 할 수 있나?"

**발생 시점**: 24.1절 중반, 곱셈/나눗셈 알고리즘 상세 설명 구간

**심리 프로필**:
- "Radix-4 Booth Encoding? Restoring Division? 알고리즘이 너무 복잡하다"
- "32비트 나눗셈기를 직접 설계하라고?"
- "Ch23의 Tomasulo처럼 또 이해 못 하면..."

**심화 요인**: Ch23에서 Tomasulo 알고리즘의 추상성에 한 번 좌절을 경험한 상태. "또 복잡한 알고리즘인가?" 경계감이 있음.

**완화 방안**:

```html
<aside class="tip">
💡 <strong>곱셈기 설계, 생각보다 간단합니다</strong>

Basys 3 보드의 Artix-7 FPGA에는 <strong>DSP48E1</strong>이라는 전용 곱셈 블록이
내장되어 있습니다. 이 블록 하나가 25x18비트 곱셈을 1사이클에 처리합니다.

SystemVerilog에서 곱셈기를 "설계"하는 코드는 놀랍도록 짧습니다:
<code>assign product = a * b;</code>

Vivado 합성기가 이 한 줄을 DSP48E1로 자동 매핑합니다.
"곱셈 알고리즘을 비트 단위로 이해해야 한다"는 압박은 불필요합니다.

나눗셈기는 조금 더 복잡하지만, 이 챕터에서는 iterative restoring division의
<strong>원리</strong>만 이해하면 됩니다. 최적화된 구현은 IP 코어를 사용하는 것이
실무에서도 일반적입니다.
</aside>
```

**추가 전략**:
- 곱셈: `*` 연산자 → DSP 자동 매핑이라는 "1줄 구현"을 먼저 보여주어 안심
- 나눗셈: iterative 방식의 원리만 다루고, "IP 코어 사용이 실무 표준"임을 명시
- Ch23과의 차이점 강조: "Ch23은 개념 탐구, Ch24는 직접 구현 — 코드가 돌아갑니다"

**구현**: 24.1절 초반에 `<aside class="tip">` 배치

### 불안 #2: F 확장의 깊이 — "IEEE 754는 뭐고... rounding mode는... (포기)"

**발생 시점**: 24.2절 진입, IEEE 754 규격 설명 시작

**심리 프로필**:
- "부동소수점 표현 자체가 혼란스럽다 (sign, exponent, mantissa)"
- "NaN, Infinity, denormalized... 예외 케이스가 너무 많다"
- "rounding mode가 5가지나 있다고?"
- "이걸 하드웨어로 구현하라면... 절대 무리"

**심화 요인**: 부동소수점은 정수와 달리 비직관적 동작이 많음(0.1+0.2 != 0.3). 이미 M 확장에서 에너지를 소모한 상태에서 완전히 새로운 패러다임 진입.

**완화 방안**:

```html
<aside class="faq">
❓ <strong>"F 확장, 꼭 다 알아야 하나요?"</strong>

<strong>짧은 답: 아닙니다.</strong>

F 확장은 RISC-V 확장 중에서도 가장 복잡한 축에 속합니다.
하드웨어 부동소수점 유닛(FPU)을 완전히 구현하려면
Basys 3의 DSP 블록 30~50개가 필요하며, 이는 이 교재의 범위를 넘어섭니다.

이 절의 목표는 세 가지입니다:
1. IEEE 754 단정밀도의 <strong>기본 구조</strong> (sign + exponent + mantissa)
2. F 확장 명령어가 <strong>어떤 것들이 있는지</strong> (FADD, FMUL, FLW, FSW 등)
3. 하드웨어 구현 vs 소프트웨어 에뮬레이션의 <strong>트레이드오프</strong>

IEEE 754의 모든 예외 케이스나 rounding mode를 외울 필요는 없습니다.
칩 설계 진로가 아니라면, <strong>5분 읽고 핵심만 파악해도 충분합니다</strong>.
</aside>
```

**추가 전략**:
- "C 프로그램의 float/double은 GCC가 소프트웨어 에뮬레이션으로 처리" → 하드웨어 구현이 유일한 방법이 아님
- 구현 복잡도 표를 먼저 보여주어 "범위"를 정의 → 불확실성 제거
- 24.2절은 의도적으로 짧게 (2000자 이내) → 인지 부하 최소화

**구현**: 24.2절 앞에 `<aside class="faq">` 배치

## 4. 자기효능감 관리

### 4.1 첫 성공 필수: 24.1 코드 시뮬레이션 100% 성공률 보장

**원칙**: M 확장 곱셈기 코드는 반드시 첫 시도에 성공해야 합니다.

**구현 방법**:
1. 완전한 테스트벤치 제공 (입력값 + 기대 출력 모두 포함)
2. 단계별 안내: "Step 1: 파일 생성 → Step 2: 컴파일 → Step 3: 시뮬레이션 → Step 4: 결과 확인"
3. 예상 출력 화면 스크린샷 또는 텍스트 제공 → "이 결과가 나오면 성공입니다"
4. 흔한 실수 FAQ: "합성 경고가 나와도 정상입니다 — DSP 추론 메시지일 뿐"

### 4.2 실패 정상화 문구

**문구 1** (24.1절 나눗셈 알고리즘 도입부):
> "나눗셈 알고리즘의 수학적 증명까지 이해할 필요는 없습니다. 실무에서도 나눗셈기는 IP 코어를 사용하거나, Vivado의 자동 합성에 맡기는 경우가 대부분입니다. 핵심 원리(반복적 뺄셈과 쉬프트)만 파악하면 면접에서도 충분합니다."

**문구 2** (24.2절 IEEE 754 도입부):
> "IEEE 754 표준은 1985년에 처음 제정되었고, 지금까지도 '완전히 이해한다'고 자신하는 엔지니어는 드뭅니다. rounding mode의 세부 동작이나 denormalized number의 처리 규칙을 모르는 것은 전혀 이상하지 않습니다."

**문구 3** (24.4절 미니 과제 도입부):
> "이 과제는 Ch12에서 만든 파이프라인에 실행 유닛 하나를 추가하는 것입니다. 완전히 새로운 설계가 아닙니다. 이미 만들어본 데이터패스에 '곱셈 경로'를 하나 더 연결하는 확장 작업입니다."

## 6. 종합 평가

### 6.1 가장 위험한 드롭 지점

**24.2절 IEEE 754 도입부** — 불안 수준 중간

Ch24의 불안 최고점은 Ch23만큼 깊지 않습니다. 이유:
