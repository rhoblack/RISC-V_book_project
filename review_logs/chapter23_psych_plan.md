## 1. 감정 곡선 설계

### 1.1 Ch23의 심리학적 위치: "클라이맥스 이후의 탐험"

Ch22에서 "최종 SoC 데모"라는 감정적 정점을 달성한 직후입니다. 수강생은 다음 상태에 있습니다:

| 심리 요소 | 상태 | 의미 |
|----------|------|------|
| 자기효능감 | **매우 높음** | "나는 프로세서 설계자다" 정체성 확립 |
| 학습 동기 | **내재적 전환** | 의무→호기심 기반 (선택 수강이므로) |
| 불안 수준 | **낮음** | 졸업 프로젝트 압박 해제 |
| 인지 여력 | **중간** | 20주 누적 피로 vs 성취 에너지 |

**핵심 통찰**: Part 9는 "선택 수강"이므로, 여기에 도달한 수강생은 **이미 높은 내재적 동기**를 가지고 있습니다. 따라서 Ch1~Ch22와 달리 "불안 완화"보다 **"지적 호기심 충족"**에 무게를 두어야 합니다.

- **진입점**: "당신의 파이프라인 CPI=1.2. 이론적 최소 CPI=1.0. 그 갭을 줄일 수 있을까? — 더 나아가, CPI < 1.0도 가능할까?" (숫자 기반 호기심)

<p>

### 2.2 각 절 종결부: "지금까지 배운 것의 연장선"

| 절 | 연결 메시지 | 심리적 효과 |
|-----|----------|----------|
| 23.1 | "슈퍼스칼라 = 파이프라인 라인을 2개로 복제" | 새 개념을 익숙한 개념으로 재프레임 |
| 23.2 | "토너먼트 예측기 = Ch11의 2-bit 카운터를 조합한 것" | 이전 학습의 확장임을 인식 |
| 23.3 | "비순차 실행 = 해저드 해결의 궁극적 형태" | Ch10 포워딩의 자연스러운 진화 |
| 23.4 | "2-이슈 구조 = 당신의 파이프라인 + 복제 + 의존성 검사" | 직접 설계 가능한 수준임을 확인 |

### 2.3 미니 과제 (23.4절): 초도 성공 설계

**난이도 조절 원칙**:
- **In-order 2-이슈** 구조만 다룸 (OOO는 23.3에서 개념만 소개)
- 스켈레톤 코드 제공: 디스패치 로직의 핵심 조건만 학생이 채우기
- 의존성 검사 표 제공: "두 명령어가 동시에 발행 가능한 조건" 체크리스트

```
미니 과제 구조:
Step 1: 주어진 명령어 쌍이 동시 발행 가능한지 판단 (표 채우기) → 성공률 95%
Step 2: 디스패치 조건을 SystemVerilog 의사코드로 작성 → 성공률 80%
Step 3: (도전) 3-명령어 시퀀스의 IPC 계산 → 성공률 60%
```

Step 1에서 반드시 성공을 경험하도록 설계합니다. Step 3는 "도전 과제"로 명시하여 못 풀어도 좌절하지 않도록 합니다.

## 3. 불안 지점 감지 & 완화

### 불안 지점 #1: 슈퍼스칼라의 복잡도 인식 (23.1절 후반)

**발생 시점**: "2-이슈 = 데이터패스를 2개 복제해야 하나? 레지스터 파일 포트도 2배?"

**심리 프로필**:
- "파이프라인 하나도 힘들었는데 2개라니..."
- "포워딩 경로가 얼마나 복잡해지는 거지?"
- "이걸 Basys 3에 올릴 수 있나?"

**완화 방안**:
```html
<aside class="tip">
💡 <strong>슈퍼스칼라가 "2배로 복잡한" 것은 아닙니다</strong>

공장 비유로 생각해보세요:
- 파이프라인 = 하나의 조립 라인 (각 단계가 동시에 작업)
- 슈퍼스칼라 = 조립 라인 2개 (추가로 "어떤 제품을 어느 라인에 배정할지" 관리자 필요)

핵심 추가 요소는 딱 하나: <strong>디스패치 로직</strong> (= 관리자).
나머지는 당신이 이미 알고 있는 파이프라인의 확장입니다.
</aside>
```

**추가 전략**: "이 챕터에서는 개념과 구조 이해에 집중합니다. 전체 합성 가능한 구현은 이 교재의 범위를 넘어서며, 여기서는 설계 원리를 파악하는 것이 목표입니다."

### 불안 지점 #2: 토너먼트 분기 예측기의 구조 복잡도 (23.2절 중반)

**발생 시점**: "지역 예측기, 전역 예측기, 메타 예측기... 3개를 조합한다고?"

**심리 프로필**:
- "Ch11에서 2-bit 카운터 하나도 헷갈렸는데 3개를 합치라고?"
- "BHT, PHT, GHR... 약어가 너무 많다"

**완화 방안**:
```html
<aside class="faq">
❓ <strong>토너먼트 예측기가 너무 복잡하게 느껴질 때</strong>

세 가지만 기억하세요:
1. <strong>지역 예측기</strong>: "이 분기는 과거에 어떻게 행동했나?" (개인 기록)
2. <strong>전역 예측기</strong>: "최근 프로그램 전체의 분기 패턴은?" (팀 전체 기록)
3. <strong>메타 예측기</strong>: "둘 중 누가 더 잘 맞추나?" (심판)

Ch11의 2-bit 카운터를 기억하시나요? 지역/전역 예측기는 각각
그 2-bit 카운터의 <em>배열</em>입니다. 새로운 원리가 아니라
기존 원리의 조합입니다.
</aside>
```

### 불안 지점 #3: Tomasulo 알고리즘의 추상성 (23.3절 — 최고 불안 지점)

**발생 시점**: "예약 스테이션(Reservation Station), 공통 데이터 버스(CDB), 태그 브로드캐스트, 레지스터 리네이밍..."

**심리 프로필**:
- "이건 완전히 새로운 패러다임 같다"
- "지금까지 배운 파이프라인과 전혀 다른 것 아닌가?"
- "실제로 구현하라면 절대 못 할 것 같다"

**완화 방안 (3단계)**:

**1단계 — 실패 정상화**:
```html
<aside class="instructor-tip">
📌 <strong>이 섹션이 어렵게 느껴지는 것은 당연합니다</strong>

비순차 실행(Out-of-Order Execution)은 컴퓨터 아키텍처에서
가장 정교한 기법 중 하나입니다.

현업 CPU 설계자들도 OOO 파이프라인의 버그를 잡는 데
수개월이 걸리기도 합니다. Intel의 초기 Pentium Pro 개발팀도
이 구조를 구현하는 데 수년이 걸렸습니다.

이 절의 목표는 <strong>Tomasulo를 구현하는 것이 아닙니다</strong>.
"왜 비순차 실행이 필요하고, 어떤 원리로 작동하는지"를
이해하는 것입니다. 그것만으로도 충분합니다.
</aside>
```

**2단계 — 비유를 통한 접근**:
```html
<aside class="tip">
💡 <strong>은행 창구 비유로 이해하는 Tomasulo</strong>

은행에 3개의 창구가 있고, 고객 5명이 번호표를 받았습니다.

- <strong>번호표</strong> = 태그(Tag) — 고객을 식별
- <strong>대기석</strong> = 예약 스테이션 — 필요한 서류가 모일 때까지 대기
- <strong>전광판</strong> = 공통 데이터 버스(CDB) — "3번 고객 처리 완료!" 알림

고객 3번이 고객 1번의 결과를 기다리고 있다면?
→ 대기석에서 기다리다가, 전광판에 "1번 완료"가 뜨면 즉시 창구로 이동.

<strong>핵심</strong>: 도착 순서(프로그램 순서)와 처리 순서(실행 순서)가 다를 수 있지만,
최종 결과(통장 잔액)는 반드시 올바릅니다.
</aside>
```

**3단계 — 학습 범위 명시**:
```html
<aside class="metacognition">
🔍 <strong>이 절에서 당신이 이해해야 할 것 / 이해하지 않아도 되는 것</strong>

✅ 이해해야 할 것:
- 왜 비순차 실행이 성능을 높이는가 (캐시 미스 동안 다른 명령어 실행)
- 예약 스테이션의 역할 (데이터 의존성 대기)
- CDB의 역할 (결과 브로드캐스트)

❌ 지금 이해하지 않아도 되는 것:
- 정확한 RTL 구현 (산업용 OOO CPU는 수만 줄)
- 리오더 버퍼(ROB)의 세부 구현
- 메모리 디스앰비규에이션(memory disambiguation)

이 구분을 기억하세요. "전부 알아야 한다"는 압박은 불필요합니다.
</aside>
```

**발생 시점**: 미니 설계 과제 시작 시점

| 23.1 | "파이프라인에서 배운 '시간 분할(temporal)'을 이제 '공간 분할(spatial)'로 확장합니다. 파이프라인은 하나의 명령어를 단계별로 나누었습니다. 슈퍼스칼라는 여러 명령어를 동시에 처리합니다." | Ch09 파이프라인 기초 |

| 23.3 | "Ch10에서 데이터 해저드를 포워딩으로 해결했습니다. 비순차 실행은 그 아이디어의 궁극적 확장입니다 — 데이터가 준비되지 않은 명령어를 기다리는 대신, 준비된 다른 명령어를 먼저 실행합니다." | Ch10 데이터 해저드 |
| 23.4 | "Ch12에서 파이프라인을 완성하고 성능을 측정했습니다. 이제 그 파이프라인을 확장하여 IPC > 1을 달성하는 구조를 직접 설계해봅니다." | Ch12 파이프라인 완성 |

### 4.2 23.4절 체크포인트 (자가 진단 질문)

미니 과제 중간에 배치할 메타인지 체크포인트:

```html
<aside class="metacognition">
🔍 <strong>여기까지 점검해보세요</strong>

다음 질문에 답할 수 있으면 Step 2로 진행하세요:

1. "ADD와 SUB가 동시에 발행 가능한 조건은?"
   → 힌트: 두 명령어 사이에 RAW 의존성이 없어야 합니다.

2. "ADD x1, x2, x3 다음에 SUB x4, x1, x5가 오면?"
   → x1에 RAW 의존성 → 동시 발행 불가

3. "ADD x1, x2, x3 다음에 SUB x4, x5, x6이 오면?"
   → 의존성 없음 → 동시 발행 가능!

✅ 3개 모두 맞추셨다면 핵심을 이해한 것입니다.
❌ 헷갈린다면 23.1절의 의존성 검사 표를 다시 확인하세요.
</aside>
```
