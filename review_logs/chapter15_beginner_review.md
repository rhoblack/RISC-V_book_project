# Ch15 초보자 독자 리뷰

## 종합 이해도: ⭐⭐⭐⭐ (4/5)

**승인 여부: ✅ 승인 (최소 기준 ⭐⭐⭐ 충족)**

Ch15는 Ch13·14에서 각각 완성한 I-Cache와 D-Cache를 실제 메모리에 연결하는 "마지막 퍼즐"입니다.
분량이 적절하고(약 900줄), FSM 수정 내용이 이전 챕터와 명시적으로 비교되어 있어 전체적인 이해도는 높습니다.
다만 일부 전문 용어가 설명 없이 등장하고, 15.3절(시뮬레이션)에서 실습 코드가 테스트벤치 골격만 제공되어
"직접 실행해 볼 수 있는가"라는 측면에서 ⭐⭐⭐⭐로 평가합니다.

## 비유 평가

### 15.1절 — 두 창고와 중앙 물류센터 ⭐⭐⭐⭐⭐
**평가: 매우 효과적**
- "설계도 창고(I-Cache)" / "부품 창고(D-Cache)" / "배송 트럭 한 대(단일 버스)" 매핑이 직관적임.
- "부품 창고를 먼저 처리한다는 규칙" = D-Cache 우선 중재기 설명이 자연스럽게 연결됨.
- 비유의 한계(Starvation 위험)까지 소자(※)로 명시한 점이 정직하고 좋음.
- **아쉬운 점**: 버스 점유 시 I-Cache가 기다리는 모습이 비유에 명시적으로 표현되지 않음. "설계도 창고가 트럭이 돌아올 때까지 문 앞에서 대기한다" 정도의 묘사 추가 권장.

### 15.2절 — 마트 계산대의 카트 통째 처리 ⭐⭐⭐⭐
**평가: 효과적, 한계 명시 적절**
- "물건 하나씩 처리 = 단일 전송" / "카트 전체 스캔 = 버스트 전송" 대비가 명확함.
- "카트 처리가 끝나야 다음 카트" = 버스트 중 선점 금지 원리가 직관적.
- **아쉬운 점**: 비유에서 "8개의 물건"이 "8워드(32바이트 캐시 라인)"와 대응된다는 설명이 명시적으로 표현되면 더 좋을 것 같음. 카트에 8개만 들어간다는 제약이 비유에 빠져 있음.

## 막힘 포인트 (상위 3개)

### 막힘 포인트 1: 기준 주소 비트 마스킹 계산 (15.2절)
**위치**: "주소 정렬 규칙" 섹션, 기준 주소 계산 예시 박스

**문제**:
```
CPU 요청 주소: 0x0000_0014 (인덱스=0, 오프셋=5번째 워드)
캐시 라인 기준: {0x0000_0014[31:5], 5'b0} = 0x0000_0000
```
Verilog 비트 슬라이싱 표기법(`[31:5]`)으로 주소 마스킹을 설명하는데,
이 표기법이 실제 숫자 연산으로 어떻게 작동하는지(하위 5비트를 0으로 강제함) 텍스트 설명이 없음.
처음 보는 독자는 "왜 0x0000_0014의 상위 비트를 가져오면 0x0000_0000이 되는가"를 이해하기 어려울 수 있음.

**개선 제안**: 16진수 → 2진수 변환 단계를 1줄이라도 명시.
예: `0x14 = 0b10100 → 상위 27비트만 취하면 0 → 기준 주소 = 0x00000000`

### 막힘 포인트 2: D-Cache FSM 상태 전이 복잡도 증가 (15.1절)
**위치**: "D-Cache FSM 수정" 섹션, 상태 목록

**문제**:
Ch14에서 5상태이던 FSM이 Ch15에서 7상태(WAIT_WB_GRANT, WAIT_REFILL_GRANT 추가)로 증가함.
상태 목록은 불릿 리스트로 제공되지만, 상태 전이 다이어그램 SVG가 없음.
그림 15.1은 "통합 블록 다이어그램"이라 D-Cache FSM 내부 상태 전이가 별도 SVG로 제공되지 않음.
19사이클 페널티 계산 표는 있지만, 어떤 상태가 몇 사이클인지를 시각적으로 확인하기 어려움.

**개선 제안**: D-Cache FSM 전용 상태 전이 다이어그램 SVG(ch15_sec01_dcache_fsm.svg) 추가.
각 상태 옆에 "몇 사이클" 레이블을 붙이면 19사이클 계산이 시각적으로 자명해짐.

### 막힘 포인트 3: 15.3절 실습 코드의 불완전성
**위치**: 벤치마크 실습 1~3 코드 섹션

**문제**:
세 개의 벤치마크 실습이 소개되지만 코드 발췌가 "개념 스케치" 수준임.
`burst_read_icache()` 태스크 함수가 선언 없이 호출되고,
테스트벤치 전체 코드는 전체 소스 섹션에도 "요약 주석만" 제공(`// (전체 코드: code_examples/ch15_cache_tb.sv 참조)`).
"반드시 좋은 결과가 나오도록 설계되어 있으니 안심하고 시작하십시오"라는 격려 문구가 있지만,
실제로 복사·붙여넣기하여 바로 실행할 수 있는 코드가 없음.
이는 심리적 안전감을 해칠 수 있음.

**개선 제안**: `ch15_cache_tb.sv` 전체 소스를 전체 소스 섹션에 포함하거나,
최소한 벤치마크 TEST 1의 완성 코드를 제공. `burst_read_icache()` 태스크 시그니처라도 명시.

## 개선 제안

### 필수 개선 (이해도에 직접 영향)

1. **D-Cache FSM 상태 전이 SVG 추가** (막힘 포인트 2)
   - `ch15_sec01_dcache_fsm.svg`로 7상태 FSM 다이어그램 추가
   - 19사이클 Dirty Miss 경로를 빨간색 화살표로 강조
   - 각 상태 박스에 소요 사이클 수 레이블 부착

2. **워킹 세트(Working Set) 용어 설명 추가** (미설명 용어 섹션)
   - 15.3절 메타인지 박스에 1문장 삽입: "워킹 세트(Working Set)란 프로그램이 현재 집중적으로 접근하는 데이터 집합을 의미합니다."

3. **기준 주소 계산 예시에 2진수 전개 추가** (막힘 포인트 1)
   - 16진수 → 2진수 변환 1줄 추가로 마스킹 원리 명시

### 권장 개선 (이해도 향상)

4. **테스트벤치 TEST 1 완성 코드 추가**
   - 독자가 직접 실행하여 "Pass" 결과를 경험하게 하는 첫 성공 경험 보장

5. **루프 인터체인지(Loop Interchange) 간단 설명 추가**
   - 강사 꿀팁 박스에서만 등장하는 용어이므로 1줄 각주 정도면 충분

6. **DMA 컨트롤러 각주 추가** (15.4절)
   - "직접 메모리 접근(Direct Memory Access) 컨트롤러: CPU를 경유하지 않고 메모리에 직접 접근하는 하드웨어"

### 선택적 개선 (완성도 향상)

7. **Spatial Locality 용어 재등장 시 1줄 복습**
   - 15.2절 비유 박스에서 "(공간적 지역성은 인접한 데이터를 곧 사용할 가능성이 높다는 원리, Ch13 참조)" 추가

8. **`icache_stall`과 `dcache_stall` 신호 생성 위치 명시**
   - 15.1절 스톨 코드 발췌가 `ch15_cache_system.sv`에서 가져온 것인데, 이 파일이 전체 소스 섹션에 없음. 독자가 코드를 어디서 찾아야 하는지 혼란스러울 수 있음.

## 긍정적 평가 요약

- **Ch13·14와의 연계가 매우 명확**: "Ch13에서는 단순화 5사이클, Ch15에서는 실제 11사이클"이라는 대비가 학습 동기를 유지시킴.
- **미스 페널티 계산표**: 4가지 시나리오(Ch13 단순화 / I-Cache / D-Cache Clean / D-Cache Dirty)를 표로 정리한 것이 이해하기 쉬움.
- **FAQ 박스 "D-Cache 우선 이유"**: 이 질문은 대부분의 독자가 반드시 떠올리는 질문이며, 답변이 논리적이고 충분함.
- **Part 5 성취 체크리스트**: 챕터를 마치는 시점에서 3챕터의 성과를 돌아보게 해주어 성취감을 높임.
- **다음 챕터 예고**: "직접 만든 프로토콜 위에 표준 이름표를 붙이는 작업"이라는 표현이 AHB 학습에 대한 기대감을 효과적으로 형성함.
