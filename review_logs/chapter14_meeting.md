## 안건별 논의 및 수정 결정

### 안건 1: 14.1절 / 14.3절 비유 한계 명시 (기술 리뷰어 m-1 연계, 초보자 Major-2)
- **현황**: 도서관 비유, 지정석 비유 모두 한계 문구 없이 독자가 비유를 절대적으로 수용할 위험이 있음
- **결정**: 두 비유 모두 마지막 문장 뒤에 한계 문구 1문장 추가 → **적용 완료**
  - 14.1절: "단, 이 비유에서 도서관 사서(메모리 컨트롤러)가 항상 최신 원본을 관리한다는 전제가 실제 하드웨어와 완전히 대응하지는 않습니다."
  - 14.3절: "단, 이 비유에서 '누가 더 최근에 앉았는가'라는 LRU 판단이 하드웨어에서는 1비트 플래그로 구현된다는 점은 이 비유가 포착하지 못합니다."

### 안건 2: 14.4절 Byte Enable 출처 설명 (초보자 Major-1)
- **현황**: `cpu_byte_en_i` 신호의 발생 원천(funct3 → byte_en)이 설명되지 않아 초보자가 신호 출처를 추적하기 어려움
- **결정**: MEM 스테이지 D-Cache 접근 설명 직후에 funct3별 byte_en 값 명시 문단 추가 → **적용 완료**
  - SW(funct3=010) → 4'b1111, SH(funct3=001) → 4'b0011, SB(funct3=000) → 4'b0001

### 안건 3: latched_replace_way 직관적 설명 (교육심리전문가 P-1)
- **현황**: 코드에 `latched_replace_way` 신호가 등장하지만 왜 래치가 필요한지 본문에 설명 없음 → 학습자 불안 유발
- **결정**: 14.3절 "2-Way D-Cache 전체 구현" 소제목 바로 앞에 설명 문단 삽입 → **적용 완료**
  - 조합 논리 `replace_way_sel`이 상태 전이 후 변할 수 있음을 명시

### 안건 4: 14.7절 마무리 문장 보강 (교육 설계자 M-1)
- **현황**: 14.7절 본문이 단 1문장으로 끝나 감정 곡선(성취감) 형성 미흡
- **결정**: 성취감 문장 + Ch15 연결 예고 문장 추가 (총 3문단으로 확장) → **적용 완료**

### 안건 5: FENCE.I 코드 의사코드 명시 (기술 리뷰어 m-2)
- **현황**: FENCE.I 처리 코드가 의사코드임을 밝히지 않아 독자가 합성 가능 코드로 오해할 수 있음
- **결정**: 코드 블록 위에 "의사코드(Pseudo-code)" 안내 문단 추가 + 코드 내 주석 명시 → **적용 완료**

### 안건 6: 14.2절 FSM SVG 참조 문구 (교육심리전문가 P-2)
- **현황**: 14.2절에서 FSM 5상태 표를 제시하지만, 상태 전이도 SVG가 14.5절에만 있어 독자가 앞에서 SVG를 찾지 못함
- **결정**: FSM 상태 표 아래, 경로 목록 앞에 14.5절 그림 14.5 참조 안내 문단 삽입 → **적용 완료**

### 안건 7: 선택 수정 — word_cnt 명시적 리셋 코드 (기술 리뷰어 m-1)
- **논의**: word_cnt가 `default: word_cnt <= 3'b0`으로 IDLE/DONE 등 모든 비-카운팅 상태에서 0으로 리셋되므로 기능상 문제 없음. 교육용 명시성 vs 코드 간결성 간 트레이드오프
- **결정**: 교육 목적상 현 코드 유지. 코드 분석 포인트에서 이미 Eviction 주소 생성 주의사항을 설명하고 있어 독자 인지 부담 과부하 방지를 우선함

### 안건 8: 선택 수정 — SB/SH/SW byte_en 표 추가 (교육 설계자 M-2)
- **논의**: 안건 2에서 14.4절에 byte_en 값을 인라인 텍스트로 이미 추가함. 별도 표 추가는 중복 우려
- **결정**: 인라인 텍스트로 대체 완료, 별도 표는 생략

### 안건 9: 선택 수정 — 면접 포인트 박스 및 FAIL 디버깅 힌트 (교육심리전문가 P-4, P-5)
- **논의**: 14.3절 면접 포인트 박스가 이미 Direct-Mapped vs N-Way 비교 포인트를 포함. P-5 FAIL 힌트는 분량 대비 교육 효과 재고 필요
- **결정**: 기존 면접 포인트 박스로 충분. FAIL 힌트는 14.5절 테스트벤치 실행 설명에서 `[FAIL]` 파형 분석 안내로 이미 간략히 다루고 있으므로 별도 추가 생략
