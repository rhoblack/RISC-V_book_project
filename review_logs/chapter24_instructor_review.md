# Chapter 24 교육전문강사 리뷰 (Phase 3)

## 비유 3개 검증

### 비유 #1: 곱셈 = 곱하기표 (초등학교 필산)

**원고 위치**: 24.1.1절 (line 91~100), 24.1.2절 (line 256~267)

- 정확성: ✅ "곱하기표" 및 "필산법" 모두 등장. 부분곱(partial product) 개념이 필산과 정확히 매핑됨. 123×45 예제로 구체적 숫자 제시.
- 한계 명시: ✅ "실제 하드웨어는 32개의 부분적을 순차적으로 더하지 않고, Booth 인코딩으로 부분적 수를 절반으로 줄이고(Radix-4), Wallace 트리나 Dadda 트리로 병렬 덧셈" (line 264~266). "DSP 한 사이클" 현실도 표에 명시 (line 314~319).
- 오해 방지: ✅ "전자 계산기처럼 '즉시'가 아닐 수 있습니다. 구현 방식에 따라 1~34사이클" (line 98~99). 필산=순차, HW=병렬 구분 명확.

**Phase 1 대비**: 기획안의 "곱하기표" 비유가 두 곳(ISA 소개 + HW 구현)에 자연스럽게 분배됨. 기획안의 대안 비유(2×2→4×4→32×32 패턴 확장)는 미반영이나, 4단계 진화 표(line 281~321)가 이를 대체하여 충분함.

### 비유 #2: 나눗셈 = 장제법 (Long Division)

**원고 위치**: 24.1.2절 (line 332~342)

- 정확성: ✅ "장제법" 명시. 100÷7 수동 예제 포함 (line 335~336). "한 자리씩 내리고, 빼보고" 패턴이 Restoring Division과 정확히 대응.
- 한계 명시: ✅ "Non-Restoring, SRT 같은 고급 방식은 매 사이클 2비트 이상을 결정" (line 340). "본 챕터에서는 Restoring Division을 구현합니다" 범위 한정.
- 오해 방지: ✅ "나눗셈은 곱셈보다 본질적으로 느립니다" (line 327), "순차적입니다" (line 329). 실무 팁에서 "나눗셈 비율은 전체 명령어의 1~3%에 불과" (line 404) 및 "컴파일러는 2의 거듭제곱 나눗셈을 시프트로 자동 치환" (line 406).
- 33사이클 → 원고는 "34사이클(초기화 + 32반복 + 부호 보정)" (line 349)로 더 정확하게 명시.

**Phase 1 대비**: 기획안의 "8÷3 수동 예제" 대신 "100÷7"을 사용. 더 직관적인 숫자 선택. FSM SVG(그림 24.2)가 기획안의 5단 SVG 요청에 부합.

### 비유 #3: 부동소수점 = 과학표기법

**원고 위치**: 24.2절 (line 443~454)

- 정확성: ✅ "1.5 × 10³ = 1500" 예제 명시. "1.1011 × 2^5" 이진 대응 제시 (line 449). IEEE 754 비트 분해 정확: 부호 1비트, 지수 8비트(bias=127), 가수 23비트 (line 462~464).
- 한계 명시: ✅ "가수(mantissa)는 23비트로 고정" (line 452), "약 7자리 10진수의 정밀도만 보장" (line 453). Rounding error 경고: "1.234567까지 정확, 그 이후는 반올림 오차" (line 453).
- 금융 decimal 사용: ✅ "정밀도가 중요한 금융 계산에서는 고정소수점이나 BCD를 사용합니다" (line 557~558).
- 오해 방지: ✅ 강사 꿀팁에서 "0.1 + 0.2 ≠ 0.3" 파이썬 시연 제안 (line 543~544), "오차가 발생하는 것이 정상" (line 546), "버그가 아니라 물리적 한계" (line 547).

**Phase 1 대비**: 기획안의 모든 요소(과학표기법 대응, 23비트 한계, 금융 대안, 0.1+0.2 데모) 완전 반영. 변환 예제(-6.5)도 추가되어 기획 이상.

## 강의 노트 품질

### 글쓰기 품질: ⭐⭐⭐⭐⭐

- 문장 명확성: 주어+술어 명확. "곱셈은 모든 부분적을 병렬 생성할 수 있지만, 나눗셈은 각 자릿수의 몫이 이전 단계의 나머지에 의존하므로 순차적입니다" — 강의에서 그대로 인용 가능.
- 전문 용어 정의: ✅ 첫 등장 시 괄호 설명 준수. "부분적(partial product)", "복원(Restore)", "부동소수점(floating-point)", "단정밀도(single-precision)".
- 설명 순서: ✅ 선수지식(Ch12 파이프라인) → 동기부여(SW 곱셈 느림) → ISA 정의 → HW 구현 → 파이프라인 통합. Phase 1 기획의 "MUL 먼저 → DIV 다음 → F 마지막" 순서 준수.

### 강의 예제: ⭐⭐⭐⭐⭐

- 구체적 숫자: ✅ 123×45(필산), 100÷7(장제법), -6.5(IEEE 754 변환), 0xFFFFFFFF×2(MULHU). 추상적 설명 없이 모두 구체적 수치 기반.
- 칠판 재현성: ✅ 필산 곱셈, 장제법 단계, IEEE 754 비트 분해 모두 칠판에 직접 그릴 수 있는 수준. SVG 없이도 핵심 전달 가능.

### 수강생 응답 고려: ⭐⭐⭐⭐⭐

- "MUL과 MULH 차이" → line 170~177에서 명확한 답변 가능. C 코드 예시까지 포함.
- "나눗셈은 왜 32사이클" → line 327~329 + 장제법 비유로 직관적 설명 가능.

## Q&A 5가지 답변 가능성

1. **"MUL과 MULH 차이가 뭐에요?"**
   - 원고 답변: line 170~177 + FAQ aside (line 208~215)
   - 충분한 명확성: ✅ C 코드 대응까지 포함

2. **"나눗셈은 왜 여러 사이클 걸려요?"**
   - 원고 답변: line 327~329 (병렬 불가) + 장제법 비유 (line 332~342)
   - 장제법 비유로 충분한가: ✅ 100÷7 수동 추적으로 직관적

3. **"F 확장을 꼭 배워야 하나요?"**
   - 원고 명시: ✅ "선택 확장" (line 436), "Basys 3에서는 M까지가 현실적" (line 438)
   - 정상화 문구: ✅ "대부분의 임베디드 시스템에 충분" (line 435)

4. **"IEEE 754는 어디서 배우죠?"**
   - 원고 참고자료: ❌ 별도 참고문헌 목록 미포함
   - "깊이는 대학원 과정" 메시지: 부분적 — "이 교재의 범위를 넘어서며" (line 427)로 범위 한정은 했으나, Phase 1의 구체적 참고자료(Parhami 교재, IEEE 754-2019, Stanford CS149) 미반영

5. **"DSP를 안 쓰고 로직으로 곱셈을 만들면?"**
   - 원고 트레이드오프: ✅ 진화 표에서 "면적: 대형" vs "전용 HW" (line 281~321)
   - LUT/지연 추정: 연습문제 4번(line 761~764)에서 DSP 슬라이스 수 추정 과제. 본문에서는 구체적 LUT 수치 미제시.
