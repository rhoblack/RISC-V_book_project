## 비유 품질 평가

### 14.1절 — "메모를 하면서 책 읽기" 비유 (Write-Through vs Write-Back)
**평가: ⭐⭐⭐⭐⭐ 우수**

- "책을 빌려 읽기만 하는 것(I-Cache) vs 메모를 하면서 읽는 것(D-Cache)"의 대비가 챕터 전환을 자연스럽게 연결하여 매우 효과적.
- "반납할 때 원본에 수정을 반영할지, 매번 메모할 때마다 원본도 함께 수정할지"라는 질문이 Write-Through/Write-Back의 핵심 트레이드오프를 정확히 포착함.
- 기술 사실과의 매핑이 정확하며 오해를 유발하는 요소가 없음.
- **개선 제안:** 비유의 한계(예: "도서관에서 메모는 한 권 책에만 해당하지만, 실제 캐시는 여러 주소를 동시에 관리한다")가 명시되어 있지 않음. 한계 한 문장을 추가하면 완성도가 높아짐.

### 14.3절 — "지정석" 비유 (Set-Associative)
**평가: ⭐⭐⭐⭐⭐ 우수**

- "지정석 하나(Direct-Mapped) → 지정석 두 개(2-Way)" 비유가 Set-Associative의 핵심인 "같은 인덱스에 여러 Tag를 저장한다"는 개념을 직관적으로 전달함.
- "세 번째 학생이 오면 기존 두 명 중 하나를 내보내야 한다"는 구체적 상황이 교체 정책의 필요성을 자연스럽게 도입함.
- **한계 미명시 문제:** 비유에서 "학생 = 캐시 라인" 대응이 명확하나, "학생이 자리를 점유하는 것"과 "캐시 라인이 세트 내 Way를 점유하는 것"의 차이(Way 수는 고정이지만 자리 수는 교실마다 다를 수 있다는 점 등)에 대한 한계 문구가 없음. 추가 권고.

## 코드 이해도 평가

### 14.2절 — 직접 매핑 D-Cache 스니펫 (모듈 포트 + Dirty 비트 선언)
**평가: ⭐⭐⭐⭐ 양호**

- 포트 선언과 Dirty 비트 핵심 부분만 발췌하여 적절한 길이.
- `★ Dirty 비트` 주석이 핵심 신호를 시각적으로 강조하여 효과적.
- "전체 코드는 code_examples/... 참조" 안내가 적절하여 부담감 감소.
- **코드 분석 포인트 3개**(Dirty 비트 배열, 바이트 인에이블, Eviction 주소 생성)가 명확하게 서술됨. 특히 "초보자가 가장 자주 실수하는 부분"이라는 경고가 메타인지를 자극하여 좋음.

### 14.3절 — 히트 판정 스니펫 (2-Way 병렬 비교)
**평가: ⭐⭐⭐⭐⭐ 우수**

- 15줄 이내의 짧은 스니펫으로 핵심 개념(두 Way 동시 비교)만 보여줌.
- `hit_way_sel`, `replace_way_sel` 변수 이름이 의도를 명확히 드러냄.
- LRU 갱신 코드도 10줄 이내로 간결하여 이해 부담이 낮음.

### 14.4절 — 파이프라인 제어 로직 스니펫
**평가: ⭐⭐⭐⭐ 양호**

- `pipeline_stall = load_use_stall || icache_stall || dcache_stall` OR 조합이 직관적.
- flush 우선순위(`else if (flush_if_id)` → `else if (!pipeline_stall)`)가 Ch11 패턴과 일관되어 이전 챕터 학습자에게 친숙.
- **주의:** `if_id_reg`, `if_id_next` 등 변수가 구체적 타입/선언 없이 예시로 사용됨. "예시"임을 주석으로 명확히 표시되어 있으나, 초보자는 이를 실제 신호명으로 오해할 수 있음.

### 14.5절 — 간이 메모리 모델 스니펫
**평가: ⭐⭐⭐ 보통**

- 약 20줄 분량으로 적절하나, `mem_delay_cnt`와 `MEM_LATENCY` 변수가 선언 없이 등장함. 테스트벤치 문맥에서 자연스럽지만 초보자는 변수 출처를 전체 소스 코드까지 따라가야 함.
- 전체 소스 코드 섹션에서 완전한 선언이 있으므로 치명적이지는 않음.

### 전체 소스 코드 섹션
**평가: ⭐⭐⭐⭐⭐ 우수**

- 안심 문구 3문장이 적절하게 배치됨 ("지금 당장 전부 이해하지 않아도 됩니다").
- 코드 블록이 세 파일(직접 매핑 WB, 2-Way WB, 테스트벤치)로 분리되어 구조가 명확.
- 모든 신호에 한국어 주석이 달려 있어 이해도 높음.
- 전체 소스 코드 분량이 다소 많지만, 섹션 도입부의 안심 문구가 이를 완화함.

## 감정 곡선 평가

### 호기심 유발 (챕터 도입부)
**평가: ⭐⭐⭐⭐ 양호**

- "I-Cache는 읽기 전용이었기에 비교적 단순하였습니다. 그러나 D-Cache는..."이라는 대비 구조가 자연스럽게 문제 의식을 유발함.
- "쓰기를 어떻게 처리할 것인가"라는 근본적 설계 질문 제시가 탐구 동기를 부여함.
- **개선 가능:** Ch13 마무리에서 언급된 "DRAM 접근 100~300사이클 지연"과 D-Cache의 필요성을 챕터 도입부에서 명시적으로 연결했다면 동기 부여가 더 강했을 것. 도입부에서 "배열 초기화나 스택 프레임 생성 시 매번 느린 메모리에 써야 한다면..."이라는 구체적 고통 시나리오가 있으면 이상적.

### 불안 관리 (5개 상태 FSM)
**평가: ⭐⭐⭐⭐ 양호**

- 5개 상태를 먼저 표로 정리한 후, 세 가지 경로(Hit/Clean Miss/Dirty Miss)를 번호 목록으로 요약하는 이중 구조가 불안을 크게 완화함.
- "Dirty Miss 경로"가 가장 복잡하지만, 상태 전이가 한 줄로 요약되어 한눈에 파악 가능.
- 강사 꿀팁에서 "색상별로 구분한 상태 전이도"를 칠판에 먼저 그리도록 안내하는 점이 불안 관리 측면에서 효과적.
- **개선 가능:** FSM 상태 수가 I-Cache(4개)에서 D-Cache(5개)로 1개 늘어났다는 점을 명시적으로 비교하면, 증분(incremental) 학습 부담 감을 낮출 수 있음.

### 이해의 성취감 (핵심 정리 및 연습문제)
**평가: ⭐⭐⭐⭐⭐ 우수**

- 핵심 정리가 7개 항목으로 구조화되어 학습한 내용을 체계적으로 정리할 수 있음.
- 연습문제가 [기억] → [이해] → [적용] → [분석] → [분석] → [평가] → [평가] 순으로 블룸 분류 7단계를 아우름.
- 특히 문제 2번(주소 계산)과 3번(사이클 수 계산)이 직접 손으로 풀 수 있는 구체적 문제여서 자기효능감 강화에 효과적.
- 문제 5번(메모리 트래픽 비교)이 "힌트: Eviction 횟수를 고려하시오"를 제공하여 적절한 발판을 마련함.

## 개선 권고

### 우선순위 높음 (Major)

1. **Byte Enable(바이트 인에이블) 생성 출처 설명 추가 (14.4절)**
   - 현황: `cpu_byte_en_i` 포트가 14.2절에서 소개되고 14.4절에서 파이프라인 연동이 설명되지만, EX/MEM 파이프라인 레지스터에서 byte_en 값이 어떻게 생성·전달되는지 설명이 없음.
   - 권고: 14.4절에 "MEM 스테이지 연동" 설명 중 "MEM 스테이지의 ALU 결과가 유효 주소가 되며, 명령어의 funct3 필드에서 byte_en 값이 생성된다(SW: 4'hF, SH: 4'h3, SB: 4'h1)"와 같이 한 단락 추가.

2. **비유 한계 명시 (14.1절, 14.3절)**
   - 현황: 두 절의 비유 모두 한계 문구가 없음.
   - 권고: 각 비유 마지막에 "단, 이 비유는 [한계 상황]을 표현하지 못합니다" 한 문장 추가.

### 우선순위 보통 (Minor)

3. **챕터 도입부 D-Cache 필요성 강화**
   - 현황: 도입부가 I-Cache와의 차이를 설명하는 방식으로 시작하여 논리적이지만, 실제 성능 고통이 드러나지 않음.
   - 권고: "배열 초기화처럼 Store가 반복되는 코드에서 Write-Through 방식은 매 Store마다 수십 사이클을 소비한다. Ch13에서 경험한 I-Cache 미스 페널티처럼..." 식의 동기 부여 한 단락 추가.

4. **I-Cache FSM(4상태)과 D-Cache FSM(5상태) 비교 명시 (14.2절)**
   - 현황: D-Cache FSM 표가 독립적으로 제시됨.
   - 권고: "Ch13의 I-Cache FSM 4개 상태에서 S_WRITE_BACK이 추가된 것이 D-Cache FSM입니다"라는 한 문장이 연속성과 학습 부담 감소에 효과적.

5. **14.5절 간이 메모리 스니펫 변수 선언 추가**
   - 현황: `mem_delay_cnt`, `mem_ready` 변수가 선언 없이 스니펫에 등장.
   - 권고: 스니펫 상단에 `// (위에서 선언됨: int mem_delay_cnt; logic mem_ready;)` 주석 한 줄 추가.

## 긍정적 특징 (유지 권장)

1. **I-Cache ↔ D-Cache 비교 표 (14.2절):** Valid/Dirty/Tag/Data 필드를 두 챕터 간 비교하는 표가 학습 연속성을 매우 효과적으로 지원함. Ch13 학습 내용이 즉시 연결됨.

2. **세 가지 경로 번호 목록 (14.2절):** Hit/Clean Miss/Dirty Miss 세 경로를 한눈에 볼 수 있어 FSM 복잡도에 대한 불안을 효과적으로 완화함.

3. **2-Way 파라미터 비교 표 (14.3절):** 직접 매핑에서 2-Way로 변화하는 파라미터(세트 수 128→64, Index 7→6비트, Tag 20→21비트)를 표로 정리하여 트레이드오프가 명확히 드러남.

4. **Dirty Eviction 파형 추적 5단계 (14.5절):** 시뮬레이션에서 어디를 봐야 하는지 단계별로 안내하여, 처음 파형을 접하는 학습자에게 큰 도움이 됨.
