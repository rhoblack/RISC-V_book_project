## 1. 리뷰 이슈 우선순위 결정 및 처리 결정

### Critical 이슈

#### [C1] BGE 기계어 인코딩 오류 — 처리: 수정 완료

**결정**: 리뷰어가 제시한 올바른 기계어로 교체.

- `dut.u_imem.mem[4]`: `0x03C58663` → `0x0305DE63` (BGE x11, x16, +60: funct3=101 확인)
- `dut.u_imem.mem[7]`: `0x03164463` → `0x03165463` (BGE x12, x17, +40: funct3=101, 이전 값은 BLT)
- HTML 발췌 코드의 `0x03C58663`도 `0x0305DE63`으로 수정

**근거**: `$readmemh` 방식 전환 검토 → 교육적으로 현재의 직접 초기화 방식이 이전 챕터와 일관성이 있고, 헥스 파일 생성 절차 설명이 불필요한 복잡성을 추가하므로 기계어 직접 수정이 더 적절.

#### [C2] ADD 기계어 오류 (rd=x18, 정확: rd=x19) — 처리: 수정 완료

- `dut.u_imem.mem[9]`: `0x01250933` → `0x012509B3` (rd 필드 x18→x19 수정)
- `ch12_bubble_sort.sv` 주석의 `01250933` → `012509B3` 수정

#### [C3] imm_gen 포트 불일치 — 처리: 파이프라인 전용 모듈로 해결

**결정**: 방안 A 채택 — 파이프라인 전용 `pipeline_imm_gen` 모듈을 `ch12_rv32i_pipeline_complete.sv` 파일 하단에 직접 정의.

**근거**:
- Ch04 `imm_gen`은 `inst/imm_sel[2:0]/imm_out` 인터페이스로 파이프라인과 호환 불가.
- `imm_sel`을 control_unit에서 받으려면 C4 이슈(control_unit 포트 불일치)까지 연쇄적으로 얽힘.
- 파이프라인에서는 opcode만으로 즉치수 타입을 자동 결정하는 것이 자연스럽고 Ch09부터 사용하던 방식.
- 파일 하단에 정의함으로써 "파이프라인용 별도 버전"임을 명확히 함.

**수정 사항**:
- `ch12_rv32i_pipeline_complete.sv`: 인스턴스명 `imm_gen → pipeline_imm_gen`, `control_unit → pipeline_control_unit`으로 변경
- `pipeline_imm_gen` 모듈 신규 정의 (opcode case문, 6개 타입)
- HTML 12.3절 코드 발췌도 `pipeline_imm_gen`, `pipeline_control_unit`으로 수정
- "Ch04에서 설계" 주석 → 파이프라인 전용 인터페이스임을 명시하는 aside 박스 추가

#### [C4] control_unit 포트 불일치 — 처리: 파이프라인 전용 모듈로 해결 (C3와 연동)

**결정**: `pipeline_control_unit` 모듈을 `ch12_rv32i_pipeline_complete.sv` 파일 하단에 정의.

**인터페이스** (최종 확정):
```systemverilog
module pipeline_control_unit (
   input  logic [6:0] opcode,
   input  logic [2:0] funct3,
   input  logic [6:0] funct7,
   output logic       reg_w_en,
   output logic       mem_read,
   output logic       mem_write,
   output logic       branch,
   output logic       a_sel,
   output logic       b_sel,
   output logic [3:0] alu_sel,
   output logic [1:0] wb_sel
);
```

**LUI 처리**: 어셈블러가 `rs1=x0` 강제, ALU에 `0 | imm_U = imm_U` 결과 출력. `alu_sel=OR(0011)` 사용.

### Major 이슈

#### [M1] 성능 표 수치 불일치 — 처리: 수정 완료

**결정**: 올바른 계산값으로 수정 + 캡션 수정.

올바른 상대값 계산 (단일 사이클 Fmax=25MHz 기준):
- 단일 사이클: 40ns/명령어 → 1.0 (기준)
- 멀티사이클: 82ns/명령어 → **2.05** (0.82 → 2.05로 수정)
- 파이프라인: 18.5ns/명령어 → **0.46** (0.22 → 0.46으로 수정)

표의 "실행시간 상대값 ↓" 헤더 추가 (낮을수록 좋음 표시).
figcaption "약 4.6배 빠릅니다" → "단일 사이클 대비 약 2.2배, 멀티사이클 대비 약 4.4배 빠릅니다"로 수정.
본문 텍스트 계산식 명시화: `40/18.5≈2.16배`, `82/18.5≈4.4배`.
"의외의 결과" 단락 추가: 멀티사이클이 Fmax 2배임에도 불구하고 단일 사이클보다 느린 이유 설명.
레전드 추가: `(낮을수록 좋은 값: CPI, 실행시간 상대값 | 높을수록 좋은 값: Fmax)`.

#### [M2] alu_src_b 댕글링 신호 — 처리: 수정 완료

`ch12_rv32i_pipeline_complete.sv` line 71: `logic [31:0] alu_src_b;` 선언을 주석 처리하고 실제 ALU B 입력이 `alu_b`임을 명시.

#### [M3] ALU 포트 주석 오류 — 처리: 수정 완료

ALU 인스턴스 주석을 파이프라인 전용 버전임을 명시하도록 수정:
- Ch04 원본 포트명 `operand_a/operand_b/alu_ctrl` vs Ch09+ `a/b/alu_sel` 차이 설명
- `alu_zero` 미연결 이유 (`branch_unit`이 담당) 명시

### 교육 설계 Major 이슈

#### [Edu-M1] 스캐폴딩 단계 3 완전 코드 제공 문제 — 처리: 부분 수정

**결정**: 전체 코드를 숨기지 않고 "먼저 직접 작성해보십시오" 유도 박스를 코드 직전에 삽입.

**근거**: 기계어 직접 초기화 방식 특성상 전체 오프셋을 먼저 확인해야 실제로 시뮬레이션이 가능. 코드를 완전히 숨기는 것은 실용성 저해. 유도 박스에 오프셋 계산 방법(`offset = 목적지 PC - 현재 PC`)을 예시와 함께 제공하여 분석 수준 달성 지원.

#### [Edu-M2] FPGA 마일스톤 누락 — 처리: 선택 도전 과제로 추가

12.6절에 `aside.tip` 형태로 "선택 도전 — FPGA 합성 및 다운로드 (Basys 3)" 박스 추가.
Vivado 합성 → XDC 제약 → IMEM 초기화 → ILA 확인 4단계 안내.
"부록 A (FPGA 구현 가이드) 참조" 경로 안내.
