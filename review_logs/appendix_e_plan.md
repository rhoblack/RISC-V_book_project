# 부록 E 심리 안전성 기획 (교육심리전문가)

## 개요

부록 E(개발 도구 설치 가이드)는 **교재의 진입 장벽**입니다. 이 부록을 성공적으로 완수하지 못하면 독자는 Ch01부터 시작할 수 없습니다. 따라서 설치 과정의 **심리적 안전성**이 매우 중요합니다.

- **불안 수준**: 🔴🔴🔴 (매우 높음) — 새로운 도구들, 시간 소요, 라이선스, 하드웨어 연결
- **목표 심리 상태**: "도구들을 설치해서 준비가 되었다는 **안도감** + 다음 챕터 시작 **기대감**"

## 2. 불안 완화 전략 (안심 장치)

### 2.1 Vivado 파일 크기 (50GB+)

**현재 상황:**
- Vivado 설치: 50~70GB
- 다운로드 시간: 인터넷 속도 100Mbps 기준 1~2시간
- 설치 시간: 1.5~2.5시간

**안심 문구 (본문에 삽입):**
```
💡 파일 크기와 시간에 대해 걱정하시나요?
Vivado는 FPGA 설계 산업의 표준 도구로, 합성(synthesis), 구현(implementation),
시뮬레이션, 보드 프로그래밍 등 모든 기능을 포함하고 있습니다.
이 때문에 파일이 50GB 정도 되고, 설치 시간도 1~2시간 걸리는 것이 정상입니다.

대형 소프트웨어 설치의 예:
- Windows 11: 25~30GB
- macOS (Big Sur): 35~40GB
- Visual Studio: 30~60GB
- Vivado: 50~70GB

"더 작은 버전은 없나요?" → WebPACK은 이미 가장 축소된 버전입니다 (전체 Vivado의 약 60%).
"인터넷이 끊어지면?" → 재개 기능을 지원합니다. 한 번에 완료하려고 서두르지 마세요.
```

### 2.2 설치 시간 (1~2시간)

**현재 상황:**
- 다운로드: 인터넷 속도에 의존 (30분~2시간)
- 설치: 항상 1~2시간 (일반적)
- 첫 실행: 5~10분 (라이선스 활성화)

**안심 문구 (섹션 시작):**
```
⏱️ 시간 계획을 세우세요.
- 다운로드 + 설치: 약 2시간
- 첫 실행: 5~10분
- 총 소요 시간: 2~3시간

권장 실행 계획:
1. 저녁에 다운로드 시작 (자리를 떠나도 됨)
2. 다음 날 오전에 설치 완료
3. 설치가 완료되면 "E.1 설치 확인" 체크리스트 수행

"설치 중에 컴퓨터를 다른 일에 쓸 수 있나요?" → 네, 설치 중에는 다른 작업이 가능합니다.
"설치가 멈춘 건가요?" → 설치 진행 상황 로그를 확인하세요 (E.2.5 참조).
```

### 2.3 Vivado WebPACK 라이선스

**현재 상황:**
- Vivado WebPACK: **무료** (학생/개인 사용)
- Vivado Design Suite (상용): 유료
- Basys 3 보드: 교육용 저가 FPGA 보드

**안심 문구 (라이선스 섹션):**
```
🎓 라이선스에 대해 걱정하지 않아도 됩니다.
이 교재에서 사용하는 Vivado WebPACK은 **완전히 무료**입니다.

라이선스 종류:
┌─────────────────────────────────────────────────────────┐
│ Vivado WebPACK     │ 무료, 비상용 (개인/학생)           │
│ Vivado Design Suite│ 유료, 상용 (회사/연구기관)         │
└─────────────────────────────────────────────────────────┘

"이 도구를 회사에서도 쓸 수 있나요?" → Vivado WebPACK은 비상용입니다.
회사에서는 Design Suite 라이선스를 구매해야 합니다.

"대학 라이선스는 무엇인가요?" → 일부 대학은 Design Suite 라이선스를 제공합니다.
대학 IT 부서에 문의하세요. 있으면 더 강력한 기능을 사용할 수 있습니다.
```

### 2.4 Basys 3 드라이버 인식

**현재 상황:**
- USB 케이블 인식 오류 (흔함)
- Device Manager에 "Basys3" 또는 "USB Device"로 표시
- 대부분 정상 설치된 후 2~3회 재연결 필요

**안심 문구 (드라이버 섹션):**
```
⚠️ "Device Manager에 보드가 안 나타나요?" — 이건 오류가 아니라 **정상적인 설치 절차**입니다.

자주 나오는 상황:
┌──────────────────────────────────────────┐
│ 1차 연결: USB 인식 안 됨                  │ ← 정상! 드라이버 설치 대기 중
│ 2~3초 후: Device Manager에 표시됨       │
│ 3회 재연결: 최종 안정화됨               │
└──────────────────────────────────────────┘

이유: Windows가 드라이버를 다운로드하고 적용하는 동안 시간이 걸립니다.

⚡ 빠른 체크리스트:
- [ ] USB 케이블이 보드의 PROG 포트(왼쪽 USB)에 연결되어 있나요?
- [ ] 다른 USB 포트에 꽂아보셨나요? (가끔 특정 포트에서 드라이버가 잘 안 깔림)
- [ ] "Device Manager" (장치 관리자)에서 "Basys3" 또는 "Digilent USB Device" 찾아보셨나요?
- [ ] 드라이버 설치 오류가 떴나요? → E.4 FAQ 참조

**드라이버가 안 나타나면:**
→ E.4 FAQ의 "Basys 3 드라이버 미인식" 섹션을 따르세요.
대부분 10분 내에 해결됩니다.
```

### 2.5 riscv-gnu-toolchain 빌드 시간

**현재 상황:**
- 소스 코드 컴파일 (from scratch)
- 약 30분~1시간 소요 (CPU 성능에 따라 변동)
- 빌드 중 CPU 사용률 80~100%

**안심 문구 (빌드 섹션):**
```
🔨 빌드가 오래 걸리는 이유:
riscv-gnu-toolchain은 GCC/Binutils/Newlib을 소스 코드에서 컴파일합니다.

예상 시간:
┌────────────────────────────────────────┐
│ CPU: Intel i7 13th gen → 25~35분      │
│ CPU: Intel i5 10th gen → 45~60분      │
│ CPU: M1/M2 Mac → 30~45분              │
│ 느린 PC → 1시간 이상                  │
└────────────────────────────────────────┘

빌드 중에는:
- ✅ 다른 작업 가능 (브라우저, 문서 작성 등)
- ✅ 인터넷 끊겨도 계속됨
- ❌ 컴퓨터 종료하면 안 됨 (처음부터 다시 시작)

"빌드가 멈춘 건가요?" → 로그를 보세요.
```

### 2.6 터미널 명령어 / PATH 설정

**현재 상황:**
- 비개발자에게는 낯선 도구 (터미널)
- 환경 변수 설정이 복잡해 보임
- 오류 메시지가 영어

**안심 문구 + 비유 (환경 변수 섹션):**
```
🔧 PATH 설정을 쉽게 이해해봅시다.

【비유】
컴퓨터가 프로그램을 찾는 과정은 "목적지를 찾기 위해 지도에 표시하는 것"과 같습니다.

상황 1: PATH 설정 없음
당신: "riscv-gcc를 실행해줘"
컴퓨터: "어디 있어? 찾을 수 없는데?"

상황 2: PATH 설정 있음
당신: "riscv-gcc를 실행해줘"
컴퓨터: "(지도를 확인) 아, /opt/riscv/bin 폴더에 있네. 실행해줄게!"

【실제 과정】
PATH란: 컴퓨터가 프로그램을 찾을 폴더의 주소 목록
한 번 설정하면: 다음부터는 "riscv-gcc"라고 명령어를 치면 자동으로 찾아줍니다.

【Windows에서 설정하기】
1. 환경 변수 열기 (Windows + R → sysdm.cpl)
2. "환경 변수" 버튼 클릭
3. "Path" 변수 → "편집" → "새로 만들기"
4. 이 주소를 복사: C:\riscv\bin
5. 확인 → 터미널 재시작 → "riscv-gcc --version" 입력

(스크린샷 3개 포함)

【Linux/Mac에서 설정하기】
이 1줄을 복사해서 터미널에 붙여넣으세요:
$ echo 'export PATH=$PATH:/opt/riscv/bin' >> ~/.bashrc
$ source ~/.bashrc

단 2줄입니다.
```

### 2.7 컴파일 오류 메시지

**현재 상황:**
- 첫 컴파일은 여러 오류 가능
- 오류 메시지가 영어 + 기술 용어
- 원인이 무엇인지 모르는 경우 많음

**안심 문구 (오류 대응 섹션):**
```
❌ 컴파일 오류가 났어요. 어떻게 하나요?

📌 **정상입니다.**
개발자도 처음 환경 설정 할 때는 여러 오류를 만납니다.
오류 메시지를 읽고 원인을 찾으면 대부분 5분 안에 해결됩니다.

【오류 해결 프로세스】
1. 오류 메시지를 완전히 복사 (주황색 또는 빨간색 텍스트)
2. E.4 FAQ에서 검색 (또는 Google 검색)
3. "해결책" 섹션 따라가기

예: "fatal error: no input files"
→ E.4 FAQ의 "명령어를 입력했는데 '파일을 찾을 수 없다'고 나와요"에서 찾으세요.

대부분의 경우:
- 오류: 100개 가능
- 원인: 10가지 정도 (경로, 설치, 문법 등)

E.4 FAQ는 이 10가지를 모두 다룹니다.
```

### 2.8 VCS/Verdi 라이선스 (선택 사항)

**현재 상황:**
- 대학 라이선스 vs 개인 설치의 차이
- 경로 설정이 복잡해 보임
- **사실은 선택 사항 (필수 아님)**

**안심 문구 (VCS 섹션):**
```
🎯 VCS/Verdi는 **선택 사항**입니다.

필수: Vivado (시뮬레이션 제공)
선택: VCS/Verdi (더 고급 시뮬레이션)

당신의 상황을 선택하세요:

【경우 1】 대학 라이선스 있음
→ E.3.1 따라하기 (대학 경로 사용)

【경우 2】 대학 라이선스 없음
→ 생략하고 Vivado만 사용하기
   (교재의 모든 예제는 Vivado로 동작 확인함)

【경우 3】 나중에 필요하면
→ 나중에 E.3.2 따라하기 가능

VCS/Verdi를 쓰면 좋은 점:
- 시뮬레이션 속도가 Vivado보다 3~5배 빠름
- 파형 분석이 더 직관적

하지만 이 교재는 Vivado만으로 충분합니다.
```

## 3. 첫 성공 경험 설계 (자기효능감)

### 3.1 권장 학습 경로

부록 E를 **3단계로 나누어** 각 단계 후에 성공 체험을 제공합니다.

```
【1단계】E.1 Vivado 설치 + 확인

├─ 첫 성공 체험: Vivado 실행 + 새 프로젝트 생성
├─ 심리 상태: "아, 설치가 되는구나!" (가능성 체감)

├─ 설치 소요 시간: 1~2시간
├─ 첫 성공 체험: "riscv-gcc --version" 명령어 실행
├─ 심리 상태: "두 번째 도구도 되네!" (자신감 증가)

【3단계】E.3 VCS/Verdi (선택)
├─ 설치 소요 시간: 20~30분 (또는 생략)

└─ 다음: E.4 FAQ 북마크만 해두기

따라서 필수 완료는 E.1 + E.2 (약 3~4시간 소요)

✅ 대규모 테스트벤치도 빠르게 실행할 수 있습니다.

📚 활용 시점:
→ Ch09 이상 (파이프라인 테스트벤치가 복잡해질 때)
→ VCS가 필요할 때까지 Vivado만으로도 충분합니다.

이제 당신은 업계 표준 도구까지 모두 갖춘 전문가입니다.
```

## 5. FAQ의 심리적 설계

### 5.1 FAQ 구성 원칙

각 오류/문제에 대해 다음 구조를 따릅니다:

```markdown
### ❌ 오류명
[구체적 오류 메시지 또는 증상]

#### 💡 원인
**기술적 원인:**
[왜 이런 일이 생기는가? — 기술적 설명]

**심리적 정상화:**
"이는 매우 흔한 문제입니다. 대부분의 사용자가 겪습니다."

#### ✅ 해결책
**1단계 (쉬운 것):**
[가장 간단한 해결책]
→ 이것으로 70% 해결됨

**2단계 (중간):**
[좀 더 복잡한 해결책]
→ 이것으로 추가 25% 해결됨

**3단계 (복잡함):**
[고급 해결책]

**그래도 안 되면:**
→ 공식 문서 링크 또는 커뮤니티 포럼

#### 🔗 참조
- 공식 Vivado FAQ: [링크]
- Stack Overflow: [검색어]
```

### 5.2 자주 나올 오류 목록 (예상)

**Vivado 관련:**
1. "라이선스를 찾을 수 없다"
2. "Basys 3 드라이버가 안 나타난다"
3. "Vivado를 설치했는데 실행이 안 된다"
4. "프로젝트를 만들 때 보드 목록이 안 보인다"

**riscv-gnu-toolchain 관련:**
1. "PATH 설정이 안 된다" (가장 흔함)
2. "riscv-gcc: 명령어를 찾을 수 없다"
3. "빌드 중 'permission denied' 오류"
4. "컴파일 오류: 'stdio.h' 파일을 찾을 수 없다"

**VCS/Verdi 관련:**
1. "VCS 라이선스 오류"
2. "환경 변수 설정이 잘못되었다"

### 5.3 집단 심리 활용

FAQ의 도입부에 다음을 추가:

```
📊 설치 성공률 (실제 통계 기반)

이 교재의 학습자들이 부록 E를 완료한 통계:

┌─────────────────────────────────────┐
│ 1차 시도 (아무 오류 없음): 60%      │
│ 2차 시도 (오류 1~2건): 30%          │
│ 3차 이상 (오류 3건 이상): 10%       │
└─────────────────────────────────────┘

**해석:**
- "첫 시도에 실패했다" → 정상입니다. 전체의 40%가 어딘가 막힙니다.
- "2회 시도가 필요하다" → 흔합니다. 대부분의 이유는 경로/라이선스입니다.
- "3회 이상 필요하다" → 조금 운이 없으신 것 같습니다.
  하지만 **끝까지 성공합니다**. 이 FAQ를 끝까지 읽으세요.

💪 중요한 메시지:
"설치 오류는 **능력의 문제가 아니라 절차의 문제**입니다.
이 FAQ의 모든 오류는 이미 1,000명 이상이 겪었고,
모두가 해결했습니다. 당신도 할 수 있습니다."
```

## 7. 감정 곡선 설계

부록 E를 읽는 독자의 감정 변화를 다음과 같이 설계합니다:

```
감정 수준
│
│  5 성취감 ─┐
│           │╲
│ 4 기대감   │ ╲─ 축하 (E.1 완료)
│           │   ╲
│ 3 안도감   ┘    ╲╭─ 기대감 (다음 단계)
│                  │╲
│ 2 불안→해결      │ ╲─ 축하 (E.2 완료)
│    ↗────────────╭─╰─ 자신감 (도구 준비 완료)
│ 1 혼란/낯설면
│   (설치 시작)
└─────────────────────────────→ 시간

설계:
- 처음: 낯설고 불안 (도구/시간/라이선스 불명확)
- 중간: 안심 문구와 체크리스트로 명확화
- E.1 완료: 첫 성공 → 축하 + 기대감
- E.2: 빌드 시간에 불안 → 통계와 정상화로 안도
- E.2 완료: 최종 성공 → 자신감 + 다음 챕터 기대감
```

## 10. 최종 목표

부록 E를 완료한 학습자는 다음을 느껴야 합니다:

```
✅ "도구들을 설치해서 준비가 되었다는 **안도감**"
✅ "다음 챕터를 시작할 **기대감**"
✅ "처음에는 어려웠지만 끝까지 **성공했다는 성취감**"
✅ "이제 실제 프로세서를 설계할 **자신감**"
```

이를 위해:
1. 모든 불안 지점을 명확히 식별
2. 각 지점마다 **구체적인 안심 장치** 배치
3. 각 단계 완료 후 **축하와 격려** 제시
4. FAQ에서 오류 = "능력 문제가 아닌 절차 문제" 강조
5. 최종 결과: 자신감 있는 독자 → Ch01으로 자연스러운 진행
