# Chapter 18 — CSR과 시스템 명령어 (교육심리 기획)

**작성일**: 2026-03-15
**담당**: 교육심리전문가

## 1. 불안 지점 식별

**A. 도메인 낯섦 (매우 높음)**
- 특권 수준, CSR이라는 개념이 처음 등장
- 지금까지는 "명령어 설계"에서 "시스템 제어"로 전환
- 학습자 심리: "왜 이렇게 복잡해야 할까?" → 불안

**B. 정보 과부하 (높음)**
- CSR이 여러 개, 각각 비트 구조가 다름
- "모든 CSR을 외워야 하나?" 불안
- 7개 vs 12개 혼동 가능

**C. 파이프라인과 연결성 불명확 (중간)**
- 지금까지 배운 파이프라인과 CSR의 관계가 불명확
- "이게 파이프라인과 무슨 상관?" → 혼동

**D. 추상성 높음 (중간)**
- 메모리/캐시는 물리적으로 이해 가능 (데이터 저장)
- CSR은 제어 신호로 추상적
- "이걸 어디에 쓰지?" → 동기 상실

## 2. 감정 곡선 설계

**호기심** (도입, 18.1):
- 장면: "당신이 프로세서라면, 인터럽트가 왔을 때 '잠깐만' 이렇게 말할 수 있을까?"
- 연결: "프로세서가 자신의 상태를 관리하는 방법을 배우자"
- 감정: 호기심 + 기대감

**불안** (18.2, 개념 폭증):
- 장면: "아, CSR이 이렇게 많고 복잡하다고?"
- 원인: 7개 CSR, 각각의 비트 의미 설명
- 감정: 막연한 불안, 정보 과부하

**이해** (18.3~18.4, 구체적 동작):
- 장면: "아, CSR 명령어는 단순한 읽기/쓰기로군. 나도 할 수 있겠는데?"
- 이유: 코드 예제, 시뮬레이션으로 동작 확인
- 감정: 불안에서 "아!" 순간으로 전환

**성취감** (18.4, 미니 실습):
- 장면: "테스트벤치를 돌려보니 mstatus가 정말 바뀌었다!"
- 경험: 직접 조작 → 결과 확인
- 감정: "나도 프로세서를 제어할 수 있다!"

## 3. 안심 장치

**메시지 1** (도입에 포함):
"이 장에서는 7개의 CSR만 배웁니다. 각 비트의 기능은 '언제 필요한지' 명확히 하고, 나머지 세부사항은 참조용으로 남겨둡니다. 모든 CSR을 외울 필요는 없습니다."

**메시지 2** (18.2 끝에 포함):
"CSR 주소(0x305, 0x304 등)를 외우지 마세요. 실제 코딩에서는 라이브러리 함수 `write_csr()`, `read_csr()`을 사용합니다. 프로그래머는 함수 이름만 기억하면 됩니다."

**메시지 3** (18.3 시작에 포함):
"모든 CSR은 이미 하드웨어(프로세서) 내부에 존재합니다. 여러분의 일은 이미 있는 것을 '읽고 쓸 뿐'입니다. 프로세서 설계자처럼 생각하지 않으셔도 됩니다."

**메시지 4** (18.4 실습 직전):
"이제 실제로 mstatus를 조작해 봅시다. 처음에는 읽기만 → 다음에 쓰기 → 마지막에 비트조작. 각 단계가 성공하도록 설계되어 있습니다."

## 4. 첫 성공 경로 설계

**1단계: 읽기** (가장 쉬움, 성공 보장)
- 작업: CSR 읽기 명령어 1줄
- 난이도: ★☆☆☆☆
- 성공 척도: "값을 읽었다"
- 심리: "아, 이 정도면 할 수 있겠는데?"

**2단계: 단순 쓰기** (중간)
- 작업: CSRRW로 mie 비트 1개 설정
- 난이도: ★★☆☆☆
- 성공 척도: "쓴 값이 저장되었다"
- 심리: "내가 프로세서를 조종하고 있다!"

**3단계: 비트 조작** (심화)
- 작업: CSRRS로 mie 비트 추가 설정
- 난이도: ★★★☆☆
- 성공 척도: "기존 값은 유지, 새 비트만 추가"
- 심리: "원자 연산의 유용함을 몸으로 느낀다"
