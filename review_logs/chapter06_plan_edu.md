| LO-4 | 피보나치 수열 프로그램이 단일 사이클 CPU에서 올바르게 실행됨을 시뮬레이션 파형으로 **검증할 수 있다** | 적용(Apply) | 검증하다, 분석하다 |
| LO-5 | Vivado 합성 결과에서 단일 사이클 프로세서의 임계 경로와 최대 동작 주파수를 **찾아내고**, 이것이 왜 파이프라인이 필요한 이유인지 **설명할 수 있다** | 분석(Analyze) | 찾아내다, 설명하다 |

## 4. 6.2절 제어 신호 진리표 분할 전략

### 문제 상황 (불안 지점 #3)

RV32I 37개 명령어에 대한 제어 신호 진리표를 한 번에 제시하면:
- 행(명령어): 37개
- 열(제어 신호): 7~9개
- 총 셀 수: ~300개

이를 한 번에 보여주면 독자는 **"외워야 한다"는 착각**과 **"이게 맞는지 확인할 수 없다"는 무력감**을 동시에 경험한다.

### 분할 원칙

> **"명령어 유형별로, 쉬운 것부터, 익숙한 것 먼저"**

### 제시 순서 및 분할 계획

**[Step 1] R 타입 — 가장 단순한 시작점**

| 선택 이유 | R 타입은 메모리 접근 없음, 즉치수 없음 → 제어 신호 대부분이 0 또는 단순 고정값 |
|----------|--------|

- 대상 명령어: ADD, SUB, AND, OR, XOR, SLL, SRL, SRA, SLT, SLTU (10개)
- 특징: `MemRW=0`, `WBSel=ALU`, `ImmSel=X(don't care)`로 단순
- 진리표 제시 후: "이처럼 R 타입은 대부분 신호가 0이고, ALUSel만 변합니다."

**[Step 2] I 타입 (즉치수 연산) — 익숙한 패턴 확장**

| 선택 이유 | Ch03/Ch04에서 이미 다뤄 친숙. R 타입과 비교하면 ImmSel 추가만 이해하면 됨 |
|----------|--------|

- 대상 명령어: ADDI, ANDI, ORI, XORI, SLTI, SLTIU, SLLI, SRLI, SRAI (9개)
- 차이점 강조: R 타입 진리표 옆에 나란히 배치하여 `ImmSel=I` 추가만 부각
- **faq aside**: "SLLI/SRLI/SRAI가 I 타입인데 funct7[5]도 보나요?" — 디코더 특수 처리 설명

**[Step 3] S 타입 — "쓰기"라는 새 개념 도입**

| 선택 이유 | MemRW가 처음으로 활성화되는 지점. 변화 포인트 하나만 추가 |
|----------|--------|

- 대상 명령어: SW, SH, SB (3개)
- 차이점 강조: `RegWEn=0`, `MemRW=Write`
- **tip aside**: "스토어는 레지스터에 쓰지 않으므로 RegWEn=0. 당연한 것을 확인하는 과정입니다."

**[Step 4] L 타입 (Load, I 타입 변형) — "읽기 후 레지스터에 쓰기"**

| 선택 이유 | WBSel이 처음으로 MEM을 선택. WBSel의 역할이 명확히 드러나는 시점 |
|----------|--------|

- 대상 명령어: LW, LH, LB, LHU, LBU (5개)
- 차이점 강조: `WBSel=MEM`
- **metacognition**: "WBSel=ALU vs MEM의 차이를 이해했나요? 잠시 멈추고 생각해 보세요."

**[Step 5] B 타입 — PC 변경이라는 새 개념**

| 선택 이유 | PCSel이 처음 등장. 분기 명령어는 레지스터에 쓰지 않음 |
|----------|--------|

- 대상 명령어: BEQ, BNE, BLT, BGE, BLTU, BGEU (6개)
- 차이점 강조: `PCSel=Branch`, `RegWEn=0`
- **faq aside**: "분기 조건이 거짓이면 PCSel=PC+4. 제어 신호가 동적으로 바뀌나요?" — 조합 논리 vs 순차 논리 구분

**[Step 6] U 타입 & J 타입 — 마지막 퍼즐**

| 선택 이유 | 가장 특이한 패턴이므로 마지막에 배치. LUI/AUIPC/JAL/JALR 각각의 특수성 |
|----------|--------|

- 대상 명령어: LUI, AUIPC, JAL, JALR (4개)
- LUI: ALUSel=BYPASS_B (특수 — ALU 연산 없이 즉치수 바로 사용)
- JAL/JALR: `WBSel=PC+4` (복귀 주소 저장)
- **interview aside**: "JAL vs JALR의 제어 신호 차이와 서브루틴 호출 규약"

**[최종 통합 진리표]**

6단계 완료 후, **전체 통합 진리표**를 한 번에 제시한다.
이때 독자는 이미 각 행을 이해했으므로, 통합표는 **참조 테이블**로 기능한다.

> **핵심 안심 메시지**: "이 표를 외울 필요는 없습니다. 우리가 방금 유형별로 직접 채운 표입니다. 필요할 때 찾아보는 레퍼런스로 활용하세요."

## 5. 마일스톤 달성 설계 (피보나치 프로그램) — 6.4절

### 피보나치 프로그램 선택 이유

- ADDI, ADD, BLT, SW, LW, JAL 등 다양한 명령어 유형을 자연스럽게 포함
- "결과가 눈에 보인다" — F(1)=1, F(2)=1, F(3)=2, F(4)=3, F(5)=5 등 직관적 검증 가능
- 단순하지만 의미 있는 계산 — "CPU가 수학 문제를 풀었다"는 감동

### 6.4절 구간 설계

**[1구간] 도입 — 기대감 조성**

```
"지금까지 만든 모든 모듈이 드디어 하나로 동작합니다.
 Ch04의 ALU, Ch05의 메모리, Ch06의 제어 유닛이 함께
 피보나치 수열을 계산합니다."
```

- 피보나치 RISC-V 어셈블리 코드와 hex 파일 제시 (미리 준비)
- 시뮬레이션 실행 방법(VCS/Vivado Simulator) 안내

**[2구간] 첫 번째 파형 확인 — 명령어 실행 흐름 추적**

- PC 변화: 0x0000 → 0x0004 → 0x0008 → ... (순차 실행 확인)
- IMEM 출력(instr)이 올바른 opcode를 가지는지 확인
- 제어 신호(RegWEn, ALUSel 등)가 각 명령어마다 적절히 변하는지 확인

**[3구간] ★ 피보나치 결과 확인 — 마일스톤 순간**

- DMEM의 결과 주소(x10)에 올바른 피보나치 값(F(10)=55)이 저장됨을 확인
- **Verdi 파형**: `dut.regfile.regs[10]` 값이 마지막 사이클에 `32'h37` (=55)임을 관찰

**★ 마일스톤 달성 메시지 (본문 강조 박스)**

```
┌─────────────────────────────────────────────────────────────────┐
│  축하합니다!                                                      │
│                                                                  │
│  방금 여러분이 직접 설계한 RISC-V 프로세서가                         │
│  피보나치 수열을 올바르게 계산했습니다.                               │
│                                                                  │
│  Ch04부터 지금까지 수백 줄의 코드가 하나의 CPU로 동작하는 순간입니다.  │

```

### 성취감 극대화 전략

| 전략 | 구체적 구현 |

> *채점 기준*: 각 신호가 무엇을 제어하는지(레지스터 파일 쓰기 허용/메모리 읽기·쓰기 선택/쓰기 데이터 선택/다음 PC 선택)를 명시하면 정답.

**[기억 수준] — 인코딩 패턴 암기**

> **문제 2**: RISC-V RV32I에서 opcode가 `0110011`인 명령어 유형은 무엇이며, 이 유형의 명령어를 5가지 이상 쓰시오.
>
> *채점 기준*: R 타입 (ADD, SUB, AND, OR, XOR, SLL, SRL, SRA, SLT, SLTU 중 5가지 이상).

**[이해 수준] — 차이를 설명할 수 있다**

> **문제 3**: 아래 두 명령어의 제어 신호 진리표를 비교하고, 다른 신호와 그 이유를 설명하시오.
>
> - `ADD rd, rs1, rs2` (R 타입)
> - `ADDI rd, rs1, imm` (I 타입)
>
> *채점 기준*: ImmSel(R 타입은 don't care, I 타입은 I 형식 즉치수 선택), ALUSrc MUX 선택 신호의 차이를 설명하면 정답.

**[이해 수준] — 동작 원리 설명**

> **문제 4**: `LW rd, offset(rs1)` 명령어가 실행될 때 제어 신호가 데이터패스를 통해 어떤 경로로 데이터가 흐르는지 순서대로 설명하시오. (IMEM → 디코더 → ... → 레지스터 파일 순으로)
>
> *채점 기준*: IMEM 인출 → 디코더 → rs1+offset 덧셈(ALU) → DMEM 읽기 → WBSel=MEM → 레지스터 파일 쓰기의 순서와 해당 제어 신호를 명시하면 정답.

**[적용 수준] — SystemVerilog 코드를 작성할 수 있다**

> **문제 5**: 아래 불완전한 명령어 디코더 코드에서 `BEQ`와 `JAL` 명령어에 해당하는 제어 신호를 채우시오.

> ```systemverilog
> // (불완전 코드 제공 — opcode 디코딩 구조는 주어지고,

> ```

> *채점 기준*: BEQ는 PCSel=Branch, RegWEn=0, JAL은 PCSel=PC+Imm, WBSel=PC+4를 올바르게 채우면 정답.

**[적용 수준] — 테스트벤치 작성**

> **문제 6**: 단일 사이클 CPU가 `ADDI x1, x0, 5` 후 `ADDI x2, x1, 3` 두 명령어를 순서대로 실행할 때, 실행 후 `x1=5, x2=8`임을 검증하는 간단한 SystemVerilog 테스트벤치를 작성하시오. (hex 파일 준비 방법은 설명하지 않아도 됨)

**[분석 수준] — 버그를 찾을 수 있다**

> **문제 7**: 아래 제어 유닛 코드는 `SW` 명령어 실행 시 예상치 못한 결과를 냅니다. 버그를 찾고 수정하시오.
>
> ```systemverilog
> // SW 케이스 (의도적 버그 포함)
> 7'b0100011: begin  // S 타입
>    reg_wen  = 1'b1;  // ← 버그: SW는 레지스터에 쓰지 않아야 함
>    mem_rw   = 1'b1;
>    imm_sel  = 3'b001; // S 타입 즉치수
>    wb_sel   = 2'b00;
>    alu_src  = 1'b1;
> end
> ```
>
> *채점 기준*: `reg_wen = 1'b0`으로 수정하고, 이유("스토어 명령어는 목적 레지스터가 없으므로 레지스터 파일에 쓰기를 허용하면 안 된다")를 설명하면 정답.

**[분석 수준] — 타이밍 분석**

> **문제 8**: Vivado 타이밍 리포트에서 단일 사이클 프로세서의 임계 경로가 `IMEM → ImmGen → ALU → DMEM → WB MUX → RegFile`인 것을 확인했다. (a) 이 경로를 발생시키는 명령어 유형은 무엇인가? (b) 이 임계 경로를 단축하려면 어떤 아키텍처 변화가 필요한가?
>
> *채점 기준*: (a) Load 명령어(LW/LH/LB), (b) 파이프라인(멀티 클럭 스테이지 분할) 또는 멀티사이클(각 단계를 별도 클럭에 실행)을 제시하면 정답.

## 10. 교육 설계자 종합 평가 및 권고사항

### 강점

1. **마일스톤 배치 최적**: 6.4절에 피보나치 마일스톤을 배치함으로써, 가장 복잡한 절(6.2, 6.3) 직후에 성취감을 제공하는 **보상 구조**가 자연스럽게 형성된다.
2. **Gradual Reveal 완성**: Ch04~Ch06에 걸친 5단계 점진적 공개가 6.3절에서 완성되어, 불안 지점 #2를 3챕터에 걸쳐 분산 처리한다.
3. **진리표 분할**: 37개 명령어를 6단계(R→I→S→L→B→U/J)로 나누어 제시함으로써 불안 지점 #3을 효과적으로 해소한다.

### 기술 저자에 대한 권고사항

1. **6.2절 진리표 분할 순서를 반드시 지킬 것**: Step 1(R 타입)을 가장 먼저, Step 6(U/J)을 마지막에 배치. 순서 변경 시 인지 부하 설계 효과가 감소한다.
2. **6.3절 코드 제시 전에 반드시 5단계 SVG를 배치할 것**: 완성된 블록 다이어그램을 코드보다 먼저 보여줌으로써 "무엇을 구현하는지"를 시각적으로 이해한 상태에서 코드를 읽게 한다.
3. **6.4절 마일스톤 순간에 일반 본문이 아닌 강조 박스를 사용할 것**: 축하 메시지는 반드시 시각적으로 분리된 박스 형태로 제공하여 독자가 "지금 중요한 순간임"을 인지하도록 한다.
4. **6.5절 수치는 실제 Vivado 합성 결과를 사용할 것**: "약 20~30MHz 예상"이라는 목차 주석을 실제 측정값으로 대체. 독자의 실습 결과와 비교 가능해야 신뢰성이 확보된다.
