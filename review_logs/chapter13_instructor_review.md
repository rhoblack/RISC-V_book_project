## 기획 단계 예측 막힘 포인트 Top 5 — 실제 해소 여부

### 1. Tag/Index/Offset 분리 직관: "Offset → Index → Tag 역순 결정" 설명 여부
**판정: ✅ 완전 해소**

13.2절에서 "결정 순서가 중요합니다"라는 명시적 안내와 함께 3단계 결정 절차(1단계 Offset → 2단계 Index → 3단계 Tag)를 순서대로 서술하고 있다. 각 단계에 비트 폭 산출 근거(log₂ 계산)까지 병기하여 직관적 이해를 지원한다. 강의에서 그대로 판서 흐름으로 활용할 수 있는 수준이다.

**한 가지 보완 가능 포인트**: "왜 하위 비트부터 할당하는가(바이트 정렬 때문)"에 대한 추가 설명이 있으면 더 완벽하나, 교육 범위를 고려하면 현재 수준도 충분하다.

---

### 2. Valid 비트 필요성: 반례(전원 인가 직후 충돌) 먼저 제시 여부
**판정: ✅ 완전 해소**

13.2절 FAQ 박스에서 "리셋 직후 tag_mem 배열의 초기값이 0이라면, CPU가 0x0000_0000에 접근할 때 tag_mem[0] == 0이 성립하여 HIT로 판정된다. 그러나 이 슬롯에는 아무것도 저장된 적이 없다!"는 반례를 먼저 제시한다. 강의에서 학생에게 "왜 필요할까요?"를 먼저 질문하고, FAQ 박스를 정답으로 공개하는 소크라테스식 진행이 가능하다.

---

### 3. 충돌 미스(Conflict Miss): 수치 예제(같은 Index 두 주소 번갈아 → 100% MISS) 존재 여부
**판정: ✅ 완전 해소 (시나리오 4에서 정량적 재현)**

13.3절 예제 4에서 0x0000_0000(Index=0, Tag=0x00000)과 0x0001_0000(Index=0, Tag=0x00010) 충돌을 구체적 수치로 제시하고, 13.5절 시나리오 4에서 "4회 접근 모두 MISS, 20사이클 낭비, 히트율 0%"를 시뮬레이션 파형(그림 13.12)으로 재현한다. 그림 13.8(Conflict Miss 시각화)과 중첩 구성도 효과적이다.

---

### 4. icache_stall vs 기존 스톨: 비교 표(pc_en/if_id_en/id_ex_flush 3종) 삽입 여부
**판정: ✅ 완전 해소 (표 5열 구성, 13.4절)**

13.4절에 Load-Use(Ch10) / 분기 flush(Ch11) / I-Cache 미스(Ch13) 세 가지 스톨 원인을 pc_en, if_id_en, id_ex_flush, 지속 기간, 효과 5개 열로 비교하는 표가 삽입되어 있다. id_ex_flush의 차이(Load-Use: 1 NOP 삽입, I-Cache 미스: 0 홀드)를 굵고 색상으로 강조한 점이 강의 시 시선 집중에 효과적이다.

---

### 5. BRAM 1사이클 지연 역설: Tag LUTRAM + Data BRAM 분리 SVG 존재 여부
**판정: ✅ 해소 (그림 13.6 BRAM 매핑 SVG + 실무 팁 박스)**

13.2절에서 "Tag 배열 → LUTRAM(비동기 읽기, 0사이클 히트 판정)", "Data 배열 → BRAM(동기 읽기, 1사이클 지연)"의 이유를 텍스트로 상세 설명하고, Vivado 합성 속성(`ram_style` 어노테이션)까지 코드로 제시한다. 그림 13.6이 Valid(FF 128개) / Tag(LUTRAM) / Data(BRAM36) 분리 구조를 시각화한다.

**강사 관점 보완 제안**: "BRAM 1사이클 지연이 역설적으로 파이프라인 IF 스테이지에 자연 흡수된다"는 본문 설명이 충분하나, 이 역설이 "느린 것이 오히려 맞는 이유"로 느껴질 수 있으므로 강의에서 별도 판서 강조를 권장한다.

## 1. 비유 검증

### 편의점/대형마트 비유
**원고 내 위치**: 13.1절 도입부 및 메모리 계층 구조 설명에 간접적으로 반영됨

**판정: △ 비유가 명시적으로 채택되지 않음**

기획 단계에서 예상한 "편의점/대형마트" 비유는 원고에 명시적으로 등장하지 않는다. 대신 DRAM 직접 접근 CPI(41.2) 수치 충격으로 캐시 필요성을 설명하는 방식을 선택했다. 수치 기반 동기 부여는 이공계 대학원생에게 더 설득력 있으므로 이 선택은 타당하다.

**강사 의견**: 강의에서 교수자가 구두로 "편의점(캐시) vs 대형마트(DRAM)" 비유를 보조로 사용하면 즉각적 이해를 도울 수 있다. 교재에 없어도 무방하나, 강사 꿀팁 박스에 한 줄 추가하면 좋다.

---

### 물품 보관함(라커룸) 비유 — Valid+Tag+Data 구조 매핑
**원고 내 위치**: 13.2절 직접 매핑 설명

**판정: ✅ 기술 정확성 검증 통과**

| 비유 요소 | 실제 매핑 | 정확도 |
|-----------|-----------|--------|
| 128칸 라커룸 | 128 엔트리 캐시 | ✅ 정확 |
| 칸 번호 = 티켓 끝자리 | Index 필드 | ✅ 정확 |
| 이름표 | Tag 비교 | ✅ 정확 |
| 같은 칸 두 사람 충돌 | Conflict Miss | ✅ 정확 |

**한계 명시 여부**: 비유의 한계(라커룸은 "다른 가방을 강제 배출"하는 개념이 없으나 캐시는 Eviction이 발생함)를 명시적으로 언급하지 않는다. 이는 개념 복잡도를 고려한 적절한 단순화로 판단된다.

**오해 유발 가능성**: 낮음. "한 칸에 하나만 보관"이라는 직관이 직접 매핑의 핵심과 정확히 일치한다.

---

### 식당 주방/냉장고 비유 — FSM 상태 매핑
**원고 내 위치**: 13.4절 캐시 미스 처리 비유

**판정: ✅ FSM 상태 전체 동결(홀드) 개념 정확히 전달**

"재료가 올 때까지 냄비에 있는 음식들은 그 자리에 그대로 있다"는 표현이 파이프라인 전체 동결(Freeze)을 직관적으로 전달한다. Load-Use 스톨과의 대비("소금을 잘못 넣으려는 순간 멈추는 것" vs "재료 자체가 없어서 전부 기다리는 것")도 명쾌하다.

**기술 정확성 검증**:
- 비유의 "냉장고(캐시)에 넣고, 이후에는 냉장고에서 바로 꺼냄" → FILL 상태 후 캐시 히트로 전환 ✅
- "주문서(PC)를 창고(DRAM)에 보내 재료를 요청" → MISS 상태에서 mem_req=1 ✅

**한계 명시 여부**: 식당에서는 요리사가 다른 작업을 할 수 있지만 파이프라인은 완전히 멈춘다는 차이를 명시하지 않는다. 강의에서 구두 보완 권장.

---

### 아파트 동/호수 비유 — Index/Offset 직관
**원고 내 위치**: 13.2절 주소 분해 설명

**판정: ✅ 채택, 직관 정확성 양호 / 부분 주의**

| 비유 요소 | 실제 매핑 | 정확도 |
|-----------|-----------|--------|
| 도시+구+로 | Tag | ✅ 정확 |
| 동 번호 | Index | ✅ 정확 |
| 호실 내 방 번호 | Offset | △ 약간 부자연스러움 |

**주의 포인트**: "호실 내 방 번호(Offset)"는 일반적인 아파트 구조와 다소 어색하다. Offset은 "블록 내 바이트 위치"이므로, "같은 동, 같은 호 내의 서랍 번호" 정도가 더 자연스러울 수 있다. 그러나 전체 비유의 목적(3단계 계층 구조 전달)은 충분히 달성된다.

**한계 명시**: 아파트 주소는 계층 구조가 선택(어느 단지든 이사 가능)이지만 직접 매핑은 강제 매핑임을 명시하지 않는다. 물품 보관함 비유와 병용하면 보완된다.

## 2. 면접 포인트 확인

### Direct-Mapped vs N-Way 비교 표: `<aside class="interview">` 박스 삽입 여부
**판정: ✅ 확인됨 (13.2절)**

13.2절 면접 포인트 박스에 "Direct-Mapped vs. N-Way Set-Associative 비교" 텍스트로 서술. 표 형식은 아니지만 핵심 트레이드오프(구현 단순성+빠른 히트 vs 충돌 미스 감소+LRU 복잡성)를 2~3줄로 명확히 대비한다. 강의에서 판서용 표로 확장하기 좋은 형식이다.

**추가 면접 포인트 박스**: 13.5절에 "충돌 미스 완화 3가지 방법" 면접 포인트 박스가 추가 삽입되어 있어 중복 노출 효과가 있다.

---

### 3C 미스(Cold/Capacity/Conflict) 용어 포함 여부
**판정: ✅ 완전 포함**

- 13.2절 면접 포인트 박스: 3C 미스 전체 정의 및 예시 제시
- 13.5절 metacognition 박스: "Cold/Capacity/Conflict — 시나리오 1은 Cold Miss, 시나리오 4는 Conflict Miss"로 연결
- 연습문제 4번: 8회 접근 시퀀스에서 학생이 직접 각 접근을 Cold/Conflict로 분류하도록 유도

용어 체계가 교재 전반에 걸쳐 일관되게 사용되고 있으며, 면접 답변 2~3분 구조(개념 → 수치 예시 → 해결책)가 박스 내에 자연스럽게 내포되어 있다.

---

### 2~3분 답변 구조 제시 여부
**판정: △ 암묵적 구조, 명시적 가이드 없음**

면접 포인트 박스들이 "개념 정의 → 수치 비교 → 해결책 제안"의 3단 구조를 따르고 있으나, "2~3분 답변에서 이 순서로 말하십시오"와 같은 명시적 안내는 없다. 이는 강의에서 교수자가 별도로 안내해야 한다.

**강사 의견**: 13.6절 자가 점검 질문 이후에 "면접 답변 구조 예시" 박스를 한 개 추가하면 완결성이 높아진다. 현재 원고는 이 부분이 유일한 공백이다.

## 3. 강의 흐름 평가

### 1차시(13.1~13.3)와 2차시(13.4~13.6) 경계 자연스러움
**판정: ✅ 자연스러운 분절**

- **1차시 마무리 포인트**: 13.3절 연습문제 3개로 주소 분해 능력 자가 확인 → "손으로 계산했으면 이제 RTL로 구현해봅시다"로 2차시 도입부 연결 가능
- **2차시 도입부**: 13.4절 "이미 아는 것의 확장으로 이해하면 쉽습니다" 문구가 2차시 첫 문장으로 심리적 안정감 제공

**보완 가능 포인트**: 1차시 끝에 "오늘 배운 Tag/Index/Offset 분해 없이는 다음 시간 FSM 코드를 이해할 수 없습니다"와 같은 브리지 문장이 있으면 동기 부여가 더 강해진다.

---

### 13.3절 종이 실습 수업 중 진행 가능 수준 여부
**판정: ✅ 충분히 가능 (10~15분 예상)**

연습문제 3개(Q1: 주소 분해 / Q2: 충돌 주소 생성 / Q3: 블록 크기 변경 시 비트 폭)는 각각 2~3분 내 풀이 가능한 수준이며, `<details>` 태그 정답 공개 방식이 자기주도 확인에 최적화되어 있다.

**강사 꿀팁 박스(13.3절 내)**에서 "종이와 연필로 먼저 계산 → 시뮬레이션 검증" 2단계를 명시하고 있어, 강의 중 실습 절차가 교재에 내포되어 있다.

**주의**: Q3(블록 크기 변경)은 약 4~5분이 필요하여, 시간 제약이 있는 강의에서는 Q1+Q2만 수업 중 진행하고 Q3는 과제로 돌리는 것을 권장한다.

### 수강생이 막힐 추가 포인트 (기획에 없었던 신규 발견)

1. **DONE 상태의 역할**: FSM이 IDLE→MISS→FILL→DONE→IDLE으로 전환될 때, DONE 상태가 왜 1사이클 필요한지 명시적 설명이 없다. 강의에서 "DONE 상태는 파이프라인이 재개될 준비 신호를 1사이클 전달하기 위한 것"이라는 설명을 추가로 해주어야 한다.

2. **fill_cnt 초기화 타이밍**: FSM 코드에서 `if (state == MISS && mem_ready) fill_cnt <= 3'b0;`이 MISS→FILL 전환 시 fill_cnt를 리셋하는데, 이를 처음 보는 학생은 "MISS 상태에서도 mem_ready가 와야 하는가?"라고 의문을 가질 수 있다. 주석 보강을 권장한다.

3. **cpu_rdata MUX 조건**: `assign cpu_rdata = (state == DONE) ? mem_rdata : bram_rdata_reg;` 에서 DONE 상태에서 mem_rdata를 직접 사용하는 이유(마지막 워드를 BRAM 1사이클 지연 없이 즉시 제공)가 코드 주석에만 있고 본문 설명이 없다. 이 부분은 고급 질문이 나올 수 있는 포인트다.
