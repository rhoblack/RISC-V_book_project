### 2.2 기술 리뷰 Critical 상세 분석

#### C1: MMIO 주소 불일치

**현황**:
- HTML: 0x6000_0000 (라인 47, 74, 418-421, 474-476, 506-509, 698, 815)
- 실제 코드: 0xC000_0000 (ch22_drivers.h, ch22_linker.ld)

**영향도**: 🔴 **Critical** — 코드 실행 불가능 (모든 MMIO 접근 실패)

**해결책 (권장)**: HTML의 모든 MMIO 주소를 0xC000_0000으로 통일

**수정 대상**:
- 라인 47: 메모리 맵 설명
- 라인 74: 그림 캡션
- 라인 105: 링커 스크립트 템플릿
- 라인 418-421: UART_BASE 정의
- 라인 474-476: GPIO_BASE 정의
- 라인 506-509: TIMER_BASE 정의
- 라인 698: 체크리스트
- 라인 815: 연습문제

#### C2: DMEM 주소/크기 불일치

**현황**:
- HTML: 0x0000_1000 ~ 0x0000_1FFF (4KB)
- 실제 링커 스크립트: 0x8000_0000, 8KB

**영향도**: 🔴 **Critical** — 스택 포인터 초기화 오류로 프로그램 크래시

**해결책**: 모든 DMEM 참조를 0x8000_0000, 8KB로 통일

**수정 대상**:
- 라인 45-46: DMEM 주소/크기 설명
- 라인 74: 그림 캡션
- 라인 105: 링커 스크립트 메모리 영역

## 3. Phase 4 수정 지시사항

### 3.1 기술 저자에게 전달할 구체적 지시

#### 지시 1: HTML 메모리 주소 전체 수정 (2~3시간)

**파일**: `manuscripts/part8/chapter22.html`

**필수 수정 사항**:

1. **라인 45-47 (메모리 맵 설명)**
   ```
   Before: D-Cache (DMEM): 주소 0x0000_1000 ~ 0x0000_1FFF (4KB, 또는 확장 가능)
   After:  D-Cache (DMEM): 주소 0x8000_0000 ~ 0x8000_1FFF (8KB)
   ```

2. **라인 74 (그림 캡션)**
   ```
   Before: 그림 22.1: Basys 3 메모리 맵 — IMEM(0x0), DMEM(0x1000 또는 확장), 주변 장치(0x6000_0000)
   After:  그림 22.1: Basys 3 메모리 맵 — IMEM(0x0), DMEM(0x8000_0000), 주변 장치(0xC000_0000)
   ```

3. **라인 105 (링커 스크립트 템플릿)**
   ```
   Before: DMEM (rwx) : ORIGIN = 0x20000000, LENGTH = 32K
   After:  DMEM (rwx) : ORIGIN = 0x80000000, LENGTH = 8K
   ```

4. **라인 418-421 (UART_BASE)**
   ```
   Before: #define UART_BASE 0x60000000
   After:  #define UART_BASE 0xC0000000
   ```
   (GPIO_BASE, TIMER_BASE도 동일 처리)

5. **라인 698, 815 (연습문제 & 체크리스트)**
   - 모든 0x6000 → 0xC000 변환
   - 모든 0x0000_1000 → 0x8000_0000 변환

**검증 방법**:
- Find & Replace 기능으로 정확한 주소만 변경 (과도한 변경 금지)
- 수정 후 ch22_drivers.h, ch22_linker.ld와 비교 검증

#### 지시 2: 신규 SVG 4개 생성 (교육 설계 요청)

**파일 위치**: `figures/`

**1. ch22_sec01_linker_effect.svg** — 링커 적용 전후
- **왼쪽**: 링커 전 (.o 파일들이 산재, 순서 불명확)
- **오른쪽**: 링커 후 (메모리 맵에 배치, 주소 명확)
- **중앙**: 화살표로 매핑 표시
- **색상**: 파란색(IMEM), 초록색(DMEM), 주황색(MMIO)

**2. ch22_sec02_startup_flow.svg** — 부팅 시퀀스 타임라인
- **축**: 시간축 (상→하)
- **단계**: _start → sp 초기화 → .bss 클리어 → main() → while(1)
- **각 단계**: 레지스터/메모리 상태 표시
- **색상**: 파란색(코드 영역), 초록색(메모리 접근)

**3. ch22_sec02_stack_init.svg** — 스택 초기화 시각화
- **메모리 영역**: IMEM / DMEM (스택 위치) / 힙 공간
- **sp(스택 포인터) 초기값**: 0x8000_1FFF
- **방향**: 감소 방향(↓) 표시
- **색상**: DMEM 초록색, 스택 화살표 빨간색

### 3.2 기술 저자에게 권고하는 추가 검토 사항

**Major 3건** (강력 권고, 필수 아님):
- M1: volatile 키워드 선언 명확화
- M2: 비트 연산 unsigned 접미사 (1U << pin)
- M3: CSR 접근 인라인 어셈블리 단순화

→ 우선순위가 낮으므로, Critical 2건 + SVG 4개 완료 후 검토 가능
