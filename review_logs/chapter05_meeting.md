## 1단계: 4가지 관점 병렬 검토 결과

### A. 기술 리뷰

#### Critical 이슈 검토 결과

기술 리뷰어가 사전에 제시한 3개의 Critical 주석에 대한 반영 여부를 확인합니다.

**[CRITICAL-1] $readmemh는 시뮬레이션 전용. Vivado BRAM IP에서는 COE 파일로 초기화. 두 방법을 모두 설명할 것**
- **상태**: ✅ 반영 완료
- **반영 위치**: 5.2절 "실무 팁 — `$readmemh` vs COE 파일" aside 박스
- **확인 내용**:
  - "`$readmemh`는 시뮬레이션 환경에서만 동작"을 명시적으로 강조
  - COE 파일 형식(memory_initialization_radix, memory_initialization_vector) 예시 코드 포함
  - Vivado IP Catalog → Block Memory Generator → COE 파일 지정 경로 안내
  - 코드 주석에 "합성 시에는 이 구문이 무시될 수 있으므로, Vivado BRAM IP를 사용할 경우 COE 파일로 별도 초기화 필요" 명시
  - 면접 포인트 박스에 두 방법의 차이를 면접 관점으로 정리
  - 권장 워크플로("$readmemh로 개발 → FPGA 구현 시 COE 파일 전환") 명시

**[CRITICAL-2] 하버드 구조(Harvard Architecture)와 프린스턴 구조(Princeton/Von Neumann Architecture)의 차이를 5.2절 도입부에서 명시. IMEM/DMEM 분리 이유가 명확해짐**
- **상태**: ✅ 반영 완료 (5.1절에 배치)
- **반영 위치**: 5.1절 "두 메모리가 필요한 이유: 하버드 구조 vs. 폰 노이만 구조" 소절
- **확인 내용**:
  - 폰 노이만 구조(Princeton Architecture 병기) 설명과 "폰 노이만 병목" 개념 포함
  - 하버드 구조 설명 및 단일 사이클 프로세서에서의 필요성 ("같은 사이클에 명령어 인출과 데이터 메모리 접근이 동시에 일어나야") 명시
  - "수정 하버드 구조(Modified Harvard Architecture)" 팁 박스로 현대 프로세서와의 연결성 제공
  - 도서관/창고 비유로 하버드 구조의 직관적 이해 지원
  - 5.2절 도입 전에 개념을 충분히 설명하여 IMEM 설계의 근거 제공

**[CRITICAL-3] DMEM 바이트 주소 접근 시 리틀 엔디언 순서 확인 (addr+0 = 최하위 바이트)**
- **상태**: ✅ 반영 완료
- **반영 위치**: 5.3절 "리틀 엔디언 저장 방식" 소절, "강사 꿀팁" aside 박스
- **확인 내용**:
  - "RISC-V는 리틀 엔디언을 기본으로 한다" 명시
  - 0xDEADBEEF를 주소 0x1000에 저장 시 각 바이트 위치 표 형식으로 명시
  - 코드 주석에 "RISC-V 리틀 엔디언(Little-Endian): 낮은 주소 = 낮은 바이트" 명시
  - "강사 꿀팁" 박스에 "{mem[addr+0], ...}"로 작성 시 빅 엔디언 버그가 발생함을 경고
  - 테스트벤치(테스트 2)에서 dut.mem[0x1_0000]=0xEF, dut.mem[0x1_0001]=0xBE 등 바이트별 직접 검증
  - 연습문제 4번에서 리틀 엔디언 버그 코드를 직접 수정하는 실습 포함

#### 추가 기술 검토 사항

**코드 품질 검토**:
- SystemVerilog IEEE 1800-2017 준수: ✅ (always_ff, always_comb, logic 타입 사용)
- 들여쓰기 3칸: ✅ (모든 코드 블록 확인)
- snake_case 명명규칙: ✅ (imem_sel, dmem_sel, mmio_sel, byte_addr 등)
- 한국어 주석: ✅ (모든 주석이 한국어 또는 한국어+영어 병기)
- 합성 가능한 코드: ✅
  - imem: assign 비동기 읽기, initial만 비합성 (명시적 주석 포함)
  - dmem: always_ff 동기 쓰기, assign 비동기 읽기
  - memory_map: 순수 조합 논리 (assign만 사용)
  - mem_subsystem: 개념 코드임을 명시 ("Chapter 06에서 완성" 주석)

**BRAM 추론 규칙 검토**:
- BRAM vs 분산 RAM 비교 표 포함 ✅
- Artix-7(Basys 3) BRAM 프리미티브(RAMB18E1, RAMB36E1) 확인 방법 안내 ✅
- 출력 레지스터 비활성화 방법과 ram_style 속성 안내 ✅

### B. 초보자 독자 관점 검토
