# Chapter 24 교육전문강사 기획

## 강의 노트 스타일 체크

### 24.1 곱셈기 — 강의 1단락 샘플

> "자, 곱셈을 생각해봅시다. 초등학교 때 곱하기표 배웠죠? 23 × 15를 손으로 풀 때,
> 먼저 23×5=115, 그 다음 23×10=230, 마지막에 115+230=345. 이게 '부분곱(partial product)'을
> 만들고 더하는 겁니다. 하드웨어 곱셈기도 **정확히 같은 원리**예요. 다만 2진수니까
> 각 비트가 0 또는 1 — 곱하기표가 아주 단순해집니다. 그리고 32비트끼리 곱하면 결과는
> 최대 64비트. MUL 명령어는 하위 32비트만, MULH는 상위 32비트만 가져옵니다.
> 마치 345에서 백의 자리(3)와 일·십의 자리(45)를 따로 꺼내는 것과 같아요."

**체크포인트**: 수강생이 "부분곱"과 "결과 64비트" 두 가지만 기억하면 성공.

### 24.2 부동소수점 — 5분 강의 스크립트

> "부동소수점은 5분이면 충분합니다. 핵심은 딱 하나: **과학 표기법**이에요.
> 1500을 1.5 × 10³으로 쓰죠? IEEE 754는 같은 걸 2진수로 합니다.
> 부호 1비트, 지수 8비트, 가수 23비트 — 합쳐서 32비트.
> 넓은 범위를 표현할 수 있지만, 정밀도에 한계가 있어요.
> 0.1을 10번 더하면 1.0이 아닙니다. 이게 부동소수점의 본질이에요.
> F 확장은 '선택'입니다. 임베디드 프로세서 대부분은 소프트웨어 float로 충분하고,
> 하드웨어 FPU는 GPU/DSP 설계할 때 깊이 다루면 됩니다."

**체크포인트**: "과학 표기법의 2진수 버전" + "오차 존재" + "선택 확장"

### 24.3 Zicntr — 기존 지식 연결

> "Ch18에서 CSR 배웠죠? mcycle, minstret 기억나시나요? Zicntr은 그걸 '표준화'한 겁니다.
> 이미 아는 내용의 공식 이름표 붙이기예요. cycle, time, instret — 3개 카운터.
> 성능 측정할 때 CPI = cycle ÷ instret, 이것만 기억하세요."

**체크포인트**: "CSR 복습 + 표준 이름 3개"

## 핵심 비유 3개

### 비유 #1: 곱셈기 = 곱하기표 (초등학교 필산)

| 항목 | 내용 |
|------|------|
| **기술 사실** | 32×32→64비트 병렬 곱셈. 승수(multiplier)의 각 비트를 스캔하여 피승수(multiplicand)의 시프트된 복사본(부분곱)을 생성하고, 이를 캐리세이브 가산기 트리로 누적 |
| **비유** | "초등학교 곱하기표처럼, 각 자릿수별로 곱하고 자리 맞춰서 더해요" |
| **사실성** | ✅ 정확 — 부분곱 생성→누적 구조가 필산과 동일. 2진수는 0/1이므로 '곱하기'가 AND 연산으로 단순화 |
| **한계 명시** | "실제 HW는 병렬 가산기 트리(Wallace/Dadda tree)로 1~3사이클에 완료. 필산처럼 순차적이지 않음. 또한 Booth encoding으로 부분곱 수를 절반으로 줄이는 최적화도 있음" |
| **오해 방지** | "32비트×32비트=64비트 결과"라는 점 강조. 학생이 "32비트 결과"로 오해하면 MULH 존재 이유를 이해 못함 |
| **대안 비유** | 그림으로 2×2 곱셈(4가지 부분곱) → 4×4(16가지) → "32×32는 1024개 부분곱이지만 트리로 빠르게 합산" 패턴 확장 |

### 비유 #2: 나눗셈기 = 장제법 (긴 나눗셈)

| 항목 | 내용 |
|------|------|
| **기술 사실** | Restoring Division: 매 사이클마다 나머지(remainder)에서 제수(divisor)를 빼보고, 음수면 복구(restore), 양수면 몫 비트 1. 32비트 나눗셈에 32+α 사이클 필요 |
| **비유** | "손으로 하는 나눗셈 그대로예요. 한 자리씩 내리고, 빼보고, 되면 몫에 1, 안 되면 0" |
| **사실성** | ✅ 매우 정확 — 알고리즘 자체가 장제법의 2진수 버전. 학생이 손으로 따라할 수 있음 |
| **한계 명시** | "HW는 매 클록마다 1비트씩 처리하므로 32사이클 소요. Non-restoring, SRT 등 최적화 알고리즘이 있지만 본질은 동일. 곱셈(1~3사이클)보다 10배 이상 느림" |
| **오해 방지** | "나눗셈이 느리다"는 점을 반드시 인식시킬 것. 실시간 시스템에서 DIV를 루프 안에 넣으면 성능 치명적. 가능하면 시프트 연산으로 대체하는 최적화 습관 |
| **대안 비유** | 수동으로 8÷3 장제법 수행 → 각 스텝을 HW 신호(remainder, quotient_bit, restore 여부)로 1:1 추적하는 표 작성 |

### 비유 #3: 부동소수점 = 과학 표기법 (Scientific Notation)

| 항목 | 내용 |
|------|------|
| **기술 사실** | IEEE 754 single precision: 부호(1비트) + 지수(8비트, bias=127) + 가수(23비트, implicit 1). 표현 범위 ≈ ±1.18×10⁻³⁸ ~ ±3.40×10³⁸ |
| **비유** | "1.5 × 10³ = 1500처럼, 1.가수 × 2^(지수-127) 형태로 넓은 범위를 32비트에 압축" |
| **사실성** | ✅ 정확 — 과학 표기법과 구조적으로 동일. 밑(base)만 10→2로 변경 |
| **한계 명시** | "가수가 23비트이므로 약 7자리 십진수 정밀도. 0.1처럼 2진수로 무한소수인 값은 정확히 표현 불가. 덧셈 순서에 따라 결과가 달라질 수 있음 (결합법칙 불성립)" |
| **오해 방지** | "부동소수점 = 실수"라는 오해 차단. 실수는 무한 정밀도, float는 유한 근사. 금융/회계에는 고정소수점이나 BCD 사용. 또한 NaN, ±∞, denormalized number 등 특수값 존재 언급 |
| **대안 비유** | 라이브 데모: Python에서 `0.1 + 0.2 == 0.3` → False 보여주기. "이게 부동소수점의 현실입니다" |

## 수강생 Q&A 시나리오

### Q1: "MUL과 MULH 차이가 뭔가요?"
**A**: "32비트 × 32비트 = 64비트 결과가 나옵니다. MUL은 하위 32비트(일상적 곱셈 결과), MULH는 상위 32비트(오버플로우 검출용)를 가져옵니다."
**팁**: "long multiplication 하면 자릿수가 2배 되잖아요? 레지스터는 32비트라서 두 번에 나눠 가져오는 거예요."
**후속 질문 대비**: "그럼 64비트 전체 결과가 필요하면?" → "MUL + MULH 두 명령어를 연속 실행. HW가 최적화하여 한 번만 곱셈 수행하고 결과만 나눠 전달"

### Q2: "나눗셈은 왜 여러 사이클 걸려요?"
**A**: "곱셈은 부분곱을 동시에(병렬로) 만들어서 트리로 합산 → 1~3사이클. 나눗셈은 이전 비트의 결과(나머지)를 알아야 다음 비트를 계산 → 본질적으로 순차적. 32비트면 최소 32사이클."
**팁**: "손 나눗셈 상상하세요 — 첫째 자리 결과를 모르면 둘째 자리 계산을 시작할 수 없죠. 이 '데이터 의존성'이 병렬화를 막습니다."
**후속 질문 대비**: "그럼 나눗셈 피하는 방법은?" → "2의 거듭제곱 나눗셈은 시프트로 대체. 컴파일러가 자동 최적화. 상수 나눗셈은 역수 곱셈(reciprocal multiplication)으로 변환"

### Q3: "F 확장은 꼭 구현해야 하나요?"
**A**: "아닙니다. F 확장은 '선택(Optional)'입니다. 임베디드 MCU 대부분은 M 확장만 포함하고, 부동소수점은 소프트웨어 라이브러리(soft-float)로 처리합니다. HW FPU는 GPU, DSP, HPC 칩에서 필요합니다."
**팁**: "면접에서 '왜 FPU를 넣지 않았나'라고 물으면, '면적/전력 트레이드오프 — 타겟 워크로드에 float 연산이 5% 미만이면 soft-float가 합리적'이라고 답하세요."

### Q4: "IEEE 754는 어디서 더 배우나요?"
**A**: "이 책에서는 구조만 소개합니다. 깊이 있는 학습은: ①교재 'Computer Arithmetic' (Parhami), ②IEEE 754-2019 표준 문서, ③Stanford CS149 온라인 강의. 대학원에서 '컴퓨터 산술' 과목이 있으면 수강 추천."

### Q5 (추가): "DSP 블록이 뭔가요? 왜 쓰나요?"
**A**: "FPGA 칩 안에 미리 만들어진 곱셈기 회로예요. Basys 3의 Artix-7에는 DSP48E1 블록 90개가 있습니다. 로직(LUT)으로 곱셈기를 만들면 수백 개 LUT 소모, DSP 블록 1개면 끝. 합성 도구가 `*` 연산자를 자동으로 DSP에 매핑합니다."
**팁**: "Vivado에서 'Utilization Report' 열어보면 DSP 사용량 확인 가능 — 면접에서 리소스 인식 보여주는 좋은 포인트"

## 면접 연결

### 빈출 질문 3가지

1. **"곱셈기 구현 방식을 설명하세요"**
   - 기대 답변: "기본은 시프트-가산(shift-and-add). 최적화로 Booth encoding(부분곱 절반 감소), Wallace/Dadda tree(가산기 단계 최소화). FPGA에서는 DSP48 블록 활용. 파이프라인 곱셈기는 throughput 1 cycle/result 달성 가능"
   - 깊이 조절: "Booth encoding까지 설명하면 충분. Radix-4 Booth는 보너스"

2. **"DSP 블록 vs LUT 구현 트레이드오프"**
   - 기대 답변: "DSP 블록: 고속(전용 회로), 전력 효율적, 수량 제한(Artix-7: 90개). LUT 구현: 유연하지만 면적/지연 증가. 설계 시 DSP 자원 예산 확인 필수. 다수 곱셈기 필요 시 DSP 부족하면 시분할(time-multiplexing) 고려"
   - 팁: "Utilization Report에서 DSP 사용률 언급하면 실무 경험 어필"

3. **"부동소수점 오차 경험이 있나요?"**
   - 기대 답변: "IEEE 754 단정밀도는 가수 23비트 → 약 7자리 십진수 정밀도. 누적 연산 시 오차 증가. 게임 개발에서 카메라 좌표 누적 오차로 떨림 발생한 사례. 해결: double precision 전환 또는 주기적 정규화(normalization). 금융은 고정소수점 또는 decimal 타입 사용"

## 슬라이드/그림 요청

### 1. 곱하기표 → 병렬 곱셈기 진화 과정 (4단 SVG)
- **Step 1**: 초등학교 필산 (10진수 23×15)
- **Step 2**: 2진수 필산 (4비트 × 4비트, 부분곱 4줄)
- **Step 3**: 시프트-가산 하드웨어 (시프트 레지스터 + 가산기, 순차)
- **Step 4**: Wallace tree 병렬 곱셈기 (부분곱 동시 생성 → 트리 합산)
- **색상**: 부분곱 각 단계를 파란 계열 그라데이션(#DBEAFE→#2563EB)으로 구분

### 2. 나눗셈 장제법 수동 예제 (5단 SVG)
- **예제**: 13 ÷ 3 (= 몫 4, 나머지 1) — 4비트로 표현
- **Step 1**: 초기 상태 (Remainder=0000_1101, Divisor=0011, Quotient=0000)
- **Step 2**: 시프트 + 비교 (Remainder 왼쪽 시프트, Divisor와 비교)
- **Step 3**: 뺄셈 성공 → 몫 비트 1
- **Step 4**: 뺄셈 실패 → 복구(restore), 몫 비트 0
- **Step 5**: 최종 결과 (Quotient=0100, Remainder=0001)
- **하이라이트**: 각 스텝에서 변경되는 레지스터를 #2563EB로 강조

### 3. IEEE 754 비트 분해 (1개 SVG)
- **예제**: 단정밀도로 -1.5 표현
- **구조**: [부호 1비트 | 지수 8비트 | 가수 23비트] = 32비트 블록 다이어그램
- **값**: 부호=1(음수), 지수=01111111(127=bias, 2⁰), 가수=10000...0(0.5 → 1.5)
- **대응**: 과학 표기법 -1.5 × 2⁰ 와 비트 필드 1:1 매핑 화살표
- **색상**: 부호=#EF4444(빨강), 지수=#2563EB(파랑), 가수=#10B981(초록)

### 4. M 확장 통합 블록도 (1개 SVG)
- **구조**: EX 스테이지에 MUL/DIV 유닛 추가
- **신호 흐름**: rs1_data, rs2_data → MUL/DIV Unit → EX/MEM 파이프라인 레지스터
- **제어**: funct7[0] = M 확장 선택, funct3 = 연산 종류
- **스톨**: DIV 수행 중 파이프라인 스톨 신호 표시

### 설명 순서 최적화
1. **MUL 먼저** (간단, 성공 경험) → **DIV 다음** (복잡, "곱셈 이해했으니 나눗셈도 가능")
2. **F 확장은 마지막** ("알면 좋고, 몰라도 괜찮다" 메시지)
3. **Zicntr은 Ch18 복습으로** (새 개념 부하 최소화)

### 실습 난이도 조절
- 24.1 실습: 기존 파이프라인에 MUL 명령어 1개 추가 (성공 보장)
- 24.4 과제: 전체 M 확장 통합 (도전적이지만 24.1 기반 확장)
