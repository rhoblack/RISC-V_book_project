## 절별 상세 분석

### 16.1절: "왜 버스 표준이 필요한가"

**설명 품질**: ⭐⭐⭐⭐⭐

**비유 검증 — "USB 표준과 AMBA"**:
- **매핑 정확성**: ✅ 완벽 (USB 호환성 ↔ AMBA IP 재사용성)
- **한계 명시**: ✅ 명확 (USB 점대점 vs AHB 공유 버스)
- **오해 유발 여지**: ❌ 없음
- **강의 적합성**: ⭐⭐⭐⭐⭐ 그대로 사용 가능

### 16.2절: "AMBA 버스 패밀리와 AHB-Lite 신호 체계"

**설명 품질**: ⭐⭐⭐⭐ (용어 밀집도 높음)

**개선 권장**: 신호 3그룹 분류(A/B/C)를 먼저 강조한 후, 세부는 나중에

**FAQ "HREADY는 누가 구동하나요?"**: ✅ 적절함. 면접 필수 개념.

### 16.3절: "전송 타입과 타이밍 다이어그램"

**설명 품질**: ⭐⭐⭐⭐ (HTRANS 명명이 초보자에게 혼란스러움)

**수강생 막힘 포인트 #1: HTRANS 4개 명명의 의도**

강사 팁 (신규 추가 권장):
```
NONSEQ = "새로운 주소로 시작" (버스트의 첫 번째)
SEQ = "주소가 자동으로 증가" (버스트의 2~4번째)
BUSY = "버스트 중 잠깐 쉬어가기" (최신 표준에서 권장 안 함)
IDLE = "버스 미사용"

ARM이 1996년에 버스트 전송을 고려해서 이렇게 명명했습니다.
지금은 NONSEQ와 IDLE만 기억하세요."
```

**수강생 막힘 포인트 #2: 1사이클 파이프라인**

강점: 340~343줄 명확함. Ch09와 연결할 때 더욱 효과적.

강의안:
```
"Ch09의 IF/ID 오버랩을 기억하세요?
AHB도 정확히 같습니다.

T1: Master가 주소·제어 신호 구동 → Slave가 래치
T2: Slave가 HRDATA 구동 → Master가 HWDATA 구동

HWDATA = HADDR + 1사이클이 핵심입니다!"
```

### 16.4절: "Wait State와 HREADY 메커니즘"

**비유 검증 — "고속도로와 신호등"**:
- **매핑**: ✅ 우수 (HREADY=0 = 적색 신호)
- **한계 명시**: ✅ 있음
- **강의 적합성**: ⭐⭐⭐⭐⭐

**수강생 막힘 포인트 #3: HREADY=0 동안 신호 동결**

강사 팁:
```
"HREADY=0을 받으면 Master는 정지합니다.

신호 동결(Freeze):
1. HADDR 고정
2. HTRANS 고정
3. HSIZE, HWRITE 고정
4. HWDATA도 고정

하나라도 바꾸면 Slave가 잘못 처리합니다!"
```

**FAQ "HREADY 체크리스트"**: ✅ 우수. 5가지 오류 사례 제시.

---

### 16.5절: "AHB Master FSM 설계"

**설명 품질**: ⭐⭐⭐⭐⭐

**수강생 막힘 포인트 #4: cache_addr vs addr_lat**

강사 답변:
```
"M_ADDR은 신선한 요청이므로 cache_addr 직접 사용.
M_WAIT은 캐시가 신호를 바꿀 수 있으니,
M_ADDR 진입 순간에 cache_addr을 래치하고
그 래치값(addr_lat)을 계속 사용합니다.

이것이 '신호 동결'입니다!"
```

**실무 팁 (704~715줄)**: ✅ "HWDATA 타이밍이 핵심" — 강사가 그대로 사용 가능

---

### 16.6절: "AHB SRAM Slave 설계"

**설명 품질**: ⭐⭐⭐⭐

**수강생 막힘 포인트 #5: 래치 조건 "HSEL && HTRANS[1] && HREADY_in"**

강사 설명:
```
"3가지 조건이 모두 필요합니다.

조건 1: HSEL=1 → 이 Slave 선택
조건 2: HTRANS[1]=1 → 실제 전송 (IDLE/BUSY 무시)
조건 3: HREADY_in=1 → 주소가 안정적

하나라도 빠지면 잘못 래치됩니다!"
```

**FAQ "WAIT_CYCLES=1인데 왜 2사이클?"**: ✅ 명확. S_WAIT + S_DONE 설명이 좋음.

---

### 16.7절: "AHB 인터커넥트 설계"

**설명 품질**: ⭐⭐⭐⭐⭐

**수강생 막힘 포인트 #6: HRDATA MUX가 HSEL_d를 사용하는 이유**

강사 설명:
```
"왜 HSEL_d일까요?

T1: Master가 HADDR=0x0001_0004 구동
    → HSEL_dmem=1 (DMEM 선택)

T2: DMEM Slave가 HRDATA 구동
    Interconnect가 "어느 Slave 데이터를 보낼까?"를 결정

    ❌ 현재 HSEL 사용 → T2에서 주소가 이미 바뀔 수 있음
    ✅ 1사이클 전의 HSEL_d 사용 → T1의 선택을 T2에 적용

이것이 파이프라인 타이밍을 올바르게 처리하는 방법입니다!"
```

**면접 포인트 (1015~1025줄)**: ✅ 3가지 대표 질문. Q3가 면접 필수 문제.

## 수강생 7가지 막힘 포인트 및 강사 대응

| 막힘 포인트 | 증상 | 강사 대응 |
|-----------|------|---------|
| HTRANS 4개 명명 | "왜 IDLE, BUSY, NONSEQ, SEQ일까?" | 버스트 전송 고려한 ARM의 설계 역사적 배경 설명 |
| HWDATA 1사이클 지연 | "왜?" + 구현 오류 | Ch09 파이프라인 상기 + "모든 설계자가 경험합니다" |
| HREADY=0 신호 동결 | "주소는 고정하는데 왜 HTRANS도?" | Slave가 동시에 래치하므로 전부 동결 필요 |
| Wait State 지연 계산 | "WAIT_CYCLES=1인데 2사이클?" | S_WAIT + S_DONE 구조, 파라미터는 대기만 포함 |
| Slave 래치 3조건 | "1개 조건만으로 안 되나?" | HSEL(선택), HTRANS[1](전송), HREADY_in(안정성) 각각 필요 |
| HRDATA MUX HSEL_d | "복잡한데 왜?" | T1→T2 파이프라인 타이밍 차이 → 1사이클 지연 필요 |
| cache_addr vs addr_lat | "왜 다른 신호 쓰나?" | M_ADDR은 신선, M_WAIT은 캐시 변경 가능 → 래치 필수 |

## 강의 흐름 추천 (4차시)

### 1차시: 16.1~16.3 (신호 및 타이밍)

1. 16.1 (10분): USB → AMBA 비유
   - 문제: 자체 프로토콜 확장성 한계
   - 해결: 표준화
   - 한계: AHB-Lite는 단일 마스터

2. 16.2 (15분): 신호 3그룹 분류
   - A: 주소/제어 (HADDR, HTRANS, ...)
   - B: 데이터 (HWDATA ↔ HRDATA)
   - C: 흐름 제어 (HREADY, HRESP)

3. 16.3 (15분): 1사이클 파이프라인
   - Ch09 IF/ID 오버랩 상기
   - AHB: T1(주소) + T2(데이터)
   - HWDATA = HADDR + 1사이클

**과제**: HTRANS 4종 정리

### 2차시: 16.4 (Wait State)

1. 고속도로 신호등 비유 (10분)
2. 신호 동결 규칙 (15분)
3. FAQ & 5가지 오류 (5분)

**과제**: HREADY=0 조건 5가지 기억

### 3차시: 16.5~16.6 (코드 구현)

1. Master FSM (20분)
2. Slave 래치 조건 (15분)
3. 코드 읽기 (5분)

### 4차시: 16.7~16.8 (시스템 통합)

1. HRDATA MUX 1사이클 지연 (15분)
2. 테스트벤치 분석 (10분)
3. SVA 자동 검증 (5분)

**과제**: Write→Read 시뮬레이션
