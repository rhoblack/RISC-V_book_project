  - 핵심 개념 정리, 자가 점검 질문 5개, Ch19 예고

#### 2. 신규 SVG 다이어그램 (3~4개)

   - 크기: ~200줄 (모듈 선언 + 읽기/쓰기 로직)
   - 특징: 1비트 필드(MIE) 제외한 나머지는 최소 구현

2. **code_examples/ch18_csr_tb.sv**
   - 목적: CSR 명령어 시뮬레이션 테스트벤치
   - 범위: mstatus 읽기 → CSRRW로 쓰기 → mie 비트 조작 검증
   - 크기: ~150줄
   - 특징: 명령어별 동작 확인 (CSRRW, CSRRS, CSRRC 각 1회)

#### 4. 주요 비유 개발
- **CSR ≈ "프로세서의 설정창"**: Windows 제어판처럼, 시스템 전체의 동작을 제어
  - 한계 명시: "CSR은 설정창이지만, 각 비트가 하드웨어 동작에 직접 영향을 미친다 (소프트웨어 단순 설정이 아님)"
  
- **M-mode ≈ "관리자 권한"**: 사용자 계정 vs 시스템 관리자
  - 한계 명시: "실제로는 프로세서의 '모드'이지, 계정 같은 개념은 아니다"

- **mstatus ≈ "프로세서 상태 플래그"**: 자동차 대시보드의 경고등
  - 한계 명시: "경고등은 표시만 하지만, mstatus는 하드웨어 동작을 제어한다"

#### 5. 본 장 특별 주의사항
- CSR은 완전히 새로운 도메인 (파이프라인과 분리하여 설계)
- Ch18은 CSR 자체만 집중, Ch19에서 예외 처리와 연결
- 모든 CSR 구현은 "최소" 수준 (필수 기능만)

- 18.3: "CSRRW, CSRRS, CSRRC 명령어의 동작 원리를 분석할 수 있다" (L4)
- 18.4: "CSR 명령어를 이용해 mstatus를 조작하고 검증할 수 있다" (L3)

#### 2. 학습 흐름 설계

**도입** (호기심 유발):
- 질문: "프로세서가 자신의 상태를 어떻게 관리할까?"
- 실제 예제: "인터럽트가 발생했을 때, CPU는 '현재 상태'를 어디에 저장할까?"

**개념** (단계적 확대):
1. M-mode 개념 (특권 수준)
2. CSR의 정의 및 주소 공간
3. 7개 핵심 CSR의 역할 (각각 1~2문장)
4. CSR 명령어 6개 (I-타입, 읽기/쓰기/읽기-수정-쓰기)

**예시** (구체적 시나리오):
- "프로세서가 인터럽트를 받으면, mie 비트를 확인한다"
- "예외가 발생하면 mepc에 복귀 주소를 저장한다"

**실습** (동작 검증):
- 시뮬레이션: mstatus 읽기 → CSRRW로 쓰기 → 레지스터 값 확인
- 테스트벤치: CSRRW, CSRRS, CSRRC 각 1회 실행 및 검증

**정리** (핵심 요약):
- CSR의 용도별 분류
- CSR 명령어의 원자성 보장
- "다음은 이 CSR들이 실제 예외 처리에 사용되는 모습을 배울 것"

#### 3. 인지 부하 분석

**신규 개념** (절당 평균 2~3개):
- 18.1: M-mode(新) + CSR 개념(新) + 주소 공간(新) = 3개
- 18.2: mstatus 구조(新) + 나머지 6개 CSR(누적) = 1~2개
- 18.3: CSRRW/RS/RC(新) + I-타입 인코딩(누적) = 2개
- 18.4: 시뮬레이션 환경(누적) = 0개 신규
- 18.5: 정리(누적) = 0개 신규

**인지 부하 완화**:
- CSR 주소 외우기 금지 → 코드 라이브러리 함수(write_csr) 제공
- 12개 CSR → 7개로 축약
- 각 비트의 의미는 "언제 필요한지"만 명확히 (세부 사항은 참조용)

#### 4. 연습문제 설계 (총 5개, L2~L4 분포)

**L2 (이해)**:
1. "mstatus의 MIE 비트가 무엇인가?" 
   - 정답: "Machine Interrupt Enable. CSR이 인터럽트 신호를 받아들일지 여부를 제어"

2. "CSRRW와 CSRRS의 차이는?"
   - 정답: "CSRRW는 전체 덮어쓰기, CSRRS는 비트 OR(특정 비트 설정)"

**L3 (적용)**:
3. "CSRRW로 mtvec을 0x80000000으로 설정하는 어셈블리 코드를 작성하시오"
   - 정답: `li t0, 0x80000000; csrrw x0, mtvec, t0`

4. "다음 C 코드를 어셈블리로 변환하시오: `uint32_t status = read_csr(mstatus);`"
   - 정답: `csrr t0, mstatus`

**L4 (분석)**:
5. "mie와 mip가 별도로 존재하는 이유는 무엇인가?"
   - 정답: "mie는 '어떤 인터럽트를 허용할지' 결정, mip는 '현재 어떤 인터럽트가 대기중인지' 표시. 소프트웨어가 둘을 비교하여 처리 가능한 인터럽트 판단"

## Teammate 3: 교육심리전문가 (Educational Psychologist)

### 임무
불안 관리 및 감정 곡선 설계

### 요청사항

#### 1. 불안 지점 식별

**A. 도메인 낯섦 (매우 높음)**
- 특권 수준, CSR이라는 개념 자체가 처음 접함
- 지금까지는 "명령어 설계"였는데, 이제는 "시스템 제어"의 영역
- 학습자: "왜 이렇게 복잡해야 할까?" → 불안

**B. 정보 과부하 (높음)**
- CSR이 12개나 있고, 각각 비트 구조가 다름
- "모든 CSR을 외워야 하나?" 불안
- 선택지: mie, mip, mtvec, mepc, mstatus, mcause, mscratch (7개 vs 12개 혼동)

**C. 파이프라인과의 연결성 불명확 (중간)**
- 지금까지 배운 파이프라인과 CSR의 관계가 불명확
- 학습자: "이게 파이프라인과 무슨 상관이 있지?" → 혼동

**D. 추상성 높음 (중간)**
- 메모리/캐시는 "물리적"으로 이해 가능 (데이터 저장)
- CSR은 "제어 신호"로 충분히 추상적
- 학습자: "이걸 어디에 쓰지?" → 동기 상실

#### 2. 감정 곡선 설계 (호기심 → 불안 → 이해 → 성취감)

**호기심** (도입, 18.1):
- 장면: "당신이 지금 프로세서라면, 인터럽트가 왔을 때 '나는 지금 일 중이니까 잠깐만' 이렇게 말할 수 있을까?"
- 연결: "프로세서가 자신의 상태를 관리하는 방법을 배우자"
- 감정: 호기심 + 기대감

**불안** (18.2, 개념 폭증):
- 장면: "아, CSR이 이렇게 많고 복잡하다고?"
- 원인: 7개 CSR, 각각의 비트 의미 설명
- 감정: 막연한 불안, 정보 과부하

**이해** (18.3~18.4, 구체적 동작):
- 장면: "아, CSR 명령어는 단순한 읽기/쓰기로군. 나도 할 수 있겠는데?"
- 이유: 코드 예제, 시뮬레이션으로 동작 확인
- 감정: 불안에서 "아!" 순간의 이해로 전환

**성취감** (18.4, 미니 실습):
- 장면: "테스트벤치를 돌려보니 mstatus가 정말 바뀌었다!"
- 경험: 직접 조작 → 결과 확인 → 자기효능감 상승
- 감정: "나도 프로세서를 제어할 수 있다!"

#### 3. 안심 장치 제시

**메시지 1** (도입에 포함):
"이 장에서는 7개의 CSR만 배웁니다. 각 비트의 기능은 '언제 필요한지' 명확히 하고, 나머지 세부 사항은 참조용으로 남겨둡니다. 모든 CSR을 외울 필요는 없습니다."

**메시지 2** (18.2 끝에 포함):
"CSR 주소(0x305, 0x304 등)를 외우지 마세요. 실제 코딩에서는 라이브러리 함수 `write_csr()`, `read_csr()`을 사용합니다. 프로그래머는 함수 이름만 기억하면 됩니다."

**메시지 3** (18.3 시작에 포함):
"모든 CSR은 이미 하드웨어(프로세서) 내부에 존재합니다. 여러분의 일은 이미 있는 것을 '읽고 쓸 뿐'입니다. 프로세서 설계자처럼 생각하지 않으셔도 됩니다."

**메시지 4** (18.4 실습 직전):
"이제 실제로 mstatus를 조작해 봅시다. 처음에는 읽기만 → 다음에 쓰기 → 마지막에 비트 조작. 각 단계가 성공하도록 설계되어 있습니다."

#### 4. 첫 성공 경로 설계

**1단계: 읽기 (가장 쉬움, 성공 보장)**
- 작업: CSR 읽기 명령어 1줄 실행
- 난이도: ★☆☆☆☆
- 성공 척도: "값을 읽었다"
- 심리: "아, 이 정도면 할 수 있겠는데?"

**2단계: 단순 쓰기 (중간)**
- 작업: CSRRW로 mie 비트 1개 설정
- 난이도: ★★☆☆☆
- 성공 척도: "쓴 값이 정말 저장되었다"
- 심리: "내가 프로세서를 조종하고 있다!"

**3단계: 비트 조작 (심화)**
- 작업: CSRRS로 mie 비트 추가 설정
- 난이도: ★★★☆☆
- 성공 척도: "기존 값은 유지되고 새 비트만 추가되었다"
- 심리: "원자 연산의 유용함을 몸으로 느낀다"

#### 5. 메타인지 촉진 장치

**각 절 말미의 자가 점검 박스**:
- 18.1 끝: "지금까지 배운 것: CSR은 ___, M-mode는 ___ (답 제시)"
- 18.2 끝: "이제 알게 된 것: 7개 CSR 각각의 역할을 1줄씩 설명하시오"
- 18.3 끝: "CSR 명령어의 공통점: 모두 ___ 타입이고, ___ 연산을 수행한다"
- 18.4 끝: "내가 해본 것: 읽기 → 쓰기 → 비트 조작. 어떤 점이 제일 유용했나?"
- 18.5 말미: "다음 단계로: Ch19에서는 이 CSR들이 ___ 처리에 사용될 것"

**메타인지 질문의 역할**:
- 이전 학습 상기
- 현재 이해도 점검
- 향후 학습과의 연결고리 인식

#### 6. 기대 설정 문구

**도입 직후** (18.1 초반):
"이 장은 총 5개 절로 나뉩니다. 먼저 개념(18.1~18.2)을 익히고, 명령어 구조(18.3)를 배운 후, 직접 실습(18.4)하며 마무리(18.5)합니다. **이 장에서는 CSR 자체만 학습합니다.** 인터럽트나 예외 처리는 다음 장(Ch19)에서 배울 것입니다."

**18.4 실습 전**:
