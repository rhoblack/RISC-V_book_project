## 1. Part별 이해도 예측 (1~5점)

| Part | 챕터 | 이해도 | 근거 |
|------|------|:------:|------|
| Part 0 | Ch01 | ⭐⭐⭐⭐⭐ | Vivado 설치, LED 점멸은 제가 이미 해본 것과 비슷합니다. SystemVerilog 복습도 Verilog 기반이라 부담 없습니다. |
| Part 1 | Ch02~03 | ⭐⭐⭐⭐ | ISA 자체는 새롭지만, 레지스터/메모리 개념은 알고 있으므로 읽을 만합니다. 다만 명령어 47개를 한꺼번에 보면 약간 압도될 수 있습니다. |
| Part 2 | Ch04~06 | ⭐⭐⭐⭐ | ALU, 레지스터 파일은 Verilog로 만들어 본 경험이 있어서 친숙합니다. 다만 단일 사이클 전체 통합(Ch06)에서 제어 신호 매핑이 복잡해 보입니다. |
| Part 3 | Ch07~08 | ⭐⭐⭐⭐ | FSM은 Verilog 수업에서 많이 다뤘기 때문에 익숙합니다. 멀티사이클 개념도 단일 사이클을 이해한 후라면 자연스럽게 따라갈 수 있을 것 같습니다. |
| Part 4 | Ch09~12 | ⭐⭐⭐ | 파이프라인 자체는 개념적으로 이해하겠지만, 해저드/포워딩/스톨이 동시에 등장하면 머릿속이 복잡해질 것 같습니다. 특히 Ch10~11이 걱정됩니다. |
| Part 5 | Ch13~15 | ⭐⭐⭐ | 캐시 개념은 컴퓨터구조 수업에서 들었지만, 직접 RTL로 구현해 본 적은 없습니다. Write-Back, LRU 같은 정책을 하드웨어로 어떻게 만드는지 감이 잘 안 옵니다. |
| Part 6 | Ch16~17 | ⭐⭐ | AMBA 버스는 이름만 들어봤습니다. AHB/APB 프로토콜, 브리지, 아비터 등 처음 접하는 개념이 한꺼번에 나와서 압도될 것 같습니다. |
| Part 7 | Ch18 | ⭐⭐ | CSR, 트랩, 특권 수준, 정확한 예외... 전부 처음 듣는 용어입니다. 파이프라인과 예외를 동시에 고려해야 한다니 난이도가 상당히 높아 보입니다. |
| Part 8 | Ch19~21 | ⭐⭐⭐ | FPGA 합성 자체는 해봤지만, 타이밍 클로저나 ILA 디버깅은 경험이 부족합니다. 다만 "실제로 동작하는 것을 본다"는 동기부여가 강력합니다. |
| Part 9 | Ch22~24 | ⭐⭐ | 슈퍼스칼라, 비순차 실행, 멀티코어는 완전히 새로운 세계입니다. 선택이라 다행이지만, 읽는다면 상당한 배경지식이 필요합니다. |

## 2. 두려움 유발 지점

| 심각도 | 챕터/절 | 두려움 내용 |
|--------|---------|------------|
| **Critical** | Ch10 (데이터 해저드와 포워딩) | 목차만 봐도 "RAW/WAW/WAR", "EX-EX 포워딩", "MEM-EX 포워딩", "포워딩 우선순위"... 한 챕터에 새로운 개념이 너무 많이 몰려 있습니다. "제가 이걸 설계할 수 있을까?"라는 생각이 먼저 듭니다. |
| **Critical** | Ch18 (CSR과 예외 처리) | 절이 8개나 되고, 모든 용어가 낯섭니다. "정확한 예외", "트랩 진입/복귀", "CSR 원자적 읽기-수정-쓰기"... 이 챕터 하나가 독립된 책 같습니다. |
| **Major** | Ch11 (제어 해저드와 분기 처리) | 절이 7개이고, "Predict-Not-Taken", "2-bit 포화 카운터", "BHT", "BTB" 등 새 용어가 쏟아집니다. Ch10 직후라 피로 누적 상태에서 만나면 더 힘들 것 같습니다. |
| **Major** | Ch16 (AMBA AHB) | HADDR, HTRANS, HWRITE, HWDATA, HRDATA, HREADY, HRESP... 신호 이름만 7개. 프로토콜 규칙까지 익혀야 하니 진입장벽이 높습니다. |
| **Major** | Ch14 (L1 데이터 캐시) | Write-Back + Dirty 비트 + 2-way 연관 + LRU를 한 챕터에 다 넣은 건 부담스럽습니다. |
| **Minor** | Ch06 (제어 유닛과 단일 사이클 통합) | 37개 명령어 완전 디코딩이라는 표현이 무섭습니다. 제어 신호 진리표가 얼마나 클지 상상이 안 됩니다. |
| **Minor** | Ch15 (메모리 컨트롤러) | "캐시 미스 처리 FSM", "버스트 전송"은 처음 보는 개념입니다. |

## 3. 미설명 용어 탐지

아래는 제 사전 지식(Verilog 기본 + 디지털 논리 기초 + 기본 컴퓨터 구조)에 없는데, 목차 기준으로 선행 설명 없이 등장할 수 있는 용어들입니다.

| 심각도 | 용어 | 등장 위치 | 문제 |
|--------|------|----------|------|
| **Critical** | ABI (Application Binary Interface) | Ch02.2 | "ABI 이름 (ra, sp, gp, tp...)"이라고만 되어 있는데, ABI가 뭔지 먼저 설명이 필요합니다. |
| **Critical** | CSR (Control and Status Register) | Ch18.1 | 약어 자체가 낯설고, "Zicsr 확장"이란 표현도 처음입니다. |
| **Critical** | 트랩(Trap) | Ch18.6 | 예외와 인터럽트의 통칭이라는 설명이 앞에 있어야 합니다. |
| **Major** | HTIF (Host-Target Interface) | Ch20.4 | riscv-tests와 함께 언급되는데, 무엇인지 전혀 감이 안 옵니다. |
| **Major** | BHT (Branch History Table) / BTB (Branch Target Buffer) | Ch11.5 | 약어만 보면 무슨 뜻인지 모릅니다. |
| **Major** | 하버드 구조 / 프린스턴 구조 | Ch12.1, Ch07 주석 | 목차에 등장하지만 별도 설명 절이 보이지 않습니다. |
| **Major** | SVA (SystemVerilog Assertion) | Ch16.6 주석 | 기술 리뷰어 주석에 언급되었고, 본문에도 나올 수 있는데 SVA를 배운 적 없습니다. |
| **Major** | 리타이밍(Retiming) | Ch19.1 | 합성 최적화 기법인데, Verilog 수업에서 다루지 않는 개념입니다. |
| **Major** | WNS / TNS | Ch19.3 | 타이밍 분석 용어인데 처음 봅니다. |
| **Minor** | COE 파일 | Ch05 주석 | Vivado BRAM IP 초기화 포맷인데 처음 보는 파일 형식입니다. |
| **Minor** | MESI 프로토콜 | Ch24.1 | 캐시 일관성 프로토콜인데 약어가 낯섭니다. |
| **Minor** | 토마슐로(Tomasulo) 알고리즘 | Ch22.3 | 인명 기반 알고리즘이라 맥락 없이는 이해 불가합니다. |
| **Minor** | LR/SC (Load-Reserved / Store-Conditional) | Ch24.2 | A 확장 명령어인데 RV32I 범위를 넘어서는 개념입니다. |

## 4. 자연스러운 궁금증

### Part 0
- "Verilog와 SystemVerilog가 정확히 뭐가 다른 거지? 내가 아는 Verilog 코드 그대로 써도 되나?"
- "VCS/Verdi는 유료 아닌가? 대학원 라이선스로 쓸 수 있는 건가?"

### Part 1
- "RISC-V 명령어가 47개라는데, 이걸 다 외워야 하나?"
- "x86이나 ARM하고 뭐가 다른 거지? 왜 굳이 RISC-V를 배우는 거지?"
- "R/I/S/B/U/J 타입... 6가지나 되는데 패턴이 있는 건가?"

### Part 2
- "ALU 10가지 연산을 한 모듈에 다 넣으면 합성 시 면적이 어떻게 되지?"
- "단일 사이클로도 동작하는데 왜 더 복잡한 걸 만드는 거지?" (동기부여 질문)
- "피보나치 수열이 진짜 내가 만든 CPU에서 돌아가는 거야?"

### Part 3
- "멀티사이클이 파이프라인보다 느린 거면, 왜 배우는 거지? 바로 파이프라인 하면 안 되나?"
- "FSM 상태가 몇 개까지 늘어나는 거지?"

### Part 4
- "해저드가 3종류라는데, 실제로 어떤 명령어 조합에서 발생하는 거지?"
- "포워딩이 없으면 어떻게 되는 건지, 정말 NOP을 삽입하는 건가?"
- "분기 예측이 틀리면 성능이 얼마나 떨어지는 거지?"

### Part 5
- "캐시 크기를 어떻게 정하는 거지? 큰 게 무조건 좋은 거 아닌가?"
- "Write-Back이 Write-Through보다 좋으면 왜 Write-Through를 먼저 가르치는 거지?"

### Part 6
- "AHB, APB, AXI 중 실무에서 뭘 가장 많이 쓰는 거지?"
- "UART를 직접 만든다고? 기존 IP를 가져다 쓰면 안 되는 건가?"

### Part 7
- "인터럽트가 파이프라인 중간에 들어오면 지금 실행 중인 명령어는 어떻게 되는 거지?"
- "M-mode만 구현하면 충분한 건가? Linux를 올리려면 더 필요한 거 아닌가?"

### Part 8
- "시뮬레이션에서 다 통과했는데 FPGA에서 안 돌아가면 어디서부터 봐야 하지?"
- "C 프로그램이 내가 만든 CPU에서 정말 실행되는 거야? printf도 되는 거야?"

## 5. 포기 위험 구간

| 위험도 | 구간 | 포기 이유 | 제안 |
|--------|------|----------|------|
| **매우 높음** | Ch10~Ch11 (Part 4 중반) | 데이터 해저드 포워딩을 겨우 이해했는데 바로 제어 해저드까지 나옵니다. 개념이 누적되면서 "나는 이걸 따라갈 수 없다"는 느낌이 올 수 있습니다. 교재 전체에서 가장 위험한 구간입니다. |  Ch10과 Ch11 사이에 "중간 점검" 절을 넣거나, 작은 성취 경험(예: 포워딩만 있는 프로세서로 간단한 프로그램 실행)을 배치해 주세요. |
| **높음** | Ch18 (Part 7) | Part 4의 고난을 넘고, Part 5~6까지 소화한 후인데 또 완전히 새로운 큰 주제(예외/인터럽트)가 나옵니다. 체력이 바닥난 시점이라 "여기까지만 하자"가 될 수 있습니다. | Ch18 도입부에 "파이프라인까지 만든 당신은 이미 90%를 완성했다"는 격려와, Ch18의 구체적 분량 예고가 필요합니다. |
| **중간** | Ch14 (Part 5) | Write-Back + 2-way 연관 + LRU를 한 챕터에서 다루는 건 부담스럽습니다. 특히 캐시를 RTL로 구현하는 것 자체가 처음이라 자신감이 떨어질 수 있습니다. | 14.1~14.2(Write-Back)와 14.3(세트 연관)을 분리하여 단계적으로 접근하는 구조가 보이면 안심될 것 같습니다. |
| **중간** | Ch16 (Part 6) | AMBA 프로토콜이 완전히 새로운 영역이라 "이건 내 분야가 아니다"라고 느낄 수 있습니다. | 프로토콜의 실무 가치(면접, 실제 SoC 설계)를 강조하여 동기부여가 필요합니다. |
| **낮음** | Ch03 (Part 1) | 명령어 47개 나열은 지루할 수 있지만, 아직 초반이라 의지가 있습니다. | 3.8절 어셈블리 실습이 좋은 배치입니다. 이론 후 바로 실습하면 지루함을 상쇄할 수 있습니다. |

## 6. 흥미 유발 포인트

| 챕터/절 | 흥미 포인트 | 이유 |

| Ch06.4 (단일 사이클 통합 시뮬레이션) | "내가 만든 CPU에서 피보나치가 돌아간다고?!" | 이건 정말 짜릿할 것 같습니다. CPU를 직접 만들었다는 성취감이 대단할 것입니다. |
| Ch08.5 (3종 비교) | "단일 사이클 vs 멀티사이클, 어떤 게 더 빠를까?" | 내가 만든 두 가지 설계를 직접 비교할 수 있다는 점이 흥미롭습니다. |
| Ch12.5 (3종 FPGA 비교) | "세 가지 아키텍처를 Vivado로 합성해서 실제 수치 비교" | 교과서에서만 보던 트레이드오프를 직접 측정한다니 기대됩니다. |
| Ch11.5 (분기 예측) | "날씨 예보관 비유? 분기 예측이 맞고 틀리는 걸 직접 확인?" | 분기 예측은 이름부터 흥미롭고, 직접 예측기를 만들 수 있다면 재미있겠습니다. |
| Ch17.3 (UART 컨트롤러) | "내가 만든 CPU가 PC에 'Hello RISC-V'를 보낸다고?" | 하드웨어와 소프트웨어가 만나는 순간. 이건 꼭 해보고 싶습니다. |
| Ch21.4 (최종 데모) | "C 프로그램이 내 CPU에서 실행된다!" | 교재의 최종 보스전 같은 느낌. 여기까지 오면 정말 뿌듯할 것 같습니다. |
| Ch20.2 (ILA) | "FPGA 안을 실시간으로 들여다본다" | 오실로스코프처럼 칩 내부 신호를 볼 수 있다니 신기합니다. |

## 7. 선수 지식 갭 분석

Verilog는 알지만 RISC-V/컴퓨터구조를 깊이 모르는 독자가 겪을 주요 어려움입니다.

| 심각도 | 갭 영역 | 영향 범위 | 상세 |
|--------|---------|----------|------|
| **Critical** | ISA 설계 철학 | Part 1 전체 | 저는 Verilog로 모듈을 만들어 봤지, "명령어 집합을 정의한다"는 것이 무슨 의미인지 직관적으로 와닿지 않습니다. "왜 이렇게 비트를 배치했는지"를 먼저 이해해야 디코더를 설계할 수 있을 텐데, 그 연결고리가 목차에서 명시적이지 않습니다. |
| **Critical** | 파이프라인 실행 모델 | Part 3~4 | "여러 명령어가 동시에 실행된다"는 개념 자체가 Verilog 모듈 설계와 질적으로 다릅니다. 타이밍 다이어그램을 읽는 훈련이 필요한데, 별도 절이 보이지 않습니다. |
| **Major** | 메모리 계층 직관 | Part 5 | "왜 메모리가 느린가", "왜 캐시가 필요한가"를 체감한 적이 없습니다. Verilog에서는 메모리를 그냥 배열로 쓰니까요. 실제 DRAM 지연 시간에 대한 감각이 없으면 캐시의 필요성을 체감하기 어렵습니다. |
| **Major** | 버스 프로토콜 개념 | Part 6 | Verilog 모듈 간 연결은 해봤지만, "프로토콜"이라는 개념(핸드셰이크, 전송 타입, 응답 코드)은 경험이 없습니다. 왜 단순 와이어 연결로는 안 되는지부터 설명이 필요합니다. |
| **Major** | 특권 수준과 OS 연동 | Part 7 | M-mode, 트랩 핸들러 같은 개념은 OS 수업에서 배우는 내용인데, 하드웨어 관점에서 접근하는 건 전혀 다른 이야기입니다. |

### 최종 소감

저는 Verilog를 아는 대학원생으로서 이 목차를 보고 전체적으로 "도전해 볼 만하다"고 느꼈습니다. 특히 Part 0에서 시작하는 부드러운 도입과, 각 Part마다 구체적인 마일스톤이 있다는 점이 심리적으로 안정감을 줍니다. "피보나치 수열이 내 CPU에서 돌아간다"는 목표는 정말 매력적입니다.

다만 솔직히 말하면, **Ch10~Ch11 구간이 가장 두렵습니다**. 해저드 3종류, 포워딩, 스톨, 분기 예측이 연달아 나오는데, 중간에 숨 쉴 틈이 없어 보입니다. 그리고 **Ch18(예외/인터럽트)**은 이 책에서 가장 생소한 영역이 될 것 같습니다. 파이프라인까지는 "하드웨어 설계"의 연장선이지만, CSR/트랩은 "시스템 소프트웨어와 하드웨어의 경계"라서 완전히 새로운 사고방식이 필요합니다.

**Critical 이슈 3개(C1, C2, C3)를 해결하면** 이 목차는 Verilog 경험 대학원생이 18주 안에 RISC-V 파이프라인 프로세서를 완성할 수 있는 매우 훌륭한 로드맵이 될 것입니다.
