# Appendix D 초보자 독자 평가

## 이해도 종합 평가: ⭐⭐⭐⭐⭐ (5/5)

---

### 강점

1. **D.1 리소스 요약 표가 "프로젝트 예상" 열을 포함한다.** 단순히 전체 리소스 수만 나열하지 않고, 본 교재 프로젝트의 예상 사용량과 사용률을 함께 보여주어, "내 설계가 보드에 들어갈 수 있는가?"를 바로 판단할 수 있다. 이것이 없으면 숫자가 무의미해진다.

2. **D.1의 BRAM 활용 계획 표가 매우 실용적이다.** IMEM 4개, DMEM 4개, I-Cache 1개... 처럼 용도별 BRAM 사용량을 정리하여, 학생이 자신의 설계에서 BRAM 예산을 관리할 수 있다. LUTRAM으로 구현되는 항목(I-Cache Tag, D-Cache Data)을 "0"으로 명시한 것도 좋다.

3. **D.3 핀 배치 표의 XDC 열이 복사-붙여넣기 가능하다.** LED 16개, 스위치 16개, 버튼 5개, 7-세그먼트, UART, 클록까지 모든 핀의 XDC 구문이 그대로 제공되어, 학생이 직접 XDC 파일을 처음부터 작성할 필요가 없다. 이는 초보자에게 큰 진입 장벽 제거 효과가 있다.

4. **D.4 리셋 동기화 설명이 원리부터 제공된다.** "왜 리셋을 동기화해야 하는가?" 소제목 아래에서 메타스태빌리티의 원인(클록 에지 근처 해제 → 셋업/홀드 위반), 결과(불확정 값 전파), 해결책(2단 FF → MTBF > 10^20년)을 단계적으로 설명한다. 초보자가 "왜 이 회로가 필요한가?"를 완전히 이해할 수 있다.

5. **D.4의 FAQ "왜 3단이 아니라 2단인가?"가 좋다.** 학생이 실제로 물어보는 질문이며, MTBF 관점에서 2단이면 충분하다는 근거를 제시하여, 과잉 설계를 방지한다.

6. **D.4 코드가 2개(클록 생성기 + 리셋 동기화기) 모두 완전하다.** `MMCME2_BASE` 인스턴스화와 2단 FF 리셋 동기화기가 모듈 단위로 제공되어, 학생이 자신의 프로젝트에 바로 포함시킬 수 있다. 특히 MMCM의 파라미터 계산(VCO = 100MHz * 10 = 1000MHz, CLKOUT0 = 1000/20 = 50MHz)이 주석으로 명시되어 있다.

7. **D.5 리소스 이력 표가 챕터별 성장 추세를 보여준다.** Ch06(LUT 2,500) → Ch22(LUT 13,000)로 5배 증가하는 추세를 한눈에 파악할 수 있어, 학생이 "내 설계가 갈수록 커지는 게 정상인가?"라는 불안을 해소할 수 있다.

8. **D.3의 핵심 포인트가 액티브 로우 혼동을 경고한다.** "7-세그먼트와 LED의 극성이 다르다(seg=0이면 켜짐 vs led=1이면 켜짐)" — 초보자가 가장 많이 실수하는 부분을 정확히 짚었다.

9. **D.1 핵심 포인트의 전략적 조언이 유용하다.** "병목은 LUT → 메모리는 BRAM으로, 곱셈은 DSP로 매핑하라" — 리소스 최적화의 기본 원칙을 한 줄로 요약했다.

---

### 약점 (개선 제안)

1. **D.1에서 "CLB Slice"의 구성 설명이 비고에만 간략히 있다.** "각 Slice = 4 LUT + 8 FF"라고 되어 있지만, CLB(Configurable Logic Block)와 Slice의 관계(1 CLB = 2 Slice)가 없다.
   - 권장: D.1 본문에 "Artix-7의 기본 논리 단위는 CLB(Configurable Logic Block)이며, 각 CLB는 2개의 Slice로 구성된다. 각 Slice에는 4개의 6-input LUT와 8개의 FF가 포함된다." 1~2줄 추가

2. **D.3에서 XDC 구문을 "어떻게 프로젝트에 적용하는가?"의 절차가 없다.** XDC 구문은 제공되지만, Vivado에서 "Add Sources → Add or Create Constraints → .xdc 파일 추가"하는 절차가 설명되어 있지 않다.
   - 권장: D.3 서두에 "이 표의 XDC 구문을 사용하는 방법: ① Vivado에서 Add Sources → Add or Create Constraints 선택 ② .xdc 파일 생성 ③ 필요한 핀 배치 구문을 복사-붙여넣기 ④ 미사용 핀은 주석 처리" 4단계 안내 추가

3. **D.5 리소스 이력 표의 WNS 열이 모두 빈칸이다.** "합성 후 report_timing_summary에서 확인하여 기입한다"고 안내하지만, 예상값이라도 있으면 학생이 자신의 결과와 비교할 수 있다.
   - 권장: 예상 WNS 값(예: Ch06 ~15ns, Ch12 ~5ns, Ch22 ~0.5ns)을 참고값으로 제공

4. **D.2 보드 블록 다이어그램의 SVG가 유일한 시각 자료인데, 텍스트 보완이 부족하다.** SVG가 로드되지 않으면 보드 구성을 전혀 파악할 수 없다.
   - 권장: SVG 아래에 주요 구성 요소 목록 (FPGA, 100MHz 오실레이터, USB-UART, LED x16, SW x16, BTN x5, 7-SEG x4, PMOD 커넥터) 텍스트로 나열

### 설명 없이 등장하는 용어

- [ ] **CLB (Configurable Logic Block)** — D.1 표에서 "CLB Slices"로 등장. CLB 자체의 정의 없음.
- [ ] **IOB (I/O Block)** — D.1 표에서 사용. FPGA의 I/O 핀 전용 블록이라는 설명 없음.
- [ ] **BUFG (Global Buffer)** — D.1 표에서 사용. 클록 신호를 FPGA 전체에 균일하게 분배하는 전용 버퍼라는 설명 없음.
- [ ] **MMCM** — D.1과 D.4에서 사용. "Mixed-Mode Clock Manager"의 약어이며 PLL의 상위 호환이라는 설명이 없음. D.4 코드에서 MMCME2_BASE로 등장하지만 약어 풀이 없음.
- [ ] **LVCMOS33** — D.3 모든 표에서 "I/O 표준"으로 등장. 3.3V CMOS 신호 레벨이라는 설명이 없음.
- [ ] **MTBF** — D.4에서 "MTBF > 10^20년"으로 사용. Mean Time Between Failures의 약어이나 괄호 설명 없음.

---

### 실용성 평가

- **D.3 핀 배치를 직접 프로젝트에 적용할 수 있는가?** — **가능**. XDC 구문이 그대로 복사 가능하며, IOSTANDARD까지 포함되어 있다. 단, Vivado에서 XDC 파일 추가 절차가 없어 처음 사용하는 학생은 헤맬 수 있다.
- **D.4 클록 회로를 자신의 설계에 포함시킬 수 있는가?** — **가능**. `clk_gen` 모듈과 `rst_sync` 모듈이 완전한 형태로 제공되어, 자신의 top 모듈에서 인스턴스화하면 된다. MMCM 파라미터 계산 과정이 주석에 있어 주파수 변경도 가능하다.

### 최종 판정: ✅ 승인 (개선 권장사항 선택적 적용)

부록 D는 4개 부록 중 가장 완성도가 높다. 리소스 예산 관리(D.1), 핀 배치 XDC(D.3), 클록/리셋 회로(D.4), 리소스 이력(D.5)이 모두 실전에서 바로 사용할 수 있는 수준이다. 특히 D.4의 메타스태빌리티 원리 설명과 D.5의 챕터별 성장 추세가 초보자의 이해와 안심에 크게 기여한다. MMCM/CLB/BUFG 등 FPGA 전용 약어의 풀이를 추가하면 더욱 완벽해질 것이다.
