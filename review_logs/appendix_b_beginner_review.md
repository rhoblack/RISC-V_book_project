# Appendix B 초보자 독자 평가

## 이해도 종합 평가: ⭐⭐⭐⭐ (4/5)

---

### 강점

1. **B.1 합성 가능/불가 분류표가 3단계 색상으로 명확하다.** 합성 가능(초록 O), 조건부(주황 △), 불가(빨강 X) — 한눈에 판별 가능하며, 각 구문의 비고 열이 실용적이다.

2. **B.2 추론 규칙이 코드 패턴과 함께 제공된다.** BRAM/LUTRAM/DSP/SRL 각각에 대해 "이렇게 쓰면 이것이 추론된다"는 코드 예제가 있어, 복사하여 바로 사용할 수 있다. 특히 BRAM(동기 읽기)과 LUTRAM(비동기 읽기)의 차이가 코드 한 줄 차이로 명확히 드러난다.

3. **B.2의 각 추론 조건 표에 "본 교재 사용" 행이 있다.** BRAM은 IMEM/DMEM/I-Cache(Ch05, Ch13), LUTRAM은 레지스터 파일/Tag(Ch04, Ch13, Ch14)처럼 교재 내 실제 사용 사례를 연결하여, "이 추론이 왜 중요한가"를 바로 알 수 있다.

4. **B.3 pragma 표가 10개 속성을 일목요연하게 정리한다.** `ram_style`, `use_dsp`, `keep`, `dont_touch`, `fsm_encoding` 등이 적용 대상/값/효과로 깔끔하게 분류되어 있다.

5. **B.4 XDC 템플릿이 Basys 3 기준으로 바로 사용 가능하다.** 100MHz 오실레이터, 50MHz PLL 분주, I/O 타이밍, false path, multicycle path 등이 주석과 함께 제공되어, XDC 작성 경험이 없는 학생도 복사-붙여넣기로 시작할 수 있다.

6. **B.5 합성 경고/오류 Top 10이 매우 실용적이다.** "Inferring latch", "Multi-driven net", "Timing constraint not met" 등 Vivado 초보자가 가장 자주 만나는 메시지를 원인/해결법과 함께 정리하여, 경고 메시지를 보고 당황하지 않도록 도와준다.

7. **전체 소스 코드 섹션에 4개 완전한 모듈이 제공된다.** `bram_single_port`, `lutram_async_read`, `dsp_multiplier`, `srl_delay` — 각각 독립적으로 합성 가능하며, Vivado에서 추론 결과를 직접 확인할 수 있다.

8. **핵심 포인트 aside가 실무적 경고를 제공한다.** "불완전 분기 시 래치 추론", "`full_case`/`parallel_case`의 시뮬레이션-합성 불일치 위험", "합성 경고를 0건으로 만들라" 등이 학생에게 좋은 습관을 심어준다.

---

### 약점 (개선 제안)

1. **B.2에서 "왜 이렇게 쓰면 BRAM이 추론되는가?"의 원리 설명이 부족하다.** "동기 읽기 필수"라고만 되어 있고, BRAM이 물리적으로 동기 읽기 포트만 가지고 있기 때문이라는 하드웨어 근거가 없다.
   - 권장: "BRAM(Block RAM)은 FPGA 칩 내부에 별도 실리콘 영역으로 배치된 전용 메모리 블록이며, 읽기 포트가 클록 에지에 동기화된 구조이므로 RTL에서도 동기 읽기 패턴을 작성해야 합성기가 BRAM으로 매핑할 수 있다" 한 문장 추가

2. **B.1에서 `always_comb`과 `always @*`의 차이가 언급되지 않는다.** 표에 `always_comb`만 있고 Verilog-2001의 `always @*`는 없다. Verilog 경험이 있는 대상 독자는 이 둘의 차이를 궁금해할 수 있다.
   - 권장: `always_comb` 비고에 "(Verilog-2001의 `always @*`보다 엄격: 불완전 감도 목록 자동 생성, 래치 추론 시 경고)" 추가

3. **B.3에서 `full_case`와 `parallel_case`의 위험성이 핵심 포인트에서만 경고된다.** 표 자체에서는 "모든 경우가 커버됨을 선언"이라고만 되어 있어, 초보자가 무심코 사용할 위험이 있다.
   - 권장: 표의 효과 열에 "(주의: 오용 시 시뮬레이션-합성 불일치)" 경고 문구 추가

4. **B.4 XDC에서 `set_input_delay` / `set_output_delay`의 의미가 불명확하다.** "-max 3.0"이 "외부 디바이스에서 FPGA 핀까지 최대 도착 시간 3.0ns"라는 것은 알겠지만, 왜 이 값이 3.0인지, 어떻게 계산하는지 모른다.
   - 권장: 간략한 설명 추가 — "LED/SW 같은 단순 I/O는 정밀한 타이밍이 불필요하므로, 보수적인 값(3.0ns)을 넣어두면 된다. 외부 고속 인터페이스에서는 데이터시트 기반으로 정확히 계산해야 한다."

5. **B.5 표에서 일부 메시지가 Vivado 정확한 메시지 ID 없이 요약만 되어 있다.** 예: "Inferring latch for signal..."만으로는 Vivado 경고 창에서 검색하기 어렵다.
   - 권장: 가능하면 Vivado 메시지 코드(예: [Synth 8-327]) 추가

6. **전체 소스 코드 섹션에 안심 문구가 없다.** CLAUDE.md에서 요구하는 "지금 당장 전부 이해하지 않아도 됩니다. 각 절 학습 후 참조용으로 활용하세요." 문구가 빠져 있다.
   - 권장: 전체 소스 코드 섹션 시작 부분에 안심 문구 추가

### 설명 없이 등장하는 용어

- [ ] **래치(latch)** — B.1 비고와 B.5에서 반복 사용. "의도하지 않은 래치"가 왜 문제인지는 aside에서 설명하나, 래치 자체의 정의(레벨 감응 저장 소자)가 없음.
- [ ] **추론(inference)** — "BRAM 추론", "DSP 추론" 등 반복 사용. 합성기가 RTL 패턴을 분석하여 FPGA 전용 리소스로 자동 매핑하는 과정이라는 정의가 명시적으로 없음.
- [ ] **SRL** — B.2.4에서 "Shift Register LUT"의 약어로 사용. 소제목에 "(Shift Register LUT)"가 있어 양호하나, SRL16E/SRLC32E 같은 구체 명칭은 설명 없음.
- [ ] **CDC** — B.3 표의 `async_reg` 비고에 "CDC 동기화기"로 등장. B.4 XDC에서도 "CDC 경로" 언급. Clock Domain Crossing의 약어이나 정의 없음.
- [ ] **WNS** — B.5에서 "WNS < 0"으로 등장. Worst Negative Slack의 약어이나 설명 없음. (Appendix D.5에서도 사용)
- [ ] **팬아웃(fanout)** — B.3 `max_fanout` 설명에서 등장. 하나의 출력이 구동하는 입력 수라는 정의 없음.

### 코드 예제 명확성

- 4개 전체 소스 코드(BRAM, LUTRAM, DSP, SRL)는 **복사하여 바로 합성 가능한 수준**이다.
- 각 코드에 한국어 주석이 1줄씩 있으나, 더 상세한 주석(예: 각 포트의 용도)이 있으면 좋겠다.
- `<` → `&lt;`, `>` → `&gt;` HTML 이스케이프가 올바르게 적용되어 있다.

### 최종 판정: ✅ 승인 가능 (개선 권장사항 선택적 적용)

부록 B는 SystemVerilog 합성 레퍼런스로서 매우 실용적이다. 합성 가능/불가 분류표, 추론 코드 패턴, pragma 정리, XDC 템플릿, 경고/오류 대처법이 한 곳에 모여 있어 RTL 코드 작성과 합성 디버깅 시 즉시 참조 가능하다. BRAM 추론 원리 설명, CDC/WNS 용어 정의, 안심 문구 추가를 적용하면 ⭐⭐⭐⭐⭐가 될 수 있다.
