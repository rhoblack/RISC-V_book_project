## 1. 불안 지점 분석 (4가지)

### P1: 신호 암기 부담 (APB 신호 세트)

**구체적 문제**:
- APB는 PSEL, PENABLE, PWRITE, PWDATA, PRDATA, PREADY 등 새로운 신호 세트
- Ch16 AHB (HADDR, HDATA, HWRITE 등)과의 구분 필요
- 초보자: "또 다른 신호를 외워야 한다"는 무력감

**위험도**: 🟡 **중간**

**완화 전략**:
1. **도입부 명시**: "APB는 AHB보다 신호가 훨씬 단순합니다. 핵심 신호는 5개뿐입니다."
2. **비유 활용**: "AHB가 고속도로(6차선, 복잡한 신호)라면, APB는 이면도로(2차선, 간단한 신호)입니다."
3. **비교표 배치**: AHB vs APB 신호 3행 대조 (빠른 이해)
4. **안심 문구**: "산업에서 APB는 가장 흔한 저속 버스입니다. AMBA 표준의 가장 간단한 부분이죠."

**배치 위치**: 17.1 절 도입부 (처음 500자)

---

### P2: FIFO 복잡성 (순환 버퍼 메커니즘)

**구체적 문제**:
- UART FIFO: 쓰기 포인터 vs 읽기 포인터 관리
- "가득 참" 판정: `wr_ptr == rd_ptr && wr_valid` 조건의 직관성 부족
- 초보자: "포인터가 같은데 비어 있다고? 차있다고?" 혼동

**위험도**: 🟡 **중간**

**완화 전략**:
1. **선행 지식 연결**: "Ch14 캐시의 인덱스 포인터와 동일한 개념입니다."
2. **단계별 예제**:
   - Step 1: 초기 상태 (rd_ptr=0, wr_ptr=0, empty)
   - Step 2: 1개 쓰기 후 (rd_ptr=0, wr_ptr=1, 1개 들음)
   - Step 3: 4개 쓰기 후 (rd_ptr=0, wr_ptr=4, 4개 들음)
   - Step 4: 순환 (rd_ptr=2, wr_ptr=6 mod 4 = 2, 가득참? → wr_valid 비트로 판정)
3. **SVG 포함**: 16단계 FIFO 상태 애니메이션 (static SVG로 4개 상태만)
4. **메타인지**: "포인터가 같아도 유효 비트로 구분한다"는 원칙 명시

**배치 위치**: 17.3 절 UART 구현 (FIFO 부분)

---

### P3: 4개 주변장치 동시 구동 복잡성

**구체적 문제**:
- UART + GPIO + Timer + (Interrupt Controller) 동시 작동
- 시뮬레이션 디버깅: 신호 추적 어려움 (waveform 복잡)
- 초보자: "뭔가 안 되는데, 뭐가 문제인지 모르겠어요"

**위험도**: 🔴 **높음** (프로젝트의 마지막 고비 전 최대 불안 지점)

**완화 전략**:
1. **단계별 추가 권고**:
   - Phase 1: UART만 (17.3)
   - Phase 2: UART + GPIO (17.4)
   - Phase 3: UART + GPIO + Timer (17.5)
   - Phase 4: 전체 통합 + SoC 검증 (17.6)
2. **테스트벤치 제공**: 각 단계마다 검증 가능한 TB 코드
3. **디버깅 팁 박스**: "한 주변장치씩 활성화→모두 OFF 후 추가" 권고
4. **실패 정상화**: "모두가 이 단계에서 시간을 씁니다. 정상입니다."

**배치 위치**: 17.6 절 도입부 + 연습문제 섹션

### P4: 인터럽트 신호 처리의 불명확성

**구체적 문제**:
- 초보자가 UART/GPIO/Timer의 인터럽트 신호를 생성하려 함
- 하지만 Ch17에서는 신호만 생성, 처리는 Ch19 (예외 처리)에서
- 초보자: "신호를 만들었는데, 왜 처리가 안 되지?" 혼동

**위험도**: 🟡 **중간**

**완화 전략**:
1. **명확한 경계선**: "Ch17은 신호 생성까지만 합니다. 처리는 Ch19 (예외 처리)에서 배웁니다."
2. **FAQ 박스 추가**: "Q: 인터럽트를 처리하려면? A: 지금은 신호만 확인하세요. Ch19에서 처리합니다."
3. **비유**: "신호는 '전화벨'이고, 처리는 '전화받기'입니다. 지금은 벨만 만듭니다."
4. **안심 문구**: "이것은 정상 설계 흐름입니다. 모든 SoC가 인터럽트 생성과 처리를 분리합니다."

**배치 위치**: 17.5 절 Timer (인터럽트 신호 언급 시) + 종합 FAQ

## 3. 자기효능감 강화 전략

### 3.1 첫 성공 보장 (초반 성공 원칙)

**Goal**: 17.3 UART 송신 → 실제 PC에서 "Hello" 수신

**구현**:
1. **최소 코드 예제**: UART만 동작하는 top 모듈 제공
2. **시뮬레이션 재현**: 하드웨어 SIM → waveform에서 신호 확인
3. **PC 수신 검증**: minicom/Tera Term 캡처 이미지 제공 (or 의사 코드)
4. **성취감 명시**: "축하합니다! 당신은 UART를 통해 처음 통신했습니다."

**심리 효과**:
- Bandura의 자기효능감 이론: 실제 성공 경험 = 가장 강력한 동기 강화
- 이후 GPIO/Timer/통합 도전에 자신감 전이

### 3.2 누적 경험 설계

**경험 흐름**:
```
Ch16 (AHB Master/Slave FSM)
  ↓ [신뢰도 ⭐⭐⭐⭐⭐]
Ch17 (APB FSM + 3개 주변장치)
  ↓ [자신감 누적]
Ch20~22 (전체 SoC 통합 + FPGA 구현)
```

**설계**:
- 17.2 FSM: "Ch16 Master FSM 설계와 동일한 프로세스입니다." 명시
- 17.6 통합: "3개를 동시에 제어했다면, 당신은 이미 Vivado 엔지니어입니다."

### 3.3 시각적 피드백

**각 단계별 확인 가능한 아웃풋**:
- 17.3 UART: PC 모니터에 "Hello" 출력 (청각/시각 피드백)
- 17.4 GPIO: LED 켜기/끄기 (육안 확인 가능)
- 17.5 Timer: LED 깜빡임 (시간 경과의 가시화)
- 17.6 통합: 모든 주변장치가 예측 가능하게 동작

**효과**:
- Immediate feedback = 학습 동기 증폭
- 디버깅 용이성 = 좌절감 감소

## 4. 심리적 안전성 설계

### 4.1 안심 문구 배치 (6가지)

#### 17.1 절 도입부 (APB 신호 소개)
```
"AMBA 버스 설계는 두 단계입니다.
 첫 번째는 고속 AHB (Ch16 완료),
 두 번째는 저속 APB입니다.

 APB는 AHB보다 신호가 훨씬 간단합니다.
 핵심 신호는 단 5개입니다:
 PSEL, PENABLE, PWRITE, PWDATA, PRDATA.

 비유하자면, AHB는 고속도로의 신호등(복잡)이고,
 APB는 이면도로의 신호등(간단)입니다.

 당신은 이미 고속도로를 설계했습니다.
 이면도로는 훨씬 쉬울 거예요."
```

#### 17.2 절 도입부 (APB FSM)
```
"FSM은 Ch16에서 Master FSM으로 충분히 배웠습니다.
 APB FSM은 더 간단합니다.
 상태는 단 3개: IDLE → SETUP → ACCESS.

 설계 프로세스도 동일합니다:
 1. 상태 정의
 2. 신호 정의
 3. 전이 조건
 4. 출력 로직

 당신은 이미 전문가입니다."
```

#### 17.3 절 도입부 (UART 구현)
```
"UART는 모든 마이크로컨트롤러와 FPGA의 표준 인터페이스입니다.
 산업에서 가장 흔한 통신 프로토콜이죠.

 이 절에서는 처음으로 '실제 데이터'를 주고받습니다.
 PC의 터미널에 직접 메시지를 띄울 수 있어요.

 FIFO 부분이 조금 복잡해 보이지만,
 Ch14 캐시의 인덱스 포인터와 정확히 동일한 개념입니다.

 단계별로 차근차근 따라가시면,
 당신도 UART를 완전히 이해할 수 있습니다."
```

#### 17.4 절 도입부 (GPIO)
```
"GPIO는 가장 간단한 주변장치입니다.
 기본은 단순합니다:
 입력 레지스터 (32비트, 각 비트 = 1개 핀)
 출력 레지스터 (32비트, 각 비트 = 1개 핀)
 방향 레지스터 (1=출력, 0=입력)

 LED를 켰다, 껐다 하면서 즉시 결과를 확인할 수 있어요.
 디버깅도 가장 쉽습니다."
```

#### 17.5 절 도입부 (Timer)
```
"Timer는 '카운터 + 비교기'입니다.
 복잡해 보이지만, 이전에 배운 ALU의 비교부(>/<) 기능과 동일합니다.

 타이머는 3가지 주요 동작을 합니다:
 1. 카운트 (매사이클 1씩 증가 또는 감소)
 2. 비교 (설정값과 비교)
 3. 인터럽트 신호 생성 (조건 만족 시)

 신호 생성은 이 절에서, 처리는 Ch19에서 배웁니다.
 당신은 신호만 확인하면 됩니다."
```

#### 17.6 절 도입부 (통합)
```
"축하합니다! 이제 4개의 주변장치를 모두 설계했습니다.

 지금부터 17.6절에서는 이 4개를 하나의 SoC에 통합합니다.
 복잡해 보일 수 있지만,
 각 주변장치는 독립적으로 동작합니다.
 당신은 각각을 이미 검증했으니까요.

 통합 과정을 단계별로 진행합니다:
 1단계: UART만 활성화 (기준선)
 2단계: GPIO 추가 (신호 추적 간단히)
 3단계: Timer 추가
 4단계: 모두 함께 검증

 한 단계씩 진행하면,
 문제가 생겨도 원인을 쉽게 찾을 수 있습니다.

 이 과정을 완료하면, 당신은 SoC 설계자입니다!"
```

### 4.2 실패 정상화 (5가지 예상 문제점)

**각 문제점에 대한 정상화 문구**:

#### 실패 1: UART 데이터가 안 받아져요
```
"FIFO 문제가 95% 확률입니다. 정상입니다.

 디버깅 단계:
 1. FIFO 쓰기 신호 확인: wr_en = 1?
 2. 읽기 포인터 확인: rd_ptr이 증가하나?
 3. UART TX 신호 확인: txd 신호가 변하나?

 모두 정상이면, 클록 분주기(baud rate)를 확인하세요.

 참고: 모든 엔지니어가 첫 UART에서 시간을 씁니다.
 당신만 아닙니다."
```

#### 실패 2: GPIO가 안 켜져요
```
"방향 레지스터를 놓치는 경우가 매우 흔습니다.
 FPGA 보드 핀을 출력 모드로 설정했나요?

 확인 사항:
 1. gpio_dir 레지스터에서 해당 비트가 1인가? (출력 모드)
 2. gpio_out 레지스터에서 해당 비트가 1인가? (HIGH)
 3. 보드의 LED 연결은 맞는가?

 특히 1번이 가장 자주 잘못됩니다.
 이것은 학습 과정입니다. 정상입니다."
```

#### 실패 3: Timer 인터럽트가 안 나와요
```
"정상입니다. Ch17에서는 신호 생성만 합니다.

 확인 사항:
 1. Timer CNT가 증가하나? (타임베이스 생성 확인)
 2. CNT = CMP가 되는 순간, intr_out 신호가 1이 되나?
 3. 신호는 몇 사이클 동안 유지되나?

 이것은 Ch19에서 배우는 '예외 처리'가 필요합니다.
 지금은 신호 생성만 확인하세요.

 생성된 신호가 정상이면, 당신의 Timer는 완벽합니다."
```

#### 실패 4: 4개가 동시에 안 돌아요
```
"이 상태는 모든 초보 SoC 설계자가 겪습니다.
 정상입니다.

 해결 전략:
 1. 한 주변장치만 활성화 (나머지는 클록 OFF)
 2. 정상 동작 확인
 3. 다음 주변장치 추가
 4. 신호 충돌 확인
 5. 중재기 업데이트

 급하게 4개를 동시에 디버깅하지 마세요.
 차근차근 추가하는 것이 전문가의 방법입니다."
```

#### 실패 5: 시뮬레이션 waveform이 너무 복잡해요
```
"신호 수가 증가했으니 당연합니다.

 디버깅 팁:
 1. 관심 신호만 선택해서 추적하세요 (Vivado: 4~5개 신호)
 2. 시간 단위를 조정하세요 (마이크로초 → 밀리초)
 3. Zoom in/out으로 특정 구간 분석

 Vivado (또는 VCS) 마스터는 이것을 잘 압니다.
 당신도 곧 할 수 있게 될 거예요."
```

**각 절 마지막에 배치할 자가 점검 질문**:

### 17.1 절 (APB 신호)
```
🔍 메타인지 점검:

1. AHB와 APB의 핵심 차이 3가지를 설명할 수 있는가?
   (힌트: 속도, 신호 수, 사용 목적)

   PSEL, PENABLE, PWRITE, PWDATA, PRDATA

3. PENABLE 신호는 언제 1이 되는가?
   (힌트: PSEL이 1인 상태에서, SETUP 단계 완료 후)

확인: 3개 모두 설명할 수 있다면, ✅ 다음 절로 진행
      1개라도 불명확하면, 다시 읽어보세요.
```

### 17.2 절 (APB FSM)
```
🔍 메타인지 점검:

1. APB Slave FSM의 3가지 상태를 그릴 수 있는가?
   IDLE → SETUP → ACCESS (→ IDLE)

2. PSEL 신호를 어느 상태에서 검사하는가?
   (힌트: IDLE 상태에서)

3. PREADY 신호는 어느 상태에서 생성되는가?

확인: 3개 모두 답변할 수 있으면, ✅ UART 구현 준비 완료
```

   (rd_en = 1이고, FIFO가 비어있지 않을 때)

## 6. 의도적 실패 설계 (Challenge Zone)

### 목표
- Vygotsky의 "근접 발달 영역(ZPD)" 활용
- 독립적 해결 가능 + 약간의 도움으로 해결 가능한 수준의 과제

### 과제 1: FIFO 오버플로우 처리 (17.3)
**문제**:
```
FIFO가 가득 찬 상태에서도 wr_en = 1이 들어온다면?
- wr_ptr이 오버플로우(순환)되나?
- 기존 데이터가 손실되나?
```

**도움 수준** (단계적 힌트):
1. 레벨 1 (약간): "가득 차면 wr_en을 무시하는 코드를 찾아보세요."
2. 레벨 2 (중간): "FIFO 크기는 DEPTH 파라미터. 포인터는 [log2(DEPTH)-1:0]로 자동 순환."
3. 레벨 3 (상세): "16-entry FIFO라면, wr_ptr[3:0]이 15→0으로 자동 순환."

### 과제 2: GPIO 입출력 충돌 (17.4)
**문제**:
```
같은 핀을 입력과 출력으로 동시에 설정하면?
- gpio_dir[0] = 1 (출력)인데, gpio_out[0]과 gpio_in[0]의 관계는?
```

**도움 수준**:
1. 레벨 1: "입출력 모드 설정 로직을 찾아보세요."
2. 레벨 2: "출력 모드면 외부 입력을 무시하고, 자신의 출력값만 반영."
3. 레벨 3: "실제 핀 드라이버는 삼중상태 버퍼(tri-state)로 구현."

### 과제 3: Timer 주기 변경의 타이밍 (17.5)
**문제**:
```
Timer가 실행 중일 때, CMP 값을 런타임에 변경하면?
- 현재 사이클의 CNT와 비교하는가?
- 다음 사이클부터 적용되는가?
```

**도움 수준**:
1. 레벨 1: "CMP 업데이트 신호의 타이밍을 waveform에서 확인해보세요."
2. 레벨 2: "APB 쓰기가 완료된 후, 다음 사이클부터 새로운 CMP가 적용."
3. 레벨 3: "Vivado에서 waveform zoom in → 정확히 언제 비교가 이루어지는지 확인."
