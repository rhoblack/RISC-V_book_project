### 19.3 비동기 인터럽트 처리

| 항목 | 평가 | 상태 |
|------|------|------|
| 3단 마스킹 비유 | ⭐⭐⭐⭐⭐ | ✅ 탁월 |
| 세 인터럽트 종류 | ⭐⭐⭐⭐ | ✅ 명확 |
| mcause bit31 의미 | ⭐⭐⭐⭐ | ✅ 명확 |
| SystemVerilog 코드 | ⭐⭐⭐ | ⚠️ 복습필요 |
| 우선순위 인코더 | ⭐⭐ | 🔴 막힘 |
| **섹션 종합** | **⭐⭐⭐** | **주의** |

**강점:**
- 회사 내선전화 비유가 매우 효과적 (3단 AND → 명확)
- 표가 체계적 (mip/mie 비트, mcause, 우선순위)
- 인터럽트 순서가 반복되어 외워짐

**개선 의견 (🔴 중요):**
- **우선순위 인코더 로직 설명 미흡**:
  - if-else 구조가 MEI를 최우선으로 만드는 원리 명확화 필요
  - 제안: "첫 번째 조건부터 검사하므로, MEI를 맨 위에 배치 → mei_pending=1이면 다른 인터럽트 무관하게 MEI 선택"
- mip 레지스터 업데이트 경로가 불명확 (Ch18 참조로만 설명)

### 19.4 트랩 진입/복귀 메커니즘

| 항목 | 평가 | 상태 |
|------|------|------|
| 비행기 비유 | ⭐⭐⭐⭐⭐ | ✅ 탁월 |
| 5단계 시퀀스 명확도 | ⭐⭐⭐⭐ | ✅ 좋음 |
| SVG 도움도 | ⭐⭐⭐⭐ | ✅ 필수 |
| FSM 상태 이해 | ⭐⭐⭐ | ✅ 따라갈수있음 |
| MRET 복귀 설명 | ⭐⭐⭐⭐ | ✅ 명확 |
| MPIE 개념 | ⭐⭐⭐ | ⚠️ 복습필요 |
| **섹션 종합** | **⭐⭐⭐⭐** | **OK** |

**강점:**
- 비행기 비유: 블랙박스(CSR), 자동조종(MIE) → 직관 명확
- 5단계 순서가 체계적
- MRET과 MPIE 관계가 역순으로 잘 설명됨

**개선 의견:**
- MPIE 역할이 초보자에게 처음에는 이상할 수 있음
  - 제안: "중첩 인터럽트 방지: 트랩 진입 시 MIE ← 0으로 차단, MRET에서 MPIE 복원"
- CSR 단일 포트 제약이 FSM 4사이클 사용 원인 → "한 사이클에 모든 CSR을 동시 쓸 수 없음" 명시

### 19.5 파이프라인과 예외 처리 통합

| 항목 | 평가 | 상태 |
|------|------|------|
| 도미노 비유 | ⭐⭐⭐⭐⭐ | ✅ 탁월 |
| 정확한 예외 개념 | ⭐⭐⭐ | ⚠️ 보강필요 |
| 파이프라인 스냅샷 분석 | ⭐⭐⭐ | ⚠️ 복습필요 |
| MEM > EX > ID 우선순위 | ⭐⭐⭐ | ⚠️ 이해필요 |
| 공항 검색대 비유 | ⭐⭐⭐⭐ | ✅ 좋음 |
| CSR 해저드 설명 | ⭐⭐ | 🔴 어려움 |
| 플러시 신호 병합 | ⭐⭐⭐ | ✅ 따라갈수있음 |
| 디버깅 가이드 | ⭐⭐⭐⭐ | ✅ 실용적 |
| **섹션 종합** | **⭐⭐** | **🔴 심화 학습 필요** |

**강점:**
- 도미노 비유: "이미 쓰러진(완료) vs 아직 쓰러지지 않은(미완료)" → 정확한 예외 직관 명확
- 그림 19.5가 파이프라인 상태를 시각적으로 잘 표현
- 4단계 디버깅 체크리스트가 실무적

**개선 의견 (🔴 중요):**
- **"정확한 예외" 정의가 추상적**: "프로그램 순서상 예외 명령어 이전 모든 명령어는 완료, 이후는 취소"로 명시 필요
- **"In-Order 파이프라인에서 정확한 예외 가능한 이유" 불명확**:
  - 현재: "ALU 연산 자체는 부작용이 없음"
  - 초보자 관점: "부작용"의 의미가 추상적
  - 제안: "EX 명령어를 플러시해도, ALU 결과는 아직 **어디에도 기록되지 않았으므로** 영향 없음. 부작용은 메모리/레지스터 쓰기 → WB에서만"
- **MEM > EX > ID 우선순위 이해 어려움**: 파이프라인 타임라인 예제 필요
  ```
  사이클 N: IF: D / ID: C / EX: B / MEM: A
  프로그램 순서: A(가장 먼저) → B → C → D(가장 최신)
  따라서 A의 예외가 최우선
  ```
- **CSR 해저드**: "범용 레지스터와 CSR의 포워딩 경로가 다르다"는 설명 필요
