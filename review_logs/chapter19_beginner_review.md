## 1. 절별 이해도 평가

### 19.1 파이프라인 구조 핵심 복습 — ⭐⭐⭐⭐⭐

- Ch09~12에서 배운 내용의 복습이라 매우 편안하게 읽힘
- 5단계 파이프라인 표가 간결하고 명확
- 플러시/스톨의 두 가지 메커니즘을 짧게 정리한 것이 효과적
- **"예외 처리는 본질적으로 새로운 종류의 플러시"** — 이 한 문장이 19장 전체의 불안을 크게 줄여줌
- Ch18 CSR 6개를 표로 다시 보여준 것도 좋음
- Ch17 타이머/UART의 `timer_irq`→`mip.MTIP`, UART→`mip.MEIP` 연결이 명확
- FAQ(분기 플러시 vs 예외 플러시)가 핵심 차이를 간결하게 설명
- 메타인지 박스의 빈칸 채우기가 복습으로 적절

### 19.2 동기 예외 처리 — ⭐⭐⭐⭐

- "동기 예외"가 처음 등장하지만, Python `try-except` 비유가 즉시 이해를 도움
- 비유의 한계("스택 추적 없이 mtvec로 점프")도 명시되어 오해 방지
- 3종 예외 표(Illegal Instruction, Misaligned, ECALL)가 깔끔. **"3가지만 구현하면 된다"** 안심 문구 효과적
- ID/EX 스테이지별 감지 코드: 주석이 한글로 충분히 달려 있어 따라가기 쉬움
- EX 스테이지 `case(ex_funct3[1:0])` 구조가 Word/Halfword/Byte 구분에 명확

**예외 태깅 부분이 핵심 난관:**
- "예외 정보를 WB까지 전파"하는 개념이 처음이라 한 번 읽어서는 완전히 와닿지 않음
- 다만 "왜 즉시 처리하지 않는가?" 설명과 "19.5절에서 자세히 다룹니다" 예고가 있어 불안하지는 않음
- 파이프라인 레지스터 태깅 코드(ID/EX→EX/MEM 전파)가 두 블록으로 나뉘어 있는데, "같은 명령어에서 나중 스테이지 예외가 우선"이라는 규칙을 코드 앞에 한 줄로 요약하면 더 좋겠음

- 면접 포인트(동기 vs 비동기 차이)가 간결하게 정리
- "4사이클 안에 처리 완료" 문구가 안심을 줌

### 19.3 비동기 인터럽트 처리 — ⭐⭐⭐⭐

- "인터럽트는 예외와 거의 같은 메커니즘" — 도입부의 안심 문구 효과적
- 전화 비유가 직관적: "현재 통화 마무리 → 긴급 전화 → 원래 복귀", mepc="어디까지 얘기했는지", MRET="원래 통화로 돌아가기"
- 한계("프로세서는 인터럽트를 거절할 수 있다, 우선순위 인코더가 하나만 선택")도 명시

- 3가지 인터럽트 소스 표(MEI, MSI, MTI)는 명확. mcause가 `0x8000_000B` 형태인데 괄호 안 (11), (3), (7)이 있어서 이해 가능
- **3중 게이트** 개념: `irq_pending[N] = mip[N] & mie[N] & mstatus.MIE` 논리식이 간결
- 우선순위 인코더(`interrupt_controller` 모듈): 독립 모듈로 제시되어 구조 명확. if-else 체인으로 MEI>MSI>MTI 순서가 코드에서 바로 보임
- **명령어 경계(instruction boundary)** 개념: WB 완료 후에 인터럽트를 수락한다는 설명이 명확
- mepc 저장 규칙(예외=해당 PC, 인터럽트=다음 PC) 차이가 잘 구분됨
- FAQ(MIE=0일 때 Pending은 유지, 나중에 MIE=1이면 처리)가 실용적

### 19.4 트랩 진입/복귀 메커니즘 — ⭐⭐⭐⭐

- 블랙박스(Flight Data Recorder) 비유: CSR이 PC/원인/상태를 자동 기록 → 직관적
- 한계("블랙박스는 분석용, CSR은 실시간 처리용")도 명시

- **트랩 진입 6단계**가 번호 리스트로 명확하게 정리. 하드웨어 코드가 6단계와 1:1 대응
- MRET 복귀 3단계도 "진입의 역순"이라는 설명이 직관적
- `csr_mstatus[7] <= csr_mstatus[3]` (MPIE←MIE) 등 비트 위치가 코드에 직접 나오는데, 주석이 있어서 따라갈 수 있음

**트랩 핸들러 어셈블리 예제:**
- RISC-V 어셈블리로 보는 것은 처음이라 약간 당황
- 하지만 한글 주석이 잘 달려 있어 흐름 파악 가능
- `csrr a0, mcause` → `bltz a0, handle_interrupt` → 원인별 분기 → `mret` 복귀 흐름이 체계적
- ECALL 핸들러에서 mepc+4 하는 이유가 실무 팁으로 설명됨

- mstatus.MPP 첫 등장 시 "Machine Previous Privilege"의 약어 풀이가 없음 → 추가 필요

### 19.5 파이프라인과 예외 처리 통합 — ⭐⭐⭐

- **이 절이 가장 어려움**. "최고 난이도 구간"이라는 예고가 있어 심리적 준비는 됨
- "각 부품은 이미 배웠습니다. 신호 흐름만 추적하면 됩니다" — 안심 문구 효과적
- "새로운 개념이 4개뿐" — 인지 부하 예고도 좋음

**정확한 예외(Precise Exception):**
- 두 조건(이전 명령어 완료, 이후 명령어 취소)이 명확하게 정의됨
- 영화 촬영 비유("컷!": 이전 촬영분은 유효, 이후는 폐기)가 직관적
- 한계("물리적 삭제가 아니라 valid 비트를 끄는 논리적 취소")도 명시
- 그림 19.5의 초록(완료)/빨강(플러시) 색상 코딩이 핵심 이해를 도움

**WB 스테이지 커밋 방식:**
- 19.2절 예외 태깅과 연결: "아, 그래서 WB까지 보내는 거구나" 이해됨
- 투기적 명령어의 예외가 자연스럽게 무시된다는 설명이 좋음

**통합 플러시 로직:**
- `trap_flush > branch_flush` 우선순위가 코드에서 바로 보임
- `next_pc` 선택 로직(삼항 연산자 체인)이 간결

**CSR 해저드 부분이 가장 난해:**
- "CSR 쓰기 명령어가 WB에 있으면 인터럽트 샘플링을 1사이클 지연"이라는 규칙은 이해했음
- 그러나 **왜 이것이 필요한지**의 구체적 타이밍 시나리오가 텍스트로만 설명되어 직관이 부족
- 사이클별 파이프라인 상태 예시(표 또는 타이밍 다이어그램)가 있었으면 훨씬 이해하기 쉬웠을 것

- 면접 포인트 2개(정확한 예외 정의, 동시 예외 처리)가 핵심을 잘 요약

### 19.6 예외/인터럽트 테스트벤치 — ⭐⭐⭐⭐

- 4가지 시나리오가 난이도 순(★☆☆☆☆→★★★★☆)으로 배치 → 점진적
- **시나리오 1(ECALL)**: 가장 단순. `assert(mepc==0x04)`, `assert(mcause==11)` 검증이 명확 → 첫 성공 경험
- **시나리오 2(Load Misaligned)**: 19.2절 addr[1:0]!=00 조건과 직접 대응
- **시나리오 3(Timer Interrupt)**: mie/mstatus 설정 필요 → 19.3절 3중 게이트와 대응. `mcause==0x80000007` 검증 명확
- **시나리오 4(CSR Hazard)**: 19.5절의 CSR 해저드 개념의 코드 구현이지만, assert 문이 없고 `$display`만 있어서 "정말 올바르게 동작하는 건지" 확인이 어려움
- 강사 꿀팁("시나리오 1 먼저 성공시키라")이 심리적으로 도움

### 19.7 본 장 요약 및 다음 단계 — ⭐⭐⭐⭐⭐

- Part 7 통합 조감도 표(Ch16~19 역할/산출물)가 한눈에 정리
- "Ch17 타이머 → mip.MTIP → 인터럽트 컨트롤러 → 트랩 → mtvec 점프" 신호 흐름이 한 문장으로 연결
- Part 8(FPGA 구현) 예고가 성취감과 기대감을 동시에 줌
- 메타인지 박스가 Part 7 전체를 복습하게 해줌
- 핵심 정리 5개 항목이 간결하고 명확

## 6. 상세 피드백

### 특히 이해하기 쉬웠던 부분
1. **19.1절 전체**: "예외 = 새로운 종류의 플러시"라는 프레이밍이 불안을 줄여줌
2. **19.2절 "3가지만 구현"**: 인지 부하를 확실히 관리. "나머지는 같은 메커니즘의 반복"이 안심
3. **19.3절 3중 게이트**: 논리식이 간결하고 SVG가 시각적으로 보강
4. **19.4절 트랩 6단계**: 번호 리스트 → 코드 → SVG의 3중 설명이 효과적
5. **19.7절 통합 조감도**: 4개 챕터를 한 표로 정리하고 신호 흐름을 한 문장으로 연결

### 어려웠던 / 막혔던 부분
1. **19.2절 예외 태깅 전파 코드**: "같은 명령어의 다른 스테이지 예외"와 "이전 스테이지에서 전파된 예외"의 우선순위가 헷갈림
2. **19.5절 CSR 해저드**: 텍스트만으로는 구체적 시나리오가 직관적이지 않음
3. **19.4절 어셈블리 핸들러**: RISC-V 어셈블리 형태가 처음이라 약간 당황 (한글 주석으로 극복 가능)
4. **전체 소스 trap_controller.sv**: mstatus 비트 조작에서 비트 번호를 직접 계산해야 함

## 8. 종합 의견

Ch19는 예외/인터럽트라는 어려운 주제를 다루지만, **"이미 아는 것의 확장"**이라는 프레이밍과 단계적 구성(복습→동기→비동기→트랩→통합→검증→정리)이 매우 효과적입니다.

**강점:**
- 19.1절의 복습으로 자신감 확보 → "예외 = 새로운 종류의 플러시"
- "3가지 예외만 구현" 안심 문구로 인지 부하 관리
- 비유 4개(try-except, 전화, 블랙박스, 영화 촬영) 모두 적절하고 한계 명시
- SVG 5개 모두 효과적, 특히 그림 19.3(3중 게이트)과 19.5(정확한 예외)가 결정적
- 메타인지 박스 7개가 적절한 위치에 배치
- 연습문제 5개가 L2~L4 난이도 분포로 단계적

**개선 필요:**
- 19.5절 CSR 해저드에 구체적 타이밍 예시 추가 (🔴 B3)
- 용어 정의 보강: 커밋, MPP, 직교적 (🟡 B1, B2, B5)
- 시나리오 4 테스트의 assert 보강 (🟡 B4)

**결론: ✅ 합격 (전체 ⭐⭐⭐⭐, 모든 절 ⭐⭐⭐ 이상)**

B3(CSR 해저드 타이밍 예시)가 반영되면 19.5절이 ⭐⭐⭐⭐로 올라갈 수 있습니다.
