- 병렬화 vs 순차화

**영향**:
- 인지 부하 ⬆️ (학습자 피로)
- 5개를 동시 비교하기 어려움
- 각 기법의 깊이 부족 가능성

## 권장 해결안 (3가지 옵션)

### Option A: 21.5 분할 (강력 권장 ⭐⭐⭐)

**목표**: 인지 부하 분산 + 각 기법 깊이 추가

**구조**:
- **21.5A**: DVFS + Clock Gating (2개 개념, 구현 중점)
  - DVFS: 전압 조정 원리 + 구현 (레귤레이터 제어)
  - Clock Gating: 회로도 + 타이밍 검증
  - 시뮬레이션 결과 비교

- **21.5B**: 메모리 + 파이프라인 + 병렬화 (3개 개념, 아키텍처 선택)
  - 메모리: BRAM vs LUTRAM vs Distributed (표 비교)
  - 파이프라인: 깊이 vs CPI (그래프)
  - 병렬화: 32비트 곱셈 사례 확장

**장점**:
- 각 섹션 신규 개념 ≤ 3 ✅
- 각 기법에 충분한 설명 공간
- 학습자 부하 분산
- 자연스러운 흐름 (회로 레벨 → 아키텍처 레벨)

**단점**: 섹션 수 증가 (8 → 9)

### Option B: 21.5 축약 (약한 권장 ⭐⭐)

**목표**: 신규 개념 4개로 감소

**방식**: "병렬화" 내용 축약

**구조**:

  - 면적/전력 트레이드오프만 언급
  - 깊이 있는 예제 제거

**장점**:
- 섹션 수 유지
- 빠른 구현

**단점**:
- 병렬화 개념 박약
- 학습자가 실제 선택에 어려움
- 고급 아키텍처 설계 준비 부족
