## 2. 불안 해소 전략 평가

### "AMBA 새 도메인" 진입 불안 해소 — "Ch15 교체" 프레이밍

**매우 효과적으로 구현됨** (강점).

- 16.1절 첫 단락에서 "Ch15의 `mem_req`/`mem_ack`/`mem_addr`을 AHB-Lite로 교체"라는 프레임이 명시적으로 제시됨.
- 16.2절의 "Ch15 자체 프로토콜 vs AHB-Lite 신호 대응 관계" 표가 특히 탁월함. 학생이 이미 알고 있는 `mem_req`, `mem_addr`, `mem_we`, `mem_rdata`, `mem_ready` 각각에 대응하는 AHB 신호를 1:1로 보여줌으로써, 완전히 새로운 영역이 아니라 "친숙한 개념의 표준화"임을 체감하게 한다.
- "완전히 새로운 개념이 아니라 친숙한 개념의 표준화임을 이해할 수 있습니다"라는 직접적 안심 문구가 16.2절에 포함됨.

**결론**: 불안 해소 전략 ✅ 매우 효과적.

## 3. 첫 실습 성공 설계 평가

**양호하나 개선 여지 있음**.

첫 번째 직접 해보기는 16.3절 메타인지 박스의 "빈칸 채우기 — 타이밍 다이어그램 연습"이다. 질문 3개는 적절히 쉽고, `<details>` 정답 확인 장치가 있어 스스로 확인 가능하다.

그러나 **첫 코드 작성 실습(16.5절 FSM 구현)**은 완성된 코드를 제시하는 방식으로, 학생이 직접 타이핑하여 실행해 보는 유도가 명시적으로 없다. "이 코드를 복사하여 Vivado에서 실행해 보십시오. 시뮬레이션 로그에 `[PASS]`가 나타나면 성공입니다"와 같은 안내 문구가 16.8절 앞부분에 있었으면 성취감 유도가 더 강화되었을 것이다.

**개선 필요 항목 P1**: 16.8절 시작 부분에 "지금까지 설계한 코드를 그대로 실행하면 반드시 다음 출력이 나타납니다"라는 성공 예상 출력 예시를 추가할 것을 권장한다.

## 4. 실패 정상화 평가

**부분적 구현 — 강화 필요**.

현재 원고에는 다음과 같은 실패 정상화 요소가 있다:
- 16.4절 FAQ 박스: "HREADY 관련 가장 흔한 오류들" 체크리스트 (❌ 항목 4개 + ✅ 1개)
- 16.5절 tip 박스: "AHB에서 가장 흔한 설계 오류는 HWDATA를 M_ADDR 상태에서 구동하는 것"

그러나 "HREADY 타이밍 오류는 모두가 겪는다"류의 **명시적 정상화 문구**가 없다. "이 오류를 겪었다면 AHB를 진지하게 학습하고 있다는 증거"와 같은 감정 인정 문구가 필요하다.

**개선 필요 항목 P2**: 16.4절 FAQ 박스 또는 16.5절 tip 박스에 "HWDATA 타이밍 오류와 HREADY 처리 실수는 AHB를 처음 구현하는 모든 설계자가 반드시 한 번씩 겪는 과정입니다. 이 체크리스트에서 자신이 놓친 항목을 발견했다면, 그것은 학습이 깊어지고 있다는 신호입니다"와 같은 정상화 문구를 추가할 것.

## 6. 자기효능감 평가

**전반적으로 양호**, 다음 설계가 특히 효과적이다:

- "Cortex-M 시리즈 마이크로컨트롤러의 내부 버스가 바로 이 AHB-Lite입니다. 우리의 RV32I 파이프라인 코어도 이 표준을 채택함으로써 실제 SoC 설계와 동일한 구조를 갖추게 됩니다" — 산업 수준의 설계를 한다는 자기효능감 강화.
- 16.8절에서 `[PASS] 읽기 데이터 일치: 0xDEAD_BEEF` 출력이 나오는 성공 시나리오 설계가 성취감을 유발한다.
- Ch17 예고("Hello, RISC-V!")가 다음 단계 동기를 자연스럽게 유발한다.

**소폭 개선 가능 항목 P3**: 16.1절에서 "이 챕터를 마치면 여러분의 RISC-V 코어는 Cortex-M 급 SoC 구조를 갖추게 됩니다"와 같이 학습 목표 달성 후의 구체적 위상을 명시하면 자기효능감이 더욱 강화된다.
