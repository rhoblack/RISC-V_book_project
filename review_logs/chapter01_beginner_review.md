## 설명 없이 등장하는 용어 목록

| 용어 | 최초 등장 위치 | 필요한 설명 |
|------|---------------|-------------|
| ISA (Instruction Set Architecture) | 1.1절 첫 문단 | 한글 병기("명령어 집합 구조")는 되어 있으나, ISA가 구체적으로 무엇을 정의하는지(명령어 형식, 레지스터 수, 주소 공간 등) 한 문장 정도의 부연이 있으면 좋겠다. Verilog만 다뤄본 학생에게 ISA는 낯선 개념일 수 있다. |
| SoC (System on Chip) | 1.1절 | 한글 병기("시스템 온 칩")는 되어 있으나, 프로세서 코어와 SoC의 차이를 Verilog 학생 수준에서 설명하면 좋겠다. |
| 데이터 포워딩 (Data Forwarding) | 1.1절 SoC 구성 요소 목록 | 해저드 처리 유닛의 하위 개념으로 등장하는데, 이 시점에서는 해저드 자체의 개념도 설명되지 않았다. |
| 스톨 (Stall) | 1.1절 SoC 구성 요소 목록 | 파이프라인 문맥 없이 등장하여 의미를 유추하기 어렵다. |
| 분기 예측 (Branch Prediction) | 1.1절 SoC 구성 요소 목록 | 프로세서 개념을 처음 접하는 독자에게는 생소하다. |
| AMBA AHB-Lite, APB | 1.1절 SoC 구성 요소 목록 | 버스 프로토콜 이름만 나열되어 있으며, AHB와 APB가 무엇의 약자인지, 왜 두 가지가 필요한지 설명이 없다. |
| CSR 레지스터 | 1.1절 SoC 구성 요소 목록 | CSR이 무엇의 약자인지(Control and Status Register) 병기가 누락되어 있다. |
| 트랩 핸들러 (Trap Handler) | 1.1절 SoC 구성 요소 목록 | "트랩"이 무엇인지 이 시점에서는 알 수 없다. |
| 래치 (Latch) | 1.3절 always_comb 설명 | Verilog 학생이라면 알 수 있지만, "의도치 않은 래치"가 왜 문제인지 한 문장 보충이 있으면 좋겠다. |
| 넷리스트 (Netlist) | 1.4절 합성 설명 | 괄호 안 표기만 있고, 넷리스트가 무엇인지 설명이 없다. 합성 결과물인 게이트 수준 회로 기술이라는 정도의 설명이 필요하다. |
| LUT, FF | 1.4절 합성 완료 후 | 리소스 사용량을 확인할 수 있다고 하면서, LUT와 FF가 무엇인지 설명이 없다. FPGA 경험이 없는 Verilog 학생에게는 낯설 수 있다. |
| 배치(Place)와 배선(Route) | 1.4절 구현 단계 | FPGA 설계 흐름의 핵심 개념인데 한 줄 설명이 없다. |
| `$clog2` | 1.5절 파라미터화된 코드 | SystemVerilog 시스템 함수인데 설명 없이 사용되었다. log2를 구하는 함수라는 설명이 필요하다. |
| `'0` (fill literal) | 1.5절 파라미터화된 코드 | `counter <= '0;`에서 `'0`은 SystemVerilog의 fill literal인데, 1.3절에서 다루지 않았다. Verilog 학생에게는 생소한 문법이다. |
| `task automatic` | 1.5절 테스트벤치 | 테스트벤치에서 task와 automatic 키워드가 설명 없이 사용되었다. |
| `$urandom`, `$urandom_range` | 1.5절 테스트벤치 | SystemVerilog 시스템 함수인데, Verilog의 `$random`과의 차이나 용도가 설명되지 않았다. |
| FSDB | 1.5절 VCS/Verdi 명령어 | `.fsdb` 확장자가 설명 없이 등장한다. VCD와의 차이가 궁금해질 수 있다. |
| IOSTANDARD LVCMOS33 | 1.4절 XDC 파일 | XDC 구문에서 LVCMOS33이 무엇을 의미하는지(I/O 전압 레벨 표준) 설명이 없다. |

## "여기서 막힘" 포인트

1. **위치**: 1.1절 — SoC 구성 요소 목록 (46~52행)
   **원인**: 해저드, 포워딩, 스톨, 분기 예측, 캐시, AMBA AHB/APB, CSR, 트랩 등 고급 개념이 한꺼번에 쏟아진다. 각 용어에 영어 병기가 있지만, 개념 자체를 모르는 상태에서는 의미 파악이 어렵다.
   **제안**: "이 목록의 각 항목은 뒤에서 하나씩 자세히 배우게 되므로, 지금은 최종 목표의 전체 그림만 파악하면 충분하다"는 안내 문구를 추가한다. 또는 각 항목 옆에 해당 챕터 번호를 표기하여 "나중에 배울 내용"이라는 인식을 심어준다.

2. **위치**: 1.4절 — 분주 설명 (524행)
   **원인**: "상승 에지와 하강 에지를 모두 사용하므로 100,000,000이 아닌 50,000,000이다"라는 설명이 혼란스럽다. 실제 코드에서는 클록의 상승 에지(posedge clk)만 사용하며, 50M 카운트 후 토글하여 1Hz를 만든다. 상승/하강 에지 "모두 사용"이라는 표현은 DDR 클록킹을 연상시킬 수 있다. 정확히는 "50M 카운트마다 LED 패턴을 한 번 전환하므로 1초에 한 번 전환된다"로 설명하는 것이 코드와 일치한다.
   **제안**: "100MHz 클록은 1초에 1억 번 상승 에지가 발생한다. 50,000,000번째 상승 에지에서 LED를 전환하면 0.5초마다 전환되어 약 1Hz의 점멸 효과를 얻는다"와 같이 수정하거나, 코드의 실제 동작(tick 신호가 50M 카운트마다 1 사이클 동안 활성화)과 일치하도록 설명을 다듬는다.

3. **위치**: 1.5절 — 파라미터화된 led_blinker (915행)
   **원인**: `$clog2(COUNT_MAX+1)-1`이라는 표현이 설명 없이 등장한다. `$clog2`가 무엇인지, 왜 `COUNT_MAX+1`에 적용하는지, 결과적으로 카운터의 비트 폭이 어떻게 결정되는지 모른다.
   **제안**: `$clog2`가 "ceiling of log base 2, 즉 주어진 값을 표현하는 데 필요한 최소 비트 수를 반환하는 SystemVerilog 시스템 함수"라는 설명을 추가한다. 1.3절의 SystemVerilog 문법 복습에 포함시키거나, 최소한 사용 시점에서 주석이나 본문으로 설명한다.

4. **위치**: 1.5절 — 가산기 테스트벤치의 `task automatic` (744행)
   **원인**: `task automatic check(...)`에서 `task`와 `automatic` 키워드가 1.3절에서 다루어지지 않았다. Verilog에서 task를 사용해 본 학생이라면 유추할 수 있지만, `automatic` 키워드는 SystemVerilog 특유의 개념(동적 변수 할당)이라 낯설다.
   **제안**: 코드 내 주석이나 본문에서 "task는 반복되는 검증 코드를 함수처럼 묶는 구문이며, automatic 키워드는 호출 시마다 독립적인 변수 공간을 생성한다"는 한 줄 설명을 추가한다.

5. **위치**: 1.5절 — 파라미터화된 코드의 `'0` 문법 (920행)
   **원인**: `counter <= '0;`에서 `'0`은 1.3절에서 소개되지 않은 SystemVerilog fill literal이다. Verilog 학생은 `26'd0`이나 `{26{1'b0}}`은 알지만 `'0`은 모른다.
   **제안**: 1.3절에 fill literal(`'0`, `'1`, `'x`, `'z`)을 간략히 소개하거나, 1.5절에서 처음 사용할 때 주석으로 "모든 비트를 0으로 채우는 SystemVerilog 축약 표현"이라고 부연한다.

## 선수 지식 부족 영역

1. **FPGA 기초 개념**: 이 챕터는 Verilog 경험이 있는 대학원생을 대상으로 하지만, 반드시 FPGA 경험이 있다고 가정할 수는 없다. ASIC 시뮬레이션 위주로 Verilog를 배운 학생의 경우, LUT/FF/비트스트림/제약 파일 등의 FPGA 특유 개념이 낯설 수 있다. 1.2절이나 1.4절 초반에 FPGA의 기본 구조(CLB, LUT, FF, 라우팅 자원)를 2~3문장 정도로 소개하면 좋겠다.

2. **컴퓨터 구조 기초**: 1.1절에서 파이프라인 5단계(IF, ID, EX, MEM, WB)를 약어로만 제시한다. 괄호 안에 한글 역할 설명이 있어서 큰 문제는 아니지만, 왜 이 5단계로 나누는지에 대한 동기 부여가 없다. 물론 이후 챕터에서 다루겠지만, "왜 파이프라인인가?"에 대한 한 줄 복선이 있으면 이해에 도움이 될 것이다.

3. **테스트벤치 작성 패턴**: `int` 타입, `task automatic`, `$urandom`, `$urandom_range` 등 SystemVerilog 테스트벤치 특유의 문법이 1.3절의 복습 범위를 넘어선다. 이들이 "합성 불가능한 검증 전용 문법"이라는 점을 명시하고, 간략한 소개를 추가하면 좋겠다.

## 전체 읽기 경험 소감

이 챕터를 Verilog 경험만 있는 대학원생으로서 읽으면, 전반적으로 **안심이 되는 도입부**라는 느낌이 강하다. "Verilog를 아는 당신은 이미 절반을 안다"라는 문장이 불안감을 효과적으로 줄여준다. 레고 비유, 수동/자동 변속기 비유, Hello World 비유 등이 적절하게 배치되어 어렵지 않게 읽힌다.

Verilog와 SystemVerilog를 나란히 비교하는 1.3절의 구성은 특히 훌륭하다. 기존 지식에 새 지식을 연결짓는 방식으로, 거부감 없이 SystemVerilog로 전환할 수 있다는 자신감이 생긴다.

다만 두 가지 부분에서 불안감이 올라온다.

첫째, 1.1절의 SoC 구성 요소 목록이 너무 많은 개념을 한꺼번에 던진다. 최종 목표를 보여주려는 의도는 이해하지만, "이걸 다 만들어야 한다고?"라는 압박감이 레고 비유의 안심 효과를 상쇄시킬 수 있다. "이 목록은 20주 후의 완성 그림이다. 지금은 모르는 용어가 있어도 전혀 문제없다"는 명시적 안내가 필요하다.

둘째, 1.5절의 파라미터화된 코드에서 `$clog2`와 `'0` 같은 새 문법이 설명 없이 등장하면, 1.3절에서 쌓은 "SystemVerilog 별거 아니네"라는 자신감이 흔들린다. "아직 모르는 게 더 있구나"라는 느낌이 든다.

전체적으로는 **잘 설계된 첫 챕터**이다. LED가 켜지는 경험을 통해 성취감을 주려는 의도가 명확하고, 코드 품질도 깔끔하며, 코딩 규칙이 일관성 있게 적용되어 있다.
