# Ch23 교육 설계자 기획안 — 성능 최적화 기법

**작성일**: 2026-03-15
**담당**: 교육 설계자 (Instructional Designer)

---

## 1. 각 절별 학습 목표 (Bloom 분류)

### 23.1 슈퍼스칼라 기초 개념
- **[L2 이해]** 슈퍼스칼라 프로세서의 핵심 원리(다중 발행)를 설명하고, IPC > 1이 달성되는 조건을 서술할 수 있다.
- **[L4 분석]** 슈퍼스칼라 설계의 복잡도 증가(디코더, 해저드 검출, 레지스터 포트 수)와 성능 이점 사이의 트레이드오프를 분석할 수 있다.
- **[L2 이해]** Ch12 파이프라인(CPI≈1.2)의 성능 한계를 식별하고, IPC > 1을 위해 어떤 구조적 변화가 필요한지 설명할 수 있다.

### 23.2 토너먼트 분기 예측기
- **[L3 적용]** 지역 예측기(PHT)와 전역 예측기(GHR+PHT)의 동작을 주어진 분기 시퀀스에 대해 추적할 수 있다.
- **[L4 분석]** 토너먼트 예측기의 선택 메커니즘(메타 예측기)이 지역/전역 예측기 중 더 정확한 쪽을 선택하는 과정을 분석할 수 있다.
- **[L3 적용]** 주어진 분기 패턴에 대해 2-bit 포화 카운터의 상태 전이를 추적하고 예측 성공률을 계산할 수 있다.

### 23.3 비순차 실행 개요
- **[L2 이해]** Tomasulo 알고리즘의 3대 구성요소(예약 스테이션, CDB, 레지스터 리네이밍)의 역할을 설명할 수 있다.
- **[L4 분석]** WAR/WAW 해저드가 비순차 실행에서 왜 문제가 되며, 레지스터 리네이밍이 이를 어떻게 해결하는지 분석할 수 있다.
- **[L2 이해]** In-order 파이프라인(Ch09~12)과 OOO 실행의 구조적 차이를 비교·대조할 수 있다.

### 23.4 미니 설계 과제: 2-이슈 구조
- **[L5 평가]** 2-이슈 슈퍼스칼라 구조에서 발생하는 추가 해저드를 식별하고, 해결 전략의 장단점을 평가할 수 있다.
- **[L6 창조]** 간단한 2-이슈 in-order 파이프라인의 블록 다이어그램과 해저드 검출 로직을 설계할 수 있다.

## 2. 학습 흐름 (도입→개념→예시→실습→정리)

### 도입 (23장 서두)
- **왜 필요한가**: Ch12에서 완성한 파이프라인의 CPI≈1.2를 상기. "CPI=1이 이론적 한계인가? 더 빠르게 만들 수 있는가?"라는 질문으로 호기심 점화.
- **프레이밍**: "Part 8까지 완성한 프로세서는 실무 수준의 교육용 CPU. 이제 산업계가 수십 년간 발전시켜 온 최적화 기법을 맛봅니다. 여기서 다루는 개념은 여러분이 사용하는 스마트폰, 노트북의 CPU 내부에 실제로 구현된 기술입니다."
- **기대 설정**: "이 챕터는 '구현'보다 '이해'에 초점을 맞춥니다. 23.4절의 미니 설계 과제만 직접 설계하고, 나머지는 개념을 깊이 이해하는 것이 목표입니다."
- **선행 지식 연결**: Ch11(분기 예측 2-bit 카운터) → 23.2(토너먼트), Ch10(데이터 해저드/포워딩) → 23.3(Tomasulo)

### 개념 소개 순서 (단계별)

| 단계 | 절 | 핵심 질문 | 선행 지식 연결 |
|:----:|:--:|----------|--------------|
| 1 | 23.1 | "한 사이클에 명령어 2개를 동시에 실행하면?" | Ch09 파이프라인 스테이지 → 폭(width) 확장 |
| 2 | 23.2 | "분기 예측을 더 정확하게 만들면?" | Ch11.5 2-bit 카운터 → 지역+전역 조합 |
| 3 | 23.3 | "명령어 순서를 바꿔서 실행하면?" | Ch10 RAW 해저드 → WAR/WAW 추가, 리네이밍 |
| 4 | 23.4 | "직접 설계해보자!" | 23.1~23.3 종합 |

**설계 근거**: 난이도 순서 (슈퍼스칼라 < 분기예측 < OOO). 슈퍼스칼라는 기존 파이프라인의 "폭 확장"으로 직관적. 분기 예측은 Ch11의 확장. OOO가 가장 추상적이므로 마지막 개념으로 배치.

### 예시 (각 개념별 구체적 시나리오)

| 절 | 예시 유형 | 구체적 내용 |
|----|----------|-----------|
| 23.1 | 타이밍 다이어그램 SVG | 1-이슈 vs 2-이슈 파이프라인에서 동일 프로그램(5개 명령어) 실행 비교. CPI 차이 시각화 |
| 23.1 | 리소스 비교표 | 1-이슈 대비 2-이슈의 추가 하드웨어: ALU ×2, 디코더 ×2, 레지스터 포트 4R/2W, 해저드 검출 복잡도 |
| 23.2 | 분기 시퀀스 추적표 | 10회 분기 시퀀스에 대해 지역/전역/토너먼트 예측기의 예측 결과를 단계별 추적 |
| 23.2 | 예측률 비교 SVG | for 루프(규칙적), if-else 체인(불규칙적) 패턴에서 정적/지역/전역/토너먼트 예측 성공률 비교 바 차트 |
| 23.3 | Tomasulo 스냅샷 SVG | 예약 스테이션 3개 + CDB를 포함한 구조도. 3개 명령어가 이슈→실행→완료되는 4사이클 스냅샷 |
| 23.3 | 리네이밍 전/후 비교표 | WAR/WAW 해저드가 있는 코드 → 리네이밍 후 해저드 제거 과정을 표로 추적 |

### 실습 (23.4 미니 설계 과제 상세)

**과제 구성** (3단계 점진적 난이도):

1. **Step 1 [L4 분석]**: 주어진 5개 명령어 시퀀스에 대해 2-이슈 파이프라인의 발행 가능 여부를 판단하라 (해저드 분석표 작성)
2. **Step 2 [L5 평가]**: 주어진 2-이슈 블록 다이어그램에서 해저드 검출 로직의 입력/출력 신호를 정의하고, 포워딩 경로의 추가 복잡도를 평가하라
3. **Step 3 [L6 창조]**: 간단한 2-이슈 in-order 파이프라인의 발행 규칙(issue rule)을 SystemVerilog pseudo-code로 작성하라 (합성 불필요, 의사코드 수준)

**안심 문구**: "이 과제는 완전한 구현이 아니라 설계 사고(design thinking) 연습입니다. 정답이 하나가 아닌 문제를 통해 아키텍트의 시각을 경험해보세요."

### 정리 (성능 향상 수량화)

| 기법 | 이론적 CPI 개선 | 현실적 CPI | 복잡도 증가 |
|------|:-------------:|:---------:|:---------:|
| In-order 5단계 (Ch12) | 1.0 | ~1.2 | 기준선 |
| 2-이슈 슈퍼스칼라 | 0.5 | ~0.7~0.9 | ALU ×2, 디코더 ×2 |
| +토너먼트 분기예측 | — | CPI -5~15% | BHT + 메타 예측기 |
| OOO (참고) | — | ~0.3~0.5 (현대 CPU) | ROB, RS, CDB, 리네이밍 |

## 4. 연습문제 아이디어 (블룸 분류)

### Remember (기억) — L1
1. 슈퍼스칼라 프로세서에서 IPC > 1을 달성하기 위한 3가지 필수 하드웨어 구성요소를 나열하시오.
2. 토너먼트 분기 예측기를 구성하는 3개의 하위 예측기 이름을 쓰시오.
3. Tomasulo 알고리즘의 3대 핵심 구성요소를 나열하시오.

### Understand (이해) — L2
4. 2-이슈 슈퍼스칼라에서 레지스터 파일 포트 수가 1-이슈 대비 왜 2배 이상 필요한지 설명하시오.
5. 전역 분기 예측기가 지역 예측기보다 우수한 분기 패턴의 예를 들고, 그 이유를 설명하시오.
6. WAR 해저드가 "가짜 의존성(false dependency)"이라 불리는 이유를 RAW 해저드와 비교하여 설명하시오.

### Apply (적용) — L3
7. 다음 10회 분기 시퀀스 [T,T,N,T,T,N,T,T,N,T]에 대해 2-bit 포화 카운터(초기 상태: Weakly Taken)의 예측 결과를 추적하고 예측 성공률을 계산하시오.
8. 다음 3개 명령어가 예약 스테이션에 들어갈 때, 각 스테이션의 Qj/Qk/Vj/Vk 필드 값을 채우시오.
   ```
   MUL x3, x1, x2
   ADD x5, x3, x4
   SUB x7, x5, x1
   ```

### Analyze (분석) — L4
9. 다음 코드 시퀀스에서 2-이슈 파이프라인의 발행 가능 여부를 판단하고, 병목 원인을 분석하시오.
   ```
   ADD x1, x2, x3
   SUB x4, x1, x5    // x1 의존성
   AND x6, x7, x8
   OR  x9, x6, x10   // x6 의존성
   ```
10. 토너먼트 예측기에서 메타 예측기의 2-bit 카운터가 지역→전역으로 전환되는 시나리오를 구성하고, 왜 그 전환이 발생하는지 분석하시오.

### Evaluate (평가) — L5 (23.4 미니 과제 일부)
11. 2-이슈 슈퍼스칼라 vs 비순차 실행: Basys 3 FPGA에서 구현한다면 어느 쪽이 더 실현 가능한가? LUT/BRAM 예산을 근거로 논하시오.

## 5. 요약 및 다음 단계 절 (23.5)

### 정리할 핵심 개념 5개
1. **슈퍼스칼라**: IPC > 1 달성을 위한 다중 발행 구조, "폭(width) 확장"
2. **토너먼트 분기 예측**: 지역+전역 예측기를 메타 예측기로 선택, 적응적 예측
3. **비순차 실행**: 데이터 의존성이 해결된 명령어부터 먼저 실행
4. **레지스터 리네이밍**: WAR/WAW "가짜 의존성" 제거 기법
5. **성능-복잡도 트레이드오프**: 모든 최적화는 하드웨어 비용을 수반 (면접 빈출)

### 자가 점검 질문 5개
1. "우리가 Ch12에서 만든 파이프라인의 CPI가 1.2인 이유 3가지를 말할 수 있는가?" (분기 페널티, Load-Use 스톨, 캐시 미스)
2. "2-이슈 슈퍼스칼라에서 해저드 검출이 왜 4배 복잡해지는지 설명할 수 있는가?"
3. "토너먼트 예측기가 단순 2-bit 카운터보다 나은 시나리오를 하나 들 수 있는가?"
4. "Tomasulo의 예약 스테이션이 포워딩 유닛(Ch10)과 어떤 점에서 유사한지 설명할 수 있는가?"
5. "WAR 해저드와 RAW 해저드의 본질적 차이를 한 문장으로 말할 수 있는가?"

### 후속 심화 주제 예고 (Ch24, Ch25)
- Ch24: "성능을 더 높이는 다른 방법 — 명령어 세트 자체를 확장하면? M 확장(곱셈/나눗셈)과 F 확장(부동소수점)을 추가합니다."
- Ch25: "코어를 2개로 늘리면? 멀티코어에서 캐시 일관성이라는 새로운 도전이 시작됩니다."
