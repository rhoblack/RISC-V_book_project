## 항목별 검토 결과

### 1. 설명 품질: 강의에서 그대로 쓸 수 있는 수준인가?

**평가: ⭐⭐⭐⭐ (양호)**

전체적으로 강의 직접 활용 수준에 근접하나 절별로 차이가 있다.

**강의 직접 활용 가능 (우수) 구간:**

- **15.1절 D-Cache 우선 근거 설명**: "접근 빈도와 우선순위는 별개의 문제입니다" + 파이프라인 여유 / Dirty Eviction 긴박성 두 축 설명은 강의 판서 논리로 그대로 사용 가능하다.
- **15.2절 버스트 카운터 설명**: `beat_cnt[2:0]`의 역할, 기준 주소 마스킹(`{addr[31:5], 5'b0}`), 8-beat 완료 조건이 순서대로 제시되어 칠판 설명과 일치하는 흐름이다.
- **15.3절 순차 vs 스트라이드 성능 비교**: 72사이클 vs 352사이클의 수치 계산 과정이 단계별로 나와 있어 칠판 예제로 즉시 활용 가능하다.
- **15.4절 자체 프로토콜 한계 3가지**: 확장성 / 재사용성 / 표준화 부재의 구분이 깔끔하여 강의 마무리 정리로 적합하다.

**보완이 필요한 구간:**

- **15.2절 중재기 FSM 코드 직전 설명**: "3상태 FSM으로 구현됩니다"라고 바로 코드로 넘어가기 전, 왜 3상태인지(IDLE/SERVE_D/SERVE_I의 역할 분담)를 산문으로 한 문장 더 설명하면 강의 흐름이 자연스러워진다. 현재는 FSM 다이어그램이 없는 상태에서 코드가 먼저 나와 강의 중 판서로 보완해야 한다.
- **15.3절 CPI 공식 도입부**: `CPI_실효 = CPI_기본 + LW_비율 × 미스율 × 미스_페널티` 공식이 별도 설명 없이 공식 박스로 바로 제시된다. 이 공식의 각 항이 "파이프라인 기본 동작", "데이터 접근 빈도", "캐시 실패율", "대기 사이클"에 각각 대응됨을 한 문단으로 먼저 설명하면 강의 중 공식 유도가 가능해진다.

### 2. 비유 검증

#### 비유 1: 두 창고와 중앙 물류센터 (15.1절)

| 검증 항목 | 결과 |
|----------|------|
| ① 기술 사실과 매핑 | ✅ 적절 — 설계도 창고(I-Cache), 부품 창고(D-Cache), 물류센터(Main SRAM), 트럭(버스), D-Cache 우선 규칙(부품 창고 우선 정책)이 정확히 대응됨 |
| ② 한계 명시 | ✅ 명시 — "실제 버스 중재는 공정성(Fairness) 보장이 필요한 경우도 있으며, I-Cache 기아(Starvation) 위험을 내포합니다" |
| ③ 오해 유발 여부 | ⚠️ 경미한 위험 — "트럭은 한 대뿐"이라는 표현이 버스 대역폭 개념을 단순화했으나, 실제 멀티채널 버스와 혼동될 수 있음. 본 챕터 맥락에서는 단일 포트 SRAM이므로 사실에 부합하나, 강의 중 "여기서는 단일 포트 SRAM만 가정한다"는 한마디 보완 권장 |
| ④ 대안 비유 제시 | ❌ 없음 |

**대안 비유 제안**: "응급실 트리아지(Triage) 시스템" — 중증(D-Cache: 즉각적 처치 필요) vs 경증(I-Cache: 대기실에서 잠시 기다려도 됨). 우선순위의 의료적 근거가 직관적으로 납득된다.

#### 비유 2: 마트 계산대의 카트 통째 처리 (15.2절)

| 검증 항목 | 결과 |
|----------|------|
| ① 기술 사실과 매핑 | ✅ 적절 — 개별 물건 스캔(Single Transfer) vs 카트 통째(Burst Transfer), 공간적 지역성(인접한 물건이 카트에 함께 있음)이 자연스럽게 대응됨 |
| ② 한계 명시 | ✅ 명시 — "버스트 전송 중에는 버스를 선점할 수 없으며, 캐시 라인 전송이 완료될 때까지 다른 요청이 대기해야 합니다" |
| ③ 오해 유발 여부 | ✅ 없음 — 카트 = 캐시 라인(고정 8워드)의 고정 크기 개념이 잘 전달됨 |
| ④ 대안 비유 제시 | ❌ 없음 |

**대안 비유 제안**: "택배 박스 단위 배송" — 물건을 하나씩 배달(단일 전송)하는 것보다 박스 단위(버스트)로 보내는 것이 트럭 왕복 횟수를 줄인다. 박스 크기가 캐시 라인 크기에 대응된다.

### 4. 막힘 포인트: FAQ / instructor-tip 배치

**평가: ⭐⭐⭐⭐ (양호)**

**잘 배치된 지점:**

- **FAQ (15.1절)**: D-Cache 우선 이유 — 수강생이 "I-Cache가 더 자주 접근하지 않나요?"라는 직관적 반론을 제기하는 지점에 정확히 배치됨. 답변의 논리 구조(접근 빈도 ≠ 우선순위)가 명확하다.
- **FAQ (15.3절)**: 캐시 추가 후 CPI 증가 현상 — 수강생이 결과를 보고 당황하는 지점(히트율이 낮으면 역효과)에 정확히 배치됨.
- **Instructor-tip (15.3절)**: 순차 vs 랜덤 시연 방법 — 실제 수업 운영 팁으로 실용적이다. 루프 인터체인지까지 연결하는 흐름이 우수하다.
- **Tip (15.1절)**: Ch13 FSM 비교 — "Ch13에서 단순화했던 것"을 명시하여 이전 챕터와의 불일치로 인한 혼란을 예방한다.
- **Tip (15.2절)**: 버스트 중 선점 금지 — 직관적으로 이해되지 않는 제약 규칙에 정확히 배치됨.

**추가가 필요한 막힘 포인트:**

1. **15.2절 Grant 신호 타이밍 이해 어려움**: `icache_grant_o`와 `dcache_grant_o`가 조합논리로 생성되어 동일 사이클에 FSM 상태 전이가 발생하는 타이밍을 처음 보는 수강생은 혼란스러워한다. FAQ 또는 tip으로 "grant 신호는 IDLE 상태에서의 1사이클 펄스이며, 캐시 FSM은 이 신호를 래치하여 버스 사용을 시작합니다"를 보완 권장.

2. **15.3절 beat_cnt가 BRAM 1사이클 지연과 어떻게 맞물리는지**: `serve_i_q` / `serve_d_q` 래치를 통한 1사이클 지연 ACK 출력이 처음에는 이해하기 어렵다. 타이밍 설명이 본문보다 코드 주석에만 있어 강의 설명 포인트가 부족하다.

## 개선 제안 (우선순위 순)

### P1 — interview aside 2개 추가
- **위치 A**: 15.1절 — D-Cache 우선 설명 직후
  - 질문: "I-Cache Starvation 가능성을 어떻게 관리하겠습니까?"
  - 답변 힌트: 타임아웃 카운터 방식, Round-Robin 방식, AMBA AHB의 공정 중재기 예고
- **위치 B**: 15.4절 — 자체 프로토콜 한계 3가지 직후
  - 질문: "커스텀 버스와 표준 버스 중 어느 것을 쓰겠습니까? 그 이유는?"
  - 답변 힌트: 프로젝트 규모, 팀 크기, IP 재사용 필요성에 따른 트레이드오프
- **이유**: 현재 interview aside 1개는 기술 계산 문항에 집중되어 있고, 설계 판단력 및 시스템 설계 역량을 묻는 질문이 없다.

### P2 — 15.2절 중재기 FSM 코드 직전 산문 보완
- **위치**: 중재기 FSM 코드 블록 직전 "중재기는 3상태 FSM으로 구현됩니다" 이후
- **내용**: 각 상태(ARB_IDLE/ARB_SERVE_D/ARB_SERVE_I)의 역할과 전이 조건을 코드 이전에 2~3문장으로 기술.
- **이유**: 코드만으로는 강의 중 칠판 설명이 필요한 간격이 발생함. 산문 선행 설명으로 코드가 "확인"의 역할을 하도록 구조 변경.

### P3 — CPI 공식 항별 의미 설명 추가
- **위치**: 15.3절 CPI 박스 직전
- **내용**: "이 공식은 기본 파이프라인 동작(CPI_기본)에 Load/Store 명령어 비율(LW_비율), 캐시 미스율, 미스 시 대기 사이클(미스_페널티)의 곱을 더한 것입니다. 세 항 중 하나라도 줄이면 실효 CPI가 개선됩니다."
- **이유**: 공식의 각 항이 최적화 레버로 연결됨을 강의 설명 없이 전달하기 어려움.

### P4 — Grant 타이밍 혼란 예방 FAQ 또는 tip 추가
- **위치**: 15.2절 중재기 FSM 코드 직후
- **내용**: grant 신호가 1사이클 펄스임과 캐시 FSM이 이를 어떻게 래치하는지 간단 설명.
- **이유**: grant 신호 타이밍은 RTL 경험자도 처음에는 혼란스러운 포인트이며, 실습 중 디버깅 시간의 원인이 될 수 있음.

### P5 — 두 비유에 대안 비유 추가 (선택)
- **비유 1 대안**: 응급실 트리아지 시스템 (D-Cache = 중증 환자 우선)
- **비유 2 대안**: 택배 박스 단위 배송 (캐시 라인 = 박스 크기)
- **이유**: 현재 두 비유 모두 "한계 명시"는 있으나 "대안 비유"가 없어 비유 검증 4항목 중 1항목 미충족. 강의 중 수강생 반응에 따라 다른 비유로 전환할 수 있는 옵션 제공.
