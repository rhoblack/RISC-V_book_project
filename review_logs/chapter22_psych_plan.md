### 🔴 **불안 지점 #2: 메모리 주소를 어떻게 설정해야 하나? (추상적 개념)**

**발생 시점**: 22.1절 후반 메모리 맵 결정
**심리 프로필**:
- "IMEM은 0x0000_0000부터, DMEM은 어디부터지?"
- "스택은? 힙은?"
- "잘못 설정하면 코드가 실행 안 될 텐데?"

**근본 원인**:
- Verilog에서는 하드와이어드 주소 (예: `if (addr[15:12]==4'b0000)`)
- C 에서는 링커가 동적으로 배치 → "자유도"가 높아 혼란

**안심 장치 (22.1절 SVG + 실습)**:
1. **SVG 다이어그램**:
   - 32비트 주소 공간 전체 표시
   - 색상으로 영역 구분:
     - 파란색: IMEM (0x0000_0000~0x0000_FFFF)
     - 초록색: DMEM (0x1000_0000~0x1000_FFFF)
     - 주황색: 스택 (0x2000_0000, 감소 방향)
   - 표시: "이 그림은 Ch15.1의 메모리 맵과 동일합니다"

2. **22.1절 실습: "2개 섹션 배치하기"**:
   ```
   실습: 다음 메모리 맵에 .text와 .data를 배치하세요
   - .text (명령어) → 0x0000_0000부터
   - .data (초기화 데이터) → 0x1000_0000부터
   정답은 22.1.3에 있습니다. (지금 당장 보지 마세요!)
   ```
   → **성공 경험**을 먼저 제공

3. **FAQ 박스**:
```
<aside class="faq">
❓ **자주 틀리는 질문: 스택 초기값은?**
- A: DMEM의 최상단이 아닙니다!
- 우리 설정에서 스택은 0x2000_0000부터 *감소* 방향입니다.
- 스타트업 코드에서 sp = 0x2000_FFFF로 초기화합니다.
</aside>
```

### 🔴 **불안 지점 #3: "UART printf가 안 나온다" (하드웨어-소프트웨어 통합 어려움)**

**발생 시점**: 22.3절 주변 장치 드라이버 작성
**심리 프로필**:
- "코드는 맞는데 PC에 아무것도 안 나와"
- "UART 드라이버가 뭔지 몰라... 어디서 시작하지?"
- "하드웨어 문제인가, 소프트웨어 문제인가?"

**근본 원인**:
- 시뮬레이션 성공 ≠ 하드웨어 성공 (Ch20~21의 교훈)
- UART, GPIO, 타이머 = 새로운 하드웨어 인터페이스
- 디버깅 난이도가 높음 (하드웨어+소프트웨어 동시 점검 필요)

**안심 장치 (22.3절 초반 배치)**:
1. **심리적 안전장치 (명시적 문구)**:
```
<aside class="instructor-tip">
📌 **이 섹션이 어려운 이유**
UART printf는 교재 최고 난이도 실습입니다.
이것은 하드웨어(UART 컨트롤러) + 소프트웨어(드라이버) + 통신(PC 터미널)
세 가지가 완벽히 맞아야 하기 때문입니다.

혼자 못 풀었다면 — 그것은 당신이 못해서가 아닙니다.
모든 엔지니어가 여기서 막힙니다. 이것이 임베디드의 현실입니다.
</aside>
```

2. **"UART 드라이버는 이미 Ch17에서 봤던 것" 연결고리**:
```
<aside class="tip">
💡 **복습: Ch17을 다시 열어보세요**
- Ch17.3: UART 컨트롤러 (하드웨어)
  - TX_DATA, TX_FULL, RX_DATA, RX_EMPTY 레지스터
- Ch22.3: 이제 이 레지스터를 C 함수로 감싸는 것입니다!
  ```c
  void uart_putchar(char c) {
    // Ch17에서 봤던 TX_DATA 레지스터에 쓰기
    while (*(volatile uint32_t *)UART_STATUS & TX_FULL);
    *(volatile uint32_t *)UART_TX_DATA = c;
  }
  ```
- 어? 이게 다입니다! "드라이버"는 레지스터를 C 함수로 감싸는 것.
</aside>
```

3. **단계별 디버깅 가이드**:
```
<aside class="faq">
❓ **UART printf가 안 나올 때 확인 순서**
1️⃣ 하드웨어 확인 (Ch21의 ILA 사용):
   - UART_TX_FULL 신호는 변하나?
   - UART_TX_DATA 레지스터에 값이 쓰이나?
2️⃣ 소프트웨어 확인:
   - printf()가 uart_putchar()를 호출하나?
   - 혹은 uart_putchar()를 호출했는가?
3️⃣ PC 터미널 확인:
   - 터미널 보드레이트가 115200인가?
   - USB 포트가 맞나?
</aside>
```

4. **제공되는 완성 코드**:
   - 최소 UART 드라이버 (10줄)
   - printf 구현 (30줄)
   - "이 파일을 복사-붙여넣기하여 반드시 성공하도록 설계했습니다"

### 🔴 **불안 지점 #4: "드라이버를 어떻게 짜지?" (시스템 프로그래밍 진입)**

**발생 시점**: 22.3절 중반 GPIO, 타이머 드라이버
**심리 프로필**:
- "UART 드라이버는 예제를 봤으니 가능할 것 같은데..."
- "GPIO는? 타이머 초기화는? 어디까지 내가 만들어야 하나?"
- "혹시 알고리즘을 몰라서 못 풀면?"

**근본 원인**:
- 드라이버 = 추상적 개념 ("인터페이스", "래퍼", "추상화 계층")
- GPIO/타이머 = 설정 레지스터 많음
- 독자가 설계자 입장으로 선택해야 함

**안심 장치 (22.3절 구조 설계)**:
1. **드라이버의 재정의**:
```
<aside class="tip">
💡 **"드라이버"를 다시 정의하면**
드라이버 = 하드웨어 동작을 C 함수로 감싸는 것

3단계:
1. 하드웨어 레지스터 주소 → C 포인터로 정의
2. 레지스터 비트 조작 → 함수로 패키징
3. C 코드에서 함수 호출 → 하드웨어 제어

이것이 전부입니다. 신비로운 것 없습니다.
</aside>
```

2. **제공되는 "템플릿 드라이버"**:
   - `gpio_init()`
   - `gpio_set()`, `gpio_get()`
   - `timer_start()`, `timer_isr()`
   → "이 함수들만 채우세요" 형태의 스켈레톤 코드

3. **실습 흐름**:
   ```
   Step 1: UART 드라이버 복사 (완성)
   Step 2: GPIO 드라이버 스켈레톤 (학생 작성)
   Step 3: 검증 실습 (LED 깜빡임)
   Step 4: 타이머 드라이버 (Step 2와 동일 방식)
   ```
   → 각 Step마다 **작은 성공** 경험

#### 22.3절: "드라이버 = 간단한 함수"
```html
<aside class="tip">
💡 <strong>드라이버의 정의를 다시 정리하면</strong>
<pre><code class="language-c">
// 하드웨어 레지스터 주소 (Ch17에서 배웠습니다)
#define GPIO_DATA ((volatile uint32_t *)0x40000000)

// C 함수로 감싸기
void gpio_write(uint32_t pin, uint32_t value) {
  if (value)
    *GPIO_DATA |= (1 << pin);  // 비트 set
  else
    *GPIO_DATA &= ~(1 << pin); // 비트 clear
}

// 이제 main()에서 사용
gpio_write(0, 1);  // LED ON
</code></pre>

이것이 전부입니다. 신비로운 것 없습니다.
</aside>
```

### 4.2 제공되는 완성 코드

**파일 1: `demo_led_blink.c` (반드시 성공)**
```c
#define GPIO_DATA ((volatile uint32_t *)0x40000000)
#define CLOCK_FREQ 50_000_000  // 50MHz

int main() {
    while (1) {
        *GPIO_DATA = 0xFF;     // LED ON
        for (int i = 0; i < CLOCK_FREQ / 2; i++);  // 1초 대기
        *GPIO_DATA = 0x00;     // LED OFF
        for (int i = 0; i < CLOCK_FREQ / 2; i++);  // 1초 대기
    }
    return 0;
}
```

#define UART_DATA ((volatile uint32_t *)0x60000000)
#define UART_STAT ((volatile uint32_t *)0x60000004)

void uart_putchar(char c) {
    while (*UART_STAT & 0x1);  // TX_FULL 대기
    *UART_DATA = c;
}

int main() {
    uart_putchar('H');
    uart_putchar('i');

}

## 부록: 참고 자료

### A. 이 분석에서 참고한 교육심리학 개념

1. **Bloom's Taxonomy (개정판, Anderson & Krathwohl 2001)**
   - 인지 수준: Remember → Understand → Apply → Analyze → Evaluate → Create
   - Ch22: Understand (CSR/드라이버 개념) + Evaluate (성능 측정, 의사결정)

2. **Self-Determination Theory (Deci & Ryan)**
   - 동기 유지: 자율성(선택), 능력감(성공), 관계성(공동체)
   - Ch22에서의 구현:
     - 자율성: 드라이버를 "학생이 직접 구현" (템플릿 제공)
     - 능력감: 완성 코드로 "반드시 성공" 보장
     - 관계성: "당신은 프로세서 설계자" (정체성 인정)

3. **Flow Theory (Csikszentmihalyi)**
   - 몰입 상태: 도전 수준과 능력 수준의 균형
   - Ch22에서의 구현:
     - 도전: "C 프로그램 실행" (최종 미션)
     - 능력: "템플릿 + 완성 코드" (준비된 환경)
     - 결과: 몰입 상태 달성 + 성취감

4. **Zone of Proximal Development (Vygotsky)**
   - Scaffolding: 교사의 지지를 단계적으로 제거
   - Ch22에서의 구현:
     - 22.1: 링커 스크립트 템플릿 제공 (높은 지지)
     - 22.2: C 프로그램 개념 설명 (중간 지지)
