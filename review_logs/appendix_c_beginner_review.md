# Appendix C 초보자 독자 평가

## 이해도 종합 평가: ⭐⭐⭐⭐ (4/5)

---

### 강점

1. **C.1 AHB-Lite 신호 표가 완벽하게 구조화되어 있다.** 신호명, 방향(Master/Slave/Global), 비트 폭, 설명, Ch16 사용 여부가 한 표에 모여 있어, 특정 신호의 의미를 즉시 찾을 수 있다. 방향 열의 색상 구분(Master=파랑, Slave=초록)도 직관적이다.

2. **HTRANS/HBURST/HSIZE 인코딩 표가 별도로 제공된다.** 2비트 HTRANS, 3비트 HBURST, 3비트 HSIZE의 인코딩 값이 명확하게 정리되어 있어, RTL 코드에서 매직 넘버 대신 참조할 수 있다.

3. **C.2 타이밍 다이어그램이 4가지 시나리오를 커버한다.** 단일 전송(C.1), 파이프라인(C.2), 웨이트 스테이트(C.3), 버스트(C.4) — AHB의 핵심 동작을 시각적으로 이해할 수 있다.

4. **C.3 APB 신호 표가 AHB와 동일한 형식으로 정리되어 있다.** AHB 표와 같은 구조(신호명/방향/비트폭/설명/챕터)를 사용하여, 두 프로토콜을 비교하기 쉽다.

5. **C.3의 핵심 포인트가 AHB vs APB 사용 기준을 명확히 제시한다.** "성능이 중요한 메모리는 AHB에, 저속 주변 장치(UART, GPIO, 타이머)는 APB에" — 독자가 "언제 어느 프로토콜을 쓰는가?"에 대한 답을 얻을 수 있다.

6. **C.5 브리지 FSM이 상태 전이도(SVG) + 상태별 출력 표 + 코드 조각으로 3중 설명된다.** SVG로 전체 흐름을 파악하고, 표로 각 상태의 출력 신호를 확인하고, 코드로 구현 방법을 알 수 있어 완벽한 삼위일체이다.

7. **C.5 브리지 코드에서 HREADY 출력 규칙이 명확하다.** `assign hready_out = (state == ST_APB_SETUP) ? 1'b0 : (state == ST_APB_ACCESS) ? pready : 1'b1;` — 이 한 줄이 브리지의 핵심 동작을 압축하고 있다.

8. **C.1의 "Ch16" 열과 C.3의 "Ch17" 열이 유용하다.** 각 신호가 본 교재에서 실제 사용되는지(사용/미사용)를 표시하여, 학생이 "내가 구현할 때 이 신호를 신경 써야 하는가?"를 바로 판단할 수 있다.

---

### 약점 (개선 제안)

1. **C.1에서 "Address Phase"와 "Data Phase" 용어가 설명 없이 등장한다.** HADDR 설명에 "Address Phase에서 유효"라고 되어 있으나, Address Phase가 무엇인지는 C.2까지 가야 알 수 있다.
   - 권장: C.1 본문에 "AHB 전송은 주소를 보내는 Address Phase와 데이터를 보내는 Data Phase의 2단계로 구성된다 (상세는 C.2 참조)" 한 문장 추가

2. **C.2 타이밍 다이어그램의 SVG가 없으면 이해 불가능하다.** 현재 텍스트 설명이 각 그림에 대해 한 줄(figcaption)만 있어, SVG가 로드되지 않는 환경에서는 AHB 동작을 전혀 이해할 수 없다.
   - 권장: 각 타이밍 다이어그램 아래에 2~3줄의 텍스트 설명 추가 (예: "T1: Master가 HADDR, HTRANS=NONSEQ를 출력. T2: Slave가 HRDATA를 출력하고 HREADY=1로 완료 표시")

3. **C.3에서 APB가 AHB보다 느린 구체적 이유가 명시되지 않는다.** "최소 2사이클"이라고만 되어 있고, AHB는 파이프라인으로 1사이클에 데이터를 전달할 수 있다는 비교가 약하다.
   - 권장: "AHB는 Address Phase와 Data Phase를 오버랩하여 파이프라인 전송 시 매 사이클 데이터를 전달할 수 있지만, APB는 SETUP + ACCESS를 순차적으로 처리하여 최소 2사이클이 필요하다. 이는 APB가 프로토콜 단순화를 위해 의도적으로 성능을 희생한 설계이다." 추가

4. **C.4 APB 타이밍이 쓰기/읽기 2개만 제공된다.** AHB는 4가지 시나리오가 있는데, APB는 back-to-back 전송이나 에러 응답 시나리오가 없다.
   - 권장: 최소한 "연속 전송" 시나리오 하나 추가 (PSEL이 유지된 상태에서 다음 전송으로 넘어가는 경우)

5. **C.5 브리지 FSM에서 ST_AHB_DECODE 상태의 필요성이 불분명하다.** "AHB 주소/제어 래치. APB 주소 디코딩"이라고만 되어 있고, 왜 IDLE에서 바로 APB_SETUP으로 갈 수 없는지 설명이 없다.
   - 권장: "AHB의 Address Phase에서 주소/제어 신호를 래치하여 APB 측으로 전달하기 위한 중간 상태. AHB는 파이프라인이므로 주소가 1사이클만 유효하여 반드시 래치해야 한다." 설명 추가

---

### 설명 없이 등장하는 용어

- [ ] **Address Phase / Data Phase** — C.1 신호 설명에서 등장. C.2에서 그림으로 보여주지만, C.1 시점에서는 정의 없음.
- [ ] **AMBA** — 부록 제목에 등장하지만, "Advanced Microcontroller Bus Architecture"의 약어라는 설명이 없음. (본문 Ch16에서 설명될 수 있으나, 부록 단독 참조 시 불편)
- [ ] **AHB-Lite** — C.1 첫 문단에 "단일 마스터 버전의 AMBA AHB"로 설명되어 있어 양호.
- [ ] **beat** — C.2.4, HBURST 표에서 "4-beat", "8-beat" 등 사용. 버스트 전송의 단위 전송 횟수라는 설명 없음.
- [ ] **Master / Slave** — C.1 방향 열에서 사용. 버스 프로토콜에서 요청을 시작하는 쪽(Master)과 응답하는 쪽(Slave)이라는 기본 정의가 없음. (C.3에서는 Requester/Completer로 바뀌어 혼란 가능)
- [ ] **Requester / Completer** — C.3에서 APB 방향에 사용. Master/Slave와의 관계 설명 없음. (ARM의 최신 명명 규약이나, AHB는 Master/Slave, APB는 Requester/Completer로 혼용됨)
- [ ] **래핑(wrapping)** — HBURST 표의 "WRAP4", "8-beat 래핑"에서 등장. 주소가 경계에서 되돌아간다는 개념 설명 없음.

---

### SVG 이해도 평가

- C.2의 4개 AHB 타이밍 SVG와 C.4의 2개 APB 타이밍 SVG는 프로토콜 이해에 **필수적**이다.
- C.5의 브리지 FSM SVG도 상태 전이 흐름 파악에 핵심적이다.
- **SVG 없이는 타이밍 동작을 이해할 수 없다** — 텍스트 보완이 필요하다.
- C.7(브리지 FSM)은 상태별 출력 표와 코드가 있어, SVG 없이도 구현은 가능하지만 전체 그림 파악이 어려움.

### 최종 판정: ✅ 승인 가능 (개선 권장사항 선택적 적용)

부록 C는 AMBA 프로토콜 퀵 레퍼런스로서 신호 목록, 타이밍 다이어그램, 브리지 FSM을 체계적으로 정리하고 있다. 특히 C.5의 3중 설명(SVG + 표 + 코드)이 우수하다. Address Phase/Data Phase 선행 정의, 타이밍 다이어그램 텍스트 보완, Master/Slave vs Requester/Completer 용어 통일 설명을 추가하면 ⭐⭐⭐⭐⭐가 될 수 있다.
