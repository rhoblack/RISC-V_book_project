### 13.1 메모리 계층 구조와 지역성 원리 — ⭐⭐⭐⭐⭐

**평가 근거**:
- DRAM 접근 100~300사이클이라는 숫자와 CPI 계산(1.2 → 41.2)으로 캐시 필요성을 충격적으로 전달. 동기 부여 매우 효과적.
- "메모리 장벽(Memory Wall)"이라는 용어를 처음 사용할 때 명확히 정의함.
- AMAT 공식이 직관적이고 수치 예제로 즉시 납득됨.
- 시간적 지역성/공간적 지역성을 버블정렬(이미 아는 코드)로 설명 — 추상 개념의 구체화 성공.
- 캐시 라인(32바이트) 단위 전송 이유가 공간적 지역성과 연결되어 자연스럽게 이해됨.
- "cache-unfriendly" 패턴 예시(해시 테이블)가 역사례로 이해도를 강화.

**우수 요소**:
- 감정 곡선이 명확함: CPI 41.2 충격(호기심/불안) → AMAT로 해결 가능성(이해) → 지역성 원리(성취감).
- SVG 3종(ch13_sec01_memory_hierarchy.svg, ch13_sec01_locality_principle.svg, ch13_sec01_hit_miss_concept.svg) 존재 확인됨.

**개선 불필요**.

### 13.2 직접 매핑 캐시 설계 — ⭐⭐⭐⭐

**평가 근거**:
- 라커룸 비유와 아파트 주소 비유 모두 Tag/Index/Offset을 직관적으로 전달.
- 비트 필드 결정 순서(Offset → Index → Tag)가 단계적으로 설명되어 이해 가능.
- Valid 비트 FAQ가 적절한 타이밍에 배치됨. 리셋 후 Tag=0인 슬롯이 오판될 수 있다는 위험을 사전 차단.
- SystemVerilog 코드 스니펫이 짧고 명확함.

**문제점 및 개선 요청**:

1. **[중요] LUTRAM vs BRAM 설명 순서 문제**
   - "비동기 읽기(asynchronous read)"와 "동기 읽기(synchronous read)"의 차이가 이 절에서 처음 등장하는데, 사전 설명 없이 바로 설계 결정에 활용됨.
   - Verilog를 안다고 해도 BRAM의 "1사이클 지연"이 파이프라인에서 왜 "자연스럽게 흡수"되는지 처음 보는 사람은 이해하기 어려움.
   - **개선안**: "비동기 읽기 = 클록 없이 입력이 바뀌면 출력이 바로 바뀐다(LUTRAM), 동기 읽기 = 클록 rising edge에서만 출력이 갱신된다(BRAM)"를 2~3줄 추가 설명 후 설계 결정 제시 권장.

2. **[사소] 그림 참조 파일명 불일치**
   - 본문 `<img src="../../figures/ch13_sec02_cache_structure.svg">` → 실제 파일 존재 확인됨 (OK).
   - 본문 `<img src="../../figures/ch13_sec02_bram_mapping.svg">` → 실제 파일 존재 확인됨 (OK).
   - 단, **`ch13_sec02_address_decomposition.svg`** 파일이 figures 폴더에 존재하나, 이 파일은 13.2절이 아닌 **13.3절 SVG와 혼동 가능**. 네이밍은 OK이나 figcaption 내용을 보면 그림 13.4는 13.2절에 배치되어 있어 문제없음.

3. **[중요] 3C 미스 분류(Cold/Capacity/Conflict)가 면접 포인트에 갑자기 등장**
   - 13.2절 면접 포인트에서 3C 미스 용어가 처음 소개되는데, Cold Miss / Capacity Miss / Conflict Miss 모두 이 교재에서 첫 등장.
   - 간략한 설명이 포함되어 있으나, "Cold Miss = 처음 접근", "Capacity Miss = 캐시가 작아서", "Conflict Miss = 같은 슬롯 충돌"이라는 한 줄 정의를 면접 포인트 내부가 아닌 **본문에 먼저** 등장시키면 이해도가 높아질 것으로 판단.
   - **개선안**: 13.2절 본문 "Valid 비트의 필요성" 단락 다음에 "미스의 종류: 3C 분류" 소제목을 추가하고, 이후 13.3~13.5절에서 각 미스 유형을 체험적으로 학습하는 흐름 권장.

**결론**: 충분히 이해 가능하나, LUTRAM/BRAM 차이 미설명 부분에서 일부 독자가 막힐 수 있음.

### 13.4 캐시 미스 처리: Stall 메커니즘 — ⭐⭐⭐⭐

**평가 근거**:
- "이미 아는 것의 확장"으로 캐시 미스 스톨을 Load-Use 스톨과 비교하는 전략이 효과적.
- 스톨 비교 표가 pc_en / if_id_en / id_ex_flush 세 신호를 한눈에 비교하게 해줌 — 차별점 명확.
- 식당 주방 비유가 "전체 홀드"의 감각을 전달함. "재료가 없어서 전부 기다린다"는 표현이 직관적.
- FSM 4상태(IDLE→MISS→FILL→DONE)가 한국어 주석과 함께 제시되어 첫 FSM 접촉자도 따라갈 수 있음.

**문제점 및 개선 요청**:

1. **[중요] FILL 상태에서 fill_cnt 카운터 동작이 본문에 설명 없음**
   - FSM 코드에 `fill_cnt`가 등장하고, 전체 소스 코드 섹션에서 fill_cnt의 역할이 드러나지만, 13.4절 본문에는 "블록을 워드 단위로 8번 수신"하는 동작에 대한 설명이 없음.
   - 처음 보는 독자는 FILL 상태에서 "왜 8번 기다리는가"가 본문에서 명확히 연결되지 않음.
   - **개선안**: FSM 소개 단락에 "FILL 상태에서는 fill_cnt가 0에서 7까지 증가하며, 워드 하나씩 총 8회 수신합니다. 미스 페널티 5사이클은 MISS(1사이클) + FILL(최소 1사이클이지만 단순화 모델에서 5사이클로 고정됨)"과 같이 카운터 동작을 2~3줄로 설명 추가 권장.

2. **[경미] FSM 다이어그램 SVG 참조 파일 확인**
   - `ch13_sec04_miss_fsm.svg` → 실제 파일 존재 확인됨 (OK).
   - `ch13_sec04_stall_pipeline.svg` → 실제 파일 존재 확인됨 (OK).

3. **[사소] "Critical Word First" FAQ가 다소 이른 시점에 등장**
   - 기본 동작 이해 전에 최적화 기법 FAQ가 나오면 "어렵게 느껴지는" 불안감을 유발할 수 있음.
   - 단, "이 챕터는 단순화"라는 해명이 즉시 뒤따르므로 심각하지는 않음.

**결론**: 이해 가능하나, FILL 상태 카운터 동작 미설명으로 일부 독자가 전체 소스 코드를 먼저 열어봐야 할 수 있음.

### 13.5 L1 명령어 캐시 시뮬레이션 — ⭐⭐⭐⭐⭐

**평가 근거**:
- 4개 시나리오가 Cold Miss, 공간적 지역성, 시간적 지역성, Conflict Miss를 순서대로 체험하는 구성. 이론을 수치로 확인하는 흐름이 명쾌.
- 각 시나리오의 히트율(0%, 87.5%, 66.7%, 0%)이 수치로 제시되어 비교 가능.
- 시나리오 4(Conflict Miss 히트율 0%)에서 "낙담하지 마십시오"라는 감정 보정 문구가 적절.
- 히트율 자동 집계 코드가 간결하여 시뮬레이션 결과를 스스로 검증하는 방법을 제시.

**우수 요소**:
- SVG 파형 다이어그램 2종(ch13_sec05_waveform_hit_miss.svg, ch13_sec05_waveform_conflict.svg) 존재 확인됨.
- 3C 미스 분류를 마지막 metacognition에서 다시 정리함으로써 "아, 이래서 3C 분류를 배웠구나" 연결 성공.

**개선 불필요**.

## 구체적 개선 요청 우선순위

### [우선순위 1 — 반드시 반영]

**LUTRAM/BRAM 비동기/동기 읽기 개념 보충 (13.2절)**
- 위치: 13.2절 "FPGA 자원 매핑: Tag-LUTRAM, Data-BRAM" 소절 시작 부분
- 추가 내용: "비동기 읽기(Asynchronous Read)는 클록 없이 입력 주소가 바뀌면 즉시 출력이 갱신됩니다(LUTRAM). 동기 읽기(Synchronous Read)는 클록 rising edge에서만 출력이 갱신됩니다(BRAM). 히트 판정은 같은 사이클에 결과가 필요하므로 LUTRAM을 사용합니다."

### [우선순위 2 — 강력 권장]

**FILL 상태 카운터 동작 설명 보충 (13.4절)**
- 위치: 13.4절 "캐시 미스 FSM 설계" 소절, FSM 코드 직전 또는 직후
- 추가 내용: "FILL 상태에서 fill_cnt는 0부터 7까지 증가합니다. mem_ready 신호가 1이 될 때마다 카운터가 1씩 증가하며, 8개 워드(32바이트)가 모두 수신되면 DONE 상태로 전이합니다."

### [우선순위 3 — 권장]

**3C 미스 분류를 13.2절 본문에 먼저 소개 (13.2절)**
- 현재 면접 포인트 aside 내부에만 있어 본문 독해 중 먼저 만나기 어려움.
- 13.2절 마지막 또는 13.3절 시작 부분에 "미스의 세 가지 종류(Cold / Capacity / Conflict)" 소절을 1~2 문단으로 추가 권장.

### [우선순위 4 — 선택]

**예제 3 이진수 표기 보완 (13.3절)**
- 0x0000_0020의 비트 분해([11:5]=0b0000001)를 명시하여 Index=1 도출 과정 가시화.

## 종합 의견

Ch13은 캐시를 전혀 모르는 독자에게 개념 동기부여(13.1) → 설계 원리(13.2) → 직접 계산(13.3) → 파이프라인 통합(13.4) → 시뮬레이션 검증(13.5) → 정리(13.6)로 이어지는 탁월한 학습 설계를 보여줍니다. 비유의 질과 예제 단계의 적절한 배치가 특히 우수합니다.

주요 개선 포인트는 LUTRAM/BRAM 개념 미설명과 FILL 카운터 동작 미설명으로, 초보자가 코드와 본문 사이에서 연결 고리를 찾기 어려울 수 있는 부분입니다. 이 두 가지를 보완하면 이해도 ⭐⭐⭐⭐⭐ 달성 가능합니다.

**편집장 전달 메시지**: Critical 이슈 0건, Major 이슈 2건(LUTRAM/BRAM 설명, FILL 카운터 설명), Minor 이슈 2건(3C 분류 위치, 이진수 표기). 수정 후 재검토 불필요, 직접 병합 가능합니다.
