## 2. Major 이슈 8개 우선순위 정렬

### 🔴 **S1 긴급 (합성 오류 + 학습 이해도)**

#### 1-1. **기술 M3**: exception_unit.sv wb_async_irq 중복 assign
- **파일**: code_examples/ch19_exception_unit.sv (19.5절)
- **문제**: `assign wb_async_irq = ...` 두 번 나타남 → 합성 오류
- **영향**: Vivado 합성 불가, 합성 도구에서 오류 발생
- **수정**: 중복 제거, 신호 병합 로직으로 통일 (AND/OR 연산)
- **검증**: Vivado xsim 합성 가능 확인

#### 1-2. **강사 M1 + 초보 B3**: 19.5절 CSR 해저드 사이클별 타이밍 예시
- **파일**: manuscripts/part7/chapter19.html (19.5절 본문)
- **문제**: "1사이클 지연"만 기술, 구체적 타이밍 표(IF/ID/EX/MEM/WB별) 없음
- **예시 필요**:
  ```
  - mie 수정 @ cycle N의 WB 스테이지
  - 인터럽트 신호 감지 @ cycle N+1의 IF 스테이지
  - 결과: 1사이클 뒤에 인터럽트 처리 허용
  ```
- **형식**: <table> 또는 타이밍 다이어그램 SVG 참조
- **영향**: 강의 설명도, 초보자 이해도 ⭐⭐⭐→⭐⭐⭐⭐ 상향
- **우선순위**: 강사 + 초보자 모두 지적 → **최우선**

### 🟡 **S2 주요 (기능 + 심화)**

#### 2-1. **기술 M2**: branch_misaligned 감지 후 EX/MEM 전파 누락
- **파일**: code_examples/ch19_exception_unit.sv (19.2절)
- **문제**: Illegal Instruction과 달리, branch_misaligned 신호가 후속 스테이지 전파 로직 부재
- **동작**: EX에서 감지 → MEM/WB까지 전파 필요 (예외 우선순위 처리)
- **수정**: tag_misaligned[IMEM/DMEM] 래치 추가, MEM/WB에서 확인 로직
- **검증**: TB에서 Misaligned load 시나리오 실행, mepc 저장 확인

#### 2-2. **설계 M1**: 19.7절 Part 7 종합 분석 심화
- **파일**: manuscripts/part7/chapter19.html (19.7절)
- **현황**: 5줄 요약 + Part 8 예고만 있음
- **L4 목표**: 분석, 종합, 평가 수준
- **개선 방안**:
  - **반사실적 질문**: "mepc가 없다면 어떻게 될까?" → 하드웨어 필수성 강조
  - **통합 블록 다이어그램**: Ch16~19 4개 장을 하나의 시스템으로 보여주는 SVG
  - **성능 지표**: "예외 처리 오버헤드 4사이클" 정량화
- **분량**: 현 300자 → 600~800자 확대

#### 2-3. **강사 M2**: 19.6절 시나리오 vs 전체 TB 관계 안내
- **파일**: manuscripts/part7/chapter19.html (19.6절 본문)
- **문제**: 본문에서 "시나리오 1~4"를 설명하는데, 뒤의 전체 TB와의 관계 불명확
- **개선**: "시나리오 1은 TB의 ___ 부분입니다" 가리키는 문구 추가
- **예시**: "시나리오 3 (ECALL)은 아래 TB의 test_ecall 태스크에 대응됩니다"

### 🟢 **S3 권장 (선택, 강화)**

#### 3-1. **심리 P1**: 도입부 "HW mepc 저장 필수성" 문구

- **현황**: 안심 문구는 있으나, HW가 왜 mepc를 저장해야 하는지 동기 부족

- **배치**: 19.1 도입 마지막 문단
