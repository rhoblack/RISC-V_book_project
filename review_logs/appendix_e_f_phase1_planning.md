## 🧠 안건 3: 감정 곡선 & 심리적 안전성 설계

### 부록 E: 최고 불안 지점 3가지

| 위험도 | 불안 지점 | 심리 원인 | 안심 장치 |
|--------|----------|---------|----------|
| 🔴 1위 | "설치 후 실행이 안 됨" | 2~3시간 투자 후 실패 → 무력감 | **사전 예고**: "60%가 1~2회 재시도" + **FAQ 체계화** + **감정 인정**: "이 순간이 가장 답답합니다. 하지만 이것은 환경 문제입니다" |
| 🔴 2위 | Vivado 50~70GB + 설치 시간 | 진행률 멈춤 → "고장난 건가?" | **비교 데이터**: "VS: 25GB, Vivado: 50GB" + **시간 계획**: "저녁 다운로드→다음날 확인" + **정상 진행 체크**: "CPU 사용률 확인" |
| 🔴 3위 | PATH 환경변수 + 터미널 낯설음 | 하드웨어 엔지니어에게 낯은 영역 | **비유**: "PATH = 컴퓨터 주소록" + **복사-붙여넣기** + **3단계 스크린샷** + **검증 명령어**: `gcc --version` 직접 실행 |

### 부록 F: 최고 불안 지점 3가지

| 위험도 | 불안 지점 | 심리 원인 | 안심 장치 |
|--------|----------|---------|----------|
| 🔴 1위 | 테스트 실패 시 원인 파악 불가 | "Test FAILED"만 보임 → 전체 설계 부정 | **3단계 디버깅**: 명령어 찾기→값 확인→모듈 특정 + **실패 유형 분류**: 구조(5%), 로직(70%), 타이밍(15%), 포워딩(10%) + **산업 정상화**: "Intel도 동일 프로세스" |
| 🔴 2위 | "공식 테스트 실패 = 설계 쓸모없음" | 20주 노력이 부정되는 느낌 | **통계**: "첫 시도 15%만 통과, 60%는 일부 실패" + **재프레이밍**: "실패 = 버그 발견 기회" + **점진적 목표**: 5/10→8/10→10/10 단계별 축하 |
| 🟡 3위 | Makefile/HTIF/Spike 새 도구 20개 | 인지 과부하 | **개념 수 제한**: 한 세션 4~5개만 + **학습 분산**: 섹션 사이 휴식 + **"몰라도 돼"**: 템플릿 복사-붙여넣기만 |

### 첫 성공 경험 설계

**부록 E: 3단계 점진적 성공**
1. E.1 완료: Vivado 실행 + 새 프로젝트 생성 (2~3시간) → "설치가 된다!"
2. E.2 완료: `gcc --version` 확인 (1~2시간) → "두 번째 도구도 된다!"
3. **보상**: LED 깜박이기 성공 🎉 + **1일 휴식** (번아웃 방지)

**부록 F: 가장 작은 테스트부터**
1. Phase 1: Spike에서 `rv32ui-p-add` 실행 (15분) → "공식 테스트 체험!"
2. Phase 2: 자신의 설계에서 add, addi 통과 (1~2시간) → "내 설계도 통과하네!"
3. Phase 3: 5/10 → 8/10 → 10/10 점진적 달성 (3~7일) → 🎉 "산업 표준 통과!"

### 메타인지 촉진 장치

1. **진행도 표시기** (시각적):
   ```
   [████████░░░░░░░░░░░░] E.1 완료 (25%)
   [████████████████░░░░] E.2 완료 (75%)
   [████████████████████] E.3 완료 (100%)
   ```

2. **설치 체크리스트** (자가 평가):
   - "모두 체크했으면 다음 단계로"
   - "하나 미체크 → FAQ 참조"

3. **자기 점검 질문** (각 절 마지막):
   - 기술 확인: "Vivado에서 새 프로젝트 만들 수 있나요?"
   - 감정 확인: "지금 기분이 어떤가요? 좌절감이 든다면, 15분 쉬고 돌아오세요."
   - 메타인지 평가: 통과율 10/10 vs 8~9/10 vs 5~7/10 vs <5/10 각각 다음 단계 안내

### 실패 정상화 문구

**부록 E:**
> "환경 설치 ≠ 하드웨어 설계. 설치는 '소프트웨어 운영 문제'입니다. 첫 시도에 실패하는 것이 정상입니다. 삼성·SK·Intel 신입도 3~4회 시도 끝에 성공합니다."

**부록 F:**
> "테스트 실패 = 버그 발견 기회. 이것이 검증 엔지니어의 일입니다. 첫 시도에 100% 통과하는 설계는 매우 드뭅니다 (15%만). 당신의 2~3회 재테스트는 산업 프로세스의 축소판입니다."

**추가 — "실패 후 3분 규칙":**
> (1) 3분간 아무것도 하지 마세요 (감정 안정)
> (2) 로그의 마지막 5줄만 읽으세요
> (3) 디버깅 가이드의 3단계를 따르세요
> → 대부분의 버그는 2시간 내에 찾을 수 있습니다.
