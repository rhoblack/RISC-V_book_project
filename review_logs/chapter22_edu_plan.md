## 3. 인지 부하 분석 (Cognitive Load Analysis)

### 3.1 높은 인지 부하 지점 (High Cognitive Load)

#### 3.1.1 링커 스크립트 문법 (22.1절)
- **원인**
  - 새로운 도메인: 하드웨어 레지스터 ↔ 메모리 주소 공간 매핑
  - 추상적 개념: "섹션"이 구체 주소로 배치되는 과정
  - 문법 학습: `SECTIONS { }`, `AT`, `>`, `. += expr` 등 생소한 기호

- **분산 전략**
  1. **시각적 스캐폴딩**: "메모리 배치도" SVG (IMEM/DMEM/BRAM 물리 주소 표시)
  2. **단계적 공개 (Gradual Reveal)**
     - Step 1: "링커는 왜 필요한가?" (개념)
     - Step 2: "메모리는 어떻게 나뉘어 있나?" (구조)
     - Step 3: "각 섹션을 어디에 배치할까?" (결정)
     - Step 4: "링커 스크립트로 표현하기" (구문)
  3. **템플릿 제공**: "실습용 최소 링커 스크립트 템플릿" 코드 제공 (복사-붙여넣기 가능)
  4. **비유 강화**: "건축 설계도(링커 스크립트) ↔ 실제 건물(메모리 배치)"

#### 3.1.2 메모리 주소 공간의 추상도 (22.1~22.3절)
- **원인**
  - Basys 3 메모리 맵: IMEM (주소 0x0000_0000) / DMEM (0x0000_1000) / MMIO (0x8000_0000+)
  - 학생은 "32비트 주소 = 4GB" 이론만 배웠지만, 실제 배치는 크기 제한
  - C 포인터 `uint32_t *p = (uint32_t *)0x80000100;` 의미 불명확

- **분산 전략**
  1. **메모리 맵 다이어그램 (SVG)**
     ```
     0x0000_0000 ┌─────────────────────┐
                 │   I-Cache (4KB)     │ ← 명령어 저장
     0x0000_1000 ├─────────────────────┤
                 │   D-Cache (4KB)     │ ← 데이터 저장
     0x0000_2000 ├─────────────────────┤
                 │   DRAM(확장가능)    │ ← 향후 확장
     0x8000_0000 ├─────────────────────┤
                 │   UART (4B)         │ ← MMIO (주변)
     0x8000_0004 ├─────────────────────┤
                 │   GPIO (4B)         │
     0x8000_0008 ├─────────────────────┤
                 │   Timer (8B)        │
     0x8000_0010 └─────────────────────┘
     ```

  2. **22.1절 실습**: "주소 ↔ 섹션 매핑 종이 작업"
     - "0x00000100에 저장된 데이터가 무엇인가?" 추적 연습
     - 답: 링커 스크립트로 정의한 `.data` 섹션의 3번째 변수

  3. **"거울 뷰" 기법**: 같은 정보를 2개 관점에서 제시
     - 좌측: C 소스코드 (`global_var = 5;`)
     - 우측: 링커 스크립트 (`.data { global_var = 0x00001000; }`)
     - 중앙: 메모리 다이어그램 (0x00001000 ← "5")

#### 3.1.3 C 포인터와 메모리 주소 혼용 (22.2~22.3절)
- **원인**
  - 학생은 C에서 `int *p = malloc(...)` 경험 있지만 FPGA에는 malloc 없음
  - 링커 스크립트에서 정의한 절대 주소를 C에서 포인터로 접근하는 관념 전환 필수
  - 예: `#define UART_DATA (*(volatile uint32_t *)0x80000000)` 문법 낯섦

- **분산 전략**
  1. **3단계 전환 (Progression)**
     - Stage 1: 링커가 정의한 심볼 사용 (`extern uint32_t _uart_base;`)
     - Stage 2: 캐스팅으로 절대 주소 접근 (`(volatile uint32_t *)0x80000000`)
     - Stage 3: 매크로로 편의성 확보 (`UART_DATA` 읽기/쓰기)

  2. **비유**: "주소록(링커 심볼) ↔ 직접 통화(절대 주소 포인터)"

### 3.2 중간 인지 부하 (Medium Cognitive Load)

#### 3.2.1 크로스 컴파일 체인 이해 (22.2절)
- **원인**: riscv32-unknown-elf-gcc 실행 옵션 다양 (`-nostdlib`, `-Wl,--script=`, `-Wl,--defsym=` 등)
- **분산 전략**
  1. **"마법의 명령어" 제시**: 완성된 Makefile 제공, 내부 옵션은 "22.3절에서 분석"
  2. **옵션별 의미 표**

  | 옵션 | 의미 | 이유 |
  |------|------|------|
  | `-nostdlib` | C 표준 라이브러리 제외 | 임베디드 환경에는 malloc/printf 없음 |
  | `-Wl,--script=link.ld` | 링커 스크립트 지정 | 메모리 배치 제어 |
  | `-Wl,-Map=program.map` | 심볼 맵 출력 | 디버깅: 각 변수의 실제 주소 확인 |
  | `-O2` | 최적화 | 단일사이클 CPU에서도 성능 중요 |

#### 3.2.2 스택 초기화와 ABI 규약 (22.2절)
- **원인**: 스택 포인터(sp=x2) 초기화, 프레임 포인터(fp=x8) 설정 등 저수준 요소
- **분산 전략**
  1. **스택 다이어그램 (SVG)**
     ```
     메모리       C 코드                      상태
     ────────────────────────────────────
     0x0000_1000 ┌──────────────┐
                 │  main 스택   │ ← sp=0x00001000 초기
                 │  (grow down) │
     0x0000_0800 ├──────────────┤
                 │   변수 x     │
     0x0000_0804 ├──────────────┤
                 │   변수 y     │
     0x0000_0808 └──────────────┘
     ```
  2. **"손으로 따라하기" 실습**: 어셈블리 명령어 추적
     - `addi sp, sp, -16` (스택 공간 예약)
     - `sw x1, 12(sp)` (복귀 주소 저장)
  3. **리뷰 없이 이해 불가능 장소 표시**: 의도적 생략 → 22.4절 최종 데모에서 자동 검증

> ```
> MEMORY {
>   IMEM : ORIGIN = 0x00000000, LENGTH = 0x1000
>   DMEM : ORIGIN = 0x00001000, LENGTH = 0x1000

> - MMIO: 0x8000_0000 ~ 0x8000_0FFF (4KB)

### 4.2 22.2절 후: "main() 진입 전 스택 초기화 순서" 실습

**목표**: Apply 수준 — "스택 초기화 단계를 올바른 순서로 설명할 수 있다"

**연습 문제**

> **문제 2**: 다음 스타트업 코드를 읽고, 스택 포인터(sp) 값의 변화를 추적하세요.
> ```assembly
> .text
> .globl _start
> _start:
>     la sp, _stack_top      # sp ← 0x00001FF8 (최상단)
>     jal zero, main         # main() 호출
>
> .data
> _stack_top:              # 스택 최상단 주소 심볼
> ```
>
> **답안 서식**:
> | 명령어 | 직전 sp | 직후 sp | 설명 |
> |--------|---------|---------|------|
> | `la sp, _stack_top` | — | 0x00001FF8 | 링커가 정의한 심볼에서 주소 로드 |
> | `jal zero, main` | 0x00001FF8 | 0x00001FF8 | 분기만 하고 복귀 주소 불필요 |

**채점 기준**
- ✅ sp 값의 기본 이해 (하향 스택)
- ✅ `la` 명령어가 "링커 심볼"을 해석함을 이해
- ⚠️ jalr 분기 후 sp 변화 (선택사항)

### 4.3 22.3절 후: "UART printf 드라이버 추가" 과제

**목표**: Apply 수준 — "MMIO 레지스터 접근으로 드라이버를 작성할 수 있다"

**실습 과제**

> **과제 1**: 다음 UART 컨트롤러 매뉴얼을 참고하여 `putchar()` 함수를 완성하세요.
>
> **UART 레지스터 맵** (Ch17에서 설계한 APB Slave)
> - Base Address: 0x8000_0000
> - Data Reg (0x00): TX/RX FIFO
> - Status Reg (0x04): bit[0]=TX_READY, bit[1]=RX_VALID
> - Control Reg (0x08): bit[0]=TX_EN, bit[1]=RX_EN
>
> **불완전한 코드**:
> ```c
> #define UART_BASE 0x80000000
> #define UART_DATA   (*(volatile uint32_t *)(UART_BASE + 0x00))
> #define UART_STATUS (*(volatile uint32_t *)(UART_BASE + 0x04))
>
> void putchar(char c) {
>     // TODO: UART_STATUS[0]이 1일 때까지 대기
>     // TODO: UART_DATA에 c를 기록
> }
> ```
>
> **풀이 코드 (제시)**:
> ```c
> void putchar(char c) {
>     while ((UART_STATUS & 0x1) == 0);  // TX_READY 대기
>     UART_DATA = c;                      // 송신
> }
> ```

**채점 기준**
- ✅ 폴링(polling) 루프로 준비 신호 대기
- ✅ `volatile` 키워드 이해 (최적화 방지)
- ⚠️ FIFO 오버플로우 처리 (선택사항)

> **과제 2**: 다음 요구사항을 충족하는 C 프로그램을 작성하고 Basys 3에서 실행하세요.

> **요구사항**:
> 1. LED[0:3]을 순환 점멸 (1초 간격, 타이머 인터럽트 기반)

> 3. 프로그램 시작 시 "System Ready\n" 메시지 출력
>
> **개선 사항 평가 질문**:
> - "왜 폴링 방식(while 루프) 대신 인터럽트를 사용했는가?"
> - "링커 스크립트에서 `.bss` 섹션을 별도로 정의한 이유는?"
> - "왜 UART/GPIO 레지스터를 `volatile`로 선언했는가?"

**채점 기준**
- ✅ 프로그램이 FPGA에서 정상 동작
- ✅ 링커 스크립트 문법 정확 (섹션 배치)
- ✅ 스타트업 코드 필요성 이해
- ⭐ 추가 점수: 임베디드 설계 원칙 설명 (volatile, 인터럽트 선택 근거)

### 6.3 Section 22.3: 주변 장치 드라이버 작성

**Step 3: UART 드라이버 (300~400어)**
- 레지스터 맵: Data, Status, Control (Ch17 설계 상기)
- 송신 함수 (`putchar`)
  - Status의 TX_READY 폴링
  - Data 레지스터에 바이트 기록
  - 예: `printf()` 구현 기초
- 수신 함수 (`getchar`), 인터럽트 기반 수신 (선택)

**Step 4: GPIO 드라이버 (200~300어)**
- LED 제어: 비트 연산 (`|`, `&`, `^`)
- 스위치 읽기: 상태 확인
- 간단한 콘솔 인터페이스 (UART + GPIO)

**Step 5: Timer 드라이버 (200~300어)**
- Timer 레지스터 맵: Count, Compare, Interrupt (Ch17 설계 상기)
- 인터럽트 기반 타이머 설정
- ISR (Interrupt Service Routine) 작성

**Step 6: 실습 (드라이버 작성 + 통합, 1시간)**
- 주어진 헤더 파일 (레지스터 정의)에 따라 구현
- 각 드라이버를 단독 테스트 (단위 테스트)
- 통합 테스트: LED + UART + Timer 동시 동작

#### 인지 부하 분산
- ✅ 낮음: 하드웨어 설계는 이미 완료, 소프트웨어는 단순 레지스터 접근
- 💡 안심 장치:
  - aside (tip): "이 드라이버는 나중에 다시 재사용할 수 있습니다. 표준 인터페이스를 지키세요."
  - 템플릿: `uart.h`, `gpio.h`, `timer.h` 제공 (함수 프로토타입만 명시)

#### 코드 예시
```c
// uart.h
#define UART_BASE 0x80000000
#define UART_DATA   (*(volatile uint32_t *)(UART_BASE + 0x00))

char getchar(void);    // 학생이 구현

// gpio.h
#define GPIO_BASE 0x80000010
#define GPIO_OUT (*(volatile uint32_t *)(GPIO_BASE + 0x00))

```

### 9.2 안심 장치 (Psychological Safety Nets)

1. **aside (tip)**: 링커 스크립트의 복잡도 정상화
   > "링커 스크립트는 한 번 작성 후 거의 수정하지 않습니다. 여기서는 원리만 이해하세요. 나머지는 템플릿을 복사-붙여넣기하세요."

2. **aside (instructor-tip)**: 디버깅 실패 정상화
   > "첫 FPGA 실행에서 100% 성공하면 매우 운이 좋은 것입니다. ILA로 신호를 추적하고, UART 디버그 메시지를 전략적으로 배치하세요. 실패는 배움입니다."

3. **template code**: 스켈레톤 제공으로 심리적 진입 장벽 낮춤
   - `main.c`, `uart.h`, `gpio.h` 등 구조만 제시
   - 학생이 구현할 부분은 명확히 표시 (`// TODO:`)

4. **단계적 요구사항**: 한 번에 모든 기능을 요구하지 않음
   - Step 1: UART로 "System Ready" 출력 (성공 체험)
   - Step 2: LED 순환 점멸 (시각적 만족)
   - Step 3: 스위치 입력 감지 (인터랙션)
   - Step 4: 타이머 인터럽트 기반 개선 (심화)

5. **aside (faq)**: 학생들의 단골 질문 선제적 답변
   - "왜 링커 스크립트가 필요한가?"
   - "왜 `.bss` 섹션을 0으로 초기화하는가?"
   - "왜 UART를 `volatile`로 선언했는가?"
