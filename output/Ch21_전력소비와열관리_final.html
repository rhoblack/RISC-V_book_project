Chapter 21

전력 소비와 열 관리

RISC-V 프로세서 설계의 마지막 단계는 전력 소비를 이해하고 관리하는 것입니다. 이 챕터에서는 FPGA 설계에서 발열이 왜 중요한지, 그리고 어떻게 측정하고 최적화할 수 있는지 배웁니다.

학습 목표

  • 전력 소비의 3가지 원천(동적, 정적, 글리치)을 설명할 수 있다.
  • 동적/정적 전력 공식의 파라미터를 해석하고 정량적으로 계산할 수 있다.
  • Xilinx Vivado 전력 분석 도구를 사용하여 설계 전력을 측정할 수 있다.
  • 성능(CPI) + 전력 데이터를 통합하여 에너지/명령어(EPI) 메트릭을 계산할 수 있다.
  • 전력 소비 병목을 식별하고 개선 우선순위를 기술적 근거와 함께 제시할 수 있다.
  • PPA(Power-Performance-Area) 트레이드오프를 평가하여 주어진 제약 조건 하에서 최적의 설계 전략을 선택할 수 있다.

21.1 전력 소비의 원천

당신의 FPGA 보드가 1시간 이상 동작 중이라면, 칩 표면이 따뜻해지는 것을 느꼈을 겁니다. 적외선 카메라로 찍으면 더 뜨거운 부분과 차가운 부분이 보입니다. 이 발열은 어디서 오는 걸까요? 바로 **전자 회로가 일을 할 때 소비하는 전력**이 열로 변환되기 때문입니다.

FPGA 설계에서 전력 소비는 크게 **3가지 요소**로 나뉩니다.

1. 동적 전력(Dynamic Power)

동적 전력은 **회로가 신호를 토글(0→1→0...)할 때 소비하는 전력**입니다. 공식은 다음과 같습니다:

Pdyn = C × V² × f

여기서:

  • C: 회로 노드의 커패시턴스(용량성 부하) [pF = 10-12F]
  • V: 공급 전압 [Volt]
  • f: 클록 주파수 [Hz]

차원 분석을 하면 [F] × [V²] × [Hz] = [Coulomb/Volt] × [V²] × [1/second] = [Joule/second] = [Watt]가 됩니다.

Basys 3에서 실제 수치로 생각해 봅시다. 예를 들어:

  • C = 10,000 pF = 10 nF (전체 FPGA 칩의 평균 커패시턴스)
  • V = 1.0 V (공급 전압)
  • f = 100 MHz
이를 대입하면:
Pdyn = 10 × 10-9 × 1.0² × 100 × 106 = 1.0 W

복잡해 보이지만, 각 항(V, f, C)은 물리적 의미가 명확합니다:

비유: 춤추는 사람의 피로
동적 전력은 "춤을 출 때의 피로"처럼 생각할 수 있습니다.
  • 강도↑(V↑): 더 큰 움직임(높은 전압) → 훨씬 피곤 (V²이므로 제곱으로 증가)
  • 빈도↑(f↑): 더 자주 춤 (높은 주파수) → 더 피곤
  • 체형↑(C↑): 더 큰 체격 (높은 커패시턴스) → 같은 움직임도 더 피곤
한계: 실제로는 활동도(activity factor)가 포함되어야 합니다. 모든 신호가 매 클록마다 토글되지는 않습니다.
대안: "춤 동작의 크기와 주파수, 그리고 뮤지션의 체력"이 모두 영향을 미친다고 생각하세요.

2. 정적 전력(Static Power)

정적 전력은 **회로가 유휴(idle) 상태일 때도 발생하는 누설 전류**에 의한 전력입니다. 공식은:

Pstatic = Ileak × V

여기서:

  • Ileak: 누설 전류 [mA]
  • V: 공급 전압 [V]

흥미로운 점은 Ileak이 온도와 전압에 **지수적으로** 의존한다는 것입니다. 온도가 10°C 증가할 때마다 누설 전류가 약 2배 증가합니다. 이것이 나중에 배울 **열 폭주(thermal runaway)**의 원인입니다.

Basys 3의 경우:

  • 상온(25°C)에서: Ileak ≈ 10 mA, Pstatic ≈ 10 mW
  • 고온(55°C)에서: Ileak ≈ 30 mA, Pstatic ≈ 30 mW (온도에 따라 급증)

비유: 아이들링 자동차와 기초대사량
정적 전력은 "자동차 엔진을 끄지 않고 대기할 때의 연료 소비"처럼 생각할 수 있습니다.
  • 자동차가 움직이지 않아도 엔진이 돌고 있으면 연료를 소비합니다.
  • 더운 날씨에는 에어컨 압축기가 많이 작동하므로 아이들링 연료도 증가합니다.
한계: 실제 반도체의 누설은 온도뿐 아니라 공정 변수, 전압, 기하학적 형태에도 의존합니다.
대안: "엔진의 크기, 나이(공정), 외부 온도가 모두 아이들링 연료에 영향을 미친다"고 생각하세요.

3. 글리치 전력(Glitch Power)

글리치 전력은 **회로의 경로 지연 차이로 인해 신호가 여러 번 토글**할 때 발생하는 추가 전력입니다. 예를 들어, AND 게이트의 두 입력이 다른 시간에 도착하면, 예상치 못한 중간 값(glitch)이 발생하고, 이 값이 토글되면서 전력을 소비합니다.

FPGA에서는 LUT(Look-Up Table) 조합 로직이 글리치에 더 취약합니다. Vivado의 전력 분석기는 보통 글리치를 추정에 포함하지만, 정확한 계산은 post-placement-and-routing 단계에서만 가능합니다.

💡 실무 팁

동적 전력은 f²(!)에 비례하므로, 주파수를 50% 감소시키면 동적 전력은 75% 감소합니다. 반면 정적 전력은 온도에 지배적으로 의존하므로, 냉각이 중요합니다.

❓ 수강생 단골 질문

Q: 왜 정적 전력이 중요해요? 동작하지 않는데?

A: 현대 데이터센터에서는 서버가 대기 상태(유휴)에서도 전체 전력의 40% 이상을 소비합니다. 클라우드 서비스의 안정성은 정적 전력 관리에 달려 있습니다.

21.2 동적 전력 상세 분석

동적 전력이 정말 CV²f 공식을 따르는지, 실제로 설계에서 어떻게 나타나는지 살펴봅시다.

스위칭 에너지와 활동도

한 번의 스위칭(0→1 또는 1→0)에 소비되는 에너지는:

Eswitch = ½ × C × V²

이는 **캐퍼시터에 저장된 에너지** ½CV²이 모두 열로 방산된다는 의미입니다. 만약 신호가 1초에 f번 토글된다면, 1초 동안의 에너지는:

Pdyn = ½ × C × V² × f × α

여기서 α는 **활동도(activity factor)**로, 실제로 몇 %의 신호가 토글되는지를 나타냅니다(0 ≤ α ≤ 1). 보통 α는 0.1~0.3 범위입니다. 즉, 모든 신호가 매 클록마다 바뀌지는 않습니다.

주파수와 전력의 선형성

주파수를 2배로 올리면 전력은 (이론적으로) 2배가 됩니다. 하지만 실제로는:

  • 고주파 운영: 배선의 저항(RC 지연)이 커져서 약간의 추가 손실 발생
  • 전압 스케일링: 높은 주파수를 유지하려면 전압을 올려야 하고, V²의 영향으로 전력은 지수적으로 증가

용량성 부하의 원천

FPGA에서 전력을 소비하는 주요 요소는:

  • 배선(Interconnect): FPGA 설계에서 대부분의 용량성 부하는 배선입니다. 배선이 길수록, 많을수록 전력 증가
  • 메모리: BRAM과 LUTRAM의 읽기/쓰기 시 높은 토글 활동도
  • I/O 핀: 보드 외부로의 신호 전송이 매우 용량성 부하(pF 단위)
💡 실무 팁

Vivado Power Analyzer가 모든 신호의 활동도를 정확히 알 수 없으므로, 평균 활동도(switching probability)를 추정합니다. 따라서 Vivado 추정값과 실측값의 차이는 ±10~20% 정상입니다.

21.3 정적 전력과 PPA 트레이드오프

이제 전력(P)뿐 아니라, **성능(Performance)**, **면적(Area)** 세 가지를 동시에 고려해야 합니다.

누설 전류의 온도 의존성

누설 전류는 보통 다음과 같이 모델링됩니다:

Ileak(T) = I0 × eT/T₀

여기서 T는 온도(°C), T₀는 온도 상수(약 40~50°C)입니다. 이는 온도가 증가할수록 누설 전류가 **지수적으로** 증가함을 의미합니다.

실제 측정:

  • 25°C: Ileak = 10 mA
  • 45°C: Ileak = 20 mA (약 2배)
  • 65°C: Ileak = 40 mA (약 4배)

EPI 메트릭: Energy Per Instruction

단순히 전력만으로는 설계 품질을 판단할 수 없습니다. 같은 1W라도, 초당 10개의 명령을 처리하는 설계와 100개의 명령을 처리하는 설계는 효율성이 다릅니다.

따라서 우리는 **EPI(Energy Per Instruction)** 메트릭을 정의합니다:

EPI = Pavg / (f / CPI) = Pavg × CPI / f [Joule/Instruction]

예시:

  • 설계 A: P = 0.5W, f = 50MHz, CPI = 2.0 → EPI = 0.5 × 2.0 / 50 = 0.02 mJ/Instr
  • 설계 B: P = 1.0W, f = 100MHz, CPI = 1.0 → EPI = 1.0 × 1.0 / 100 = 0.01 mJ/Instr
설계 B가 같은 명령당 절반의 에너지로 처리합니다!

PPA 트레이드오프

설계 최적화는 3가지 목표를 균형 있게 맞추는 과정입니다:

  • Performance(성능): 더 높은 주파수 또는 더 낮은 CPI
  • Power(전력): 더 낮은 동적/정적 전력 소비
  • Area(면적): 더 적은 LUT, BRAM, FF 사용

그런데 이 세 목표는 대부분 상충합니다:

  • 성능↑ (파이프라인 추가): 면적↑, 전력↑
  • 면적↓ (로직 최소화): 성능↓ (더 느린 구현)
  • 전력↓ (전압 감소): 성능↓ (느린 게이팅)
비유: 요리의 시간/맛/가격 삼각 관계
좋은 음식을 만들 때는 세 가지 목표가 항상 상충합니다.
  • 빠른 조리: 품질이나 가격을 포기해야 함
  • 맛있는 음식: 시간이 오래 걸리거나 재료비가 비쌈
  • 저가격: 시간이나 품질을 포기
한계: 요리는 보통 선형적이지만, FPGA 설계는 기하급수적일 수 있습니다.
대안: "대학생의 공부 시간, 성적, 건강"을 생각해보세요. 이 셋을 모두 챙기기는 힘듭니다.

질문: "전력과 속도 중 어느 것을 우선할까요? 정당화해주세요."

기본 답변: 설계 목표에 따라 다릅니다. 모바일 기기(배터리 제한) → 전력 중심. 데이터센터(전력 공급 충분) → 성능 중심.

21.4 Vivado 전력 분석 도구

복잡한 공식을 손으로 계산할 수는 없습니다. Xilinx Vivado는 **Power Analyzer**라는 자동화된 도구를 제공합니다.

Vivado Power Analyzer 흐름 (5단계)

Step 1: 프로젝트 열기
이미 합성되고 배치/배선 완료된 프로젝트를 엽니다.

Step 2: Implementation Run 선택
"impl_1"을 우클릭 → "Report Power"

Step 3: Switching Activity 설정
Power Analyzer는 3가지 모드를 제공합니다:

  • Typical: 평균 활동도 가정 (기본값, α = 0.2)
  • Worst Case: 최악의 경우(α = 1.0, 모든 신호 토글)
  • Custom: 시뮬레이션 VCD 파일을 읽어서 실제 활동도 적용

Step 4: Report 생성
"Generate" 버튼 → power_report.txt 생성

Step 5: 결과 분석
보고서는 다음과 같은 형태입니다:


========================================
         POWER REPORT
========================================

Dynamic Power  [mW]:     350
Static Power   [mW]:     150
Total Power    [mW]:     500

Thermal:
Junction Temperature [°C]: 42.5
Ambient Temperature [°C]:  25.0

Power Report 해석

Dynamic Power: 회로 동작으로 인한 전력. 주파수/활동도에 따라 크게 변함.

Static Power: 누설 전류. 온도와 공급 전압에 의존.

Total Power: Dynamic + Static

Junction Temperature(Tj): 계산된 칩 표면 온도. 공식:

  • Tj = Tambient + Ptotal × θja
  • θja: 접합-주변 열저항(thermal resistance, 약 50°C/W for Basys 3)

추정값 vs 실측값

Vivado 추정은 다음 이유로 실측과 다를 수 있습니다:

  • 활동도 미지수: Vivado는 "typical" 활동도를 가정하지만, 실제 응용은 다를 수 있음
  • Post-Layout 효과: 배치/배선 후 글리치가 증가할 수 있음
  • 온도 변화: 실제 동작 중 온도가 변하면서 정적 전력도 변함

따라서 Vivado 추정값은 상대적 비교에 더 신뢰성이 있습니다. "설계 A가 설계 B보다 20% 절약한다"는 신뢰할 수 있지만, "정확히 0.5W"는 ±15% 오차를 고려해야 합니다.

21.4A 전압/주파수 조정과 클록 게이팅

지금까지 Vivado 도구로 전력을 측정하고 분석하는 방법을 배웠습니다. 이제 실제로 발열을 줄이는 기법들을 살펴봅시다. 이번 섹션과 다음 섹션에서는 5가지 기법을 다루는데, 먼저 런타임에 동적으로 제어할 수 있는 2가지 기법부터 시작합니다.

기법 1: DVFS (Dynamic Voltage Frequency Scaling)

원리: Pdyn = CV²f 공식에서 V를 동적으로 조정합니다.

V를 절반으로 줄이면 동적 전력은 **1/4로 감소**합니다. 예:

  • V = 1.0V, f = 100MHz, P = 0.5W
  • V = 0.7V, f = 60MHz, P ≈ 0.15W (70% 절감!)

구현: 보드의 전원 공급부(voltage regulator)를 제어하여 런타임에 전압을 조정합니다. Basys 3는 기본적으로 고정 1.0V이지만, 추가 레귤레이터를 연결할 수 있습니다.

한계: 전압을 낮추면 최대 동작 주파수도 감소합니다(timing margin 감소). 또한 레귤레이터 전환에 오버헤드가 발생하므로, 1ms 이상 동작할 때만 효과적입니다.

기법 2: Clock Gating (클록 게이팅)

원리: 비사용 모듈로의 클록을 차단하여 불필요한 신호 토글을 제거합니다.

예: Ch15의 메모리 컨트롤러가 유휴 상태(IDLE)일 때, 내부 FSM과 레지스터가 계속 토글되지 않도록 클록을 차단합니다.

구현: 단순합니다: 


module cg_cell (
  input  logic clk, en,
  output logic clk_out
);
  wire latch_out;

  // 클록이 low일 때만 en을 래치
  always_latch
    if (~clk) latch_out <= en;

  assign clk_out = clk & latch_out;
endmodule

효과: 모듈 활성도 50%일 때, 약 20~30% 동적 전력 절감. 정적 전력은 변화 없습니다.

한계: 글리치 제거가 복잡하고, 타이밍 검증이 까다롭습니다. Vivado의 자동 clock gating은 아직 기본 수준입니다.

DVFS vs Clock Gating 비교

DVFS와 Clock Gating은 모두 동적 전력을 줄이지만, 적용 시점과 복잡도가 다릅니다.

  • DVFS: 전체 칩의 전압/주파수를 조정. 효과는 크지만(70% 절감), 구현 복잡. 시스템 부팅 후 상태 전환 시간 필요(~1ms)
  • Clock Gating: 개별 모듈의 클록만 차단. 구현은 간단하지만 효과는 중간(20~30% 절감). 거의 즉시 적용 가능

실제 설계에서는 둘 다 함께 사용합니다: DVFS로 전역 최적화를 하고, Clock Gating으로 세부 최적화를 추가합니다.

💡 실무 팁

DVFS는 1ms 이상의 긴 시간 주기에 걸친 전력 절감에 효과적이고, Clock Gating은 나노초 단위의 짧은 유휴 구간을 활용합니다. 따라서 두 기법을 보완적으로 사용하면 전체 전력 절감을 극대화할 수 있습니다.

❓ 수강생 단골 질문

Q: DVFS와 Clock Gating을 둘 다 써야 하나요?

A: 가능하다면 좋습니다. 하지만 구현 난이도와 시간이 제한적이면, Clock Gating부터 시작하세요. 간단하면서도 효과가 실질적입니다.

21.4B 메모리/아키텍처 최적화

21.4A에서는 런타임에 동적으로 제어하는 DVFS와 Clock Gating을 배웠습니다. 이제는 설계 초기 단계에서부터 고려해야 할 3가지 기법을 살펴봅시다. 이들은 하드웨어 아키텍처를 결정하는 중요한 선택이며, 나중에 바꾸기 어렵습니다.

기법 3: 메모리 타입 선택

원리: 메모리 구현 방식에 따라 전력이 크게 다릅니다.

  • BRAM: 1회 접근 = 2ns(빠름), 에너지 = 10pJ/access
  • LUTRAM: 1회 접근 = 4ns(느림), 에너지 = 2pJ/access
  • 분산 RAM(Distributed RAM): 조합 읽기, 에너지 낮음, 속도 느림

설계에서 메모리 접근 빈도에 따라 선택:

  • 높은 빈도(매 사이클) → BRAM (속도 우선)
  • 낮은 빈도(수십 사이클마다) → LUTRAM (전력 우선)

Ch20-21 설계 선택: D-Cache는 LUTRAM, I-Cache는 BRAM으로 최적화했습니다.

기법 4: 파이프라인 깊이 조정

원리: 더 깊은 파이프라인은 높은 주파수를 가능하게 하지만, 더 많은 FF(플립플롭)를 필요로 합니다.

예:

  • 5-stage 파이프라인: 45MHz, CPI=1.2, 전력=0.4W, 면적=5,000 LUT
  • 8-stage 파이프라인: 65MHz, CPI=1.0, 전력=0.5W, 면적=6,500 LUT

더 깊은 파이프라인은 주파수와 CPI 개선의 이득이 전력 증가를 상쇄할 수 있습니다. 하지만 더 많은 면적(FF)을 사용합니다.

기법 5: 병렬화 vs 순차화

원리: 같은 작업을 더 많은 하드웨어(병렬)로 할지, 적은 하드웨어를 여러 번(순차)으로 할지 선택합니다.

예: 32-비트 곱셈

  • 병렬(1사이클): 32×32 multiplier, 면적 크, 전력 높, 지연 짧음
  • 순차(4사이클): 8×32 multiplier ×4번, 면적 작, 전력 낮, 지연 길음

설계 선택 기준: 이용 가능한 면적과 열 용량으로 선택합니다. Basys 3는 제한적인 FPGA이므로 순차 처리가 적합합니다. EPI(Energy Per Instruction) 메트릭으로 순차와 병렬의 에너지 효율을 비교하고, 그에 따라 선택하세요.

5가지 기법 종합 가이드

기법 3~5는 모두 설계 단계의 중요한 선택입니다. 어떻게 결정할까요?

  • 메모리 접근 빈도가 높다면? → BRAM 우선 (속도 중요)
  • 메모리 접근 빈도가 낮다면? → LUTRAM 우선 (전력 중요)
  • 높은 성능이 필요하다면? → 더 깊은 파이프라인 (주파수 우선)
  • 면적이 매우 제한적이다면? → 더 얕은 파이프라인 (면적 우선)
  • 열 제약이 심하다면? → 순차 처리 (전력 우선)
  • 열 여유도가 충분하다면? → 병렬 처리 (성능 우선)

최종 결정은 EPI 메트릭으로 비교합니다. 같은 작업을 처리할 때 명령당 소비 에너지가 가장 낮은 설계점을 선택하세요.

💡 실무 팁

대부분의 FPGA 설계에서는 메모리 선택이 가장 중요합니다. 왜냐하면 메모리 접근이 전체 전력의 30~50%를 차지하기 때문입니다. 파이프라인과 병렬화는 성능-면적 트레이드오프 측면에서 생각하세요.

21.5 열 관리와 설계 제약

전력은 궁극적으로 열로 변환됩니다. FPGA 설계에서 열 관리는 안정성과 신뢰성의 핵심입니다.

열 경로와 열저항

열이 흐르는 경로는:

  • 칩 내부 (Si 기판) → 칩 표면 (접합, junction) → PCB 보드 → 공기

각 단계에서 열저항(thermal resistance, θ)이 있어서 온도가 상승합니다:

Tj = Tambient + P × θja

여기서:

  • Tj: 접합 온도(junction temperature, 칩 표면)
  • Tambient: 주변 온도(실내 25°C)
  • θja: 접합-주변 열저항, Basys 3는 약 50°C/W
  • P: 소비 전력 (Watt)

예: P = 0.5W, Tambient = 25°C라면,
Tj = 25 + 0.5 × 50 = 50°C

Basys 3의 열 특성

Xilinx XC7A35T(Basys 3의 칩)는:

  • 최대 접합 온도(Tjmax): 85°C (초과하면 칩 손상 위험)
  • 권장 운영 범위: 0~70°C (충분한 여유도)
  • 실측 범위: 30~55°C (실제 학생 설계, 자연냉각)
  • 자체 냉각팬: 없음 (자연냉각만)
  • 온도 모니터: 가능(XADC, 정확도 ±5°C)

안심 문구: Basys 3는 대부분의 학생 설계에서 문제없이 동작합니다. 발열은 정상입니다. 설계가 일하고 있다는 증거입니다!

열 폭주(Thermal Runaway)

온도가 증가하면 누설 전류가 지수적으로 증가하고, 누설 전류의 증가는 더 많은 열을 발생시킵니다. 이는 **양의 피드백 루프**입니다:

T↑ → Ileak↑ → Pstatic↑ → T↑ (악순환!)

이를 막기 위해 현대 칩들은 열 폐쇄(thermal shutdown)를 구현합니다: Tj > 80°C이면 자동으로 클록을 낮추거나 전원을 차단합니다.

Basys 3는 이 기능을 구현하므로, Tj가 85°C를 초과하기 전에 자동으로 보호됩니다.

💡 실무 팁

Basys 3에는 온보드 INA226(I2C 전류 센서)가 있어서, 실측 전류를 읽을 수 있습니다. Python으로 I2C를 제어하면 정확한 전력 측정이 가능합니다.

21.6 Basys 3 실측 분석 및 최적화

지금까지 배운 개념을 실제 설계에 적용해봅시다. 3가지 벤치마크를 통해 전력 최적화의 효과를 측정합니다.

벤치마크 1: 순차 처리 (Sequential ALU Operations)

목표: 순수 ALU 연산만 반복 (메모리 접근 최소)

작업: 100,000회 덧셈 반복

  • x += 1, x += 2, ... (지역 변수 사용)
  • 메모리 접근 0회
  • 신호 활동도: 매우 높음 (매 사이클 토글)

예상 결과:

  • 동적 전력 ↑ (높은 활동도)
  • 정적 전력 ~ (온도 약간 상승)
  • 온도: 30~35°C
  • CPI: 1.0 (파이프라인 안정적)

벤치마크 2: 메모리 스래싱 (Cache Thrashing)

목표: 캐시 미스 반복 (메모리 접근 최악의 경우)

작업: 큰 메모리 영역에 순차 접근

  • 주소 0x1000, 0x2000, 0x3000, ... (캐시 라인별로 다름)
  • D-Cache 미스율: 99% (모든 접근이 미스)
  • 메모리 버스 포화

예상 결과:

  • 동적 전력 ↑↑ (메모리 컨트롤러 활동)
  • 정적 전력 ↑ (높은 온도)
  • 온도: 35~45°C
  • CPI: 10~15 (메모리 대기)

벤치마크 3: 최적화 후 (Optimized)

목표: Clock Gating + 캐시 친화적 코드

작업:

  • Clock Gating 활성화 (유휴 모듈로의 클록 차단)
  • 캐시 친화적 루프(연속 메모리 접근)
  • 불필요한 메모리 접근 제거

예상 결과:

  • 동적 전력 ↓ (Clock Gating 효과)
  • 정적 전력 ↓ (낮은 온도)
  • 온도: 28~32°C
  • CPI: 1.5 (캐시 히트율 90%+)

실측 vs 예상 괴리 분석

실제 측정할 때는 다음 요소들을 고려합니다:

  • Vivado 추정 ±15%: 상대값 비교 신뢰, 절대값은 검증 필요
  • INA226 측정 오차 ±3%: 가장 정확한 측정값
  • 온도 센서 오차 ±5°C: XADC 사용 시
  • 실제 주변 온도: 시험 당시 실내 온도에 의존

21.7 요약 및 Part 8 마무리

핵심 정리 (9가지)

  1. 동적 전력 = CV²f — 전압과 주파수에 크게 의존. V를 10% 낮추면 P는 19% 감소!
  2. 정적 전력 = Ileak × V — 온도에 지수적 의존. 온도 관리가 정적 전력 관리의 핵심.
  3. Vivado Power Analyzer — 자동 계산 도구. ±10~15% 오차 정상. 절대값보다 상대값 비교가 신뢰.
  4. PPA 트레이드오프 — 성능, 전력, 면적 3가지를 동시 최적화 불가. Pareto frontier에서 선택.
  5. 5가지 절약 기법:
    • DVFS: 70% 절감(효과 최고) ↔ 구현 복잡
    • Clock Gating: 20% 절감(효과/구현 균형)
    • 메모리 선택: 애플리케이션 의존적
    • 파이프라인 깊이: 성능/면적 트레이드오프
    • 병렬화: 면적/전력 트레이드오프
  6. 열 관리 — Tj = Tambient + P × θja. Basys 3는 50°C/W. 안전 여유도 충분.
  7. 에너지 효율(EPI) — EPI = P × CPI / f. 절대 전력만큼 중요.
  8. 실측 벤치마크 — 3가지 패턴(순차/스래싱/최적화)으로 최악의 경우에 대비.
  9. FPGA vs ASIC — FPGA는 ASIC보다 전력 효율이 낮지만(약 10배), 개발 시간이 짧고 유연합니다.

ch21_design_optimization.py — PPA 탐색 자동화 (선택)


# ch21_design_optimization.py
# Python을 사용한 PPA 설계점 탐색 및 Pareto frontier 계산

import matplotlib.pyplot as plt

# 설계점 예시 (Real 기반)
designs = [
    {"name": "A",     "perf_mhz": 45,  "power_mw": 400,  "area_lut": 5000},
    {"name": "B",     "perf_mhz": 60,  "power_mw": 500,  "area_lut": 6500},
    {"name": "C",     "perf_mhz": 80,  "power_mw": 700,  "area_lut": 8000},
    {"name": "D",     "perf_mhz": 40,  "power_mw": 300,  "area_lut": 4000},
]

# Pareto frontier 계산 (다중 목적 최적화)
# 목표: 성능↑, 전력↓, 면적↓ (동시만족 불가)

def is_dominated(design, others):
    """design이 다른 설계점에 지배당하는지 확인"""
    for other in others:
        if (other['perf_mhz'] >= design['perf_mhz'] and
            other['power_mw'] <= design['power_mw'] and
            other['area_lut'] <= design['area_lut'] and
            (other['perf_mhz'] > design['perf_mhz'] or
             other['power_mw'] < design['power_mw'] or
             other['area_lut'] < design['area_lut'])):
            return True
    return False

pareto = [d for d in designs if not is_dominated(d, designs)]

# 결과 출력
print("Pareto Frontier (최적 설계점):")
for d in sorted(pareto, key=lambda x: x['perf_mhz']):
    epi = d['power_mw'] / (d['perf_mhz'] / 1000)  # 단순화
    print(f"  {d['name']}: {d['perf_mhz']}MHz, {d['power_mw']}mW, {d['area_lut']}LUT, EPI={epi:.1f}")

# 그래프 시각화 (2D: 성능 vs 전력)
perf = [d['perf_mhz'] for d in pareto]
power = [d['power_mw'] for d in pareto]
names = [d['name'] for d in pareto]

plt.figure()
plt.scatter(perf, power)
for i, name in enumerate(names):
    plt.annotate(name, (perf[i], power[i]))
plt.xlabel('Performance (MHz)')
plt.ylabel('Power (mW)')
plt.title('PPA Trade-off: Performance vs Power (Pareto Frontier)')
plt.grid()
plt.show()
